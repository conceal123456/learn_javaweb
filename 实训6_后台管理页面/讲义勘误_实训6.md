## 本次复核结论

1. **讲义确实有错，而且不止一处。** 共 13 条：**严重 2 条**、**一般 5 条**、**提示/没说清 6 条**。其中前两条是"照着抄就跑不出第 2 页目标界面"的硬伤。
2. **最严重的一条**：整份 `Manage.vue`（第 4–10 页，五个步骤逐段给出）**从头到尾没有 `<router-view />`**，右侧内容区一直是"搜索区域 / 数据展示区域 / 分页区域"三块占位 div。结果：`Detail.vue` 写了但**永远不会渲染**，`/manage` 和 `/manage/detail` 两张截图一模一样；而第 2 页"最后实现的界面"图里右侧明明白白是表格界面 —— **讲义自己的目标图和自己的代码互相矛盾**。
3. **第二严重**：第 10 页两个子菜单项 `<el-menu-item>管理员信息</el-menu-item>`、`<el-menu-item>普通用户信息</el-menu-item>` **漏了必填 prop `index`**。实测挂载时两条 `[Vue warn]: Missing required prop: "index"`，点击时再补一条 `Invalid event arguments: event validation failed for event "click"`，地址栏不动、右侧不动、该项也不进高亮态。
4. **"三条 index 都写 `/manage`"的现象要分场景说**（旧文档的说法不够准，本次实测三种场景）：
   - **讲义字面代码**（`/manage` 没有默认子路由）：能停在 `/manage`，**三条同时高亮**（已截图）；
   - **仓库修正版 + 从 `/manage/admin` 点"管理首页"**：会被重定向到 `/manage/detail`，此时**三条同时高亮并"粘住"**——等 2 秒不恢复，再点"内容展示"也修不回来，只有整页刷新才能恢复（已逐帧实测，根因是 element-plus 2.14.7 的 `menu.mjs:216-221`）；
   - **仓库修正版 + 直接进入 `/manage`**：一路重定向到 `/manage/detail`，高亮只有"内容展示"（这一种是正常的）。
   所以准确说法是"**这个 bug 会以不同形态出现**"，而不是"三条都不亮"（旧文档 `构建验证_实训6.md` 第 38 行那种表述要改）。
5. **排版/字数层面的重复错误不是错误**：`flex` 布局（第 5、6、8 页）、`min-height: calc(100vh - 60px)`、`flex:1; width:0`、`el-table`+`el-pagination` 配置、`el-menu` 的 `router` 写法、布尔属性一律写成裸属性（`stripe`、`background`、`router`，没有误写成 `:stripe`/`:background`）—— **这些都对**，已在最后"确认无误的部分"列出。
6. **旧文档需要修正的两处**（不改旧文件，只在本报告说明）：① `构建验证_实训6.md` 第 38 行"工程加了 `path:''` 之后根本停不在 `/manage`，所以复现不出三条同时高亮"——**讲义原版能复现**，三条同时亮我已实测截图，问题只是"这个仓库里看不到"；② 同表第 36 行说"两张截图完全相同"，实测 `/manage` 与 `/manage/detail` 的**菜单高亮不同**（三项 vs 一项），相同的是右侧内容区。

## 一、严重问题

### 勘误 1：`Manage.vue` 全文缺 `<router-view />`，Detail.vue 永远不渲染（严重）

**【讲义原文】**
- 第 3 页「整体开发思路」第 6 条：**"配置嵌套路由，点左侧菜单，右边切换内容。"**
- 第 4–10 页「一、manage.vue 后台管理页面布局」五个步骤给出的 `Manage.vue` 完整代码，右侧内容区始终是第 8 页这三块占位：

```vue
<!--第四步：右侧完整数据展示区域-->
<div style="flex:1;width:0;background-color:#f5f7ff;padding:10px;display:flex;flex-direction:column;min-height:calc(100vh-60px)">
  <div style="padding:10px;font-size:22px">搜索区域</div>
  <div style="flex:1;display:flex;align-items:center;justify-content:center;font-size:48px">数据展示区域</div>
  <div style="padding:10px;font-size:22px">分页区域</div>
</div>
```
- 第 9、10 页「5. 细节部分 导航栏的设计」给出左侧菜单完整代码，也**没有**任何一句说"把上面三块占位换成 `<router-view/>`"。

**【问题】** 讲义把嵌套路由只配了一半：`router/index.js`（第 13 页）里给 `/manage` 配了 `children`，`Detail.vue`（第 11–12 页）也写好了，但父组件 `Manage.vue` 里**没有子路由出口**。`<router-view/>` 是嵌套路由的渲染容器，没有它，命中的子路由组件没有任何地方可渲染 —— 页面不报错，只是右侧永远停在三块占位。

另外讲义的第 2 页"最后实现的界面"截图里，右侧就是搜索框 + 表格 + 分页（Detail 的内容），说明**目标效果本身就要求有 `<router-view/>`**，讲义却没有写这一步。

**【实测证据 / 原理】**
- 讲义原样代码 + `localhost:5186/manage`：右侧 `搜索区域 / 数据展示区域 / 分页区域`，`.el-input__inner` **不存在**（Detail 没渲染）。截图：`.extract/verify/shots/lab6_literal_manage.png`
- 点"内容展示"（`index="/manage/detail"`）→ 地址栏确实变成 `/manage/detail`，但右侧**仍然**是三块占位，`.el-input__inner` 依然不存在。截图：`.extract/verify/shots/lab6_literal_detail.png`
- 对照组（只做一件事：把三块占位换成 `<router-view/>`，其余保持讲义原样）：`/manage/detail` 立刻渲染出 Detail —— 搜索框 placeholder 是"请输入中药材名称查询"、表格 9 行、分页"共 50 条"。截图：`.extract/verify/shots/lab6_variantB_detail.png`
- 仓库已有的两张截图 `演示截图/06_讲义字面版_manage.png`、`06_讲义字面版_detail.png` 结论一致（右侧都是三块占位），本次复测得到同样结果。

**【正确写法】**

```vue
<!-- 第四步：右侧内容区，占位 div 换成子路由出口 -->
<div style="flex: 1; width: 0; background-color: #f5f7ff; padding: 10px;
            display: flex; flex-direction: column; min-height: calc(100vh - 60px)">
  <router-view />
</div>
```

（仓库修正版见 `实训6_后台管理页面/工程/admin-layout/src/views/Manage.vue:56-60`。）

**【影响程度】** ★★★ 严重。学生按讲义的五个步骤一步步做完，会得到"左边能点、地址栏会变、右边永远不变"的半成品；不补这一步，本讲的"点左侧菜单右边切换内容"这个核心目标就达不成，实验报告里的 Detail 截图也拍不出来。

### 勘误 2：两个子菜单项漏写必填 prop `index`，点击无任何反应（严重）

**【讲义原文】** 第 10 页（第 9 页末尾开始，第 10 页续）：

```vue
<el-sub-menu index="1">
  <template #title>
    <el-icon><User /></el-icon>
    <span>用户管理</span>
  </template>
  <el-menu-item>管理员信息</el-menu-item>
  <el-menu-item>普通用户信息</el-menu-item>
</el-sub-menu>
```

**【问题】** Element Plus 的 `el-menu-item` 把 `index` 声明为**必填 prop**（`index: { type: String, required: true }`）。讲义这两项没写 `index`，等于：
1. 组件挂载时 Vue 报 `Missing required prop: "index"`；
2. 菜单项内部的点击回调拿不到"我是哪一项"，`el-menu` 的 `router` 模式没有可 `push` 的路径 → **点了没反应**；
3. 该项也不会进入选中态（`is-active` 不会出现）。

注意这不是"报错崩溃"，而是一种**静默失效**：页面看起来完全正常，只有控制台有告警。

**【实测证据 / 原理】** `localhost:5186/manage` 首次加载控制台两条（节选）：

```
[Vue warn]: Missing required prop: "index"
  at <ElMenuItem >
  at <ElSubMenu index="1" >
  at <ElMenu router="" default-active="/manage" default-openeds=["1"] >
```

在 `/manage/detail` 点"管理员信息"：

| 观测项 | 点击前 | 点击后 |
|---|---|---|
| `location.pathname` | `/manage/detail` | `/manage/detail`（不变） |
| `history.length` | 43 | 43（不变，压根没发生导航） |
| 高亮项 | `内容展示` | `内容展示`（没有变成"管理员信息"） |
| 新增控制台告警 | — | `[Vue warn]: Invalid event arguments: event validation failed for event "click"` |

（"点击时多一条 `Invalid event arguments`"这一点旧文档没写，是本次新发现的证据：`el-menu-item` 的 click 回调签名期望收到菜单项对象，实际收到 `MouseEvent`，参数校验失败后直接返回。）

**【正确写法】**

```vue
<el-menu-item index="/manage/admin">管理员信息</el-menu-item>
<el-menu-item index="/manage/staff">普通用户信息</el-menu-item>
```

同时要在 `router/index.js` 的 `children` 里补上对应子路由，否则点得动但右侧还是空白：

```js
{ path: 'admin', name: 'admin', meta: { title: '管理员信息' }, component: () => import('../views/Admin.vue') },
{ path: 'staff', name: 'staff', meta: { title: '普通用户信息' }, component: () => import('../views/Staff.vue') },
```

**【影响程度】** ★★★ 严重。这是"点了没反应"型 bug，初学者很容易以为是浏览器/缓存问题，既不报红也不提示，排错成本高。

## 二、一般问题

### 勘误 3：管理首页/个人信息/退出登录 三条 `index` 都是 `/manage`，高亮行为与所在路由配置强相关（一般）

**【讲义原文】** 第 9–10 页：

```vue
<el-menu-item index="/manage">
  <el-icon><House /></el-icon>
  管理首页
</el-menu-item>
...
<el-menu-item index="/manage">
  <el-icon><UserFilled /></el-icon>
  个人信息
</el-menu-item>
<el-menu-item index="/manage">
  <el-icon><SwitchButton /></el-icon>
  退出登录
</el-menu-item>
```

**【问题】** `el-menu` 的高亮判断是**字符串相等**：`菜单项的 index === 当前 activeIndex`。三项共用 `/manage`，同时"个人信息""退出登录"这两项从语义上也不该指向后台首页（它们是"个人中心""登出"动作，根本没有对应路由）。讲师意图显然是"先占个位"，但代码写成了三条一样的 index，结果是：
- **按讲义原样代码**（`/manage` 没有默认子路由）：只要能停在 `/manage`，三条**同时**变蓝；
- **按仓库修正版**（`children` 里加了 `{ path: '', name: 'manageHome', redirect: '/manage/detail' }`）：一进 `/manage` 就被重定向走，这三条**都不亮**；在 `/manage/detail` 点"个人信息"，`push('/manage')` 被重定向回当前页、构成重复导航被拦下 → 地址栏、高亮**都不动**。

**【实测证据 / 原理】** 三种配置各测一遍（element-plus **2.14.7**、vue-router **5.4.0**）：

| 场景 | 操作 | 结果 |
|---|---|---|
| A. 讲义字面代码（无默认子路由） | 直接访问 `/manage` | 高亮 = **`["管理首页","个人信息","退出登录"]`**（三条同时亮） |
| A. 讲义字面代码 | 从 `/manage/detail` 点"个人信息" | 跳到 `/manage`（`history.length` 43→44），高亮变回三条 |
| B. 仓库修正版（有 `{path:'',redirect:'/manage/detail'}`） | 先在 `/manage/admin`（高亮"管理员信息"），再点"管理首页" | 落到 `/manage/detail`，高亮 **`["管理首页","个人信息","退出登录"]`**（三条粘住），`document.title` 却是"内容展示" |
| B. 同上 | 等 2 秒 | 三条仍然亮（不自动恢复） |
| B. 同上 | 再点"内容展示" | **仍然三条亮**（修不回来） |
| B. 同上 | 刷新页面 | 恢复成只有"内容展示" |
| C. 仓库修正版 | 直接访问 `/manage` | 重定向到 `/manage/detail`，高亮只有"内容展示"（正常） |

**根因**（可回源核对）：Element Plus 2.14.7 `node_modules/element-plus/es/components/menu/src/menu.mjs:216-221`：

```js
if (props.router && router) {
  const route = menuItem.route || index;
  const routerResult = router.push(route).then((res) => {
    if (!res) activeIndex.value = index;   // ← 成功时把 activeIndex 硬写成 "index"
    return res;
  });
```

- 点"管理首页"时 `index="/manage"`，`router.push('/manage')` 被**重定向**到 `/manage/detail` 且算"导航成功"→ `res` 为 `undefined` → `!res` 成立 → `activeIndex.value = "/manage"`，把 `:default-active` 那个 watch 刚设好的 `/manage/detail` **覆盖掉** → 三条 index 为 `/manage` 的项一起亮；
- 之后点"内容展示"（`index="/manage/detail"`）时目标就是当前路径，属**重复导航**，`router.push` 返回一个 NavigationFailure（**真值**）→ `!res` 不成立 → `activeIndex` 不再更新 → 就"修不回来"了。

**【正确写法】** 一个 index 对应一个真实路径；"个人信息/退出登录"要么做成独立路由，要么不用 `el-menu-item`：

```vue
<el-menu-item index="/manage/detail">内容展示</el-menu-item>
<el-menu-item index="/manage/admin">管理员信息</el-menu-item>
<el-menu-item index="/manage/staff">普通用户信息</el-menu-item>
<!-- 个人信息 / 退出登录 不是路由跳转，用普通菜单项或放头部下拉 -->
```

**【影响程度】** ★★ 一般。视觉上"三条一起变蓝"很扎眼，答辩时会被问；且**刷新才能恢复**像个"玄学 bug"。它不影响路由跳转本身，所以列一般。

### 勘误 4：`/manage` 没有默认子路由，补了 `<router-view/>` 后"管理首页"点进去右侧仍是空白（一般）

**【讲义原文】** 第 13 页 `router/index.js`：

```js
{ path: '/manage', name: 'manage', meta:{title:'后台管理'}, component: () => import('../views/Manage.vue'), children:[
    { path: 'user', ... }, { path: 'goods', ... }, { path: 'orders', ... },
    { path: 'detail', name: 'detail', component: () => import('../views/Detail.vue') },
] }
```

**【问题】** 讲义在 `children` 里**没有配 `path: ''` 的默认子路由**（也没有 redirect），而左侧菜单第一项"管理首页"的 `index` 恰好就是 `/manage`。于是即便学生按勘误 1 补上了 `<router-view/>`，点"管理首页"也只能渲染父组件本身，子路由出口是空的 —— 右侧一片空白，比"三块占位"更像坏了。

**【实测证据 / 原理】** 实验工程变体 B（补了 `<router-view/>`、其余保持讲义原样）访问 `localhost:5186/manage`：

```js
{
  path: "/manage",
  rightText: "",                      // 右侧完全空白
  rightHTML: "<!-- ... --><!---->",   // router-view 渲染出来是空注释节点
  active: ["管理首页", "个人信息", "退出登录"]
}
```

（vue-router 对"父路由自身匹配、但没有任何子路由匹配"的情况**不会给任何告警**，只会渲染空出口。）

**【正确写法】**

```js
children: [
  { path: '', name: 'manageHome', redirect: '/manage/detail' },  // 关键的一行
  { path: 'detail', ... },
  ...
]
```

**【影响程度】** ★★ 一般。是勘误 1 的"连锁坑"：只补 `<router-view/>` 还不够，还得补默认子路由，否则"管理首页"这一项是坏的。

### 勘误 5：第 2 页"最后实现的界面"与代码不自洽（9 行数据却写"共 50 条"、没做真分页）（一般）

**【讲义原文】**
- 第 2 页"最后实现的界面"截图：表格 9 行（霍山石斛…断血流），底部分页 **"共 50 条  10条/页  1 2 3 4 5  前往 [1] 页"**。
- 第 11–12 页 `Detail.vue`：

```js
tableData: [ /* 只有 9 条 */ ],
pageNum: 1,
pageSize: 10,
total: 50
```

**【问题】**
1. `:total="50"` 而 `tableData` 只有 9 条 —— 分页器会老老实实算出 5 页，但表格 `:data="data.tableData"` 传的是**全量**数组，**没有按 `pageNum/pageSize` 切片**，所以翻页只改页码、数据一行不变。讲义正文和代码注释都**没有**说明"这里只做分页 UI、不是真分页"，学生很容易以为分页坏了。
2. 第 2 页目标图里"共 50 条"是**代码跑不出来的数字**（代码只有 9 条数据）—— 目标图与代码不一致，属讲义自相矛盾的证据之一。

**【实测证据 / 原理】** 实验工程变体 B（`/manage/detail`）：
- 初始：`.el-table__body tbody tr` = **9 行**，分页文案 `共 50 条 10条/页 1 2 3 4 5 前往 页`，当前页 1。
- 点页码"2"后：当前页变 `2`，**行数仍是 9**，首行仍是"霍山石斛 安徽六安霍山县 2027-10-11"。

**【正确写法】** 二选一，别停在中间：

```js
// 方案A：只做 UI → total 和数据条数对齐，别骗人
total: 9
// 方案B：真分页 → 用计算属性切片
const pageData = computed(() =>
  data.tableData.slice((data.pageNum - 1) * data.pageSize, data.pageNum * data.pageSize)
)
// 模板：<el-table :data="pageData" stripe>
```

**【影响程度】** ★★ 一般。功能不是"错"（讲义只要求分页 UI），但**目标图与代码不自洽**会让学生在验收时对不上数。

### 勘误 6：`Detail.vue` 用了 `class="card"`，但全讲义没给 `.card` 样式（一般）

**【讲义原文】** 第 11 页 `Detail.vue` 三个区块都用 `class="card"`：

```vue
<div class="card" style="margin-bottom: 5px">
  <el-input .../>
  <el-button type="primary">查 询</el-button>
  ...
</div>
```
第 12 页 `<style scoped></style>` —— **空的**。

**【问题】** `card` 这个类名在讲义里只出现、不定 义，学生照抄后三个区块没有任何卡片外观（白底/圆角/内边距/阴影都没有）。讲义也没有说"这个类留给你自己写样式"。

**【实测证据 / 原理】** 实验工程变体 B 的 `/manage/detail`，取第一个 `.card` 的 computed style：

```js
{ background: "rgba(0, 0, 0, 0)", border: "0px none", borderRadius: "0px",
  padding: "0px", boxShadow: "none" }
```
（Element Plus 自带的表格/分页/按钮本身有白底，所以"看着还行"，但 `.card` 确实没生效。）

**【正确写法】**

```vue
<style scoped>
.card {
  background: #fff;
  border-radius: 6px;
  padding: 12px;
  box-shadow: 0 0 6px rgba(0, 0, 0, 0.08);
}
</style>
```

**【影响程度】** ★★ 一般。纯观感问题，但"给了类名不给样式"会让学生反复怀疑自己抄漏了。

### 勘误 7：`prefix-icon="Search"` 与 `import { Search }` 自相矛盾，图标能显示是靠"全局图标注册"这个隐藏前提（一般）

**【讲义原文】** 第 11 页：

```vue
<el-input ... prefix-icon="Search"></el-input>
...
<script setup>
import { reactive } from "vue";
import { Search } from "@element-plus/icons-vue"
```

**【问题】** 讲义 `import { Search }` 了却**从没用到**这个变量（模板里写的是字符串 `"Search"`），属自相矛盾。而字符串形式能生效的前提是**图标被全局注册过**（`app.component('Search', Search)`），这来自**实训3 的 `main.js`**，讲义本讲从头到尾没提。

**【实测证据 / 原理】** 实验工程（`main.js` 保留了 `for (const [key, component] of Object.entries(ElementPlusIconsVue)) app.component(key, component)`）中，`.el-input__prefix svg` 存在 → 图标确实显示，证明"字符串能找到组件"依赖全局注册。同一份讲义里的 `<House />`、`<DataAnalysis />`、`<User />`、`<UserFilled />`、`<SwitchButton />` 五个菜单图标也是**没有 import 的**，走的是同一条隐藏前提。

**【正确写法】** 二选一，别混：

```vue
<!-- 方式1：显式引入组件（推荐，不依赖全局注册） -->
<el-input :prefix-icon="Search" />   <!-- 注意冒号 -->
<script setup>
import { Search } from '@element-plus/icons-vue'
</script>
```

**【影响程度】** ★★ 一般。若学生没做实训3 的全局注册，图标和输入框前缀会静默消失（表现为"讲义上有图标我没有"），排错方向很容易跑偏。

### 勘误 8：讲义默认"这是接着实训5 的工程做的"，但没写（提示）

**【讲义原文】** 第 13 页 `router/index.js` 直接引用五个页面：`Home.vue`、`Test.vue`、`User.vue`、`Goods.vue`、`Orders.vue`；本讲正文只讲了 `Manage.vue` 和 `Detail.vue` 两个。

**【问题】** 其中 `User.vue / Goods.vue / Orders.vue` 是**实训5**（四、嵌套路由）里创建的，`Home.vue / Test.vue` 来自更早的实训。实训6 讲义没有一句"请先把实训5 的工程拷过来/在同一个工程里继续"。

**【实测证据 / 原理】** 仓库中这三个页面存在于实训5 工程（`实训5_Vue-Router实现路由跳转/工程/vue-router/src/views/`），实训6 工程的同名文件是占位页。若从空工程起手，`npm run dev` 会直接报 `Failed to resolve import "../views/User.vue"`。

**【影响程度】** ★ 提示。属于"上课时会口头补充"的信息，但自学/补做时是硬门槛。

### 勘误 9：全局守卫里的 `next()` 在 vue-router 5 已废弃（提示）

**【讲义原文】** 第 13 页：

```js
router.beforeEach((to, from, next) => {
  document.title = to.meta.title;
  next()
})
```

**【问题】** 讲义按 vue-router 4 的三参数写法讲守卫。本工程实际安装的是 **vue-router 5.4.0**（`实训6_后台管理页面/工程/admin-layout/node_modules/vue-router/package.json`），`next()` 已被标记为废弃：**功能仍然可用**，但开发模式下每次导航都会打印一条告警。

**【实测证据 / 原理】**
- 浏览器控制台实测（`localhost:5186`，每次导航一条）：

```
[VUE_ROUTER_R0025] The `next()` callback in navigation guards is deprecated.
├▶ fix: Return the value instead: `next()` becomes `return`, `next(false)` becomes `return false`,
│        `next("/path")` becomes `return "/path"`.
╰▶ see: https://router.vuejs.org/guide/advanced/navigation-guards.html#Optional-third-argument-next
```

- 源码依据（`node_modules/vue-router/dist/devtools-CN5uWJaH.js:560`）：守卫被调用时，dev 会用 `withDeprecationWarning(...)` 包一层 `next`，第一次调用触发 `VUE_ROUTER_R0025`；`dist/` 生产包里这段被 `process.env.NODE_ENV !== "production"` 剔除（在仓库已构建的 `dist/assets/*.js` 里搜不到该文案）→ **只在 dev 模式告警，生产构建不告警**。
- 同时实测到"漏调 `next()` 会静默卡死"：守卫声明了第三个参数却不调用，导航 Promise 永远不 resolve，页面不切换、不报错。

**【正确写法】**

```js
router.beforeEach((to) => {
  document.title = to.meta.title || '中药材后台管理系统'
  // 不调用 next()，直接 return（不返回值 = 放行）
})
```

**【影响程度】** ★ 提示。不影响运行，但控制台红黄一片，且"废弃 API"应该讲清楚。

### 勘误 10：`detail` 子路由没配 `meta`，标题不会变成"内容展示"（提示）

**【讲义原文】** 第 13 页 `children` 里只有 `detail` 一项没有 `meta`：

```js
{ path: 'detail', name: 'detail', component: () => import('../views/Detail.vue') },
```

**【问题】** 本讲核心卖点是"用守卫改标签标题"，但四大子路由里唯一没有 `title` 的偏偏是**菜单上真正会点的那一个**（内容展示）。学生切到 `/manage/detail` 时看到的标签还是父级的"后台管理"，容易以为守卫失效。

**注意别写错结论**：这里**不是** `undefined`。vue-router 会合并父子级 `meta`，子级没写就继承父级的 `title:'后台管理'`；`undefined` 只出现在**整条匹配链都没有 meta** 的顶级路由（`/home`、`/test`）上。

**【实测证据 / 原理】** 讲义字面代码访问 `/manage/detail`：`document.title === "后台管理"`（类型 string，不是 "undefined"）；访问 `/home` 才会变成 `"undefined"`。

**【正确写法】** `{ path: 'detail', name: 'detail', meta: { title: '内容展示' }, component: ... }`

**【影响程度】** ★ 提示。

### 勘误 11：头部文案三处不一致（提示）

**【讲义原文】**
- 第 2 页"最后实现的界面"图：左"**中药材后台管理系统**"，右"头像 + **系统管理员**"；
- 第 5 页第二步代码：`<span style="font-size:22px;color:white">网站logo</span>`、`<span style="color:white">后台用户</span>`；

**【实测证据 / 原理】** 第 2 页图已存为 `实训6_后台管理页面/勘误图/讲义_目标界面.jpg`（可放大核对）；第 2 页与第 10 页图片取自 PDF 第 2、9–10 页；代码文本来自 PDF 第 5 页文本层。

### 勘误 12：`next()` 之外的版本相关性 —— `el-menu` 的 `:default-active` 名字骗人（提示，供讲课补充）

**【讲义原文】** 第 6、8、9 页反复出现：

```vue
<el-menu router :default-active="router.currentRoute.value.path" :default-openeds="['1']" style="border:0">
```

**【问题】** 两个属性都带 `default`，行为却相反，讲义没说：
- `:default-active`：**名字像"只读初值"，实际是响应式的**（Element Plus `menu.mjs` 里有 `watch(() => props.defaultActive, ...)`），所以高亮会跟着路由变；
- `:default-openeds`：**确实只取一次初值**（挂载时 `props.defaultOpeneds.slice(0)`），运行时改数组不会展开/收起。

**【实测证据 / 原理】** 实测：`/manage` 停在三项高亮 → 点"内容展示" → 高亮就变成只有"内容展示"（说明 `default-active` 随路由响应）；仓库修正版从 `/manage` 重定向到 `/manage/detail` 后高亮同样正确。

**【正确写法】** 讲义/讲课补一句区别即可，代码本身不用改。

**【影响程度】** ★ 提示。不写也不会错，但学生问"为什么 default 还能变"时讲义答不上来。

### 勘误 13：`index.js` 配了 `user/goods/orders` 三条子路由，但左侧菜单一个入口都没有（提示）

**【讲义原文】** 第 13 页 `router/index.js` 里给 `/manage` 配了四个子路由：

```js
children:[
  { path: 'user', name: 'user', meta:{title:'用户列表'}, component: () => import('../views/User.vue') },
  { path: 'goods', ... }, { path: 'orders', ... },
  { path: 'detail', name: 'detail', component: () => import('../views/Detail.vue') },
]
```

而第 9–10 页的菜单只有：管理首页（`/manage`）、内容展示（`/manage/detail`）、用户管理（含两个**无 index** 的子项）、个人信息（`/manage`）、退出登录（`/manage`）。

**【问题】** `user / goods / orders` 三条子路由**没有任何菜单项指向它们**（"用户管理"子菜单里的两项既没 `index` 也没有路由）。结果是这三个页面只能靠手敲 URL 才能访问，而且访问后**菜单高亮 0 条**（没有 index 与之相等），看起来像"页面丢了"。

**【实测证据 / 原理】** 仓库修正版（补过 admin/staff 路由）实测：

| 访问 | 页面渲染 | 菜单高亮 |
|---|---|---|
| `/manage/user` | 正常（右侧渲染 User.vue） | **`[]`（0 条）** |
| `/manage/goods` | 正常 | **`[]`** |
| `/manage/orders` | 正常 | **`[]`** |

**【正确写法】** 要么把菜单项补上（`<el-menu-item index="/manage/user">用户列表</el-menu-item>` 等），要么把用不到的 `children` 删掉，别留"配了路由但进不去"的中间态。

**【影响程度】** ★ 提示。不影响主流程，但学生对照 `index.js` 找页面时会困惑；也让"用户管理"这个菜单形同虚设。
