## 二、菜单点击实测：3 个菜单项跳向不存在的路由

| 菜单项 | `index` | 路由表里有没有 | 点击后实测 |
|---|---|---|---|
| 管理首页 | `/manage` | 有（`path:''` → Index.vue） | 正常：URL `/manage`，渲染 Index，高亮唯一 |
| 内容展示 | `/manage/detail` | 有 | 正常 |
| 管理员信息 | `/manage/user` | 有 | 正常：渲染 User.vue，高亮唯一，标题"用户列表" |
| **普通用户信息** | `/manage/ordinary` | **没有** | URL 变成 `/manage/ordinary`、标题变兜底"后台管理系统"、**整页空白**，控制台 `[Vue Router warn]: No match found for location with path "/manage/ordinary"` |
| **王陈飞 2024207335102**（个人信息） | `/manage/profile` | **没有** | 同上，空白页 + `No match found … "/manage/profile"` |
| **退出登录** | `/manage/logout` | **没有** | 同上，空白页 + `No match found … "/manage/logout"` |

即：工程把这三条的 `index` 从实训6 的 `/manage` 改成了独立路径（比实训6 好，不再三条同 index），但**只改了菜单、没在 `children` 里补路由**，于是点下去是"跳到一个 404 路由 → 整个页面空白"，不是"没反应"。刷新后直接访问 `/manage/ordinary` 也是白屏（无 catch-all 路由）。

证据：`b_lab7_05_click_ordinary.png`、`b_lab7_08_notfound_route.png`；JSON 的 `clicks.*.console`。

## 四、接口 / 代理 / 404 实测

- `src` 下**没有** `axios`、没有 `fetch(`、没有 `XMLHttpRequest`（`package.json` 也没有 axios 依赖）——前端页面用的全是写死的 `tableData`。
- `vite.config.js` **没有** `server.proxy` 配置。
- CDP 网络抓包：一次性收集 534 条请求（含多次页面刷新），**发往 8080 或 `/api/` 的请求数 = 0**，HTTP 状态码 ≥400 的响应 = **0**。

结论：任务卡里"实训7 前端请求后端、后端未启动会 404/跨域"的预期**不适用于本工程**——它压根不发请求；所以"后端是否启动"对前端页面没有任何影响。真要做前后端联调，需要自己加 axios + Vite 代理（补基础训练营 L6 的内容，讲义7 未要求）。

## 七、与讲义的关系 / 结论

1. `实训7__新建SpringBoot项目.docx` 全文没有前端页面章节，只讲"建工程 → 配 Maven/数据库 → 写接口 → 统一返回 → 全局异常 → 字符集"，所以**前端这块没有"讲义对不对"的问题**；本讲的正确做法就是"前端不动"。
2. 讲义里唯一涉及前端的一句是"所有接口统一返回 Result，前端只需固定读取 `code`、`message`、`data`"。工程实际字段是 **`msg`**（后端 `Result.java`），讲义文字写 `message` 与代码不一致——这属后端/讲义勘误范畴，前端若真去接接口要写 `res.msg`。详见后端验证同学的报告。
3. 本前端工程的已知问题与建议：
   - 3 条菜单（普通用户信息/个人信息/退出登录）没有对应路由 → 点击白屏。建议补 `children`（`ordinary`、`profile`、`logout` 各配一个页面）或把这三项改成非路由按钮（`@click`）。
   - 缺 404 兜底路由：任意错误地址都会整页空白，建议加 `{ path: '/:pathMatch(.*)*', redirect: '/home' }` 或 404 页。
   - Test.vue 用 `reactive({id: router.currentRoute.value.query.id})` 只取一次，若在同一页面继续改 query 不会刷新（实测从 `/test?id=1` 直接改地址会重新加载页面，所以未暴露）；实训5 已改用 `useRoute()` 响应式取值，可对齐。
