## 2. 知识点精讲

### 2.1 四样软件与 Maven"不用安装"

**① 讲义怎么说** —— "一、所需软件"：`IDEA2025 、Maven3.8、JDK21`，再装 `Mysql5.7`（root/123456），Navicat 建库 `xm-pro`。"三、2"又写：**"Maven不需要安装，把软件拷贝到相应的文件夹（不要中文命名的）就行"**。

**② 一句话讲透** —— 四个东西像做菜：**JDK 是灶台**（没它一行 Java 都跑不了）；**Maven 是采购员兼仓库管理员**（大家说"我要 spring-web"，它跑去网上把几十个 jar 买回来摆好）；**IDEA 是厨房**（写字下锅装盘，但它本身不会做菜）；**MySQL 是冰箱**（本讲还没往里放东西，但灶台要先接上冰箱的电）。Maven 是**绿色压缩包**——没有安装向导，解压到英文路径 + 把 `bin` 加进 PATH 就算装好了。

**③ 示例代码** ——

```bash
java -version
mvn -v
mysql --version
```

```bash
# Maven 环境变量（系统属性 → 高级 → 环境变量）
MAVEN_HOME = D:\software\apache-maven-3.8.1     # 新建系统变量
Path       += %MAVEN_HOME%\bin                  # 编辑 Path，新增这一项
```

**④ 逐行拆解** ——
- `java -version` 只看第一行，要看到 `21.x`；显示 `1.8.0_xxx` 说明 PATH 里是 Java 8。
- `mvn -v` 信息量最大：同时告诉大家 Maven 版本、**装在哪个目录**、**用的是哪个 JDK**。若它的 `Java version` 与 `java -version` 不一致，说明 `JAVA_HOME` 指错了——**Maven 打包时用的是 `mvn -v` 里那个 JDK**（Maven 进程启动时读 `JAVA_HOME`；`java -version` 走的是 PATH 里的 `java.exe`，两者可以完全不同）。
- `MAVEN_HOME` 不是 Maven 要求的，是人要求的：换版本只改一处。**必须把 `%MAVEN_HOME%\bin` 加进 `Path`**，只建 `MAVEN_HOME` 会报 `'mvn' 不是内部或外部命令`。环境变量是**进程启动时**读的，改完必须重开终端和 IDEA。
- 为什么"不要中文命名"：`mvn.cmd` 是批处理，Windows 命令行默认按 GBK 解析；路径含中文时传给 Java 的 `-Dmaven.home=D:\课程\maven` 会变形，Java 拿着不存在的路径去加载 `maven-core`，报的却是 `ClassNotFoundException`——**大家根本想不到根因是中文路径**。

**⑤ 在你仓库里** —— 本机实测 Maven `3.8.1`（`mvn -v` 输出 `Maven home: D:\software\apache-maven-3.8.1`）、JDK `21.0.11`（`runtime: D:\software\Java\jdk21`）、MySQL 8.0.43，全部记在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 69~83 行"附0 环境"表格，第 74 行注明 Maven 与讲义同版本。

**⑥ 常见坑** —— ① `mvn` 找不到命令 → 只建了 `MAVEN_HOME` 没改 `Path` → 加 `%MAVEN_HOME%\bin` 并重开终端。② `mvn -v` 报 `ClassNotFoundException` → Maven 解压在中文路径下 → 挪到纯英文路径。③ 讲义写 MySQL 5.7 大家装的是 8.0 → 多虑了，MySQL 8 兼容 5.7 语法，只多配两个连接参数（见 2.13）——**不要为了对齐讲义去卸载重装**。

**⑦ 自测** —— `java -version` 是 21，而 `mvn -v` 里的 `Java version` 是 1.8，Maven 打包时用哪个？

<details><summary>展开解析</summary>

用 **`mvn -v` 里那个**。Maven 启动时读的是 `JAVA_HOME`，与 `PATH` 里的 `java.exe` 可以指向完全不同的 JDK。统一办法：`JAVA_HOME` 指向 JDK21，并且 `PATH` 里 `%JAVA_HOME%\bin` 排在前面，然后重开终端。

</details>

### 2.2 Spring Initializr 创建工程

**① 讲义怎么说** —— "二、创建 SpringBoot 工程"第 1 条"新建 SpringBoot3 工程"：点"创建"后弹出对话框，按讲义**"选择关闭此对话框，关掉 Idea，再打开 Idea"**，并强调**"项目的结构如下图所示才可以，否则不要再进行下一步操作"**。

**② 一句话讲透** —— Spring Initializr 是官方提供的**"选好菜再上菜"的脚手架**：大家勾"要 Web、要 MyBatis、要 MySQL 驱动"，它当场把整个骨架（目录 + pom.xml + 启动类 + 配置文件）打包给大家，连版本号都替大家填好——像奶茶店点单，它不会给大家茶叶和糖让自己配。至于"关掉 IDEA 再打开"，**文件其实早就建好了，是 IDEA 的缓存没刷新**：外卖已经放门口了，大家还盯着厨房看。

**③ 示例代码** ——

```bash
Name:        springboot
Location:    D:\course\Javaweb\实训7_新建SpringBoot项目\工程\xm-pro
Type:        Maven         Language: Java
JDK:         21            Java: 21          Packaging: Jar
Dependencies: Spring Web
              MyBatis Framework
              MySQL Driver
```

```bash
cd D:\course\Javaweb\实训7_新建SpringBoot项目\工程\xm-pro     # 确认文件夹真的在，不用 IDEA，直接看磁盘
dir
```

**④ 逐行拆解** ——
- `Name: springboot` 同时决定**文件夹名**、**artifactId**、**启动类名**（`SpringbootApplication`）——讲义图1 里那个"多出来的 springboot 文件夹"就是它。
- `Location: ...\实训7_新建SpringBoot项目\工程\xm-pro` 是**父目录**，IDEA 会在它下面新建名为 `springboot` 的子文件夹。只填到 `...\工程` 会得到 `实训7_新建SpringBoot项目\工程\springboot`（少了 `xm-pro` 这一层）；再操作失误填成 `...\工程\springboot` 就会得到 `...\工程\springboot\springboot`（嵌套两层）——两种都和讲义图1 的层级对不上。
- `Type: Maven` 而不是 Gradle：讲义全程用 pom.xml，选 Gradle 生成 `build.gradle`，后面抄的每段 XML 都对不上。
- 三个 Dependencies 是**大家唯一必须自己勾的东西**：少了要么启动不了（缺 Web），要么连不上库（缺 Driver），见 2.3。
- `Packaging: Jar`：Spring Boot 的 Jar 自带内嵌 Tomcat，`java -jar` 就是一个能跑的服务器；War 是部署到外部 Tomcat 的老路子。
- 关掉再打开的正确姿势：**File → Close Project**（回到欢迎界面），再 Open 一次——直接点 × 有时只是最小化。讲义让大家"就这一步停下来看目录"不是形式主义，**这是地基验收**。
- `dir` 里如果**根本没有** `springboot`，那就不是刷新问题，是创建参数错了。

**⑤ 在你仓库里** —— 向导填进去的内容留在 `实训7_新建SpringBoot项目/工程/xm-pro/springboot/pom.xml` 第 12~16 行：`groupId=com.example`、`artifactId=springboot`、`version=0.0.1-SNAPSHOT`、`name=springboot`。完整参数见 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 104~110 行（Location 填 `D:\course\Javaweb\实训7_新建SpringBoot项目\工程\xm-pro`）。

**⑥ 常见坑** —— ① 建完变成 `实训7_新建SpringBoot项目\工程\springboot`（少了 `xm-pro` 一层）或 `...\工程\springboot\springboot`（嵌套两层）→ Location 只填到 `工程`，或已经指到 `springboot` 了 → 把 `springboot` 挪进 `xm-pro`，或删掉重来。② 向导里没有"Spring Boot"这一项 → IDEA 社区版不支持 Initializr → 用 https://start.spring.io 网页生成 zip。③ 关掉重开磁盘上还是没有 → 先分清是磁盘问题还是缓存问题 → **`dir` 看磁盘**：磁盘也没有就是创建参数错了。

**⑦ 自测** —— 向导里的 `Name` 和 `Location`，哪个决定文件夹层级？

<details><summary>展开解析</summary>

**两个一起决定**：`Location` 决定父目录，`Name` 决定在父目录下新建的子文件夹叫什么。`Location=...\实训7_新建SpringBoot项目\工程` + `Name=springboot` 得到 `实训7_新建SpringBoot项目\工程\springboot`；若 `Location=...\实训7_新建SpringBoot项目\工程\xm-pro`，得到的就是 `实训7_新建SpringBoot项目\工程\xm-pro\springboot`——**这正是本课程仓库的最终结构**。

</details>

### 2.3 三个依赖各自的作用

**① 讲义怎么说** —— "三、1"末尾要求**"最后要有这三个依赖"**（讲义图15）：`spring-boot-starter-web`、`mybatis-spring-boot-starter:3.0.5`、`mysql-connector-j`。

**② 一句话讲透** —— 用开车类比：**`spring-boot-starter-web` 是整车**（有了它才有个能开动的东西，它里面塞着 Spring MVC 和**内嵌 Tomcat**——对，服务器是打包在大家项目里的，不是大家另外装的）；**`mybatis-spring-boot-starter` 是翻译官**（把 Java 对象和 SQL 互相翻译）；**`mysql-connector-j` 是对讲机**（Java 只会说 JDBC，MySQL 只会说 MySQL 协议，得靠它俩对接）。本讲还没有表、还不用翻译，但翻译官先请来了。

**③ 示例代码** ——

```xml
<dependencies>
    <!-- 一整辆车：Spring MVC + 内嵌 Tomcat -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <!-- 翻译官：MyBatis，把数据库的行变成 Java 对象 -->
    <dependency>
        <groupId>org.mybatis.spring.boot</groupId>
        <artifactId>mybatis-spring-boot-starter</artifactId>
        <version>3.0.5</version>
    </dependency>

    <!-- 对讲机：MySQL 的 JDBC 驱动，runtime 表示编译期不需要它 -->
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <scope>runtime</scope>
    </dependency>
</dependencies>
```

**④ 逐行拆解** ——
- `spring-boot-starter-web` **没有 `<version>`**，这是故意的：它从父工程 `spring-boot-starter-parent` 继承版本（3.5.16）。所以父版本写错，所有依赖版本一起错。
- `mybatis-spring-boot-starter` 的 `<version>3.0.5</version>` **必须自己写**：MyBatis 不是 Spring 官方的，父工程的版本清单里没有它。**规则：Spring 官方 starter 不写版本，第三方 starter 必须写。**
- `<scope>runtime</scope>`：编译大家们的 Java 代码时不需要它，跑起来才需要——大家代码里从头到尾没有 `import com.mysql.*`，只写 `jdbc:mysql://...` 这个字符串。去掉也能跑，但加上更准确。
- 为什么 Driver 这么重要却看不出效果：它的作用是**注册驱动**。没它项目照样启动成功，直到第一次连库才报 `No suitable driver found for jdbc:mysql://...`。

**⑤ 在你仓库里** —— `实训7_新建SpringBoot项目/工程/xm-pro/springboot/pom.xml` 第 25~47 行：第 27~30 行 web、第 33~37 行 mybatis 3.0.5、第 40~44 行 mysql-connector-j（带 `<scope>runtime</scope>`）；第 46 行注释写着 `<!-- 之前带有 test 的测试依赖已被删除 -->`。

**⑥ 常见坑** —— ① `Could not resolve dependencies ... spring-boot-starter-web:jar:4.1.1` → 抄了 Boot 4 的依赖名或版本只降了一半 → 见 2.7。② 启动正常，一连库就 `No suitable driver found` → `mysql-connector-j` 被误删 → 补回去。③ 只勾了 Web 和 MyBatis → 向导里没勾全 → 不用重建工程，手动往 pom 里加第三条即可。

**⑦ 自测** —— 三条依赖为什么只有中间那条写了 `<version>`？

<details><summary>展开解析</summary>

因为 `spring-boot-starter-parent` 用 `<dependencyManagement>` 把所有 **Spring 官方**依赖的版本锁死了，写不写都用 3.5.16 那一套；而 `mybatis-spring-boot-starter` 是第三方（`org.mybatis.spring.boot`），父工程管不到，不写会报 `'dependencies.dependency.version' for ... is missing`。

</details>

### 2.4 目录结构：IDEA 要打开 `xm-pro` 这一层

**① 讲义怎么说** —— "二、1"两张图：图1 红框标的是 `xm-pro` 下面同时有 `springboot` 和 `vue`；图2 是打开工程后左边树的样子，写着**"目录结构要是这样的才行，否则在资源管理器里删除 springboot 文件夹，重新再新建"**。

**② 一句话讲透** —— `xm-pro` 是**整个项目**（前后端一起），`springboot` 只是**后端那一半**。IDEA 应该打开 `xm-pro`，一个窗口左边同时看到后端和前端——像一栋楼：`xm-pro` 是楼门口，`springboot` 是三楼机房，`vue` 是二楼大堂；需要管整栋楼，就该站在楼门口，而不是站在机房里。

**③ 示例代码** ——

```bash
File → Open… → 选 D:\course\Javaweb\实训7_新建SpringBoot项目\工程\xm-pro      ← 选这一层，不是 springboot
```

```text
xm-pro  D:\course\Javaweb\实训7_新建SpringBoot项目\工程\xm-pro
 ├─ .idea            ← IDEA 打开时自动生成，不提交
 ├─ springboot       ← 后端：src + pom.xml
 └─ vue              ← 前端：实训6 的后台管理页面
```

**④ 逐行拆解** ——
- 为什么 `xm-pro` 下面要同时放两个：讲义图1 就是这么要求的。前后端一起放，交作业、写报告、给老师看截图都是一个入口。
- 打开 `xm-pro` 和打开 `springboot` **都能跑**，区不要只在左边树里能不能看到 `vue`。**打开 `springboot` 不算错，只是和讲义图2 不一致。**
- 容易混的地方：**实训1~6 只有前端，那时打开的是 `vue` 本身**；实训7 起工程根变成 `xm-pro`。两处不矛盾，是课程推进到后端后根目录升级了（`README.md` 第 20~27 行、`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 501~506 行）。
- IDEA 打开后会生成 `实训7_新建SpringBoot项目/工程/xm-pro/.idea/`，里面的 `workspace.xml` 会被频繁改写，**不要提交进 Git**（根 `.gitignore` 第 5 行已排除 `.idea/`）。

**⑤ 在你仓库里** —— `实训7_新建SpringBoot项目/工程/xm-pro/` 下实测同时有 `springboot`、`vue`、`.idea` 三个目录；`.idea` 里能看到 `workspace.xml`、`misc.xml`、`modules.xml`、`xm-pro.iml`。根 `.gitignore` 第 5 行是 `.idea/`。

### 2.5 要删掉哪些文件

**① 讲义怎么说** —— "二、2 删除不需要的文件"（讲义图9 两个红框），加上"三、2"里的**"删除包：springboot"**和**"删除测试相关依赖"**。

**② 一句话讲透** —— Initializr 生成的是"通用款"，给大家们的东西有一半是给 Linux 用户、Git 用户、测试工程师准备的。**只在 Windows + 已装 Maven + 不写单元测试的环境下做实训，那些留着只会干扰视线。** 像买家具送的螺丝包有八种螺丝，只用两种，剩下的放抽屉没问题，摊在桌上就会让大家找错螺丝。

**③ 示例代码** ——

```bash
# ① 工程根下（讲义图9 红框①）
springboot\.idea        文件夹
springboot\.mvn         文件夹
.gitattributes  .gitignore  HELP.md  mvnw  mvnw.cmd

# ② src 下（讲义图9 红框② + "删除测试相关依赖"）
springboot\src\test                      整个目录
springboot\src\main\resources\static
springboot\src\main\resources\templates

# ③ pom.xml 里：带 <scope>test</scope> 的依赖（不管它叫什么名字）
```

**④ 逐行拆解** ——
- `.mvn` + `mvnw` + `mvnw.cmd` 是 **Maven Wrapper**，作用是"用户没装 Maven 就用它自动下一份"。大家本机已有 3.8.1，用不上；而且它默认要去网上下 Maven 发行包，国内很慢。
- `HELP.md` / `.gitattributes` 是纯说明和 Git 配置，对编译零影响。
- `springboot\.idea`：**这个不同**——它是**子模块自己的** IDEA 配置，和 `实训7_新建SpringBoot项目/工程/xm-pro/.idea`（整个工程的配置）是两回事。留着会让 IDEA 困惑于"到底哪个是模块根"，**必须删。**
- `src/test`：里面是空的 `SpringbootApplicationTests`。**留着会让 `mvn package` 因为测试连不上库而失败**——这是删它最实在的理由。
- `static` / `templates`：Spring Boot 传统的"服务端渲染"目录，大家们的页面在 `vue` 里，后端只吐 JSON，这俩永远空着。
- pom 里那两条测试依赖：**名字在 Boot 4 和 Boot 3 里不一样**（见 2.7）。**删的时候看 `<scope>test</scope>`，别看名字。**

**⑤ 在你仓库里** —— 现在 `实训7_新建SpringBoot项目/工程/xm-pro/springboot` 下只有 `pom.xml` + `src`（`src` 下只有 `main`，没有 `test`）。实测列出的 8 个文件：`pom.xml`、`SpringbootApplication.java`、`common/Result.java`、`config/WebConfig.java`、`controller/WebController.java`、`exception/CustomException.java`、`exception/GlobalExceptionHandler.java`、`application.yml`。`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 92 行记着原工程里有个 `实训7_新建SpringBoot项目\新建文件夹`（IDEA 自动生成的空壳），现已删除（实测 `Test-Path` 为 False）。

**⑥ 常见坑** —— ① 删了 `src/test` 那个测试类还标红 → 没刷新 → 右键工程 → Maven → Reload Project。② `mvn package` 卡在测试阶段连数据库 → 测试目录或依赖没删干净 → 删干净，或命令行加 `-DskipTests`（验证脚本就是这么干的）。③ 把 `springboot\.idea` 和 `xm-pro\.idea` 一起删了 → 没分清 → `xm-pro\.idea` 删了下次打开会自动重建，**不算事故**，但不用特意删。

**⑦ 自测** —— 为什么删掉 `src/test` 之后 `mvn clean package` 更不容易失败？

<details><summary>展开解析</summary>

因为 `spring-boot-starter-test` 会在打包过程里**启动一次 Spring 上下文**做测试，而大家们的 `application.yml` 配了数据源——测试环境连不上 MySQL 时整个 `package` 失败，**jar 都产不出来**。删掉之后 `package` 只做"编译 + 打 jar"，跟数据库无关。

</details>

### 2.6 pom.xml 与 Maven 坐标

**① 讲义怎么说** —— "三、配置 SpringBoot 工程"第 1 条：**"在 pom.xml 中先把 SpringBoot 的版本降一下，再删除一下无用的标签"**。

**② 一句话讲透** —— `pom.xml` 是 Maven 项目的**身份证 + 购物清单 + 说明书**：说清"我是谁"（坐标）、"我要买什么"（dependencies）、"我要怎么造"（build）。它是给 Maven 这个采购员的一张 A4 纸——写着"项目叫 `com.example:springboot:0.0.1-SNAPSHOT`，需要三样货，请按我爸（parent）定的规矩买"。

**③ 示例代码** ——

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.5.16</version>
        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>springboot</artifactId>
    <version>0.0.1-SNAPSHOT</version>
    <name>springboot</name>
    <description>springboot</description>

    <properties>
        <java.version>21</java.version>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <project.reporting.outputEncoding>UTF-8</project.reporting.outputEncoding>
    </properties>
    <!-- dependencies 见 2.3；build 里只有 spring-boot-maven-plugin -->
</project>
```

**④ 逐行拆解** ——
- `<modelVersion>4.0.0</modelVersion>`：**pom 文件格式的版本**，不是大家们的项目版本，是固定值。
- `<parent>` 四行是 Maven 的**继承**：大家们的项目继承 `spring-boot-starter-parent:3.5.16`，白拿三样东西——统一锁定的依赖版本、`spring-boot-maven-plugin` 的默认配置、一堆编译插件配置。**写错了父工程找不到，整个构建直接失败。**
- `<relativePath/>`：**空标签是有意义的**，意思是"不要在本地目录找父工程，直接去仓库下载"。删掉也能跑，只是会先在 `..\` 找一遍，慢一点。
- `groupId`（组织）+ `artifactId`（项目名）+ `version`（版本）合起来叫 **Maven 坐标（GAV）**，全世界唯一。`SNAPSHOT` 表示"开发中的快照版"，可反复覆盖。
- `<name>` / `<description>` 纯给人看。讲义让删的 `<url/>`、`<licenses>`、`<developers>`、`<scm>` 也是这类——不影响编译，但占地方（`<url/>` 是空标签，容易被误以为写错了）。
- `<java.version>21</java.version>`：这个属性名是 **Spring Boot 父工程认的**，它读到后转给 `maven-compiler-plugin` 的 source/target——所以大家没写 `<maven.compiler.source>` 也能编译成 Java 21。
- `<project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>`：**和中文有直接关系**。不写的话 Maven 用平台默认编码（Windows 上是 GBK）读大家们的 UTF-8 源码，中文注释和中文常量在编译时就烂了。**注意它在 `<properties>` 里，不在 `<build>` 里。**

**⑤ 在你仓库里** —— `pom.xml`：第 5~10 行 `<parent>`（版本 3.5.16 在第 8 行）、第 12~16 行 GAV 与 name/description、第 18~23 行三个 properties（第 20 行有中文注释）、第 49~56 行 `<build>` 里的 `spring-boot-maven-plugin`。

**⑥ 常见坑** —— ① `Non-resolvable parent POM ... 3.5.16` → 版本写错或镜像没配好 → 本机实测本地仓库 `org\springframework\boot\spring-boot-starter-parent` 下**只有 `3.5.16`** 一个版本目录，说明它就是按这个拉的。② 纠结要不要写 `<packaging>jar</packaging>` → 不写时**默认就是 jar** → 不必明写。③ IDEA 里中文正常但命令行 `mvn package` 后乱码 → 少了 `project.build.sourceEncoding` → 加进 `<properties>` 并 **`clean` 后重新打包**（否则旧 class 还在）。

**⑦ 自测** —— `<properties>` 里的 `java.version` 和 `project.build.sourceEncoding` 各被谁读走、管什么？

<details><summary>展开解析</summary>

`java.version` 被 **Spring Boot 父工程**读走，转成编译器插件的 source/target（这里是 21），管"按哪个 Java 版本编译"；`project.build.sourceEncoding` 被 **Maven 核心**读走，决定**读 `.java` 文件时用哪种字符集解码**，管"源码里的中文会不会烂"。

</details>

### 2.7 降到 3.5.16 与 Boot 4 的依赖改名

**① 讲义怎么说** —— 讲义标题就叫**"新建 SpringBoot3 项目"**，"三、1"第一句是**"在 pom.xml 中先把 SpringBoot 的版本降一下"**，讲义图15 里的依赖名是 `spring-boot-starter-web`，同时要求**"删除测试相关依赖"**。讲义没解释"为什么删的时候名字对不上"。

**② 一句话讲透** —— **IDEA 给大家们的默认版本比讲义新了一整代，而且同一个东西换了两代名字。** 现在 Initializr 默认给 Spring Boot **4.1.1**，而讲义是围绕 **3.x** 写的——像老师发的是"第三册"作业，大家自动拿到的是"第四册"，章节号和题目名字都变了。同时 `spring-boot-starter-web` 与 `spring-boot-starter-webmvc` 就像"土豆"和"马铃薯"：**东西没变，去菜市场说错名字就买不到。大家"删测试依赖时名字对不上"，根因就是大家们的是 Boot 4、讲义是 Boot 3。**

**③ 示例代码** ——

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.5.16</version>   <!-- 从 Initializr 默认的 4.1.1 改掉 -->
    <relativePath/>
</parent>
```

```xml
<!-- ===== Spring Boot 3.x：讲义用的名字 ===== -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>

<!-- ===== Spring Boot 4.x：Initializr 默认给的名字 ===== -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc</artifactId>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc-test</artifactId>
    <scope>test</scope>
</dependency>
```

**④ 逐行拆解** ——
- **只改父工程 `<version>` 这一行**，`groupId` / `artifactId` / `relativePath` 都不要动——坐标名两代一样，只有版本号不同。
- 改完必须**重新加载 Maven**（IDEA 右上角循环箭头，或右键 pom → Maven → Reload Project），否则 IDEA 还按旧依赖树索引，会看到一堆莫名其妙的红。
- 为什么是 `3.5.16`：讲义截图里就是它，而且它在 Maven 中央仓库真实存在（本机仓库里只有这一个版本目录）。
- 依赖改名的事实依据：**Maven 中央仓库上 `spring-boot-starter-webmvc` 的版本列表从 4.0.0 才开始**，`spring-boot-starter-parent` 的 3.5.x 系列里没有这个成员。两个名字是**互斥的两代**，不能混写。
- 所以**"降版本"和"改依赖名"必须成对做**。降到 3.5.16 后 `spring-boot-starter-web` 才合法；想留 4.1.1，就得全换成 `webmvc` 版。**不能一个 3 一个 4。**
- 为什么不偷懒直接用 4.1.1：照讲义抄 `spring-boot-starter-web` 会直接报找不到依赖；而且 Boot 4 的自动配置行为有变化，讲义里那些日志（比如 `Tomcat started on port 8080`）不一定长得一样，会开始怀疑自己哪里写错了。

**⑤ 在你仓库里** —— 本课程仓库走了"降版本"这条路：`pom.xml` 第 8 行是 `<version>3.5.16</version>`，第 29 行是 `spring-boot-starter-web`（Boot 3 的名字），pom 里**已经没有任何 test 依赖**（第 46 行有注释说明）。改名说明在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 112 行。

**⑥ 常见坑** —— ① 删测试依赖时找不到 `spring-boot-starter-test` → 大家们的 pom 里它叫 `spring-boot-starter-webmvc-test` → **直接删带 `<scope>test</scope>` 的那条，不管名字。** ② 把 `web` 手改成 `webmvc` 但父版本还是 3.5.16 → 只改了一半 → 见上面的结论。③ 改完版本 IDEA 标红说找不到依赖 → **没 reload** → Reload Project，首次重新下载几分钟，正常。

**⑦ 自测** —— pom 父版本写着 `3.5.16`，依赖里写着 `spring-boot-starter-webmvc`，会怎么样？

<details><summary>展开解析</summary>

**构建立刻失败。** `spring-boot-starter-parent:3.5.16` 的依赖管理清单里没有 `spring-boot-starter-webmvc`（它 4.0.0 才出现），Maven 连版本号都定不下来，会报 `'dependencies.dependency.version' for org.springframework.boot:spring-boot-starter-webmvc:jar is missing` 或直接解析不到。**父版本和依赖名必须是同一代。**

</details>

### 2.8 本地仓库 repo 与两份 settings.xml 打架

**① 讲义怎么说** —— "三、2 配置Maven"：**"上图的第6点，需要到 Maven 的目录下新建文件夹 repo，用来保存下载的 jar 包"**，并配了"Maven 根据依赖去下载 jar 包的示意图"。讲义**没提** `settings.xml` 有两份、谁说了算。

**② 一句话讲透** —— 本地仓库是 **jar 包在大家硬盘上的旅馆**：pom 是购物清单，**阿里云镜像是超市**，**本地仓库是大家家冰箱**——买回来的东西全塞冰箱，下次直接从冰箱拿，不再跑超市。而 `settings.xml` 有两份，**Maven 只认用户级那份里的本地仓库设置**——像在公司群和家庭群同时发"今晚不回家吃饭"，但家里只看了家庭群，**修改了公司群（安装目录）没用**。

**③ 示例代码** ——

```text
D:\software\apache-maven-3.8.1\repo\
 └─ org\springframework\boot\spring-boot-starter-parent\3.5.16\
 └─ org\mybatis\spring\boot\mybatis-spring-boot-starter\3.0.5\
 └─ com\mysql\mysql-connector-j\9.7.0\
```

```bash
# ① 用户级（优先）：C:\Users\<你的用户名>\.m2\settings.xml
# ② 安装级（备用）：<MavenHome>\conf\settings.xml

# 别翻文件了，直接问 Maven：你到底在用哪个仓库？
mvn help:evaluate -Dexpression=settings.localRepository -DforceStdout -q
```

```xml
<!-- settings.xml 里的关键配置 -->
<localRepository>D:\software\apache-maven-3.8.1\repo</localRepository>
```

**④ 逐行拆解** ——

| 顺序 | 文件 | 说明 |
|---|---|---|
| 1 | `~\.m2\settings.xml` | **优先**。它存在时，安装目录那份的 `<localRepository>` 直接被忽略 |
| 2 | `<MavenHome>\conf\settings.xml` | 备用 |

- 目录结构是 `groupId/artifactId/version`，**点号换斜杠**（`org.springframework.boot` → `org\springframework\boot`）。知道这条规律就能自己去仓库"验尸"。本机实测：`spring-boot-starter-parent` 下**只有 `3.5.16`**、`mybatis-spring-boot-starter` 下**只有 `3.0.5`**、`mysql-connector-j` 下是 `9.7.0`——和 pom 完全对得上。
- 每个版本目录里除了 `.jar` 还有 `.pom`（这个依赖自己的清单，Maven 要照着继续买）和 `.sha1`（校验和，防下载中断产生半截文件）。
- 仓库位置**不是必须**在 Maven 目录下，设在别处完全可以，**关键是要清楚它到底在哪**。量级感：本机这个 repo 实测 **80.6 MB**（只装了这一个实训的依赖）。
- 那条排查命令逐个词拆：`help:evaluate` 让 Maven 打印某个内部设置的值；`-Dexpression=settings.localRepository` 指定打印"本地仓库路径"；`-DforceStdout` 强制打到标准输出（不加的话静默模式下什么都看不到）；`-q` 安静模式只留结果。**输出的就是 Maven 真正在用的路径，比翻文件靠谱一百倍。**
- `<mirrors>` 是**合并**的，两份里的镜像都会参与，所以"镜像改了生效、仓库改了没生效"完全可能出现。**别记这些规则，直接把两份写成一样的。**
- 为什么"改了没反应"还连带出"**目录不蓝、绿三角不出现**"：IDEA 的 Maven 导入对同一个工程只执行有限次数，**依赖解析失败后就不再重试**；导入没成功，`src/main/java` 就不会被标成 Sources Root，主类旁边也就没有绿三角。

**⑤ 在你仓库里** —— 两份 `settings.xml` 实测内容一致，`<localRepository>` 都是 `D:\software\apache-maven-3.8.1\repo`。完整复盘在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 450~493 行（附8 第 7 条），第 163~170 行有优先级表格，第 161 行记录 IDEA 里的本地仓库设置。

**⑥ 常见坑** —— ① 改了 `conf\settings.xml`，重新构建却"秒过"、新仓库里一个文件都没有 → 用户级那份还在生效 → 两份改成同一路径，再用 `mvn help:evaluate` 确认。② 仓库路径写成 `D:\soft\apache-maven-3.8.1\repo`（**少了 "ware"**），而且**不报错** → 手打漏字，Maven 默默新建了一个空目录 → 逐字核对（本机那份错路径对应的 `repo` 当时确实是 **0 个文件**，这是"一次都没下载成功过"的铁证）。③ 两份都改了 IDEA 里还是不生效 → IDEA 设置里"用户设置文件"那栏勾了"重写"并指到了别处 → 把"用户设置文件"和"本地仓库"两栏都显式填上。

**⑦ 自测** —— 怎么在不打开任何文件的情况下，一条命令说出 Maven 当前真正使用的本地仓库路径？

</details>

### 2.9 镜像必须 https、文件编码在哪里设

**① 讲义怎么说** —— "三、2"要求"配置 Maven"（配镜像，为了下载快）和"**设置文件编码**"，但讲义截图里的镜像地址是 **http** 的。

**② 一句话讲透** —— 两件互不相干但都会"无声失败"的事。**镜像**：Maven 3.8.1 起把 http 仓库当危险分子拦在门外（官方加了 `maven-default-http-blocker`），大家拿 http 的旧通行证进不去，**门卫还不解释原因，只看到"一个包都下不来"**。**编码**是三个互不相干的战场：**① 源码文件本身是什么编码**（IDEA 保存时用哪种）、**② Maven 编译时按哪种编码读源码**（pom 属性）、**③ 响应给浏览器时按哪种编码**（消息转换器，见 2.25）。一封信从"写信人用什么文字写"到"邮局怎么分拣"到"收信人怎么读"，**三次都可能出错，出错的样子各不相同**。

**③ 示例代码** ——

```xml
<mirrors>
  <mirror>
    <id>aliyun-public</id>
    <name>Aliyun Public Repository</name>
    <url>https://maven.aliyun.com/repository/public</url>
    <mirrorOf>*</mirrorOf>
  </mirror>
</mirrors>
```

```text
IDEA：设置 → 编辑器 → 文件编码，三处都设 UTF-8
  ① 全局编码 Global Encoding                        → UTF-8
  ② 项目编码 Project Encoding                       → UTF-8
  ③ 属性文件的默认编码 Default encoding for properties files → UTF-8
```

```xml
<!-- pom.xml 里对应 Maven 那一侧 -->
<properties>
    <java.version>21</java.version>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <project.reporting.outputEncoding>UTF-8</project.reporting.outputEncoding>
</properties>
```

**④ 逐行拆解** ——
- 镜像 `<url>` 的 **https 是要害**。写成 `http://maven.aliyun.com/nexus/content/groups/public` 会被 3.8.1 拦截。本机遇到过：`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 462 行记录"镜像还是 **http** 的……而 Maven 3.8.1 起默认拦截所有 http 仓库（`maven-default-http-blocker`），等于下什么都下不动"。
- `<mirrorOf>*</mirrorOf>`：星号意思是"**所有**仓库请求都改走我这里"。阿里云 `public` 聚合了 central 等，一个镜像够用；想保留官方源可写 `<mirrorOf>central</mirrorOf>`。
- `<id>` 会出现在构建日志里（`Downloaded from aliyun-public: https://maven.aliyun.com/...`）。**看日志里这个 id，就能确认镜像到底生效没有。**
- IDEA 的"全局编码"决定**新建文件**的默认编码。**这一项如果是 GBK，大家新写的每个 `.java` 都是 GBK**，编译时 Maven 按 UTF-8 读，中文注释直接变问号。
- IDEA 的"项目编码"改之后，IDEA 会把已有文件按新编码**重新解释**——所以**改编码要在刚开始写代码时就改**，写了几百行再改，中文会当场变乱码（那时要用 "Reload in another encoding" 转换）。
- `<project.build.sourceEncoding>` 才是**真正影响 `mvn package`** 的那条；`<project.reporting.outputEncoding>` 管生成报告时的输出编码，成对出现更规范。
- 本机 `mvn -v` 输出里有 `platform encoding: UTF-8`——**这不代表大家安全**，这是本机环境碰巧是 UTF-8。换台 GBK 的机器，同一份代码不带编码属性就出问题。**所以属性要写进 pom，而不是靠环境。**

**⑤ 在你仓库里** —— 两份 `settings.xml` 实测一致：`<id>aliyun-public</id>`、`<url>https://maven.aliyun.com/repository/public</url>`、`<mirrorOf>*</mirrorOf>`（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 184~191 行、第 481 行）。pom 的编码属性在 `实训7_新建SpringBoot项目/工程/xm-pro/springboot/pom.xml` 第 18~23 行，第 20 行有中文注释。

**⑥ 常见坑** —— ① 一个依赖都下不来，日志里有 `Blocked mirror for repositories` → 镜像 URL 是 http → 改 https。② 日志显示 `Downloaded from central` 没走阿里云 → `<mirrorOf>` 写成了某个具体 id → 写 `*`。③ 改完编码原来的中文全变乱码 → 文件实际字节没变，只是 IDEA 换了"读法" → 用 "Reload in another encoding" 按旧编码读一次再另存为 UTF-8；**不要全选复制粘贴，容易丢字符**。

**⑦ 自测** —— 怎么用一次构建证明"我的依赖真的从阿里云下的，不是旧缓存来的"？

<details><summary>展开解析</summary>

把本地仓库指到一个**空目录**再构建：

```bash
mvn -Dmaven.repo.local=C:\Temp\空目录 -DskipTests clean package
```

然后看日志里是否大量出现 `Downloaded from aliyun-public: https://maven.aliyun.com/...`。**本机实测空仓库下 32.9 秒构建成功**——这才叫"这份配置对全新环境也是自足的"。

</details>

### 2.10 三种启动方式与启动失败排查

**① 讲义怎么说** —— "四、启动 SpringBoot 工程"第 1 条标题就是**"三种启动方式"**（配三张 IDEA 截图）；紧接着：**"启动后一般会失败，原因是没有配置数据库"**。

**② 一句话讲透** —— 两件事。**三种启动方式跑的是同一个运行配置**，像一扇门的正门、侧门、后门，从哪进屋里都一样。**启动失败先怀疑数据库**：只是加了一个 MySQL 驱动依赖，Spring Boot 就自动认为"这项目要用数据库"，启动时必须连一次库——**连不上就干脆不启动**。像大家嘴上说"我要开车"，家里人就把钥匙塞给大家，结果大家连驾照都没有，**它连试都不让大家试第二次**。

**③ 示例代码** ——

```text

方式③ 编辑区右键：右键 → 运行 'SpringbootApplication.main()'    快捷键 Ctrl+Shift+F10
```

```text

APPLICATION FAILED TO START
***************************

Failed to configure a DataSource: 'url' attribute is not specified and
no embedded datasource could be configured.
Reason: Failed to determine a suitable driver class

```

**④ 逐行拆解** ——
- 三种方式**都在 IDEA 里**。**讲义那句"三种启动方式"如果被理解成"IDEA / mvn 命令 / java -jar"，是不对的**——命令行打 jar 属于**部署**，本实训用不到（更正见 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 52 行）。三者跑的是同一份 Run Configuration；跑过第一次后右上角出现 `SpringbootApplication`，以后直接点绿色 ▶。要最快就用 `Ctrl+Shift+F10`（运行当前光标所在的类，不用精确点小三角）。
- `Failed to configure a DataSource` 是**结论**不是原因；`'url' attribute is not specified` 才是第一层原因——`application.yml` 里没写 `spring.datasource.url`。
- `no embedded datasource could be configured`：Spring Boot 本来留了后备方案"什么都没配就起个内存数据库 H2"，但大家项目里没有 H2，后备也失败。

**⑤ 在你仓库里** —— 三者对照表在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 42~52 行。`SpringbootApplication.java` 的 main 方法在第 9~11 行：

**⑥ 常见坑** —— ① 类名旁边**没有绿三角** → IDEA 没把这个目录识别成 Sources Root（根因常在 `settings.xml`，见 2.8）→ 先修 Maven 配置再 Reload；实在不行 `File → Invalidate Caches`。② 报 `Access denied for user 'root'@'localhost'` → 密码错 → 用上面的 `mysql.exe` 直接试。③ 报 `Unknown database 'xm_pro'` → 库没建 → 见 2.14。④ URL 一行看起来完全正常却报忘了配 → **yml 缩进错了，那行根本没被解析**（见 2.11）→ 这条最阴，它报的是"url 没指定"，让如果以为没写，其实写了。

### 2.11 yml 与 properties、YAML 缩进规则

**① 讲义怎么说** —— "四、2"给了一段数据库配置代码，并专门强调：**"要注意下面红框里的代码要对齐，要有缩进，尤其是最后一行，要缩进"**（讲义图29 就是那个红框）。

**② 一句话讲透** —— `.yml` 和 `.properties` 是**同一件事的两种写法**：`.properties` 用**点号加等号平铺**（像户口本上写全名），`.yml` 用**缩进表现层级**（像家谱树上挂位置）。代价是：**家谱树靠缩进认亲，缩进错一格，这个孩子就挂到别人家去了——而且没有任何报错。**

**③ 示例代码** ——

```yml
server:
  port: 8080

# 数据库配置
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    username: root
    password: 123456
    url: jdbc:mysql://localhost:3306/xm_pro?useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&useSSL=false&serverTimezone=GMT%2b8&allowPublicKeyRetrieval=true

  # 后台返回的 JSON 使用东八区时间
  jackson:
    time-zone: GMT+8
```

```properties
# 等价的 application.properties
server.port=8080
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.username=root
spring.datasource.password=123456
spring.datasource.url=jdbc:mysql://localhost:3306/xm_pro?useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&useSSL=false&serverTimezone=GMT%2b8&allowPublicKeyRetrieval=true
spring.jackson.time-zone=GMT+8
```

**④ 逐行拆解** ——
- **只能留一个**：`src/main/resources` 下同时有 `application.yml` 和 `application.properties` 时，**`.properties` 优先**（后加载的覆盖前面的），yml 里的配置会被无声盖掉。这是"我改了 yml 怎么不生效"的另一个常见原因。
- 缩进**只能用空格，不能用 Tab**。YAML 规范禁止 Tab，IDEA 会画波浪线，但运行时可能只是"配置没生效"这种软失败。
- **同一层级必须对齐**。讲义那句"尤其是最后一行，要缩进"说的就是：`url:` 必须和 `username:` / `password:` / `driver-class-name:` 左边对齐到同一列，都属于 `datasource:` 的孩子。若 `url` 顶格写，它就成了**根级**配置项，`spring.datasource.url` 整个为空 → 启动报 2.10 那个 `'url' attribute is not specified`。**大家明明写了 url，它却说没写，原因就在这。**
- `server:` 和 `spring:` 是两个不同的顶层，都顶格写，谁也不能缩进到对方里面。
- 冒号后面**必须有一个空格**（`port: 8080`）。写成 `port:8080` 会被解析成一个字符串 key，不是键值对。
- `# 数据库配置` 注释和 `jackson:` **可以跟 `datasource:` 平级**（缩进 2 格），因为它们都是 `spring:` 的孩子。
- 用哪种：**讲义用 yml，大家就用 yml**。yml 能表达列表和嵌套结构（后面讲 `mapper-locations` 时更明显）。

**⑤ 在你仓库里** —— `application.yml` 共 17 行：第 1~2 行 `server.port: 8080`；第 5~13 行 `spring.datasource` 四行配置；第 10~12 行有一段中文注释解释为什么用 `xm_pro`；第 16~17 行 `spring.jackson.time-zone: GMT+8`。工程里**没有** `application.properties`。

**⑥ 常见坑** —— ① `url` 明明写了，启动却说 `'url' attribute is not specified` → `url` 没和 `username` 对齐，缩进层级错了 → 统一成 4 个空格，左边对齐同一列。② 改了 yml 重启还是旧行为 → ① 用了 `.properties`（或两个都在，properties 赢了）；② 改的是 `target/classes` 下的副本而不是 `src/main/resources` 下的原文；③ 没重启（yml 是启动时读的）。③ yml 里加了中文注释，启动报编码解析错 → 文件被存成了 GBK，而 Spring Boot 按 UTF-8 读 → 另存为 UTF-8（**不要带 BOM**）。

**⑦ 自测** —— 下面这段 yml 哪里错了？会导致什么现象？

```yml
spring:
  datasource:
    username: root
  url: jdbc:mysql://localhost:3306/xm_pro
```

<details><summary>展开解析</summary>

`url:` 只缩进 **2 格**，和 `datasource:` 平级了，于是它变成 `spring.url` 而不是 `spring.datasource.url`。现象：启动报 `Failed to configure a DataSource: 'url' attribute is not specified`——**大家明明写了 url，它却说没写。** 改法：把 `url:` 缩进到 4 格，和 `username:` 对齐。

</details>

### 2.12 数据源四行配置

**① 讲义怎么说** —— "四、2 配置数据库"给了这四行（放在 `spring:` → `datasource:` 下面），并强调**"数据库的名字一定要为自己的数据库名字"**。

**② 一句话讲透** —— 这四行是**给 Java 一张"怎么找到大家家冰箱"的纸条**：用哪种门（driver）、敲门时报谁的名字（username）、暗号是什么（password）、门牌号是多少（url）。`url` 是"xx 市 xx 区 xx 路 3306 号，里面住着 xm_pro 这户人家"，`driver` 是"这栋楼要用电子锁"，`username`/`password` 是门禁卡。**四个都对上，门才开。**

**③ 示例代码** ——

```yml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    username: root
    password: 123456
    url: jdbc:mysql://localhost:3306/xm_pro?useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&useSSL=false&serverTimezone=GMT%2b8&allowPublicKeyRetrieval=true
```

**④ 逐行拆解** ——
- `driver-class-name: com.mysql.cj.jdbc.Driver`：告诉 JDBC 用哪个类去讲 MySQL 的话。`cj` 是 **Connector/J** 的缩写，**MySQL 8 驱动的新包名**；老驱动是 `com.mysql.jdbc.Driver`（没有 `cj`），写了老名字会收到弃用警告但它会自己纠正——不要依赖这个。末尾 `Driver` 的 D 是大写，**Java 类名大小写敏感**。
- `username: root` / `password: 123456`：讲义指定 root/123456。**注意这是数据库的密码**，不是 Maven 的、不是 IDEA 的。一般不需要加引号，**但密码有前导零时必须加**（见下方易错点）。
- `url` 三段结构：`jdbc:mysql://` 是协议头，`localhost:3306` 是主机和端口，`/xm_pro?` 后面是库名加参数（六个参数逐个讲在 2.13）。
- `3306` 是 MySQL 默认端口。**装 MySQL 时改过端口的话这里必须跟着改**，否则报 `Communications link failure`。`localhost` 是本机，别的机器就写那台的 IP。

**⑤ 在你仓库里** —— `application.yml` 第 6~13 行，四行都在，`url` 在第 13 行（**是一整行，没有被换行拆开**——这一点很重要，yml 里 URL 折行会出问题）。

**⑥ 常见坑** —— ① `No suitable driver found for jdbc:mysql://...` → `driver-class-name` 写错或 `mysql-connector-j` 依赖丢了 → 确认类名是 `com.mysql.cj.jdbc.Driver`，确认 pom 第 40~44 行那条在。② 密码是 `0123456`，连接总是 Access denied → YAML 把 `0123456` 当八进制数字解析了 → `password: "0123456"` 加引号；**结论：密码有前导零或非数字字符，一律加引号。** ③ URL 太长，大家手工折成两行 → 想好看 → **不要折**，YAML 里裸标量折行需要 `>` 或 `|` 之类的特定语法，直接回车会把后半段变成另一个 key 或解析失败。④ 日志里一堆 `Loading class 'com.mysql.jdbc.Driver'. This is deprecated` → 老驱动类名 → 换成 `com.mysql.cj.jdbc.Driver`。

**⑦ 自测** —— 数据库密码是 `0000`，写 `password: 0000` 会怎么样？

<details><summary>展开解析</summary>

YAML 会把 `0000` 解析成**整数 0**，大家实际拿去连库的密码就变成了 `"0"`，于是报 `Access denied for user 'root'@'localhost'`——**而大家盯着 yml 看半天会觉得"我明明写的就是 0000 啊"。** 正确写法：`password: "0000"`。

</details>

### 2.13 JDBC URL 六个参数逐个讲

**① 讲义怎么说** —— "四、2"给的 URL 里带了一串参数（讲义那段有 HTML 转义、参数顺序也乱），讲义没有逐个解释每个参数。

**② 一句话讲透** —— URL 后面那串 `&key=value` 是**大家和 MySQL 之间的"附加条款"**：怎么编码、能不能一次发多条 SQL、要不要加密、时区按哪个算、要不要允许取公钥。像办业务时填的附加申请表——**不填有些业务照样办，但 MySQL 8 这张新表格必须多填两栏，少一栏就被退回。**

**③ 示例代码** ——

```yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/xm_pro?useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&useSSL=false&serverTimezone=GMT%2b8&allowPublicKeyRetrieval=true
```

```text
参数逐个拆：
  useUnicode=true                       允许使用 Unicode 字符
  characterEncoding=utf-8               传输时按 UTF-8 编码
  allowMultiQueries=true                允许一次发送多条 SQL（用分号隔开）
  useSSL=false                          不走 SSL 加密连接
  serverTimezone=GMT%2b8                服务器时区东八区（%2b 是 + 的 URL 编码）
  allowPublicKeyRetrieval=true          允许向服务器索取公钥（MySQL 8 必须）
```

**④ 逐行拆解** ——
- `useUnicode=true`：告诉驱动连接上要传 Unicode 字符。这是老参数，**现在的驱动默认就是 true**，写上是明确表态。
- `characterEncoding=utf-8`：**传输层**用 UTF-8。它管的是"Java 和 MySQL 之间这句话怎么编码"，和大家们的源码编码、HTTP 编码是三回事。**它和 `useUnicode` 要成对出现**才有意义。
- `allowMultiQueries=true`：允许一条语句里用分号发多条 SQL。**注意它有安全含义**——会让 SQL 注入的危害放大（注入语句后面能再跟一条）。本课程为了后面讲 MyBatis 批量执行方便才开着。
- `useSSL=false`：MySQL 8 默认要求加密连接，不开会打印警告 `Establishing SSL connection without server's identity verification is not recommended`。**本地开发写 false 没问题**，生产环境应改 `true` 并配证书。
- `serverTimezone=GMT%2b8`：**`%2b` 就是 `+` 号。** 因为 URL 的 query string 里 `+` 有特殊含义（代表空格），所以必须 URL 编码成 `%2b`。写 `GMT+8`，驱动收到的是 `GMT 8`，时区解析崩掉，报 `The server time zone value '???±??????' is unrecognized`，或者时间差 8 小时。
- `allowPublicKeyRetrieval=true`：**MySQL 8 必加。** MySQL 8 默认认证插件是 `caching_sha2_password`，第一次认证时若不用 SSL，需要**从服务器取一次公钥**来加密密码；而驱动出于安全默认**禁止**这种取法，直接报 `Public Key Retrieval is not allowed`。加上它 = "我允许取公钥"。**缺这一条，MySQL 8 上根本连不上。**
- **参数顺序无所谓**，但少一个就会在对应场景报错，而且报错信息完全**不提"参数"两个字**。**这就是为什么建议照抄一行完整的、实测过的 URL，而不是自己拼。**

**⑤ 在你仓库里** —— `application.yml` 第 13 行就是这一整行，六个参数齐全。`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 241 行专门记录了这段的易错点：**"讲义那段 URL 的 HTML 转义和参数顺序有点乱，照抄容易漏参数，上面这行是实测能连上的完整版"**。

**⑥ 常见坑** —— ① `Public Key Retrieval is not allowed` → MySQL 8 + 缺 `allowPublicKeyRetrieval=true` → 加上。② `The server time zone value ... is unrecognized`，或时间差 8 小时 → `serverTimezone` 写成了 `GMT+8` → 写 `GMT%2b8`。③ URL 从讲义复制过来连不上，看不出哪里不对 → **讲义那段有 HTML 转义**（如 `&amp;`），粘到 yml 里 `&amp;` 不是分隔符 → 把 `&amp;` 全替换成 `&`，或直接照抄本课程仓库第 13 行。

**⑦ 自测** —— 为什么 `serverTimezone=GMT%2b8` 里的 `+` 要写成 `%2b`？

<details><summary>展开解析</summary>

因为 URL 的 query string 里 `+` 是空格的转义字符。写 `GMT+8`，驱动解出来是 `GMT 8`，时区字符串不合法，报 `The server time zone value ... is unrecognized` 或导致时间偏移 8 小时。**顺带记住：URL 里所有字面意义的特殊字符都要 URL 编码，`+` 只是最常见的一个。**

</details>

### 2.14 数据库名 `xm-pro` 与 `xm_pro`

**① 讲义怎么说** —— "一、所需软件"让用 Navicat 新建数据库 **`xm-pro`**；"四、2"又强调"**数据库的名字一定要为自己的数据库名字，也就是讲义最先让大家新建的数据库的名字 xm-pro**"。

**② 一句话讲透** —— **带横线的名字在 SQL 里是"非法标识符"，必须用反引号包起来。** `xm-pro` 里那个 `-` 在 SQL 眼里不是名字的一部分，而是**减号**——`USE xm-pro` 会被解析成"`xm` 减 `pro`"。所以：**能改就改成 `xm_pro`（下划线），改了就一切正常；不改就得处处记得加反引号。**

**③ 示例代码** ——

```sql
-- 方案 A（推荐）：下划线。任何地方都不用特殊处理
CREATE DATABASE IF NOT EXISTS xm_pro DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- 方案 B：严格照讲义用横线。SQL 里必须加反引号
CREATE DATABASE IF NOT EXISTS `xm-pro` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE `xm-pro`;
SHOW TABLES FROM `xm-pro`;
```

**④ 逐行拆解** ——
- `CREATE DATABASE IF NOT EXISTS`：`IF NOT EXISTS` 让这条语句可反复执行，已存在时只警告不报错。**建库脚本加它是好习惯**（写作业经常要重跑）。
- `` `xm-pro` `` 里的**反引号是 SQL 的"转义标识符"**，意思近似"别解析，我说的是个名字"。MySQL 用反引号（不是标准 SQL 的双引号）。
- `DEFAULT CHARACTER SET utf8mb4`：**注意是 `utf8mb4` 不是 `utf8`。** MySQL 的 `utf8` 只能存 3 字节，存不下 emoji 和生僻字；`utf8mb4` 才是完整的 4 字节 UTF-8。讲义图1 那张建库截图就是设编码的地方。`COLLATE utf8mb4_general_ci` 是排序规则，`ci` = case insensitive。
- **JDBC URL 里带横线的库名**：`jdbc:mysql://localhost:3306/xm-pro?...` 虽然能解析，但它一旦出现在 MyBatis 的 SQL 或 `USE` 语句里，就要处处加反引号——**漏一处就是一个语法错误**。所以本课程仓库选了 `xm_pro`。
- 关键原则：**库名和 yml 里写的必须一模一样**。库叫 `xm-pro` 而 yml 写 `xm_pro`，报的是 `Unknown database 'xm_pro'`——**这个报错其实已经把答案告诉大家了。**

**⑤ 在你仓库里** —— `application.yml` 第 10~12 行的中文注释专门解释这件事：

```yml
    # xm_pro 是本机建好的数据库名。
    # 讲义上写的是 xm-pro，但数据库名里带横线在 SQL 里必须写成 `xm-pro`，容易踩坑，
    # 所以统一用下划线，数据库名和这里保持一致即可。
    url: jdbc:mysql://localhost:3306/xm_pro?useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&useSSL=false&serverTimezone=GMT%2b8&allowPublicKeyRetrieval=true
```

完整说明在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 222 行：**"本机建的是 `xm_pro`（下划线），库名和 yml 里保持一致就行，不影响功能也不影响评分，报告里写清楚自己是哪个即可。"**

**⑥ 常见坑** —— ① `Unknown database 'xm_pro'` → 库里叫 `xm-pro`（或反过来）→ `SHOW DATABASES;` 看清真实名字，把 yml 对齐。② Navicat 里建库时输入 `xm-pro` 被自动改掉 → 表单对特殊字符做了处理 → 直接用 SQL 语句建库。③ 建库忘了设 `utf8mb4` → Navicat 沿用了上次的设置 → `ALTER DATABASE xm_pro CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;`。④ 报告里写 `xm-pro`、代码里是 `xm_pro`，被老师问 → 前后没对齐 → **报告里明确写一句"本机实测使用 `xm_pro`，原因是带横线的库名在 SQL 中必须加反引号，容易出错"**——这句话本身就是加分项。

**⑦ 自测** —— 创建了个库叫 `xm-pro`，在 MyBatis 里写 `SELECT * FROM xm-pro.user` 会怎么样？

<details><summary>展开解析</summary>

报 SQL 语法错误。因为 `xm-pro.user` 被解析成"`xm` 减 `pro.user`"，`-` 是减号。正确写法是 `` `xm-pro`.user ``，或者先 `USE \`xm-pro\`;` 再直接写 `user`。**这就是为什么建议一开始就用 `xm_pro`——省掉后面所有的反引号。**

</details>

### 2.15 启动成功的两行判据与 MyBatis 警告

**① 讲义怎么说** —— "四、2"末尾：**"启动后看见如下信息，代表成功"**（讲义图30 被老师用红框圈出来的那一行）。

**② 一句话讲透** —— 启动成功的判据就两行日志，**认这两行，别认"没报错"**——像开车的"启动成功"不是"钥匙拧下去没炸"，而是"转速表指到 800、仪表盘灯全灭"，要有一个**明确、可核对的信号**。至于那行黄色的 `No MyBatis mapper was found`，是 **MyBatis 在打招呼，不是在报错**：像新员工入职第一天 HR 说"我查了一下，还没有负责的项目"，**等大家后面真正写了 Mapper，它自然就消失了。**

**③ 示例代码** ——

```text
Tomcat started on port 8080 (http) with context path '/'
Started SpringbootApplication in 2.041 seconds (process running for 2.829)
```

```text
No MyBatis mapper was found in '[com.example]' package. Please check your configuration.
```

```bash
# 访问验证
http://localhost:8080/hello
curl http://localhost:8080/hello
```

**④ 逐行拆解** ——
- `Tomcat started on port 8080 (http) with context path '/'`：**"服务器真的在听了"。** `Tomcat` 是内嵌的那个服务器（不是大家另外装的，它在 `spring-boot-starter-web` 里）；`port 8080` 对应 yml 的 `server.port`；`context path '/'` 是**应用路径前缀**——`/` 意味着接口地址就是 `http://localhost:8080/hello`，若显示 `/app`，地址就得是 `http://localhost:8080/app/hello`。
- `Started SpringbootApplication in 2.041 seconds`：**"应用初始化全部完成"。** `SpringbootApplication` 是大家们的启动类名（**改类名这行也会变**）；一两秒正常，第一次可能更久（要建连接池）。
- 两者缺一不可：只有 Tomcat 没有 Started → **应用还在初始化，或初始化中途失败了**；只有 Started 没有 Tomcat → 不可能，Tomcat 一定先起。
- `No MyBatis mapper was found in '[com.example]' package`：**扫描范围是 `com.example`，也就是大家启动类所在的包。** MyBatis 的 Spring Boot 自动配置默认从主类所在包往下扫——**这顺带告诉大家一条重要规则：将来 Mapper 接口必须放在 `com.example` 的某个子包里**（比如 `com.example.mapper`），放别处它扫不到。
- 它是 **WARN 级别（黄色）不是 ERROR（红色）**。**日志级别是判断"要不要处理"的第一依据：WARN 通常是提示，ERROR 才必须处理。** 这个警告不影响启动、不影响 `@RestController` 接请求、不影响返回 JSON，只影响数据库操作——而大家现在根本没有数据库操作。

**⑤ 在你仓库里** —— `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 54~63 行（附-1 第 4 条）记录了两行判据并注明"最后一行被老师红框圈出来"；第 65 行专门解释了那行警告："这是正常的……不影响启动和接口访问，不用管。等后面讲次真正写 Mapper 了它自然消失。" 验证脚本 `实训7_新建SpringBoot项目/_verify_lab7.ps1` 第 86~91 行用的**不是看日志**，而是**每秒钟请求一次 `/hello`，能返回就算起来**——这是更可靠的自动化判据。

**⑥ 常见坑** —— ① 看到 `Tomcat started` 就以为成功了，浏览器访问 404 → `Started ...` 还没打印，应用其实没起完；或路径写错 → 等 `Started` 出现再访问。② `Web server failed to start. Port 8080 was already in use.` → 上一次运行没停干净，旧的 java 进程还占着 8080 → 查占用者并按进程树杀：

```bash
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object OwningProcess
taskkill /PID <上面查到的PID> /T /F     # 一定要带 /T，否则子进程还在
```

  或在 yml 里临时改 `server.port: 8081`。**本机验证脚本第一版就遇到过这个易错点**：只杀父进程，`java -jar` 产生的子进程继续占着 8080，下一次验证直接起不来（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 423~429 行、第 514 行）。③ 看到黄色警告就慌了，开始改 yml 加 `mybatis.mapper-locations` → 误判成错误 → **先看颜色和级别**；不要为了让黄色消失去调日志级别——**那是把体温计砸了来退烧。**

**⑦ 自测** —— 控制台打印了 `Tomcat started on port 8080` 但**没有** `Started SpringbootApplication`，大家现在应该做什么？

<details><summary>展开解析</summary>

**继续等，或者往上翻日志找异常。** `Tomcat started` 只说明"网络端口开了"，`Started ...` 才说明"所有 Bean 都初始化完了"。只有前者的常见原因是：初始化还没跑完（再等几秒）、或某个 Bean 初始化时抛了异常（往上翻，找红色的 `APPLICATION FAILED TO START` 或 `Caused by`）。**绝对不能在这个状态下去点浏览器，然后得出"我的接口 404 是代码写错了"这个错误结论。**

</details>

### 2.16 第一个接口：`@RestController` + `@GetMapping`

**① 讲义怎么说** —— "四、3"：**"写一个接口，访问地址为 http://localhost:8080/hello，测试一下"**，然后给了 `WebController` 的完整代码。

**② 一句话讲透** —— 这几行干了三件事：`@RestController` 把普通 Java 类**变成"能接 HTTP 请求"的东西**；`@GetMapping("/hello")` 把"URL 路径"和"这个方法"**接上电线**；`return` 的值**被自动变成响应体**。像开柜台：`@RestController` 是"这个柜台开始营业"，`@GetMapping` 是"挂上 1 号窗口的牌子"，`return` 是"把东西从窗口递出去"。**大家从头到尾没写过一行 socket、监听、解析 HTTP，全被 Spring MVC 藏起来了。**

**③ 示例代码** ——

```java
package com.example.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class WebController {

    @GetMapping("/hello")
    public String hello() {
        return "Hello 安徽中医药大学！";
    }
}
```

**④ 逐行拆解** ——
- `package com.example.controller;`：**第一行必须是包声明，且必须和文件所在目录对上**。这个文件必须在 `src/main/java/com/example/controller/WebController.java`。**目录和 package 不一致，是"IDEA 报红但 `mvn compile` 能过"的经典易错点**（javac 按文件内容编译、不校验物理路径；IDEA 按目录结构校验），本课程仓库真遇到过（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 393~397 行）。
- 两个 `import`：**注解也是类，不 import 就是找不到符号。** IDEA 里可用 `Alt+Enter` 自动补。
- `@RestController`：**组合注解**，等于 `@Controller` + `@ResponseBody`。前者说"我是个处理请求的类"，后者说"我每个方法的返回值**直接当响应体**写出去，不要去找页面模板"。**两件事合起来才有"返回 JSON"的效果。**
- `@GetMapping("/hello")`：说"有人用 **GET** 访问 `/hello` 时调用下面这个方法"。用 POST 访问会得到 **405 Method Not Allowed**。
- `public String hello()`：方法名**随便起**，真正决定 URL 的是注解里的字符串。返回值类型 `String` 决定了 Spring 用哪个转换器（见 2.25）。
- `return "Hello 安徽中医药大学！"`：**这个字符串就是响应体**，会被 `StringHttpMessageConverter` 处理——**而它默认按 ISO-8859-1 编码，中文会乱码**（见 2.25）。
- 类上**没有** `@RequestMapping` 前缀，所以完整地址就是 `http://localhost:8080/hello`。若类上写了 `@RequestMapping("/api")`，就变成 `/api/hello`——**这是"统一前缀"的常用做法。**

**⑤ 在你仓库里** —— `实训7_新建SpringBoot项目/工程/xm-pro/springboot/src/main/java/com/example/controller/WebController.java`：第 12 行 `@RestController`，第 19~22 行是 `/hello`（**已改造过，返回 `Result` 而不是 `String`**）：

```java
@RestController
public class WebController {

    /**
     * 讲义第一版：直接返回字符串。
     * 想看到这个原始效果，把下面的 return 换成 return "Hello 安徽中医药大学！"; 即可。
     */
    @GetMapping("/hello")
    public Result hello() {
        return Result.success("Hello 安徽中医药大学！");
    }
```

**⑥ 常见坑** —— ① 访问 `/hello` 得到 404，但项目启动正常 → ① 类的包不在 `com.example` 下，Spring 扫不到；② 路径拼错；③ 端口不对 → 确认类在 `com.example.controller` 包下，地址一字不差抄。② `Cannot resolve symbol 'Result'` 但 `mvn compile` 通过 → `Result.java` 的物理目录和 `package` 声明不一致 → 挪到 `src/main/java/com/example/common/Result.java`。③ 改成 `@PostMapping` 后浏览器访问 404 → **浏览器地址栏只会发 GET** → 测试 POST 用 Postman、Apifox，或 `curl -X POST`。

**⑦ 自测** —— `@RestController` 和 `@Controller` 差在哪？只写 `@Controller` 会怎样？

<details><summary>展开解析</summary>

`@RestController` = `@Controller` + `@ResponseBody`。只写 `@Controller` 的话，Spring MVC 会把方法返回值当成**视图名**去解析（找 `hello.html` 之类的模板），找不到就报 404 或视图解析错误——**它不会把 "Hello 安徽中医药大学！" 这个字符串直接当响应体发出去**。前后端分离项目里接口类一律用 `@RestController`。

</details>

### 2.17 为什么要统一返回

**① 讲义怎么说** —— "五、2"原文：**"作用：原生接口返回字符串、数字、Map 等多种格式，前端对接麻烦，统一封装后所有接口返回固定 JSON 结构。"**

**② 一句话讲透** —— 没有统一返回时，前端每接一个新接口都要先问：大家这次给我的是字符串？数字？还是对象？字段叫什么？**报错的时候又长什么样？**——接口越多，前端要写的特例越多。像全班交作业，有的交 Word、有的交图片、有的交手写照片，收作业的人得逐个处理；统一规定"一律交 PDF，第一页写姓名学号"之后，收作业变成一件机械动作。**统一返回就是给所有接口定一个"作业格式"。**

**③ 示例代码** ——

```java
// ===== 包装前：每个接口一个样，前端要为每个接口写一套解析 =====
@GetMapping("/hello")   public String  hello()  { return "Hello 安徽中医药大学！"; }
@GetMapping("/number")  public Integer number() { return 168; }
@GetMapping("/map")     public Map<String,Object> map() {
    HashMap<String, Object> map = new HashMap<>();
    map.put("name", "安徽中医药大学");
    map.put("age", 18);
    return map;
}
// 报错的时候呢？前端收到的是一坨 HTML 错误页

// ===== 包装后：所有接口都长一个样 =====
@GetMapping("/hello")   public Result hello()  { return Result.success("Hello 安徽中医药大学！"); }
@GetMapping("/number")  public Result number() { return Result.success(168); }
// 报错的时候：{"code":"500","msg":"系统错误"}   —— 也是同一个结构
```

```js
// 包装之后，前端只需要一段代码，能套用在所有接口上
const res = await fetch('/api/hello').then(r => r.json())
if (res.code === '200') { 用 res.data } else { 弹 res.msg }
```

**④ 逐行拆解** ——
- 包装前的三种返回类型，前端要写三种处理方式：`await r.text()` / `await r.json()`（数字）/ `await r.json()`（对象）——**而且大家没法写一个通用函数。**
- **最麻烦的其实不是成功，是失败。** 没包装时，接口一抛异常，Spring Boot 默认返回一个 HTML 错误页（`Whitelabel Error Page`）或者一个 `{"timestamp":...,"status":500,...}` 的默认结构，**和成功时的结构完全不同**。前端的 `r.json()` 在 HTML 上会直接抛异常。
- 包装之后前端只需要那三行 JS——**这就是"统一"的全部价值。**
- 注意代价（讲义没讲，但大家该知道）：**HTTP 状态码从此不再反映业务成败**（见 2.20）。工业界更规范的做法是业务异常也返回对应的 HTTP 码。**先学会用这套约定，再知道它的取舍——这就是"会写"和"懂"的区别**（补基础训练营 §原理2 那段"为什么这样设计？这样对吗？"讲的就是这件事）。

**⑤ 在你仓库里** —— 5 个接口的实测返回（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 375~385 行、`实训7_新建SpringBoot项目/_verify_lab7.ps1` 第 142~146 行的断言）：

| 接口 | 是否包装 | 响应体 |
|---|---|---|
| `/hello` | ✅ | `{"code":"200","msg":"请求成功","data":"Hello 安徽中医药大学！"}` |
| `/result` | ✅ | `{"code":"200","msg":"请求成功","data":"测试统一返回包装类成功！"}` |
| `/business` | ✅ | `{"code":"400","msg":"用户名已存在，请换一个！"}` |
| `/number` | ✅（异常走的也是 Result） | `{"code":"500","msg":"系统错误"}` |
| `/map` | ❌ **没包装** | `{"name":"安徽中医药大学","age":18}` |

**⑥ 常见坑** —— ① 前端的统一请求函数在 `/map` 上崩了 → `/map` 没有 `code` 字段（见 2.21）→ 要么在封装函数里兼容特例，要么理解"真实项目里所有接口都必须走统一结构"。② 接口返回 200，但前端说取不到数据 → `code` 是**字符串** `"200"`，前端写了 `code === 200` 永远不成立 → `code === '200'`；这是补基础训练营 L7 的易错点①。③ 明明统一了，某个接口还是返回乱七八糟的东西 → 那个接口没走 `Result` → 全局搜 `@GetMapping`，看有没有漏网的。

**⑦ 自测** —— 统一返回之后，前端能不能做到"代码里只有一处 `fetch`"？为什么 `/map` 会成为障碍？

**能，但 `/map` 是特例。** 四个接口都能用 `if (res.code === '200')` 判断，而 `/map` 返回 `{"name":...,"age":...}`，**没有 `code` 字段**，`res.code` 是 `undefined`，判断永远走失败分支。所以那个通用函数里不得不多写一句"没有 code 字段就当作成功"。**这个矛盾恰恰证明了统一返回的价值**——补基础训练营 L7 的易错点④ 说的就是这个。

</details>

### 2.18 Result 三字段、四工厂与字段名 `msg`

**① 讲义怎么说** —— "五、2"：新建 `common` 包、创建 `Result` 类，包含三个属性——**"`code`：状态码（200 成功、500 系统异常、400 业务异常）；`message`：提示信息；`data`：接口真实返回数据（Object 类型兼容所有数据）"**；并给了四个静态工具方法 `success()` / `success(Object data)` / `error(String code, String msg)`。**注意：文字里写的是 `message`，而同一节下面的代码里是 `msg`。**

**② 一句话讲透** —— `Result` 是一个**信封**：`data` 是信，`code` 是"这封信是正常件还是退件"的戳，`msg` 是邮局给大家留的一句话说明。四个静态工厂方法就是**四种现成的信封**：成功不装信、成功装信、出错不装信、出错带说明。大家以后写任何接口，只要记得"从这四种信封里挑一个"，返回格式就永远不会跑偏。**至于字段名到底是 `msg` 还是 `message`：以代码为准，实测响应体里是 `msg`。**

**③ 示例代码** ——

```java
package com.example.common;

import com.fasterxml.jackson.annotation.JsonInclude;

/**
 * 统一返回的包装类
 */
@JsonInclude(JsonInclude.Include.NON_NULL)
public class Result {
    /** 状态码：200 成功、500 系统异常、400 业务异常 */
    private String code;
    /** 提示信息 */
    private String msg;
    /** 接口真实返回数据（Object 类型兼容所有数据） */
    private Object data;

    public static Result success() {
        Result result = new Result();
        result.setCode("200");
        result.setMsg("请求成功");
        return result;
    }

    public static Result success(Object data) {
        Result result = success();
        result.setData(data);
        return result;
    }

    public static Result error() {
        Result result = new Result();
        result.setCode("500");
        result.setMsg("系统错误");
        return result;
    }

    public static Result error(String code, String msg) {
        Result result = new Result();
        result.setCode(code);
        result.setMsg(msg);
        return result;
    }

    public String getCode() { return code; }
    public void setCode(String code) { this.code = code; }
    public String getMsg() { return msg; }
    public void setMsg(String msg) { this.msg = msg; }
    public Object getData() { return data; }
    public void setData(Object data) { this.data = data; }
}
```

```json
// 实测响应体：字段名是 msg，不是 message
{"code":"200","msg":"请求成功","data":"Hello 安徽中医药大学！"}
```

**④ 逐行拆解** ——
- `private String code;`：**注意是 `String` 不是 `int`。** 所以前端比较必须写 `code === '200'`（带引号）。讲义三个属性也都写的是 `String`。
- `private String msg;`：**`msg` 不是 `message`。** 讲义文字和代码不一致，**以代码为准**——JSON 里的 key 就是字段名，写 `msg` 响应体里就是 `"msg"`，**前端写 `res.message` 会拿到 `undefined`**，而且**不报错**，只会看到弹窗里显示 `undefined`。
- `success()` 四步：**new → 设 code → 设 msg → 返回**。不设 `data`，所以它是 `null`。
- `success(Object data)`：**先调用 `success()` 拿到"200 骨架"，再往上挂 data。** 这个复用让"200 / 请求成功"这两个常量只在一处出现——将来想把 `"请求成功"` 改成 `"操作成功"`，只改一处。**复制粘贴重写一遍就有两个地方要改，早晚漏一个。**
- `error()`（code=500、msg=系统错误）**专门给全局异常处理器用**（见 2.22）；`error(String code, String msg)` 是**参数化版本**，给业务异常用（见 2.23）。
- 六个 getter / setter **不是装饰，是必须的**：Spring Boot 用 Jackson 把对象转 JSON，**Jackson 靠 getter 找字段**。只有 `private String code;` 而没有 `getCode()`，接口返回的会是 `{}` 空对象（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 290 行专门记了这条）。

**⑤ 在你仓库里** —— `实训7_新建SpringBoot项目/工程/xm-pro/springboot/src/main/java/com/example/common/Result.java`（70 行）：第 11 行 `@JsonInclude`，第 14/16/18 行三个字段，第 20~45 行四个静态工厂，第 47~69 行六组 getter/setter。**注意 `package` 是 `com.example.common`，所以文件必须在 `src/main/java/com/example/common/` 目录下**。字段名在 `CustomException.java` 第 8 行也是 `msg`，5 个接口的实测返回体里**全是 `msg`，没有一处 `message`**。

**⑥ 常见坑** —— ① 前端弹窗显示 `undefined` → 写了 `res.message` → 改成 `res.msg`。② 接口返回 `{}` → 忘了写 getter → 用 IDEA 的 `Alt+Insert → Getter and Setter` 生成，别手打。③ `Cannot resolve symbol 'Result'` → `Result.java` 的物理目录和 `package` 声明不一致 → 挪到 `com/example/common/` 下。④ 报告里写"字段是 message"，被老师对着接口返回问 → 抄了讲义文字没对着实际返回体核 → **报告里的截图就是证据**——F12 里明明白白是 `msg`。

**⑦ 自测** —— 需要在报告里写"本接口返回 code / msg / data 三个字段"，怎么证明大家是对的（而不是抄了讲义）？

### 2.19 静态工厂 vs `new`、重载、`Object`、`NON_NULL`

**① 讲义怎么说** —— "五、2"要求**"编写静态工具方法"**并列了同名方法 `success()` / `success(Object data)`（重载）；`data` **"Object 类型兼容所有数据"**；讲义代码里没有 `@JsonInclude`，但**讲义要求的 `/number` 返回体里没有 data 字段**。

**② 一句话讲透** —— 四个点其实是一条线。**静态工厂**：别人不用记类名，只要说"给我一个成功的"——像奶茶店说"来杯招牌""来杯招牌加珍珠"，大家不需要知道杯子是什么牌子。**重载**就是"同一个名字，参数不同，做略有差别的事"。**`Object`** 是 Java 里所有类的老祖宗，像**快递箱**——里面可以放书（String）、钱（Integer）、包裹（Map）、一箱包裹（List），**箱子本身不需要知道自己装的是什么**。**`@JsonInclude(NON_NULL)`** 是"空着的格子就留白，而不是每格都写个'无'"。

**③ 示例代码** ——

```java
// 四个工厂各管一种场景
Result.success();                              // {"code":"200","msg":"请求成功"}
Result.success("测试统一返回包装类成功！");      // {"code":"200","msg":"请求成功","data":"..."}
Result.error();                                // {"code":"500","msg":"系统错误"}        给全局异常处理器
Result.error("400", "用户名已存在，请换一个！"); // {"code":"400","msg":"用户名已存在，请换一个！"}  给业务异常
```

```java
// data 是 Object，什么都能装
Result.success("Hello 安徽中医药大学！");   // String  → "data":"Hello 安徽中医药大学！"
Result.success(168);                       // Integer → "data":168
Result.success(map);                       // Map     → "data":{"name":"...","age":18}
Result.success(list);                      // List    → "data":["张三","李四"]
// 将来有 User 类，一样能塞：Result.success(new User("张三", 18))
```

```java
// @JsonInclude 的效果（实测）
Result.error();          // 加了 NON_NULL →  {"code":"500","msg":"系统错误"}          ← 没有 data
                         // 不加         →  {"code":"500","msg":"系统错误","data":null} ← 多一个 null
Result.success();        // 加了 NON_NULL →  {"code":"200","msg":"请求成功"}
```

**④ 逐行拆解** ——
- `public static Result success()`：**`static` 是要害**——有了它才能写 `Result.success()`（类名直接调）。没有它就得先有对象才能调方法，而"造对象"正是需要封装的事，**逻辑上死循环**。
- **重载规则**：名字一样、**参数列表不一样**即可。`success()` 无参、`success(Object data)` 一个参，Java 靠参数个数和类型区分。**返回值类型不参与**重载判断（所以不能写两个只有返回值不同的同名方法）。
- `Result.success(168)` 的过程：`168`（int）→ **自动装箱**成 `Integer` → **向上转型**成 `Object` → 存进 `data`。三步都是编译器自动做的。**这正是 `WebController` 第 30 行能编译通过的原因。**
- 一个易错点：**`Result.success(null)` 会调用 `success(Object)`**（`null` 能匹配 `Object`，而 `success()` 不接受参数）。结果和 `Result.success()` 一样，但写出来容易让人困惑。
- 静态工厂相比 `new` 的**另一个**好处：将来要加缓存、改成单例、加日志，只改工厂内部即可，**调用方一行都不用动**。而 `new Result()` 散落在 20 个接口里，想统一加个东西就得改 20 处。
- `Object` 是所有引用类型的父类，**"父类引用指向子类对象"天经地义**，所以任何对象都能赋给它。取出来时**必须强转**（`(String) result.getData()`）——这是 `Object` 的代价。不过在大家项目里，取 `data` 的活儿全由 Jackson 和前端 JS 干了。
- Jackson 序列化时**按运行时的实际类型**走：装 `String` 就输出字符串，装 `Map` 就输出对象。**它不看声明类型 `Object`**，所以 `Object` 不会导致"全变成 `{}`"。
- `@JsonInclude` 是 **Jackson 的注解**（`com.fasterxml.jackson.annotation`），不是 Spring 的。`NON_NULL` 含义是"值为 null 时不包含"，同族还有 `NON_EMPTY`（空串、空集合也不包含，**容易误伤**）和 `ALWAYS`（默认，永远包含）。**它加在类上，影响整个类的所有字段。**

**⑤ 在你仓库里** —— `Result.java` 第 20~45 行（四个工厂）、第 18 行 `private Object data;`、第 3 行 import 与第 11 行 `@JsonInclude(JsonInclude.Include.NON_NULL)`。调用方在 `WebController.java`：第 21 行带 data、第 30 行 `Result.success(168)`（**传 int，正好演示 `Object` 的兼容性**）；`GlobalExceptionHandler.java` 第 30 行 `Result.error()`、第 43 行 `Result.error(e.getCode(), e.getMsg())`。NON_NULL 的实测证据：`/number` 返回体是 `{"code":"500","msg":"系统错误"}`，**没有 data 这个 key**（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 381 行、`_verify_lab7.ps1` 第 143 行）。

**⑥ 常见坑** —— ① `Result.success(168)` 编译报错说找不到方法 → 参数类型写成了 `String` → 确认声明是 `Object`。② 前端写 `if (res.data)` 判断有没有数据，加了 NON_NULL 后 `typeof res.data` 从 `"object"` 变成 `"undefined"` → 字段被整个跳过了 → 用 `'data' in res` 或 `res.data != null`（宽松相等能同时盖住 null 和 undefined）。③ `data` 取出来是 `Object`，想当 `String` 用报错 → `Object` 没有 `String` 的方法 → 强转 `(String) result.getData()`，或者干脆让前端取。④ 想让 `data` 直接当 `List<User>` 用，把声明改成 `List<User>` → 那样就只能返回用户列表了 → 保持 `Object`。

**⑦ 自测** —— 为什么四个工厂方法必须加 `static`？不加会怎样？

<details><summary>展开解析</summary>

不加 `static`，调用就变成"得先有一个 `Result` 对象，才能调 `success()` 造一个 `Result` 对象"——**鸡生蛋的问题**。调用方只能写 `new Result().success()`，还不如直接 `new Result()` 加 setter，封装白做了。`static` 让方法挂在**类**上而不是**对象**上，才能做到 `Result.success(...)` 这种类名直接调。

</details>

### 2.20 两层状态码（本讲最重要的认知）

**① 讲义怎么说** —— "五、2"要求"`code`：状态码（200 成功、500 系统异常、400 业务异常）"，"六"里要求"统一返回 code=500 的 Result"。**但讲义没有指出"项目里同时存在两套状态码"。**

**② 一句话讲透** —— 大家们的项目里同时存在两套"状态码"，各说各的：第一层是 **HTTP 状态码**（Tomcat/协议层产生，取值 200/404/500，给浏览器、运维、监控系统看）；第二层是**响应体里的 `code`**（大家们的 `Result` 类产生，取值 `"200"/"400"/"500"`，给大家们的前端代码看）。像**快递单上的"运输状态"和包裹里的"商品验收单"**——运输状态写"已签收"（HTTP 200）不等于商品没问题（`code` 可能是 500）。**这一条搞不懂，后面所有联调都会怀疑人生。**

**③ 示例代码** —— 实测的 5 个接口（`实训7_新建SpringBoot项目/_verify_lab7.ps1` 真跑出来的）：

| 接口 | HTTP 状态码 | 响应体 | 响应体里的 code |
|---|---|---|---|
| `/hello` | 200 | `{"code":"200","msg":"请求成功","data":"Hello 安徽中医药大学！"}` | `"200"` |
| `/number` | **200** | `{"code":"500","msg":"系统错误"}` | `"500"` |
| `/map` | 200 | `{"name":"安徽中医药大学","age":18}` | **没有 code** |
| `/result` | 200 | `{"code":"200","msg":"请求成功","data":"测试统一返回包装类成功！"}` | `"200"` |
| `/business` | 200 | `{"code":"400","msg":"用户名已存在，请换一个！"}` | `"400"` |

```js
// ❌ 错的：在你这套后端里，除以 0 的接口 response.ok 也是 true
if (response.ok) { 当作成功 }

// ✅ 对的：判断响应体里的 code，而且它是字符串
const res = await response.json()
if (res.code === '200') { 用 res.data } else { 弹 res.msg }
```

**④ 逐行拆解** ——
- **为什么 `/number` 除了零、报错了，HTTP 状态码仍然是 200？** 因为 `WebController.number()` 里那句 `int a = 1 / 0;` 确实抛了 `ArithmeticException`，**但 `GlobalExceptionHandler` 用 `@ExceptionHandler(Exception.class)` 把它接住了**，然后**正常返回**了一个 `Result.error()`。对 HTTP 协议来说，这是一次**完全正常的响应**——所以 HTTP 是 200，只有响应体里的 `code` 是 `"500"`。**是全局异常处理器把异常"吃掉"了。**
- 表格里**5 个接口的 HTTP 状态码全是 200**，连除以 0 的那个也是——**这就是"异常被吃掉"的铁证。**
- 什么时候 HTTP 才不是 200：**请求根本没到达大家们的代码。** 路径写错（`/helloo`）→ **404**，而且这时**没有 Result 结构**，返回的是 Spring Boot 的默认错误 JSON 或 HTML 错误页。**这类错误全局异常处理器管不着**，因为它不是"大家们的 Controller 抛出的异常"。
- 后端根本没启动 → **没有 HTTP 状态码**，`fetch` 会 **reject**。这是唯一一种 `fetch` 会失败的情况（补基础训练营 §原理3）。
- **这套约定的取舍**：好处是前端永远只解析一种结构；代价是**监控系统看 HTTP 200 会以为一切正常，实际上业务在报错**。工业界更规范的做法是业务异常也返回对应的 HTTP 状态码。**这就是"会写"和"懂"的区别。**

**⑤ 在你仓库里** —— 实测表格在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 375~385 行；验证脚本 `实训7_新建SpringBoot项目/_verify_lab7.ps1` 第 119 行专门把 `$resp.StatusCode` 打出来，第 143 行断言 `/number` 返回体里的 `"code":"500"`。补基础训练营 §原理2（"两层状态码：为什么异常了还是'成功'"）整节都在讲这件事，**L5 关的第 5 题**就是"`/number` 那个接口里明明发生了错误，为什么浏览器 Network 里看到的仍然是正常返回"。

**⑥ 常见坑** —— ① 接口报错了，前端的 `catch` 没进去，页面什么都不显示 → `fetch` **只在网络层面失败时才 reject**，HTTP 500 或业务 code=500 它都认为"请求成功了" → 在 `try` 里面手动判断 `res.code`，不成功就自己弹提示（或自己 `throw`）。② 写 `if (response.ok)` 判断成功 → 把 HTTP 状态码当业务状态码了 → 读响应体判断 `code`。③ 写 `if (res.code === 200)` 永远不成立 → `code` 是**字符串** → `=== '200'`；**自己 `console.log(typeof res.code)` 验证一次，比看十篇文章都管用。** ④ 访问不存在的路径，前端崩了 → 404 时返回的不是 Result 结构 → 封装函数里先判断 `res && res.code` 存在。

### 2.21 `/map` 没被 Result 包装

**① 讲义怎么说** —— "五、1"原文：**"上面的代码返回的是 String 类型的，如果想返回 integer 和 Map 类型的，我们要写上"**——也就是说，讲义在讲"统一返回"**之前**，先演示了**原生返回（不包装）**的写法。`/map` 就是这个"包装前"的活标本。

**② 一句话讲透** —— `/map` 是**故意留着不包装**的，用来做对比。它的存在价值是：**让大家亲眼看到"不统一"长什么样，从而真正理解为什么要统一。** 像老师演示"不洗手就吃饭会拉肚子"，那盘没洗的菜不是失误，是教具。**代价是：它会在写"统一请求函数"的时候炸一次**——而这正是这堂课的重点。

**③ 示例代码** ——

```java
@GetMapping(value = "/map", produces = MediaType.APPLICATION_JSON_VALUE + ";charset=UTF-8")
public Map<String, Object> map() {
    HashMap<String, Object> map = new HashMap<>();
    map.put("name", "安徽中医药大学");
    map.put("age", 18);
    return map;
}
```

```json
{"name":"安徽中医药大学","age":18}
```

**④ 逐行拆解** ——
- 返回值类型是 `Map<String, Object>`，**不是 `Result`**。所以 Jackson 直接把 Map 序列化成 JSON 对象，**没有 code、没有 msg**。
- 为什么 Map 也能自动转 JSON：`MappingJackson2HttpMessageConverter` 支持**任意对象**的序列化——Map 变 JSON 对象、List 变 JSON 数组。**这是"返回对象"那条路，和"返回 String"那条路用的是两个不同的转换器**（见 2.25）。
- `produces = MediaType.APPLICATION_JSON_VALUE + ";charset=UTF-8"`：拼出来是 `application/json;charset=UTF-8`，**作用是"这一条接口的响应编码我指定了"**，见 2.26。
- 前端为什么会被它炸：通用函数里有 `if (res.code === '200')`，而 `/map` 的 `res.code` 是 `undefined`（**因为响应体里根本没有这个 key**），所以永远走失败分支，弹出一个空的 `undefined` 提示。
- 怎么修（两种思路）：**① 兼容特例**——没有 `code` 字段就当前端成功；**② 治本**——把 `/map` 也改成 `return Result.success(map)`。**讲义保留它是为了对比，真实项目里应该选 ②。**

**⑤ 在你仓库里** —— `WebController.java` 第 33~43 行（第 34~36 行注释就是"返回 Map，演示'不包装'时的原生 JSON 效果"）。实测返回 `{"name":"安徽中医药大学","age":18}`（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 383 行），验证脚本第 144 行断言 `'"name"\s*:\s*"安徽中医药大学"'`。补基础训练营 §原理2 实测记录第 ③ 条专门点出它："`/map` **根本没有被 Result 包装**，它是裸的 Map，连 `code` 字段都没有——这会在 L7 炸掉大家们的'统一请求函数'，见那一关的易错点④。"

**⑥ 常见坑** —— ① 前端 5 个按钮，4 个正常，点 `/map` 那个永远弹 `undefined` → 没有 `code` 字段 → 见上面的两种思路。② 把 `/map` 也改成 `Result` 之后，"统一返回"的对比就看不出来了 → 这个接口的教学价值就是"没包装" → 写报告时可以改造前后各留一份截图。③ 以为 `/map` 是"忘了改"，当成 bug 报上去 → 没读讲义"五、1"那段 → **这是讲义有意为之的对比项，不是 bug。**

**⑦ 自测** —— 前端只写一个通用请求函数，为了兼容 `/map` 最少要加什么判断？这样做有什么坏处？

<details><summary>展开解析</summary>

最少加一句"没有 `code` 字段就当成功"，例如：

```js
if (res.code === undefined || res.code === '200') { 用 res.data ?? res }
```

**坏处**：这个特例是"因为后端不统一"而被迫写进前端的，**每多一个不统一的接口，前端就多一个特例**。这就是为什么真实项目里所有接口都必须走统一结构——**把复杂度挡在后端，而不是漏给前端。**

</details>

### 2.22 `@RestControllerAdvice` 与异常日志

**① 讲义怎么说** —— "六、1"原文：**"新建 exception 包，创建 GlobalExceptionHandler 全局异常处理类：添加注解 `@RestControllerAdvice`、`@ResponseBody`；捕获顶层 Exception，拦截所有系统未知错误，统一返回 code=500 的 Result；控制台打印完整异常日志，方便定位代码报错行。"**

**② 一句话讲透** —— 这两件事是一对。`@RestControllerAdvice` 是一个**"异常总机"**：所有 Controller 抛出来的异常，不管写在哪一层、什么类型，最后都会先打到这个总机上——像公司里所有投诉电话都不直接找老板，而是先进客服中心，**客服统一话术、统一记录、统一回复**。`log.error(...)` 负责**别让线索丢了**：医院急诊前台告诉家属"正在处理"（统一返回 500），同时病历本上要写清"几号床、什么症状"（日志）。**如果只顾着安抚家属、病历上一片空白，下次同样的病还得从头查一遍。**

**③ 示例代码** ——

```java
package com.example.exception;

import com.example.common.Result;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    @ExceptionHandler(Exception.class)
    public Result handleException(Exception e) {
        log.error("系统异常：{}", e.getMessage(), e);
        return Result.error();
    }
}
```

```text
# 控制台里会打出来的完整堆栈（本机实测）
... ERROR com.example.exception.GlobalExceptionHandler - 系统异常：/ by zero
java.lang.ArithmeticException: / by zero
	at com.example.controller.WebController.number(WebController.java:29)
```

**④ 逐行拆解** ——
- `@RestControllerAdvice` 拆开看：**`Advice` = 通知/增强**（AOP 术语，指"在别的地方插入一段逻辑"）；**`Controller` 指作用范围是"所有 Controller"**；**`Rest` 是"返回值直接写进响应体"**。合起来：**在所有 Controller 外面套一层，出事时由我接管，我的返回值直接当响应体。**
- **它等于 `@ControllerAdvice` + `@ResponseBody`。** 所以讲义让大家"添加 `@RestControllerAdvice`、`@ResponseBody`"——**这两个其实重复了**，用 `@RestControllerAdvice` 就**不需要**再写 `@ResponseBody`（本课程仓库代码第 15~16 行专门注明了这一点）。
- 不加包名参数时**默认全局生效**。本课程仓库旧版曾写成 `@ControllerAdvice("com.example.controller")`——**加了包名限定后只对那个包生效，别处的异常就漏出去了**；讲义要的是全局写法（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 347 行）。
- 这个类**必须能被 Spring 扫描到**：`com.example.exception` 在启动类 `com.example` 下面，所以自动生效。**放到外面就不生效，而且不报错**——只会发现"异常处理怎么没起作用"。
- `@ExceptionHandler(Exception.class)`：**`Exception` 是 Java 异常的顶层父类**（`RuntimeException`、`NullPointerException`、`ArithmeticException` 都是它的子孙），写它就等于"**所有异常我都接**"——这就是讲义说的"捕获顶层 Exception"。
- `log.error("系统异常：{}", e.getMessage(), e);` —— **参数顺序是精髓**：`"{}"` 是 SLF4J 的**占位符**，被后面的 `e.getMessage()` 替换（用占位符而不是字符串拼接，**日志级别不够时不做拼接，省性能**，而且不用管 null）；**第三个参数 `e` 单独放最后**，因为 SLF4J 有一条规则：**最后一个参数是 `Throwable` 时会打印完整堆栈**。`e` 放中间就变成"当普通参数填 `{}`"，只打印一句 `java.lang.ArithmeticException: / by zero`，**没有堆栈，大家不知道是哪个文件哪一行**。
- `return Result.error();`：返回 `{"code":"500","msg":"系统错误"}`。**注意它不把异常信息返回给前端！** 这是刻意的——异常信息可能包含数据库结构、文件路径、类名，泄露给浏览器不安全。**真正的细节只进日志，前端只看到"系统错误"四个字。**
- 为什么必须打日志（讲义原话"方便定位代码报错行"）：**堆栈里 `at com.example.controller.WebController.number(WebController.java:29)` 直接把文件名和行号告诉大家了。** 本课程仓库原来那版**没打日志**，异常被"吃掉"后控制台什么都看不到（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 348 行）——**所以讲义这句不是装饰，是必须的。**

**⑤ 在你仓库里** —— `GlobalExceptionHandler.java`：第 18 行 `@RestControllerAdvice`、第 15~16 行注释解释它与 `@ControllerAdvice` 的关系、第 21 行 Logger 声明、第 27~31 行 `handleException`（**第 29 行就是那句 `log.error`**）。`WebController.java` 第 29 行 `int a = 1 / 0;` 是制造异常的源头。`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 361 行提醒：**这条的截图要给两张**——浏览器访问 `/number` 的返回 + IDEA 控制台里那段 `java.lang.ArithmeticException: / by zero` 红色堆栈。补基础训练营 L5 的提示也指向这个文件。

**⑥ 常见坑** —— ① 异常处理器写了，报错时前端还是收到一堆 HTML → 类没被 Spring 扫到（包在 `com.example` 之外），或注解写错 → 确认包路径和注解。② 接口报错了，控制台干干净净什么也没有 → 只写了 `return Result.error()`，没写 `log.error` → 补上，**并把 `e` 放最后一个参数**。③ 日志里只有 `系统异常：/ by zero` 没有堆栈 → `e` 没放最后 → `e` 放最后。④ 堆栈第一行 `at ...` 指向 Spring 内部类，找不到自己的代码 → **要从上往下找第一个属于 `com.example` 的那一行**，那才是大家代码出错的位置。⑤ 返回值是 `Result` 却输出成 `com.example.common.Result@1a2b3c` → 写成了 `@ControllerAdvice` 而**忘了** `@ResponseBody` → 改成 `@RestControllerAdvice`。

**⑦ 自测** —— 为什么 `log.error("系统异常：{}", e.getMessage(), e)` 里的 `e` 必须放在**最后**一个参数？

<details><summary>展开解析</summary>

因为 SLF4J 有一条约定：**如果最后一个参数是 `Throwable` 类型，它会打印完整的异常堆栈**。`e` 不在最后（比如放中间）时，SLF4J 会把它当普通参数去填 `{}`，只打印一句话描述，**堆栈（也就是"哪个文件哪一行"）就丢了**。这正是讲义强调"打印完整异常日志，方便定位代码报错行"的落点——**完整 = 有堆栈 = 有行号**。

</details>

### 2.23 CustomException 与为什么继承 RuntimeException

**① 讲义怎么说** —— "六、2"原文：**"单纯系统异常无法区分业务违规场景（如禁止访问、参数错误），自定义业务异常类：新建 CustomException，继承运行时异常，自定义 code、message 属性；在全局异常处理器中单独捕获 CustomException，返回自定义 400 业务错误码；业务代码中手动抛出异常示例：`throw new CustomException("400","禁止请求");`"**

**② 一句话讲透** —— 两件事。**第一，要把"用户犯错"和"程序犯错"分开。**"用户名已存在"不是 bug，是**正常的业务结果**，前端该给友好提示（400）；"除以零"是**程序有 bug**，前端只能说"系统错误"（500）并让运维查日志——像医院分诊，"感冒"和"心梗"走完全不同的通道，**都塞进"急诊"这一个口，医生永远分不清先救谁**。**第二，为什么必须继承 `RuntimeException`**：Java 异常分受检和非受检，`Exception` 的子类（`RuntimeException` 除外）都是**受检**的，编译器强制大家处理——要么 `try-catch`，要么方法签名上加 `throws`。像**过安检必须出示证件**（受检）与**火警响了直接跑**（非受检）。**大家希望业务代码里 `throw` 随手就能写，所以必须继承 `RuntimeException`。**

**③ 示例代码** ——

```java
package com.example.exception;

/**
 * 自定义业务异常
 */
public class CustomException extends RuntimeException {
    private String code;
    private String msg;

    public CustomException(String code, String msg) {
        this.code = code;
        this.msg = msg;
    }

    public String getCode() { return code; }
    public void setCode(String code) { this.code = code; }
    public String getMsg() { return msg; }
    public void setMsg(String msg) { this.msg = msg; }
}
```

```java
// GlobalExceptionHandler 里再加一个分支
@ExceptionHandler(CustomException.class)
public Result handleCustomException(CustomException e) {
    log.warn("业务异常：code={}, msg={}", e.getCode(), e.getMsg());
    return Result.error(e.getCode(), e.getMsg());
}

// 业务代码里手动抛
@GetMapping("/business")
public Result businessTest() {
    boolean isUserExist = true;
    if (isUserExist) {
        throw new CustomException("400", "用户名已存在，请换一个！");
    }
    return Result.success("注册成功");
}

// ===== 如果改成继承 Exception：编译不过 =====
// public class CustomException extends Exception {
//     private String code;
//     private String msg;
//     public CustomException(String code, String msg) { this.code = code; this.msg = msg; }
// }                                                              ❌ 受检异常
// throw new CustomException("400", "用户名已存在，请换一个！");
// ❌ 编译错误：Unhandled exception: com.example.exception.CustomException
```

**④ 逐行拆解** ——
- `extends RuntimeException` 是**最关键的一行**，而且**不需要 import**（`RuntimeException` 在 `java.lang` 包里，自动可见）。
- Java 异常树：`Throwable` → `Error`（JVM 级严重问题，大家管不了）和 `Exception`；`Exception` → **`RuntimeException` 及其子类（非受检）**和其他所有（受检）。
- **受检异常的"传染性"是它最麻烦的地方**：若 `CustomException extends Exception`，抛它的方法必须在签名写 `throws CustomException`，调用的上一层也得写……**一路传染到 Controller**。而 **Controller 是被 Spring MVC 反射调用的**，签 `throws` 也没用。
- **为什么全局处理器对两种都能接**：处理器接的是**已经被抛出来的异常对象**，和受检与否无关。**真正卡住大家们的是"能不能抛出来"这一步，不是"能不能接住"。**
- **`@Transactional` 也依赖这个区分**：Spring 事务默认只在遇到 `RuntimeException` 时回滚，遇到受检异常**不回滚**。所以继承 `RuntimeException` 还有一层好处，后面讲事务时用得上。
- **实用规则**：**"调用方有义务处理的"用受检异常**（如"文件不存在"）；**"调用方管不了的"用非受检异常**（如"参数非法""用户名已存在""数据库连不上"）。大家们的 `CustomException` 属于后者。
- `private String code; private String msg;`：**它自己带着"该回给前端什么"的信息**，实现了"抛异常的地方决定提示内容"。业务代码最清楚为什么不行，让它自己说，比在全局处理器里写一堆 `if` 清楚得多。
- 构造器**不调用 `super(msg)`**——消息存在自己的 `msg` 字段里。所以 `getMessage()` 会是 `null`，但 `getMsg()` 有值，**处理器用的是 `e.getMsg()`**。
- `log.warn(...)` 用 **warn 级别（黄色）而不是 error（红色）**——**因为业务异常是"预期内的事"**，用户输了个已存在的用户名不值得报警。
- `throw new CustomException(...)`：**一个 `throw` 就结束当前方法的执行**——后面的 `return Result.success("注册成功")` 永远不执行。**这正是异常的价值：不用一层层 `return` 错误码，直接"炸"上去，由总机统一接住。**
- **注意 `"400"` 是字符串**，因为 `Result.code` 是 `String`；写数字 `400` 编译不过。

**⑤ 在你仓库里** —— `CustomException.java`（30 行）：第 6 行 `public class CustomException extends RuntimeException`、第 7~8 行两个字段、第 10~13 行构造器、第 15~29 行 getter/setter。`GlobalExceptionHandler.java` 第 40~44 行是 `handleCustomException`。`WebController.java` 第 56~65 行是 `/business`。实测返回 `{"code":"400","msg":"用户名已存在，请换一个！"}`（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 385 行，验证脚本第 146 行断言 `'"code"\s*:\s*"400"'`）。

**⑥ 常见坑** —— ① `throw new CustomException(...)` 编译不过，IDEA 提示 `Unhandled exception` → 继承的是 `Exception` → 改成 `extends RuntimeException`。② 为让编译通过在本方法加了 `throws`，结果上一层也报同样的错，一路加下去停不下来 → **受检异常的传染性** → 别加 `throws`，改继承。③ 为消掉编译错误写了 `try { throw ... } catch (CustomException e) { ... }`，结果全局处理器永远收不到 → **在本地就把异常吃掉了** → 业务异常不该被本地捕获。④ 抛了 `CustomException`，前端收到的却是 500 系统错误 → 处理器里没有 `CustomException` 分支，落到了 `Exception` 兜底分支 → 补上分支。

**⑦ 自测** —— 为什么"用户名已存在"要用 `throw new CustomException(...)`，而不是直接 `return Result.error("400", "...")`？

<details><summary>展开解析</summary>

**因为 `return` 结束不了"这个方法之后还要做的事"。** 真实业务里校验往往在**更深的层**（Service 层、循环中间），那里 `return` 只能返回当前方法，调用方还得判断返回值再决定要不要继续；而 `throw` 会**一直往上抛到全局处理器**，中间所有代码直接中断。**用异常表达"这条路走不通"，比用返回值层层传递干净得多**——这也是为什么真实项目里业务校验几乎都用异常。

</details>

### 2.24 异常处理器的匹配优先级

**① 讲义怎么说** —— "六、2"只说"**在全局异常处理器中单独捕获 CustomException**"，没说为什么写了 `Exception` 分支之后，`CustomException` 还能走到自己的分支。

**② 一句话讲透** —— **Spring 找异常处理器时，按"类型由具体到宽泛"的顺序找，找到最贴合的那个就用它。** 像报警电话——"有人打架"会转给治安队，不会因为"治安队也归公安局管"就直接推给总局。**越具体的处理器优先级越高。**

**③ 示例代码** ——

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 兜底：其他所有异常 → 500
    @ExceptionHandler(Exception.class)
    public Result handleException(Exception e) {
        log.error("系统异常：{}", e.getMessage(), e);
        return Result.error();
    }

    // 具体：业务异常 → 400
    @ExceptionHandler(CustomException.class)
    public Result handleCustomException(CustomException e) {
        log.warn("业务异常：code={}, msg={}", e.getCode(), e.getMsg());
        return Result.error(e.getCode(), e.getMsg());
    }
}
```

**④ 逐行拆解** ——
- **`Exception` 分支写在前面、`CustomException` 分支写在后面，实测 `/business` 返回的仍是 400 而不是 500。** 说明 Spring **不是"从上往下取第一个能接的"，而是"找出最贴合异常实际类型的那个"**。
- 匹配判据是**异常的运行时类型**和大家声明的**参数类型**之间的继承距离。抛 `CustomException` 时：`CustomException` 分支**精确匹配**（距离 0），`Exception` 分支**隔着两层**（`CustomException → RuntimeException → Exception`），前者赢。
- 本课程仓库代码注释专门写了这一点（`GlobalExceptionHandler.java` 第 37~38 行）："注意：Spring 会优先匹配更具体的异常类型，所以 `CustomException` 会走这里，不会被上面的 `Exception` 分支吃掉。"
- **`Exception` 分支的价值是兜底**：除以零（`ArithmeticException`）、空指针、数组越界……**大家不可能每种都写一个分支**，写一个 `Exception` 保证"不管出什么错，前端拿到的都是规范的 JSON"。
- 这是"**分层兜底**"的设计模式：越具体的给越精确的提示，剩下的全部由最宽的那个接住。真实项目通常写三层：`CustomException` → `Exception` →（有的还加 `Throwable`）。
- 只有**存在继承关系**时才有"谁优先"的问题；两个毫无关系的类型（如 `NullPointerException` 和 `IllegalArgumentException`）当然各接各的。

**⑤ 在你仓库里** —— `GlobalExceptionHandler.java` 第 27~31 行是 `handleException(Exception.class)`、第 40~44 行是 `handleCustomException(CustomException.class)`。实测印证了优先级：`/number`（抛 `ArithmeticException`）→ `{"code":"500","msg":"系统错误"}`；`/business`（抛 `CustomException`）→ `{"code":"400","msg":"用户名已存在，请换一个！"}`（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 382、385 行）。

**⑥ 常见坑** —— ① 以为"`Exception` 分支写在前面会把所有异常都吃掉"，于是把 `CustomException` 挪到前面 → 误解了匹配规则 → **顺序无所谓**，但"更具体的写前面"是好习惯。② 想给 `NullPointerException` 单独一个提示，写了分支却没生效 → 可能参数类型写的是 `Exception` 而不是 `NullPointerException` → 参数类型必须具体。③ 以为一个异常会**两个分支都执行** → 一个异常只走一个处理器 → 需要多件事就在一个方法里写多行。④ 把兜底参数类型改成 `Object`，启动报错 → `@ExceptionHandler` 的参数类型**必须是 `Throwable` 的子类**，Spring 解析时会校验签名 → 写 `Exception` 或 `Throwable`。

**⑦ 自测** —— 如果把 `handleException` 的参数类型从 `Exception` 改成 `RuntimeException`，`/number` 还能返回 500 吗？如果有个接口抛的是受检异常呢？

<details><summary>展开解析</summary>

`/number` **还能**——它抛的 `ArithmeticException` 是 `RuntimeException` 的子类，匹配得上。**但如果某个地方抛的是受检异常（比如 `IOException`），它就漏出去了**，前端会收到 Spring Boot 的默认错误页而不是规范的 `Result`。**教训：兜底分支要写最宽的 `Exception`（或 `Throwable`），不要写 `RuntimeException`。**

</details>

### 2.25 中文乱码根因与两个消息转换器的分工

**① 讲义怎么说** —— 讲义**没提**这件事。这是**本课程仓库实测踩到并修好的易错点**，记录在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 附8 第 2 条。

**② 一句话讲透** —— **Spring MVC 把返回值写成响应体之前，会按返回值类型挑一个"转换器"**：**返回 `String` 的走 `StringHttpMessageConverter`**（它只管字符串，**默认 ISO-8859-1**）；**返回对象（`Result`、`Map`、`List`）的走 `MappingJackson2HttpMessageConverter`**（把对象转 JSON，`Content-Type` 默认是 `application/json`，**不带 charset**）。像**寄信和寄包裹走两个不同的窗口**——只改善了一个窗口的服务态度，另一个窗口该出错还是出错。至于 ISO-8859-1 为什么必乱：它是**西欧单字节编码**，装不下中文——**写的是中文信，寄信的人却按"英文打字机"的键位表抄了一遍**。

**③ 示例代码** ——

```java
@GetMapping("/hello")                                    // 返回类型 String
public String hello() { return "Hello 安徽中医药大学！"; } // → StringHttpMessageConverter
                                                          //   Content-Type: text/plain;charset=ISO-8859-1

@GetMapping("/number")
public Result number() { return Result.success(168); }    // 返回类型 Result（对象）
                                                          // → MappingJackson2HttpMessageConverter
                                                          //   Content-Type: application/json
```

```text

å®‰å¾½ä¸å»è¯å¤§å¦                      Hello 安徽中医药大学！

# 判断依据不是"肉眼看"，是看响应头（实测）
未修：Content-Type: application/json
已修：Content-Type: application/json;charset=UTF-8    ← 多了 charset
```

**④ 逐行拆解** ——
- **乱码发生在哪一步**：`return "Hello 安徽中医药大学！"` → Spring 拿到 String → 交给 `StringHttpMessageConverter` → **它按 ISO-8859-1 编码成字节** → 写进响应体。浏览器看到响应头里是 `application/json`（**没有 charset**），于是**按自己的默认猜测**去解码——猜错了就乱码。**两个环节都错，加起来就是"必然乱码"。**
- **最容易搞混的一点**：这和数据库的 `utf8mb4`、和 yml 的编码**一点关系都没有**。那些管的是"数据在数据库和配置文件里怎么存"，这里管的是"字符串怎么变成 HTTP 响应体的字节"。**光配数据库解决不了这个问题。**
- `StringHttpMessageConverter` 支持的媒体类型是 `text/plain` 和 `*/*`，默认字符集 ISO-8859-1。它是最"古老"的转换器，因为 HTTP 早期就是给英文设计的。
- `MappingJackson2HttpMessageConverter` 名字里 `Jackson2` 是 JSON 库的版本代号，`Mapping` 指"对象映射"。它内部写 JSON 字节时**用的是 UTF-8**，但**响应头里不写 `charset`**。
- 为什么"不带 charset"也是问题：HTTP 规范里 `application/json` 默认按 UTF-8 解释，严格说不缺 charset 也没错。但**"浏览器按规范猜"和"大家明确告诉它"是两回事**——某些浏览器、代理、前端库会更保守。**明确写上最省心。**
- 那些没被这两个接住的类型：`Integer` 这类简单类型会走 `StringHttpMessageConverter`（Spring 先把数字转成字符串），字节数组走 `ByteArrayHttpMessageConverter`，文件下载走 `ResourceHttpMessageConverter`。**只需要管这两个，它们是项目里唯二用到的。**
- **怎么确认真的修好了（不靠肉眼）**：看响应头的 `Content-Type` 有没有 `charset=UTF-8`。本课程仓库验证脚本做得更彻底——**直接校验响应体的字节**：检查有没有 `E5AE89`（「安」的 UTF-8 序列）或 `E8AFB7`（「请」），同时检查有没有出现 `B0B2`（「安」被 GBK/ISO-8859-1 处理后的字节）。
- 一个能自己动手验证的方法：把 `/hello` 的返回类型从 `Result` 改回 `String`，看响应头变成什么——**类型一变，走的路就变了，响应头也跟着变。自己撞一次比看十遍文章都记得住。**

**⑤ 在你仓库里** —— 完整记录在 `实训7_新建SpringBoot项目/实验过程_实训7.md` 第 399~403 行（附8 第 2 条）：**"原因：`@ResponseBody` 默认用 `StringHttpMessageConverter`，它的默认字符集是 ISO-8859-1……这和数据库 utf8mb4、yml 编码是两码事，光配数据库解决不了。"** 验证脚本 `实训7_新建SpringBoot项目/_verify_lab7.ps1` 第 139~141 行定义了那三组校验用的字节序列，第 142~146 行对五个接口逐个断言。实测（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 381 行）：`/hello` 的响应头是 `application/json;charset=UTF-8`，体里 `E8AFB7` = 「请」的 UTF-8。

### 2.26 `WebConfig` 与 `produces` 两种修法

**① 讲义怎么说** —— 讲义**没讲**。这是本课程仓库为修乱码加的配置（详见 2.25 的实测记录）。

**② 一句话讲透** —— 两种修法，**范围不同**。**`WebConfig` 是全局的**：`WebMvcConfigurer` 是 Spring MVC 留给大家们的合法后门——如果想让动框架内部的东西（消息转换器、拦截器、跨域规则），不用改框架代码，只要写个 `@Configuration` 类实现它、重写对应方法就行，像**租房合同里写着"允许大家换灯泡、刷墙"**；`extendMessageConverters` 就是"**在框架默认的那串转换器上做修改**"。**`produces` 是局部的**：只对写了它的那一个方法生效，像**某个窗口自己挂的牌子"本窗口办理中文业务"**。**两个一起用，既全局统一、又能在个别地方兜底。**

**③ 示例代码** ——

```java
package com.example.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.http.MediaType;
import org.springframework.http.converter.HttpMessageConverter;
import org.springframework.http.converter.StringHttpMessageConverter;
import org.springframework.http.converter.json.MappingJackson2HttpMessageConverter;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

import java.nio.charset.StandardCharsets;
import java.util.ArrayList;
import java.util.List;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void extendMessageConverters(List<HttpMessageConverter<?>> converters) {
        for (HttpMessageConverter<?> converter : converters) {
            if (converter instanceof StringHttpMessageConverter) {
                StringHttpMessageConverter c = (StringHttpMessageConverter) converter;
                c.setDefaultCharset(StandardCharsets.UTF_8);
                c.setWriteAcceptCharset(false);
            } else if (converter instanceof MappingJackson2HttpMessageConverter) {
                MappingJackson2HttpMessageConverter c = (MappingJackson2HttpMessageConverter) converter;
                List<MediaType> types = new ArrayList<>(c.getSupportedMediaTypes());
                types.removeIf(MediaType.APPLICATION_JSON::equals);
                types.add(new MediaType("application", "json", StandardCharsets.UTF_8));
                c.setSupportedMediaTypes(types);
            }
        }
    }
}
```

```java
// 局部修法：只给这一个接口声明 charset
@GetMapping(value = "/map", produces = MediaType.APPLICATION_JSON_VALUE + ";charset=UTF-8")
public Map<String, Object> map() {
    HashMap<String, Object> map = new HashMap<>();
    map.put("name", "安徽中医药大学");
    map.put("age", 18);
    return map;
}

// 等价的直白写法（效果一样，更好读）
@GetMapping(value = "/map", produces = "application/json;charset=UTF-8")
public Map<String, Object> map() {
    HashMap<String, Object> map = new HashMap<>();
    map.put("name", "安徽中医药大学");
    map.put("age", 18);
    return map;
}
```

**④ 逐行拆解** ——
- `@Configuration`：告诉 Spring"这是配置类，启动时读它"。**没有这个注解，`implements WebMvcConfigurer` 完全没用**——类不会被创建，方法也不会被调用。
- `implements WebMvcConfigurer`：**必须是这个接口**，不是 `WebMvcConfigurationSupport`（后者会**关掉** Spring Boot 的自动 MVC 配置，是另一个更重的手法）。
- `extendMessageConverters`：`extend` 一词是精髓——**它拿到的是 Spring 已经建好的那串转换器，让在上面改**；另一个方法 `configureMessageConverters` 是**把自己的转换器加进去**（而且会**替换掉默认的一整套**，很容易把 JSON 转换搞没）。**修编码要用 `extend`，不要用 `configure`。**
- `if (converter instanceof StringHttpMessageConverter)`：**`instanceof` 是"这个对象是不是这种类型"的判断**。这里必须要它——大家没法直接 `converter.setDefaultCharset(...)`，`HttpMessageConverter` 接口上没有这个方法。**先判断类型、再向下转型**，是 Java 里处理"一堆不同子类装在同一个 List 里"的标准套路。
- `StringHttpMessageConverter c = (StringHttpMessageConverter) converter;`：**向下转型**（父类型转子类型），**必须显式写括号**编译器才允许。
- `c.setDefaultCharset(StandardCharsets.UTF_8)`：**改默认字符集，这就是修乱码的关键一行。** 用 `StandardCharsets.UTF_8` 而不是字符串 `"UTF-8"`——前者是常量、编译期就检查，后者拼错了要运行时才知道。
- `c.setWriteAcceptCharset(false)`：作用是**不要在响应头里塞一长串 `Accept-Charset`**（默认会写上一堆候选字符集，响应头变长而且难看）。**去掉它功能也正常**，是个"干净一点"的小优化。
- Jackson 那一段：`getSupportedMediaTypes()` 拿到当前列表 → `removeIf(MediaType.APPLICATION_JSON::equals)` 把**不带 charset 的那个删掉** → `add(...)` 加一个**带 charset 的**进去。
- `MediaType::equals` 是**方法引用**（Java 8 语法），等价于 `t -> MediaType.APPLICATION_JSON.equals(t)`；`removeIf` 会删掉所有满足条件的元素。
- **为什么不能只 `add` 不 `remove`**：新加的排在后面，Spring 挑转换器时**优先匹配前面的 `application/json`**，大家们的 `charset=UTF-8` 永远不被选中。**必须先删再加，这个顺序是要害。**
- `produces` 那一行：`@GetMapping` 有 **`value`（路径）**和 **`produces`（产出类型）**两个属性，写了两个就**必须都带属性名**，不能省成 `@GetMapping("/map", ...)`——**这是 Java 注解的语法要求**。`MediaType.APPLICATION_JSON_VALUE` 是 Spring 提供的常量（值就是 `"application/json"`），用常量比手写字符串好：**拼错会被编译器发现**。
- `produces` 还有一个副作用（很多人不知道）：它参与**内容协商**。若请求头的 `Accept` 里不包含大家声明的类型，Spring 会返回 **406 Not Acceptable**。浏览器发的是 `Accept: text/html,...,*/*`，`*/*` 能匹配任何类型，所以没问题；但 `curl -H "Accept: application/xml"` 打这个接口就会 406。**这是"声明得越具体，限制也越多"的典型。**
- **什么时候用 `produces` 更合适**：某个接口要返回**特殊类型**时（图片 `image/png`、纯文本 `text/plain;charset=UTF-8`、CSV 下载）。**全局配不出来的，用方法级声明。**
- **一个必须点破的地方：在可以跑通的这个工程里，`/map` 上这行 `produces` 对 charset 其实是冗余的。** 用仓库自带的 `实训7_新建SpringBoot项目/_verify_lab7.ps1` 实测五个接口，响应头**全部**是 `application/json;charset=UTF-8`：

  | 接口 | 有没有 `produces` | 实测 Content-Type |
  |---|---|---|
  | `/hello` | 没有 | `application/json;charset=UTF-8` |
  | `/number` | 没有 | `application/json;charset=UTF-8` |
  | `/map` | **有** | `application/json;charset=UTF-8` |
  | `/result` | 没有 | `application/json;charset=UTF-8` |
  | `/business` | 没有 | `application/json;charset=UTF-8` |

  另外四个**没有** `produces` 的接口 charset 一样是对的 —— 这就是证据：**真正保证 UTF-8 的是 `WebConfig`，不是这一行。**
  所以准确的结论是：**它就 charset 而言已被 `WebConfig` 覆盖，属于冗余；但它不算错**——它同时还向外声明了"这个接口只产出 JSON"，参与内容协商（见上面 406 那条）。
  **留着无害，注释掉也照样不乱码**——可以自己把 `WebController.java:37` 那个 `produces` 删掉、重启、再访问 `/map`，中文依然是好的。亲手做一次这个实验，大家就彻底分清"哪一行在真正起作用"了。

**⑤ 在你仓库里** —— `实训7_新建SpringBoot项目/工程/xm-pro/springboot/src/main/java/com/example/config/WebConfig.java`（45 行）：第 26 行 `@Configuration`、第 27 行 `implements WebMvcConfigurer`、第 29~30 行方法签名、第 32~35 行处理 String、第 36~42 行处理 Jackson、第 10~12 行三个 import。类开头 Javadoc（第 14~25 行）把两条原因写得很清楚。改完的效果实测确认：**响应头由 `application/json` 变成 `application/json;charset=UTF-8`**（`实训7_新建SpringBoot项目/实验过程_实训7.md` 第 402 行）。`produces` 那一行在 `WebController.java` 第 37 行，第 34~36 行注释解释了它："`produces` 指定 UTF-8：否则 `@ResponseBody` 默认按 ISO-8859-1 处理，中文会变成乱码。"

**⑥ 常见坑** —— ① `WebConfig` 写了，一点效果没有 → ① 少了 `@Configuration`；② 包不在 `com.example` 下扫不到；③ 改完没重启 → 逐个确认。② 改成 `configureMessageConverters` 后，所有接口返回的 JSON 变成字符串了 → **那个方法会替换掉默认的一整套转换器** → 改用 `extendMessageConverters`。③ 只 `add` 了带 charset 的媒体类型没 `remove` 旧的，响应头还是 `application/json` → 匹配顺序 → 先 `removeIf` 再 `add`。④ `@GetMapping("/map", produces = "...")` 编译不过 → 多个属性时必须写属性名 → `@GetMapping(value = "/map", produces = "...")`。⑤ 接口返回 406 → 请求头的 `Accept` 和 `produces` 不匹配 → 检查调用方发的 `Accept`，或放宽 `produces`。⑥ 以为加了 `produces` 就不用写 `WebConfig` → `produces` 只对**加了它的那个方法**生效 → 全局的 `WebConfig` 仍然要写。

**⑦ 自测** —— `extendMessageConverters` 和 `configureMessageConverters` 有什么区别？修编码该用哪个？如果只给 `/map` 加了 `produces`，`/hello` 的中文还会乱码吗？

<details><summary>展开解析</summary>

**区别**：`extendMessageConverters` 是"**在框架默认的那一串上做增删改**"（拿到的是已经建好的 List）；`configureMessageConverters` 是"**我把我的转换器给大家，默认那套不要用了**"（会替换掉默认配置）。修编码要用 **`extendMessageConverters`**——需要改的是框架已经建好的那两个转换器；**用 `configure` 的话，大家没手动加回来的转换器全都没了，JSON 序列化会直接失效。**

**第二个问题：还会乱码。** `produces` 写在 `@GetMapping` 上，**只影响那一个方法**。`/hello` 没有这个声明，仍然用默认行为——而它现在返回 `Result` 对象（走 Jackson，`application/json` 不带 charset），不配 `WebConfig` 响应头就没有 charset。**想让所有接口都干净，必须配全局的 `WebConfig`；`produces` 只能救一个接口。**

</details>
