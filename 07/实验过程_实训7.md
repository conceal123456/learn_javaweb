## 附-1 怎么在 IDEA 里打开并启动（最常问的问题）

### 1. 用 IDEA 打开 `xm-pro`，不是打开 `springboot`

```
File → Open… → 选 D:\course\Javaweb\07\xm-pro        ← 选这一层
```

**为什么选这一层**：讲义图1（"观察资源管理器，就会多出来一个 springboot 文件夹"）红框标的层级就是 `xm-pro` 下面同时有 `springboot`、`vue`；讲义图2 打开工程后左边树是

```
xm-pro  D:\...\xm-pro
 ├─ .idea
 ├─ springboot      ← 刚建的后端项目
 │   ├─ src
 │   └─ pom.xml
 └─ vue             ← 之前的前端项目
```

图2 上还写着"目录结构要是这样的才行，否则在资源管理器里删除 springboot 文件夹，重新再新建"。

> 如果打开的是 `07\xm-pro\springboot`，也能跑，但左边只有后端、看不到 `vue`，和讲义图不一致。

**打开后 IDEA 会自己生成 `.idea` 文件夹**（本仓库没有提交它，它是本地配置）。第一次打开要等右下角 Maven 索引和依赖下载跑完，**1～3 分钟很正常**。

### 2. 打开后先确认三件事

1. 右边 **Maven 面板**里能看到 `springboot`；没有的话右键 `springboot/pom.xml` → `Add as Maven Project`。
2. `File → Project Structure → Project`：SDK 是 **21**，Language level 是 **21**。
3. `File → Project Structure → Modules → springboot → Sources`：`src/main/java` 必须是**蓝色**的（Sources Root），`src/main/resources` 是**带斜纹的绿色/蓝色**（Resources Root）。

### 3. 三种启动方式（讲义图27 的三种，都在 IDEA 里）

| 方式 | 操作 | 快捷键 |
|---|---|---|
| ① 类名左侧绿三角 | 点 `public class SpringbootApplication` 左边的绿色三角 → Run | — |
| ② main 方法左侧绿三角 | 点 `public static void main` 左边的绿色三角 → Run | — |
| ③ 编辑区右键 | 右键 → `运行 'SpringbootApplication.main()'` | `Ctrl+Shift+F10` |

三种入口不同，跑的是**同一个运行配置**，效果完全一样。跑第一次之后，右上角运行配置下拉框出现 `SpringbootApplication`，以后直接点绿色 ▶。

> **更正一处**：讲义说的"三种启动方式"就是上面这三种，**都在 IDEA 里**，不是"IDEA / mvn 命令 / java -jar"。命令行打 jar 属于部署，本实训用不到（想用也可以，命令见附4）。

### 4. 怎么算启动成功（讲义图30 的判据）

控制台出现这两行（最后一行被老师红框圈出来）：

```
Tomcat started on port 8080 (http) with context path '/'
Started SpringbootApplication in 2.041 seconds (process running for 2.829)
```

然后浏览器访问 `http://localhost:8080/hello` 能看到 JSON，就算通了。

> 控制台还会有一行**黄色警告**：`No MyBatis mapper was found in '[com.example]' package.`——这是正常的：本实训还没写 Mapper 接口，MyBatis 找不到 mapper 包就提醒一句，**不影响启动和接口访问**，不用管。等后面讲次真正写 Mapper 了它自然消失。

## 附4 启动与数据库配置（对应"四"）

### 1. 先建数据库

Navicat / 命令行建库，字符集 **utf8mb4**（讲义图1 第一张图就是建库时的编码设置）：

```sql
CREATE DATABASE IF NOT EXISTS xm_pro DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

> **实测坑**：讲义让建的库名是 `xm-pro`（**带横线**），但 MySQL 里带横线的库名在 SQL 里必须写成反引号 `` `xm-pro` ``，JDBC URL 里也不好写。本机建的是 `xm_pro`（下划线），**库名和 yml 里保持一致就行**，不影响功能也不影响评分，报告里写清楚自己是哪个即可。

### 2. application.yml

```yaml
server:
  port: 8080

# 数据库配置
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    username: root
    password: 123456
    url: jdbc:mysql://localhost:3306/xm_pro?useUnicode=true&characterEncoding=utf-8&allowMultiQueries=true&useSSL=false&serverTimezone=GMT%2b8&allowPublicKeyRetrieval=true
  jackson:
    time-zone: GMT+8
```

> **实测坑（本机是 MySQL 8 必须注意）**：讲义给的 URL 里有 `useSSL=false&serverTimezone=GMT%2b8&allowPublicKeyRetrieval=true`，它们是给 MySQL 5.7/8 的认证方式准备的。MySQL 8 默认用 `caching_sha2_password`，缺 `allowPublicKeyRetrieval=true` 会直接报 `Public Key Retrieval is not allowed`；缺 `useSSL=false` 会报 SSL 警告甚至连接失败。讲义那段 URL 的 HTML 转义和参数顺序有点乱，**照抄容易漏参数**，上面这行是实测能连上的完整版。
>
> 另外讲义反复强调"yml 缩进要对齐，尤其是最后一行也要缩进"（图29 红框）——`url` 和 `username`/`password`/`driver-class-name` 是同一级，必须对齐到 `datasource:` 下面。

## 附5 统一返回包装类 Result（对应"五"）

### 包路径这种事，讲义没写但会要命

讲义说"新建 common 包，创建 Result 类"，代码头是 `package com.example.common;`。**Result.java 必须落在 `src/main/java/com/example/common/` 目录下**，不能只建一个名叫 common 的顶层包。

> **实测坑**：原来那版工程里 `Result.java` 建在了 `src/main/java/common/`（默认包），而 `WebController` 里写的是 `import com.example.common.Result;`。命令行 `mvn compile` 居然能过——因为 Maven 会把 `src/main/java` 下所有文件一起交给 javac，文件的物理目录不影响 `package` 声明，产物照样是 `com/example/common/Result.class`。**但 IDEA 会直接标红报错**（它的 Source Root 按目录校验包名），看到"命令行能跑、IDEA 报错"就是这里。正规做法：目录结构必须和 package 一致。本仓库已把 `Result.java` 移到 `com/example/common/` 下。

### 代码

```java
package com.example.common;

import com.fasterxml.jackson.annotation.JsonInclude;

@JsonInclude(JsonInclude.Include.NON_NULL)
public class Result {
    private String code;   // 200 成功、500 系统异常、400 业务异常
    private String msg;    // 提示信息
    private Object data;   // 接口真实返回数据

    public static Result success() { ... }              // code=200, msg=请求成功
    public static Result success(Object data) { ... }   // 带上 data
    public static Result error() { ... }                // code=500, msg=系统错误
    public static Result error(String code, String msg) { ... }

    // 4 组 getter / setter（必须有！见下）
}
```

> **两个容易忽略的点**：
> 1. **必须有 getter/setter**。Spring Boot 用 Jackson 把对象转 JSON，Jackson 靠 getter 找字段。只有 `private String code;` 而没有 `getCode()`，接口返回的会是 `{}` 空对象。讲义前面文字写的是"message：提示信息"，但代码和属性名用的是 `msg`——**以代码为准**，前端取 `msg`。
> 2. **`@JsonInclude(NON_NULL)`** 是加的小优化：调 `Result.success()` 不带数据时，返回体就只有 `{"code":"200","msg":"请求成功"}`，不会多出一个 `"data":null`。

### 接口改造成统一返回

`/hello` 由 `String` 改成 `Result`（讲义图38"全部修改的话就是这样"的效果）：

```java
@GetMapping("/hello")
public Result hello() {
    return Result.success("Hello 安徽中医药大学！");
}
```

`/map` 保留返回 Map 的原样，用来对比"不包装"的原生 JSON 效果。

**📸 截图**：`/hello`、`/result`、`/map` 三个地址的浏览器返回（对照讲义图37/38）。

## 附6 全局异常统一处理（对应"六"）

```java
package com.example.exception;

@RestControllerAdvice
public class GlobalExceptionHandler {
    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    // 系统异常 → 500
    @ExceptionHandler(Exception.class)
    public Result handleException(Exception e) {
        log.error("系统异常：{}", e.getMessage(), e);   // 控制台打印完整堆栈，讲义图41 要求
        return Result.error();
    }

    // 业务异常 → 自定义 400
    @ExceptionHandler(CustomException.class)
    public Result handleCustomException(CustomException e) {
        log.warn("业务异常：code={}, msg={}", e.getCode(), e.getMsg());
        return Result.error(e.getCode(), e.getMsg());
    }
}
```

自定义业务异常：

```java
public class CustomException extends RuntimeException {
    private String code;
    private String msg;
    public CustomException(String code, String msg) { this.code = code; this.msg = msg; }
    // getter/setter
}
```

> **实测发现的 3 处与讲义不一致（已按讲义改）**：
> 1. 讲义要 `@RestControllerAdvice`（图40），原来写的是 `@ControllerAdvice("com.example.controller")` + 每个方法再加 `@ResponseBody`。**效果相同**（`@RestControllerAdvice` = `@ControllerAdvice` + `@ResponseBody`），但加了包名限定后只对 `com.example.controller` 包生效，别处的异常就漏出去了；讲义写法是全局。已改成讲义写法。
> 2. 讲义明确要求"**控制台打印完整异常日志，方便定位代码报错行**"，原来那版没打日志，异常被"吃掉"后控制台什么都看不到。已补 `log.error(..., e)`。
> 3. 异常处理方法名不要叫 `error`——和 `Result.error()` 一起读容易看混，这里改成 `handleException` / `handleCustomException`。

### 制造异常测试

`/number` 故意写 `int a = 1 / 0;`，访问后返回：

```json
{"code":"500","msg":"系统错误"}
```

注意 **HTTP 状态码仍是 200**，错误信息在 JSON 的 `code` 里——这是这套统一返回风格的约定，前端靠 `code` 判断成败。

## 附8 遇到的问题及解决方法（报告里"遇到的问题"就写这些，都是真实踩到的）

### 1. IDEA 里 Result 类报错，但命令行 mvn compile 能过

- **现象**：`import com.example.common.Result;` 在 IDEA 里标红 `Cannot resolve symbol 'Result'`；命令行 `mvn compile` 却 `BUILD SUCCESS`。
- **原因**：`Result.java` 建在了 `src/main/java/common/`（默认包），而它的 `package` 声明是 `com.example.common`。javac 按文件内容编译，不校验物理路径；IDEA 按 Source Root 的目录结构校验包名，所以只有 IDEA 报错。
- **解决**：把文件移到 `src/main/java/com/example/common/Result.java`。**规则：目录结构必须和 package 声明一致。**

### 2. 接口返回的中文是乱码 / 问号

- **原因**：`@ResponseBody` 默认用 `StringHttpMessageConverter`，它的默认字符集是 **ISO-8859-1**，返回 String 时中文就废了。这和数据库 `utf8mb4`、yml 编码是两码事，光配数据库解决不了。
- **解决**：加一个配置类统一指定 UTF-8（`springboot/src/main/java/com/example/config/WebConfig.java`），给 `StringHttpMessageConverter` 和 `MappingJackson2HttpMessageConverter` 都设上 UTF-8。改完响应头由 `application/json` 变成 `application/json;charset=UTF-8`，字节校验含 `E5AE89`（安）/ `E8AFB7`（请）。
- **验证方法**（不靠肉眼）：看响应头 `Content-Type` 有没有 `charset=UTF-8`，或直接用附7 的脚本。

### 3. 项目启动就报数据库连接失败

按顺序排查：

1. `MySQL80` 服务没起 → `services.msc` 或 `net start MySQL80`
2. 库名和 yml 不一致 → 讲义让建 `xm-pro`，我建的是 `xm_pro`，yml 里就得写 `xm_pro`
3. MySQL 8 认证插件 → URL 缺 `allowPublicKeyRetrieval=true&useSSL=false` 会报 `Public Key Retrieval is not allowed`
4. yml 缩进错 → `url` 这行没和 `username` 对齐（讲义图29 专门红框强调过）

**最省事的自检命令**（绕开项目，直接用客户端连，能连上说明是 yml 的问题，不是数据库的问题）：

```powershell
D:\software\MySQL\mysql-8.0.43-winx64\bin\mysql.exe -u root -p123456 -e "SHOW DATABASES;"
```

### 4. 端口 8080 被占用

- **现象**：`Web server failed to start. Port 8080 was already in use.`
- **原因**：IDEA 里上一次运行没停干净，旧的 java 进程还活着（我的验证脚本第一次也踩了这个：只杀父进程，`java -jar` 产生的子进程继续占着 8080）。
- **解决**：查占用者并杀掉进程树：

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object OwningProcess
taskkill /PID <上面查到的PID> /T /F     # 一定要带 /T，否则子进程还在
```

- **或者**在 `application.yml` 里临时改端口：`server.port: 8081`。

### 5. 命令行 `java -jar` 启动后，控制台里的中文日志是乱码（但接口返回正常）

- **现象**：用 PowerShell / cmd 运行 `java -jar`，控制台里 `系统异常：` 显示成 `绯荤粺寮傚父锛?`，但浏览器访问接口中文完全正常。
- **原因**：这是**控制台显示**的编码不一致，不是程序的问题。实测把日志文件按字节解出来是标准 UTF-8（`E7B3BB E7BB9F` = 「系统」），只是 Windows 控制台按 GBK 去解释这串 UTF-8 字节，于是显示成乱码。IDEA 的 Run 控制台默认按 UTF-8 渲染，所以在 IDEA 里看不到这个问题。
- **解决**：不必改代码。要么在 IDEA 里跑（讲义就是 IDEA），要么先把控制台切成 UTF-8：

```powershell
chcp 65001        # Windows 控制台切到 UTF-8，然后再 java -jar
```

- **报告里可以这么写**：这个问题说明"文件编码 / HTTP 编码 / 控制台编码"是三件独立的事，配好前两个不等于第三个也对。

### 6. 讲义说 Maven 3.8 / MySQL 5.7，本机版本对不上怎么办

- 本机 Maven **就是 3.8.1**，与讲义一致（之前装过 3.9.16，为了让版本和讲义统一、也为了只留一份 Maven，已删除）。
- MySQL 是 8.0.43（讲义写 5.7）：MySQL 8 对 5.7 的语法基本兼容，唯一要注意的是上面第 3 条的连接参数。报告里如实写实际版本即可，**不必为了和讲义一致去装 5.7**。

### 7. Maven 依赖一直加载不出来、IDEA 里 Maven 图标不是正常状态

这条是本机真实踩到的，**根因不在 IDEA，在 settings.xml**：

- **现象**：`设置 → 构建、执行、部署 → 构建工具 → Maven` 里"主路径"指向 `D:\software\apache-maven-3.8.1`，但 IDEA 一直加载不出依赖，`src/main/java` 目录**不是蓝色的**（不是 Sources Root），`SpringbootApplication` 旁边**没有绿色三角**（起不了），怎么刷新都不行。
- **排查过程**：打开 `D:\software\apache-maven-3.8.1\conf\settings.xml`，第 7 行写着：

  ```xml
  <localRepository>D:\soft\apache-maven-3.8.1\repo</localRepository>
  ```

  路径写的是 **`D:\soft\...`**，而实际目录是 `D:\software\apache-maven-3.8.1`——**少了 "ware"，这个本地仓库路径压根不存在**。再看它指向的 `repo` 文件夹：**0 个文件**，说明一次都没成功下载过。

  而且它的镜像还是 **http** 的 `http://maven.aliyun.com/nexus/content/groups/public`，Maven 3.8.1 起默认拦截所有 http 仓库（`maven-default-http-blocker`），等于下什么都下不动。

- **为什么这会连带"图标不变蓝"**：IDEA 的 Maven 导入对同一个工程只会执行有限的次数，**依赖解析失败后它会停止重试**；导入没成功，`src/main/java` 就不会被标记成 Sources Root，目录不蓝、主类旁边也就没有绿色三角——所以看到的是"配置明明填了，可什么都没生效"。
- **解决**：
  1. 把 `localRepository` 修成真实存在的路径：`D:\software\apache-maven-3.8.1\repo`（讲义正好要求在 Maven 目录下建 `repo` 文件夹）；
  2. 镜像换成 **https**：`https://maven.aliyun.com/repository/public`；
  3. IDEA 里 Maven 主路径 / 用户设置文件 / 本地仓库三项都指到上面这套；
  4. 点**重新加载所有 Maven 项目**，等依赖下载完。
- **自查方法**：IDEA 里 Maven 主路径下面会括号显示版本号（如 `(版本: 3.8.1)`）；命令行跑 `mvn -v` 看版本；`mvn -DskipTests compile` 能 `BUILD SUCCESS` 就说明 Maven 侧没问题了。

### 8. 关于 `.idea` 文件夹（本仓库故意没有提交它）

- `.idea` 是 **IDEA 本地的工程配置**，打开工程时自动生成，根 `.gitignore` 里已经把它排除了。
- 一开始为了"让配置开箱即用"，我手写过一份 `.idea`（含 Maven 路径、编码、模块、运行配置）。实测发现**这是错的**：IDEA 打开工程后会自己往里写（生成 `workspace.xml`、`jarRepositories.xml`、`vcs.xml`，还会把模块文件改写成 `AdditionalModuleElements` 结构），手写的那份和 IDEA 自己的 Maven 导入逻辑**互相打架**，反而更容易出现"目录不蓝 / 起不来"。
- **正确做法**：不提交 `.idea`，按附-1 的步骤让 IDEA 自己生成；Maven 那个坏掉的 `settings.xml` 修好（第 7 条）之后，重新加载 Maven 项目，目录自然就蓝了、绿三角也就出来了。

### 10. 关于验证脚本本身（诚实记录）

`07/_verify_lab7.ps1` 是我为这次核验写的，第一版自己踩了三个坑，一并记下：

1. **断言写死了一个字**：只检查返回里有没有「安」的 UTF-8 字节，而 `/result`、`/business` 的返回里本来就没有「安」字 → 误报失败。改成匹配「安/请/测/系/用」任意一个。
2. **十六进制大小写**：脚本用小写拼字节串，模板写的是大写，`-like` 匹配不上 → 全判失败，但打印出来的字节其实是正确 UTF-8。改成大小写不敏感。
3. **杀进程没杀干净**：`Start-Process java -jar` 会再产生一个子进程，只 `Stop-Process` 父进程，会留下孤儿进程继续占着 8080，下一次验证直接起不来。改成 `taskkill /PID <pid> /T /F` 按进程树杀（这也是上面"问题 4 端口被占用"的真实来源）。
