# 实训5 讲义勘误报告（Vue-Router 实现路由跳转）

审核对象：`04/实训5__Vue-Router实现路由跳转.docx`
审核方式：逐段读正文代码；其中路由守卫问题已在本机 Vue 工程里实际运行验证。

## 总体结论
路由定义、编程式导航（`$router.push/replace`）、默认路由 `redirect`、嵌套路由、路由传参的写法基本正确。路由守卫那段有一个会导致页面标题显示 `undefined` 的实质 bug（已运行复现）。

## 问题清单

### 1.（严重，已运行验证）路由守卫会把无 meta 的页面标题设成 "undefined"
```js
router.beforeEach((to, from, next) => {
    document.title = to.meta.title
    next()
})
```
只有 `/manage` 及其子路由定义了 `meta.title`，而 `/home`、`/test` 没有 `meta`。访问这些页面时 `to.meta.title` 为 `undefined`，于是 `document.title = undefined`，浏览器标签直接显示文字 "undefined"。
本机验证：临时按讲义写法配置守卫并访问 `/home`，读到的 `document.title` 确为字符串 `"undefined"`。

![讲义里的守卫代码：/home、/test 没有 meta，document.title 会被设成 undefined](勘误图/router-guard.png)

建议：给一个兜底默认值：
```js
document.title = to.meta.title || '默认标题'
```

### 2.（提示）路由传参示例里 id 值前后对不上
正文给的跳转：
```html
<el-button @click="$router.push({ path: '/test', query: { id: 2, name: '手机' } })">
```
但下一句解释写成"会自动转成 URL 字符串：/test?id=123&name=手机"。示例里 `id` 是 2，说明文字里变成 123，对不上。
建议：把两处数字统一（都用 2 或都用 123）。

### 3.（提示）组件内取参更常用 `useRoute`
讲义用 `router.currentRoute.value.query.id` 取参数，能用；但在 `<script setup>` 组件里更常见、更简洁的是 `const route = useRoute(); route.query.id`。
建议：作为风格补充告知，非错误。

### 4.（提示）"还有一种路由传参的方式"表述不完整
正文把对象写法 `$router.push({ path:'/test', query:{...} })` 称作"另一种传参方式"。严格说它仍是 **query 传参**（只是字符串写法换成对象写法），讲义这里其实是在对比"字符串 vs 对象"两种 query 写法。真正没覆盖到的是 **params 动态路由传参**（`path:'/test/:id'`，用 `route.params.id` 取）。
建议：不算讲错，但可补一句 params 传参，避免学生以为 query 就是全部。

### 5.（提示）"所有页面代码一开始就一次性加载完了"是通俗简化，与懒加载略有出入
这句在"通俗解释"里，核心意思（URL 变但不向服务器整页重取）是对的；只是本讲义每个路由都用 `() => import()` 懒加载，子页面是访问时才拉取，严格说不是"一开始全加载完"。
建议：补一句"（本项目页面按需懒加载）"，不必当成错误。

### 6.（提示）meta 的定义不准
正文把 `meta` 说成"额外补充路由参数的对象"。meta 是路由记录上的**自定义元信息**（如 title、权限标记），不是"路由参数"；路由参数指 params/query。
建议：改为"路由的自定义附加信息/元信息"。

## 正确的部分（确认无误）
- `createWebHistory(import.meta.env.BASE_URL)`、`{ path: '/', redirect: '/home' }` 正确。
- 嵌套路由子项用相对路径（`path: 'user'`）、`RouterLink to="/manage/user"`、父组件里放 `<RouterView />` 均正确。
- `$router` 全局变量在 `app.use(router)` 后可用于模板，说明正确。
