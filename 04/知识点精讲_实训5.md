### 2.1 客户端路由与 SPA：点菜单为什么不刷新页面

**① 讲义怎么说**：讲义"一、路由的定义"第 1~3 条：Vue Router 是 Vue 官方的**客户端路由**方案，"将浏览器的 URL 和用户看到的内容绑定起来……URL 会随之更新，但页面不需要从服务器重新加载"。通俗解释里说：普通网站点菜单会"刷新、转圈，去服务器重新下载一整个新网页"，单页网站则"所有页面代码一开始就一次性加载完了"。

**② 一句话讲透**：浏览器是一台电视，**URL 是频道号**。传统网站换台要换一台新电视（整页 HTML 重新下载：白屏、转圈、表单内容全丢）；SPA 是同一台电视换台。技术上就一句：**第一次把 HTML 和 JS 下载完，之后改地址栏靠 `history.pushState()`——它只改地址栏，不发网络请求。** 顺带给讲义那句"一次性加载完"打补丁：本工程每条路由都用了懒加载（2.4），启动时只加载入口那份代码，`Test.vue` 是你第一次点进去才下载的。

**③ 示例代码**：打开 http://localhost:5173/home，F12 → Console，粘贴运行：

```js
console.log('① 现在的地址：', location.href)
history.pushState({}, '', '/test')                 // 只改地址栏，不发请求
console.log('② pushState 之后：', location.href)    // 已经变成 /test
// ③ 看页面：内容还是 Home；看 Network：一条新请求都没有
// ④ 按浏览器后退：地址变回 /home，页面内容依然没变
```

**④ 逐行拆解**
- `location.href` 是完整地址，`location.pathname` 只有路径；Vue Router 匹配路由表看的就是路径加查询串。
- `history.pushState(state, title, url)`：`state` 是跟着这条历史记录一起存的数据（Vue Router 用它存内部状态，刷新后能从 `history.state` 读回）；`title` 所有浏览器都忽略（传空串）；`url` 是要显示在地址栏的新地址。
- `pushState()` **不发请求、不加载页面、也不触发 `popstate`**——它只做两件事：改地址栏、往历史记录压一条。
- `history.back()` 等价于点浏览器后退按钮；`popstate` 只在"历史记录指针移动"时触发，所以是 `back()` 触发的它。
- 只有**地址栏敲 URL、按 F5、点原生 `<a href>`** 这三种情况浏览器才真的请求服务器——这就是 SPA 部署后刷新子页面容易 404 的根源。

**⑤ 在你仓库里**
- `04/vue-router/src/App.vue:2` —— 整个文件只有 `<RouterView />`，它就是那块"屏幕"：URL 匹配到谁就往这个洞里塞谁。
- `04/vue-router/src/router/index.js:4` —— `createWebHistory(import.meta.env.BASE_URL)`，选中的就是 `pushState` 这套机制。

**⑥ 常见坑**
- 点链接整页闪一下、`Home.vue` 里填的字没了 → 你写的是原生 `<a href="/test">` 或 `location.href=` → 页面内跳转一律用 `<RouterLink>` / `router.push()`。
- 部署后刷新子页面 404（本地不会）→ `/manage/user` 在服务器上没有对应文件 → 服务器配 history fallback（Vite dev server 已配好，所以本地感觉不到）。

**⑦ 自测**

### 2.2 URL 与组件的映射表

**① 讲义怎么说**：通俗解释第 3 点原话："你提前写一份对照表：网址 /home → 显示首页组件，网址 /mine → 显示个人中心组件。Vue Router 会盯着地址栏，网址一变，就对照这份表，把对应的组件放到页面上展示出来。"

**② 一句话讲透**：这张表就是你手机里的**通讯录**——名字（URL）→ 号码（组件），你拨号（改地址栏），它去查表。背后是一条重要约定：**"当前在哪一页"永远以地址栏为准，不是你代码里的某个变量**，因为地址栏是用户唯一能复制、收藏、发群里、按 F5 还能回来的东西。

**③ 示例代码**：表本身就是 `04/vue-router/src/router/index.js:5-14` 的 `routes` 数组：

```js
routes: [
  { path: '/', redirect: '/home' },
  { path: '/home', name: 'home', component: () => import('../views/Home.vue') },
  { path: '/test', name: 'test', component: () => import('../views/Test.vue') },
  { path: '/manage', name: 'manage', meta: { title: '后台管理' }, component: () => import('../views/Manage.vue'), children: [
    { path: 'user', name: 'user', meta: { title: '用户列表' }, component: () => import('../views/User.vue') },
    { path: 'goods', name: 'goods', meta: { title: '商品列表' }, component: () => import('../views/Goods.vue') },
    { path: 'orders', name: 'orders', meta: { title: '订单列表' }, component: () => import('../views/Orders.vue') },
  ] }
],
```

想让表自己现形，在任意组件的 `<script setup>` 里加一行：`router.getRoutes().forEach(r => console.log(r.path, r.name, r.meta))`——`getRoutes()` 会把嵌套子路由也拉平列出来，排查"我到底配了几条"很好用。

**④ 逐行拆解**
- `path` 是主键，**从上往下匹配、先命中先用**；同一个 `path` 写两条：先写的赢，且不报错（本机实测）。
- `name` 也要求唯一，**重复更阴**：实测后写的赢、控制台一句警告都没有，你会莫名跳到别的页面。
- `component` 是 value，懒加载写法见 2.4；`meta` 是挂在记录上的自定义信息，2.13 讲。
- 两条"你以为会踩、其实不会"的规则先说清：**路径默认不区分大小写**（实测 `/Test`、`/TEST` 都能匹配 `path:'/test'`），**尾斜杠被忽略**（`/test/` 能匹配 `path:'/test'`）——这是默认选项 `sensitive: false`、`strict: false` 的效果。

**⑤ 在你仓库里**
- `04/vue-router/src/router/index.js:5-14` —— 表本身；`04/vue-router/src/App.vue:2` —— 表的"出口"。
- `04/vue-router/src/views/Test.vue:9` —— 页面把当前完整地址打给自己看。

**⑥ 常见坑**
- 新页面白屏 → 表里没有能对上这个路径的记录。看 Console，实测原文是 `[VUE_ROUTER_R0004] No match found for location with path "/test"`，后面带 fix 提示：**看到这条就知道不是组件写错，是表里没这条记录。**
- 改完 `routes` 浏览器没反应 → 热更新没跟上，或你改的是另一个工程的同名文件（本仓库有 5 个前端工程）→ F5 刷新，并确认终端里 dev server 的路径。

**⑦ 自测**
<details><summary>看答案</summary>

同一个 `path: '/test'` 写了两条会怎样？

访问 `/test` 时**先写的赢**（实测）。但如果两条的 `name` 都叫 `test`，那就是**后写的赢、且没有任何警告**——这种错最难查。

</details>

### 2.3 `createRouter` / `createWebHistory` / `BASE_URL`

**① 讲义怎么说**：讲义"五"贴出的 `index.js` 第 78~79 行是 `const router = createRouter({ history: createWebHistory(import.meta.env.BASE_URL),`，只给代码没解释；实验内容 1 要求"熟悉 `createRouter`、`createWebHistory` 创建路由实例"。

**② 一句话讲透**：`createRouter` 是**造一台导播台**——你把频道表（`routes`）交给它，它盯地址栏、决定播谁；`createWebHistory` 是**选地址栏长相**——正常路径 `/home`（History 模式，好看，部署要服务器配合）还是带井号的 `/#/home`（Hash 模式，丑，但扔哪都能跑）；括号里的 `BASE_URL` 回答"我这个前端最终放在服务器哪个子文件夹里"。

**③ 示例代码**：`04/vue-router/src/router/index.js` 的头尾（中间是 2.2 那张表）：

```js
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [ /* 见 2.2 */ ],
})

export default router
```

`BASE_URL` 是什么，在任意组件的 `<script setup>` 里 `console.log(import.meta.env)` 就能看到。本机实测 Vite 塞进去的对象是：`{"BASE_URL": "/", "DEV": true, "MODE": "development", "PROD": false, "SSR": false}`。想让它不是 `/`，在 `vite.config.js` 里加 `base: '/shop/'`，重启后首页地址变成 http://localhost:5173/shop/home；想切 Hash 模式，把第 1 行改成导入 `createWebHashHistory`、第 4 行改成 `createWebHashHistory()`，地址就变成 `/#/home`。

**④ 逐行拆解**
- `import { createRouter, createWebHistory } from 'vue-router'` —— **具名导入**，花括号里的名字必须和 vue-router 导出的完全一致（回顾训练营 L3）。
- `createRouter({ history, routes })` —— 只认这两个必填项：`history` 决定地址栏长相和历史记录怎么存，`routes` 就是那张对照表。
- `createWebHistory(import.meta.env.BASE_URL)` —— **不传也能跑**（默认就是 `/`），所以本地看不出差别，部署到子目录才炸：所有链接都少一层 `/shop/`。
- `export default router` 把实例给 `main.js` 用；**真正让它生效的是 `main.js:14` 的 `app.use(router)`**，不加这步 `<RouterLink>` 会被 Vue 当成不认识的组件。
- `import.meta.env` 是 **Vite 在编译时替换进去的**（不是浏览器自带，也不是 Node 的 `process.env`）；`BASE_URL` 一定以 `/` 开头、以 `/` 结尾，正好是 `createWebHistory()` 要的格式。

**⑤ 在你仓库里**
- `04/vue-router/src/router/index.js:1`（导入）、`:3-4`（造实例）、`:23`（导出）。
- `04/vue-router/src/main.js:14` —— `app.use(router)`，路由生效的开关；`04/vue-router/vite.config.js:8-18` 没配 `base`，所以实测 `BASE_URL` 是 `/`。

**⑥ 常见坑**
- 页面全白 + `[Vue warn]: Failed to resolve component: RouterLink` → `main.js` 漏了 `app.use(router)` → 补上（`import router from './router'` 会自动解析到 `router/index.js`）。
- Console 报 `Uncaught ReferenceError: process is not defined` → 你把 `import.meta.env.BASE_URL` 写成了 `process.env.BASE_URL`，**浏览器里没有 `process`** → 改回 `import.meta.env.*`。

**⑦ 自测**
<details><summary>看答案</summary>

把 `base` 改成 `'/shop/'` 重启后，为什么 `localhost:5173/home` 打不开、`localhost:5173/shop/home` 能打开？

`base` 决定"整个应用挂在哪个前缀下"：dev server 把应用挂在 `/shop/` 提供服务，同时 `import.meta.env.BASE_URL` 变成 `'/shop/'`，`createWebHistory('/shop/')` 也按这个前缀解析路由。**两件事是同一件事的两面。**

</details>

### 2.4 路由懒加载

**① 讲义怎么说**：讲义正文所有路由都写成 `component: () => import('../views/Test.vue')` 却没解释为什么；实验目的 2 要求"掌握路由懒加载写法"，实验内容 2 要求"使用路由懒加载导入组件"。

**② 一句话讲透**：懒加载是**点菜现做**，不是**开业前把整本菜单全做好**。`import('../views/X.vue')` 是动态导入，返回值是 **Promise**；写成 `() => import('../views/X.vue')` 的意思是"**先别导入，等真要进这个页面再调用这个函数**"；Vite 见到这种写法，会自动把该组件单独打成一个文件。

**③ 示例代码**：

```js
{ path: '/test', name: 'test', component: () => import('../views/Test.vue') }   // ✅ 对
{ path: '/bad',  name: 'bad',  component: import('../views/Test.vue') }         // ❌ 错：给的是 Promise
```

漏写箭头函数时，本机实测控制台原文：`[VUE_ROUTER_R0028] Component "default" in record with path "/bad" is a Promise instead of a function that returns a Promise. This will break in production if not fixed.`，它的 fix 就写着 `write "() => import('./MyPage.vue')", not "import('./MyPage.vue')"`。

懒加载到底省了什么？在本工程跑 `npm run build`，看 `04/vue-router/dist/assets/` 的真实产物：首屏 `index-DyAGkxy8.js` 是 **1157.96 kB**（含 Element Plus），而 `Home-CyA3qOY1.js` 只有 2.01 kB、`Test-DESMPkk4.js` 1.34 kB、`Manage-C0Q7KZCd.js` 0.77 kB、User/Goods/Orders 各约 0.3 kB——**每个懒加载页面都是一个独立文件，首屏不用下载它们**。

**④ 逐行拆解**
- 箭头函数是**一层包装**：vue-router 拿到它并不调用，等 URL 真要进 `/test` 时才调用、拿到 Promise 再 `await`，成功了才渲染。
- 直接写 `component: import('../views/X.vue')`，这行代码**在模块加载时就执行**——"懒"字没了，首屏反而更慢，而且 vue-router 拿到的是 Promise 不是函数（就是上面那条 R0028）。
- `'../views/Test.vue'` 是**相对当前文件**（`src/router/index.js`）算的；写 `'@/views/Test.vue'` 也行，别名配在 `vite.config.js:13-17`。
- 开发环境不打包，懒加载表现为"访问时才发一个 `/src/views/Test.vue` 请求"。想看效果：F12 → Network → 筛 JS → 清空 → 点"去测试页 Test"。

**⑤ 在你仓库里**
- `04/vue-router/src/router/index.js:7-12` —— 六条路由全是懒加载，一条静态导入都没有。
- `04/vue-router/dist/assets/` —— 上面那张产物清单就是从这里抄的（`dist/` 已被 `.gitignore` 忽略，不入库）。

**⑥ 常见坑**
- 漏写箭头函数：本地好好的、上线白屏 → 开发环境 vue-router 帮你兜住了 Promise，生产构建不兜底（R0028 原文就是这么说的）→ 写成 `component: () => import('../views/X.vue')`。
- 点进某页面才报"Failed to fetch dynamically imported module" → 懒加载把错误**推迟**了：路径写错、文件名大小写不对（Windows 不报错、Linux 服务器炸）都要等你点进去才发现 → 按报错里的路径核对文件名，别指望本地试出来。

**⑦ 自测**
<details><summary>看答案</summary>

为什么懒加载的路径写错了，启动时看不出来，点进去才炸？

`() => import('../views/X.vue')` 只是一个**等待被调用的函数**，模块加载阶段谁也不会去检查那个文件在不在。只有 URL 真匹配到这条路由、vue-router 调用它时才去下载——**错误在那一刻才产生**。这就是懒加载的代价：把编译期能发现的错误推到了运行期。

</details>

### 2.5 定义一个新路由（含 `name` 的作用）

**① 讲义怎么说**：讲义"二、定义一个新的路由"：以前能访问 Home，是"在 index.js 中定义了 Home.vue 这个路由"；现在"给 Test.vue 配上路由，也就是设置一个导航，让页面进行跳转"（配视频"新建一个路由 01.mp4"）。实验内容 2 给出四步：`views` 新建 `Test.vue` → `routes` 配置规则 → 懒加载导入 → 用 `<RouterLink>` 从 Home 跳过去。

**② 一句话讲透**：加一个页面 = **建文件 + 在表上加一行 + 写个入口跳过去**，三件事少一件都白干。`name` 是这条路由的**小名**：URL（`path`）将来可能改，小名可以不变，所以跳转时优先用 `name`。

**③ 示例代码**：第一步，新建 `04/vue-router/src/views/Test.vue`（最小可跑版）：

```vue
<template>
  <div style="padding: 20px">
```

### 2.6 声明式跳转 `<RouterLink>`

**① 讲义怎么说**：讲义"二"要求在 `Home.vue` 中"写上跳转语句"；"四、嵌套路由"的父页面也用 `<RouterLink to='/manage/user'>用户管理</RouterLink>` 切换子页面；实验内容 3-1 要求"使用 `<RouterLink to="路径">` 实现导航跳转"。

**② 一句话讲透**：`<RouterLink>` 是**一个会自己打电话的 `<a>` 标签**：渲染出来还是货真价实的 `<a href="/test">`（所以"在新标签页打开""复制链接"照样能用），但**左键点击被 vue-router 拦了下来**——不请求服务器，改用 `pushState` 换地址。

**③ 示例代码**：四种写法，抄进 `Home.vue` 就能跑：

```vue
<template>
  <!-- ① 最常用：字符串路径 -->
  <RouterLink to="/test">去测试页</RouterLink>
  <!-- ② 字符串 + 参数：参数直接拼在 ? 后面 -->
  <RouterLink to="/test?id=123&name=手机">带参数的测试页</RouterLink>
  <!-- ③ 对象形式：to 前面必须加冒号 -->
  <RouterLink :to="{ path: '/test', query: { id: 123, name: '手机' } }">对象形式</RouterLink>
  <!-- ④ 命名路由：URL 改了这里不用改 -->
  <RouterLink :to="{ name: 'test', query: { id: 3 } }">命名路由跳转</RouterLink>
</template>
```

本机实测：`to="/test"` 渲染出来的 HTML 是

```html
<a aria-current="page" href="/test" class="router-link-active router-link-exact-active">去测试页</a>
```

**④ 逐行拆解**
- `to="/test"` 传的是**字符串字面量**；`:to="{ path: '/test' }"` 的冒号是 `v-bind` 简写，意思是"引号里是 JS 表达式，当代码算"。
- `href="/test"` 是真的——这就是它能被"新标签页打开"的原因；左键点击被 `preventDefault()` 后改走 `pushState`（走的是 **push**，不是 replace）。
- 两个自动加的 class：`router-link-active`（当前路径**以**这条链接为前缀）、`router-link-exact-active`（当前路径**正好等于**它）——这是实训 6 做菜单高亮的基础。
- `aria-current="page"` 是无障碍属性，屏幕阅读器靠它念出"当前页"。

**⑤ 在你仓库里**
- `04/vue-router/src/views/Home.vue:9-10` —— 不带参数、字符串带参两种；`:31-33` —— 三个跳进嵌套子路由的链接。
- `04/vue-router/src/views/Manage.vue:4-6`、`04/vue-router/src/views/Test.vue:14` —— 父页面与返回首页的链接。

**⑥ 常见坑**
- 手一抖写成 `to="{ path: '/test' }"`（少个冒号）→ 实测整个字符串被当成路径，解析出的 path 是 `/{ path: '/test' }`，谁都不匹配（`matched = 0`）、白屏 + R0004 告警 → 要传对象，`to` 前面**必须**加冒号。
- 点了链接整页刷新 → 你把 `<RouterLink>` 写成了 `<a href>` → 页面内跳转用 `RouterLink`，只有跳**站外**才用原生 `<a href>`。
- 小知识：`to="test"`（不带斜杠）从 `/home` 出发也能到 `/test`（相对当前路由解析），能跑但别这么写。

**⑦ 自测**
<details><summary>看答案</summary>

`<RouterLink to="/test">` 和 `<a href="/test">` 渲染出的 HTML 几乎一样，为什么前者不刷新？

`<RouterLink>` 渲染的 `<a>` 上挂着 vue-router 的点击监听：左键点击时它 `preventDefault()` 掐掉浏览器默认行为（默认行为就是发请求、重新加载），然后自己 `pushState` 改地址、让 `<RouterView>` 换组件。原生 `<a href>` 没人拦它。

</details>

### 2.7 编程式跳转与 `$router` 的来历

**① 讲义怎么说**：讲义"三、1 编程式的路由"，`Home.vue` 里就是 `<el-button type="primary" @click="$router.push({ path: '/test', query: { id: 2, name: '手机' } })">路由传参</el-button>`。"注意"原文："模板中 `$router` 是全局路由操作实例……在 `main.js` 执行了 `app.use(router)`，Vue Router 会自动给所有组件模板挂载全局变量 `$router`。"实验内容 3-2 要求用按钮分别测试 `$router.push()` 和 `$router.replace()`。

**② 一句话讲透**：`<RouterLink>` 是**门上的门牌**（写死在模板里），`$router.push()` 是**你手里的遥控器**（在 JS 里按需触发）。什么时候必须用遥控器？**跳不跳要看条件的时候**。而 `app.use(router)` 不只是"启用路由"，它还往 `app.config.globalProperties`（所有组件都能读到的公共变量区）塞了 `$router` 和 `$route`——这就是模板里不 `import` 也能用 `$router` 的原因。

**③ 示例代码**：模板里直接用（`04/vue-router/src/views/Home.vue:16-18` 真身）：

```vue
<el-button type="primary" @click="$router.push('/test')">push 跳测试页</el-button>
<el-button type="warning" @click="$router.replace('/test')">replace 跳测试页</el-button>
<el-button @click="$router.back()">回退</el-button>
```

`<script setup>` 里 `$router` 用不了，要自己拿出来：

```vue
<script setup>
import router from '@/router/index.js'        // 写法一：直接 import（Home.vue:40 就是这样）
// import { useRouter } from 'vue-router'     // 写法二：组合式 API，推荐
// const router = useRouter()

const goTest = () => {
  if (!confirm('确定要离开首页吗？')) return   // 条件不满足就不跳 —— 这才是"编程式"的价值
  router.push('/test')                        // 带参数：router.push({ path: '/test', query: { id: 1 } })
}
</script>

<template>
  <el-button type="primary" @click="goTest">判断后再跳</el-button>
</template>
```

自己挂一个全局属性，原理立刻清楚——在 `main.js` 的 `app.use(router)` 后面加 `app.config.globalProperties.$sayHi = (name) => \`你好，${name}\``，任意模板里 `{{ $sayHi('同学') }}` 就能用；本机实测 `typeof app.config.globalProperties.$router` 是 `object`。反过来，把 `app.use(router)` 注释掉，模板里读 `$router` 会得到 `[Vue warn]: Property "$router" was accessed during render but is not defined on instance.`，紧接着 `Cannot read properties of undefined (reading 'currentRoute')`。

**④ 逐行拆解**
- `@click="$router.push('/test')"` —— 模板表达式里 `$router` 是全局属性；`push` 收**字符串**（路径）或**对象**（`{ path, name, query, params }`）。
- `$router` 是**路由器**（负责动作：跳转、守卫）；`$route` 是**当前路由信息**（负责数据：`path`/`query`/`params`）。**换台用 `$router`，看现在播什么用 `$route`。**
- `$router.back()` 等价于点浏览器后退；同族还有 `forward()`、`go(-2)`（后退两格）。
- `router.push()` **返回 Promise**，但导航被取消或改道时它**不抛错**，而是 resolve 一个"导航失败对象"（实测：守卫里 `return false` 时 `push()` 的 Promise 正常 resolve）——所以别用 `try/catch` 判断"跳没跳成功"。
- `<script setup>` 编译后是一段**没有 `this`** 的函数，读不到实例属性，所以 `$router` 不存在，必须 `import` 或 `useRouter()`。

**⑤ 在你仓库里**
- `04/vue-router/src/views/Home.vue:16-18`（模板用 `$router`）、`:40`（`import router`）、`:48-50`（函数里 `router.push`）。
- `04/vue-router/src/views/Test.vue:12-13` —— 回首页的 push / replace 一对按钮；`04/vue-router/src/main.js:14` —— `$router`、`$route` 的唯一来源。

**⑥ 常见坑**
- `<script setup>` 里写 `$router.push('/test')` 报 `ReferenceError: $router is not defined` → `$router` 挂在组件实例上，不是全局变量 → 改成 `import router from '@/router/index.js'` 或 `const router = useRouter()`。
- 写成 `$route.push('/home')` 报"不是一个函数" → `$route` 只是信息对象，没有 `push` → 跳转用 `$router`、读参数用 `$route`。
- 删掉 `app.use(router)`：页面全白 + `Failed to resolve component: RouterLink` + 上面那条 `$router` 警告 → 补回这一行，并 `console.log(router)` 确认不是 `undefined`。

**⑦ 自测**

为什么模板里能直接写 `$router.push('/test')`，`<script setup>` 里却不行？

因为 `$router` 是 Vue Router 插件在 `app.use(router)` 时注册到**应用级全局属性**上的；模板渲染时 `this` 指向组件实例，能顺着读到它。而 `<script setup>` 是没有 `this` 的 `setup()` 函数，只能自己 `import` 或用 `useRouter()`。

### 2.8 `push` 与 `replace` 的区别

**① 讲义怎么说**：讲义"三、1"只有一句"push 和 replace 两者区别，看视频 push 和 replace 两者区别 02.mp4"——**正文没有文字说明**。这一节就是把那个视频讲清楚。

**② 一句话讲透**：浏览器维护一个**历史记录栈**（一摞盘子）：`push` = **往最上面再放一个**（多一条记录），随时能拿走（点后退）；`replace` = **把最上面那个换掉**（数量不变），换走的再也回不来。后退按钮干的事就是"把最上面那个拿走"，所以区别只有一句：**你换掉的那一页，还能不能退回去。**

**③ 示例代码**：用本工程实测（`Home.vue:16-17` 那两个按钮）：

```text
初始（在 /home）：       [ 起始页 ] [ /home ]          ← 最右边是栈顶
点 "push 跳测试页"：      [ 起始页 ] [ /home ] [ /test ]
点浏览器后退 → 回到 /home ✅

初始（在 /home）：       [ 起始页 ] [ /home ]
点 "replace 跳测试页"：   [ 起始页 ] [ /test ]          ← /home 被覆盖掉了
点浏览器后退 → 直接回到"起始页"（看着像退出了网站）❌
```

```js
router.push('/test')      // 留历史：能退回来
router.replace('/test')   // 不留历史：退不回来
router.back()             // 等价于点浏览器后退按钮
```

`<RouterLink>` 默认走 push；想让它走 replace 加个裸属性：`<RouterLink to="/test" replace>去测试页</RouterLink>`。

**④ 逐行拆解**
- 两种写法**参数完全一样**（字符串或对象都行），唯一差别就是"留不留一条记录"。
- `router.back()` 的准确语义不是"回到上一页"，而是"**在历史记录里后退一格**"——上一格如果被 replace 覆盖了，它就退到更前面去。
- 判断标准：**"用户会不会想回到这一页？"** 会 → push；不会（登录页、支付结果页、临时中转页）→ replace。

**⑤ 在你仓库里**
- `04/vue-router/src/views/Home.vue:16-17` —— push / replace 一对按钮；`:18` 是 `$router.back()`，专门用来做对比实验。
- `04/vue-router/src/views/Test.vue:12-13` —— 回首页时同样给了 push / replace 两个选择。

**⑥ 常见坑**
- 登录成功后跳首页，用户点后退**又回到登录页**，来回鬼打墙 → 用了 `push('/home')`，登录页那条记录还在栈里 → 登录成功后用 `replace('/home')`。
- 做对比实验时两次结果看着一样 → 上一次实验的记录还在栈里 → **每做一次实验就新开一个标签页**，从 `http://localhost:5173/home` 重新开始。

### 2.9 默认路由 / `redirect` 重定向

**① 讲义怎么说**：讲义"三、2 默认路由"：当用户只访问项目域名根路径（不带任何后缀，即 `/`）时，"Vue Router 就会渲染默认路由指定的页面。通常使用 `redirect` 重定向的方式来设置默认路由"，输入 http://localhost:5173/ 就进入 Home.vue 页面。

**② 一句话讲透**：`redirect` 是路由表里的**传送门**：这条记录自己不渲染任何组件，只负责说"别停这儿，去那边"。它解决的问题是——**用户不会输 `/home`，他只会输域名。**

**③ 示例代码**：改 `04/vue-router/src/router/index.js:6`，三种写法都能用：

```js
routes: [
  // 写法一：字符串，最直观（本工程现在用的就是这种）
  { path: '/', redirect: '/home' },
  // 写法二：对象 + name，URL 改了不用回来改这里（推荐）
  // { path: '/', redirect: { name: 'home' } },
  // 写法三：函数，能按条件决定去哪（做权限判断时有用）
  // { path: '/', redirect: () => (localStorage.getItem('token') ? '/home' : '/login') },
  { path: '/home', name: 'home', component: () => import('../views/Home.vue') },
],
```

**④ 逐行拆解**
- `redirect` 的值可以是**字符串路径**、**路由对象**（`{ path }` 或 `{ name }`）或**函数**——实测三种都能跑，`push('/')` 之后最终都停在 `/home`。
- 带 `redirect` 的记录**不需要 `component`**，它永远不渲染。
- **`redirect` 发生在路由守卫之前**：实测访问 `/` 时守卫只被调用一次，`to.fullPath` 已经是 `/home`、`from` 是 `/`。**记死这一点**——守卫看到的 `to` 是"重定向之后的目标"，2.13 那个"首页标题变成 undefined"的坑，根子就在这里。
- 同一条机制也用来解决"父路由本身没内容"：实训 6 的 `05/admin-layout/src/router/index.js:16` 就是 `{ path: '', name: 'manageHome', redirect: '/manage/detail' }`。

**⑤ 在你仓库里**

**⑥ 常见坑**

### 2.10 query 传参：字符串形式、对象形式与读取

**① 讲义怎么说**：讲义"三、3 路由传参"：参数拼在地址栏 `?` 后面，"页面跳转时跟着网址一起携带数据"，例子是 `http://localhost:5173/test?id=123`；"参数获取"一节写"通过 `router.currentRoute.value.query.id` 获取 id 的值"；最后"注意：还有一种路由传参的方式"给的是对象写法（那仍然是 query，见 2.11）。**顺便纠一处讲义错误**：对象写法里是 `query: { id: 2, name: '手机' }`，紧接着的说明却写"会自动转成 URL 字符串：`/test?id=123&name=手机`"——一个写 2、一个写 123，前后对不上（`讲义勘误_实训5.md` 第 2 条）。下面统一用 `123`。

**② 一句话讲透**：query 是**贴在门牌号后面的便签**：门牌号还是那个门牌号（`/test` 这条路由没变），便签上写着"找谁、什么事"，适合传**可选的筛选条件**。而读取的三层 `router.currentRoute.value.query.id` 是：**遥控器 → 当前频道 → 频道里的参数**——`currentRoute` 是"当前频道"这个**盒子**（响应式容器），`.value` 是**打开盒子**，`.query` 是**里面那一格**；少写 `.value`，你打开的是盒子本身，盒子上没有 `query`，于是拿到 `undefined`。

**③ 示例代码**：四种跳转写法，都能跑：

```vue
<template>
  <!-- ① 字符串形式：参数直接拼在地址里 -->
```

**④ 逐行拆解**
- `?` 后面那串叫 **query string**，格式 `键=值&键=值`，是 URL 标准的一部分，跟 Vue 无关。
- **值最后一定会变成字符串**：实测传数字 `id: 123`，跳过去后 `query.id` 是字符串 `"123"`，`route.query.id + 1` 得到 `"1231"` 而不是 `124`。

- **为什么必须用 `computed`**：同一个组件实例在参数变化时**不会重建**（从 `/test?id=1` 跳到 `/test?id=2` 是同一个组件），只在 `onMounted` 里取一次的话，页面上永远停着第一次的值。

### 2.11 query 与 params 的区别 + `useRoute()`

**① 讲义怎么说**：讲义"三、3"最后那句"**注意：还有一种路由传参的方式**"，指的是把 `push('/test?id=2')` 换成 `push({ path: '/test', query: { id: 2 } })`。严格说这**不是"另一种传参方式"，它还是 query**，只是从字符串写法换成了对象写法（`讲义勘误_实训5.md` 第 4 条）。讲义真正没讲到的是 **params**。

**② 一句话讲透**：**query 是便签贴在门牌号后面**（`/detail?id=7`，门牌号还是 `/detail`）；**params 是数字本身就是门牌号的一部分**（`/detail/7`，门牌号是 `/detail/:id`）。判断标准：这个参数**用来定位资源**（哪件商品、哪个用户）→ params；**只是修饰/筛选**（第几页、搜索词）→ query。

**③ 示例代码**：本工程**没有** params 例子（讲义也没写，这就是那个缺口），下面这套直接加进 `04/vue-router` 就能跑。第一步，新建 `04/vue-router/src/views/Detail.vue`：

```vue
<template>
  <div style="padding: 20px">
    <h3>商品详情页</h3>
    <p>params 取到的 id：【{{ route.params.id }}】</p>
    <p>query  取到的 from：【{{ route.query.from }}】</p>
    <p>完整地址：{{ route.fullPath }}</p>
  </div>
</template>

<script setup>
import { useRoute } from 'vue-router'
const route = useRoute()   // params 和 query 在这一层的取法一模一样
</script>
```

第二步，在 `04/vue-router/src/router/index.js:8`（`/test` 那条）后面加一条——`:id` 是**占位符**，这一段位置上的任意值都会被接住；第三步，跳过去（**两种写法只有一种是对的**）：

```js

```

```vue

  router.push({ name: 'detail', params: { id: 7 }, query: { from: 'home' } })   // 地址变成 /detail/7?from=home

// ❌ 错：path 和 params 一起用，params 会被直接丢掉

  router.push({ path: '/detail', params: { id: 7 } })   // 地址只有 /detail

```

本机实测的告警原文：`[VUE_ROUTER_R0006] Path "/detail" was passed with params but they will be ignored because a "path" was passed.`，fix 提示是"用命名路由 `{ name, params }` 代替 `{ path, params }`"。也可以直接访问 http://localhost:5173/detail/7?from=home —— 刷新后 params 依然在，**因为它本来就是 URL 的一部分**。

**④ 逐行拆解**
- `path: '/detail/:id'` 里的 `:` 是占位符语法（动态路由参数），可以有多个：`/user/:uid/post/:pid` 对应 `params.uid`、`params.pid`。
- 取值 `route.params.id`，**取法和 query 一模一样**，只是属性名不同；值同样是**字符串**（实测 `params.id` 是 `"7"`）。
- **只有用 `name` 跳才能带 `params`**：实测 `{ name:'detail', params:{id:7} }` → `/detail/7`；`{ path:'/detail', params:{id:7} }` → 地址只有 `/detail`，参数被忽略并报 R0006。
- **`useRoute()` / `useRouter()` 是 query 和 params 的通用现代写法**：`const route = useRoute()` 之后 `route.query.id`、`route.params.id`、`route.fullPath` 随便用，不用写 `.value`。实测 `useRouter()` 拿到的就是同一个路由器实例（`useRouter() === router` 为 `true`），两者只是风格差异，新代码推荐组合式写法。

| | query | params |
|---|---|---|
| URL 长相 | `/detail?id=7` | `/detail/7` |
| 路由怎么配 | `path: '/detail'` | `path: '/detail/:id'` |
| 怎么跳 | `{ path:'/detail', query:{id:7} }` 或 `{ name:'detail', query:{id:7} }` | **只能** `{ name:'detail', params:{id:7} }` |
| 怎么取 | `route.query.id` | `route.params.id` |
| 刷新后还在吗 | 在 | 在（它就在 URL 里） |
| 值的类型 | 字符串 / 数组 | 字符串 |
| 适合传什么 | 筛选条件、页码、可选参数 | 资源标识（哪件商品、哪个用户） |

**⑤ 在你仓库里**
- `04/vue-router/src/views/Test.vue:23` —— `const route = useRoute()`，本工程唯一用组合式写法的地方；`:8` 是模板里 `route.query.id`。
- `04/vue-router/src/router/index.js:8` —— params 例子就加在这一行后面（本工程目前没有 `:id` 这种动态路由）。

**⑥ 常见坑**
- 跳转后 `route.params.id` 是 `undefined`、地址只有 `/detail` → 用了 `{ path, params }`，params 被忽略（R0006）→ 改成 `{ name: 'detail', params: { id: 7 } }`，**params 只认 `name` 不认 `path`**。

### 2.12 嵌套路由

**① 讲义怎么说**：讲义"四、嵌套路由"给了父页面模板：最外层写着"这是父级页面"，下面是三个 `<RouterLink to='/manage/xxx'>`，里面一个方框装着 `<RouterView />`（配视频"路由嵌套 04.mp4"）。实验内容 4 要求建 `Manage.vue` + `User/Goods/Orders.vue`，用 `children` 配子路由，父页面里放 `<RouterView />`，"观察父页面保留、子页面局部刷新效果"。

**② 一句话讲透**：嵌套路由就是**套娃**。`App.vue` 里的 `<RouterView />` 是第一层洞（装整个页面），`Manage.vue` 里的 `<RouterView />` 是第二层洞（装后台右侧内容区）。访问 `/manage/user` 时**两个组件同时渲染**：`Manage.vue` 铺满页面，`User.vue` 被塞进它那个洞里——所以点链接切换时黄色父页面一直在（它没被销毁），只有绿框里的组件换掉了。

**③ 示例代码**：路由配置（`04/vue-router/src/router/index.js:9-13`）：

### 2.13 路由守卫 `beforeEach` + `meta`

**① 讲义怎么说**：讲义"五、路由守卫"：好处是"集中管理、全局统一规则、路由切换必更新、和权限逻辑放一起"；核心原理是"在 routes 路由元信息 meta 中定义 title 字段……使用前置守卫 `router.beforeEach`，每次路由跳转时读取 meta.title，赋值给 `document.title`"。讲义原文注释保留如下（换成好记的话：**`from` 是你现在待着的页面，`to` 是你正要去的那页面，`next()` 是"放行"**）：

```js
// from：将要进行跳转的当前route对象 (跳转前的一些操作)
// to: 跳转后route对象 (跳转后的一些操作)
// next(): 调用该方法后, 才能进入下一个钩子
```

**② 一句话讲透**：守卫就是**小区门口的保安**：不管你从哪栋楼出来、要去哪栋楼，每次都得先过他。他手上有一张表（`to.meta`），写着"这栋楼叫什么名"，他顺手把门口大屏（`document.title`）改成新名字。好处是把"改标题"从 N 个页面挪到 1 个地方：各页面自己写一遍 `document.title = '首页'`，改规则要改 N 处；写在守卫里只改 1 处，**新加的页只要配了 meta 就自动有标题**。

**③ 示例代码**：本工程实际用的版本（`04/vue-router/src/router/index.js:17-21`）；`meta` 就挂在路由记录上，写法见 2.12 那段路由配置（`meta: { title: '后台管理' }`、`meta: { title: '用户列表' }`）：

```js
// 修正版守卫：给没有 meta.title 的页面一个兜底默认标题
router.beforeEach((to, from, next) => {
  document.title = to.meta.title || '默认标题'
  next()
})
```

`next()` 已废弃，新写法是不写第三个参数、直接 `return`：

```js
router.beforeEach((to, from) => {
  document.title = to.meta.title || '默认标题'
  if (to.path === '/vip' && !localStorage.getItem('token')) {
    return '/login'     // 没登录：改道去登录页（等价于老的 next('/login')）
  }
  if (to.path === '/free') {
    return false        // 取消这次导航，留在原地（等价于老的 next(false)）
  }
  // 什么都不返回 = 放行（等价于老的 next()）
})
```

**④ 逐行拆解**
- `router.beforeEach(fn)` 注册**全局前置守卫**：每次导航（输地址、点链接、`push`、前进后退）在**确认之前**都会跑一遍。
- `to` 是**正要去**的路由对象，`from` 是**当前所在**的路由对象（首次进入应用时 `from` 是初始空白路由）。
- `to.meta` 是**路由记录上的自定义元信息对象**。讲义把它说成"额外补充路由参数的对象"是不准的：路由参数指 `params`/`query`，`meta` 是你自己挂上去的任意附加信息（`title`、`requiresAuth` 都常见）。
- **`meta` 会自动合并父子级**：实测父路由 `meta:{title:'后台管理'}` 下，子路由没写 meta 时 `to.meta.title` **继承**成"后台管理"，不是 `undefined`。只有整条链都没配 meta（本工程的 `/home`、`/test`）才是 `undefined`。
- **`document.title = undefined` 会变成字符串 `"undefined"`**：JS 会把值自动转成字符串，浏览器标签上就明晃晃写着 undefined——这是讲义的实际 bug。
- **`next()` 已废弃**：本机 vue-router 5.3.1 每次导航都打印 `[VUE_ROUTER_R0025] The next() callback in navigation guards is deprecated.`，fix 提示是 `next()` → `return`、`next(false)` → `return false`、`next('/path')` → `return '/path'`。本工程为和讲义、报告保持一致仍用 `next()`，但你要知道它过时了。
- **声明了三个参数却忘了调 `next()`**：实测**导航永久挂住**，页面不切换，**控制台连报错都没有**，那个 `push()` 的 Promise 永远不 resolve。这是最难查的一种卡死。

**⑤ 在你仓库里**
- `04/vue-router/src/router/index.js:18-21` —— 修正版守卫；`:9-12` 是四条路由的 `meta.title`。

**⑥ 常见坑**
- 访问 `/home` 或 `/test`，浏览器标签写着 **"undefined"** → 这两条路由没配 `meta`，`to.meta.title` 是 `undefined`，赋值后被转成字符串 → 写成 `document.title = to.meta.title || '默认标题'`。**注意 `||` 的位置**：不是给 meta 兜底，是给"取出来的值"兜底。
- 控制台每条导航都刷一遍 `[VUE_ROUTER_R0025] The next() callback in navigation guards is deprecated.` → 守卫用了第三个参数 `next` → 去掉它，改 `return` 风格。
- 点链接没反应、页面不动、也不报错 → 守卫声明了 `next` 但某个分支忘了调用它 → 要么保证每条分支都调 `next()`，要么改写成 `return` 风格（推荐）。

**⑦ 自测**
<details><summary>看答案</summary>

父路由配了 `meta: { title: '后台管理' }`，子路由**没配** meta。访问子路由时标签显示什么？

显示 **"后台管理"**——`to.meta` 会把父子 meta 合并，子级没写就继承父级（实测）。所以"标签变成 undefined"只发生在**整条匹配链都没配 meta** 的顶级路由上（本工程的 `/home`、`/test`）。

## 6. 讲义勘误速查（本讲）

| 讲义原文 | 问题 | 正确写法 |
|---|---|---|
| `document.title = to.meta.title` | **严重**。`/home`、`/test` 没有 meta，`to.meta.title` 是 `undefined`，赋给 `document.title` 变成字符串 "undefined"，标签上明晃晃写着 undefined | `document.title = to.meta.title \|\| '默认标题'` |
| `$router.push({ path: '/test', query: { id: 2, name: '手机' } })`，下一句却写"会自动转成 URL 字符串：/test?id=123&name=手机" | 示例里是 2，说明文字里是 123，前后对不上 | 两处统一成同一个值（本讲统一用 123） |
| "所有页面代码一开始就一次性加载完了" | 通俗简化和本讲自己的懒加载写法有出入：启动时只加载入口那份代码，子页面是访问时才下载的 | 保留通俗讲法，补一句"（本项目页面按需懒加载）" |
| "在 routes 路由元信息 meta（meta：额外补充路由参数的对象）中定义 title" | `meta` 不是"路由参数"。路由参数指 `params`/`query`，`meta` 是挂在路由记录上的**自定义元信息** | 改成"路由记录上的自定义附加信息（元信息），如 title、权限标记" |
| "注意：还有一种路由传参的方式"（指 `{ path, query }` 对象写法） | 表述不完整：那仍然是 **query 传参**，只是字符串写法换成对象写法；真正没讲到的是 **params** | 补一节 `path: '/detail/:id'` + `route.params.id`，并写明"params 只能用 `name` 跳，用 `path` 会被忽略"（本讲 2.11） |
| `router.beforeEach((to, from, next) => { document.title = to.meta.title; next() })` | `next()` 在本机 vue-router 5.3.1 已废弃，每次导航报 `[VUE_ROUTER_R0025] The next() callback in navigation guards is deprecated.` | 去掉第三个参数，用 `return`（放行）/ `return false`（取消）/ `return '/login'`（改道） |
