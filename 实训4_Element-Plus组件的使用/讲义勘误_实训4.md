## 勘误 1（高）分页示例是"假分页"：`:data` 绑的是整份数组，从未按页切片；配 `pageSize4 = ref(100)` 连第 2 页都没有

- **性质**：讲义示例实质错误（组件用法演示失真）。
- **【讲义原文】** 十、分页组件 el-pagination：
  ```html
  <el-table :data="tableData" style="width: 100%" stripe> ... </el-table>
  <el-pagination v-model:current-page="currentPage4" v-model:page-size="pageSize4"
      :page-sizes="[5, 10, 15, 50]" :background
      layout="total, sizes, prev, pager, next, jumper" :total=tableData.length />
  ```
  ```js
  const currentPage4 = ref(1)
  const pageSize4 = ref(100)          // ← 每页 100 条
  const tableData = [ …23 条… ]
  ```
- **【问题】** `el-pagination` **不负责切数据**，只负责"告诉你是第几页、每页几条"；讲义把整份 `tableData` 直接给表格，没有 `slice`，所以：① 初始 `pageSize=100 > 23 条` → 只有 1 页，页码根本点不动；② 学生把每页条数改成 5 后，页码出来了，但**表格内容永远不变**——这是"分页"这一节最核心的失败。
- **【实测证据】**（把讲义这段原样抄进隔离工程 `.extract/verify/tmp-app/src/App.vue`，Chrome 实测）
  ```
  paginationClass : "el-pagination"          // 注意：连 is-background 都没有（见勘误 3）
  totalText       : "共 23 条"
  pageSizeShown   : "100"                    // 下拉框初始显示 100，但候选只有 5/10/15/50
  pagerPageNumbers: ["1"]                    // 只有一页，翻页无从谈起
  tableRows       : 23                       // 23 行全部渲染
  ```
  用仓库的对照页（`/comp-orig`，每页 5 条、7 行数据）补充验证"翻页不生效"：
  ```
  点第 2 页前 rows: 人参/三七/当归/山药/黄精/石斛/白芍   (7 行)
  点第 2 页后 rows: 人参/三七/当归/山药/黄精/石斛/白芍   (7 行，完全没变；只有页码高亮变 2)
  ```
  正确写法（仓库 `Components.vue`）实测第 1 页只显示 3 行（`人参/三七/当归`），翻页才换内容。
- **【正确写法】** 加计算属性切片，再交给表格：
  ```js
  const currentPage4 = ref(1)
  const pageSize4 = ref(5)
  const pagedData = computed(() => {
    const start = (currentPage4.value - 1) * pageSize4.value
    return tableData.slice(start, start + pageSize4.value)
  })
  // <el-table :data="pagedData">
  ```
  或者明确写："本例只演示分页组件的外观，切片/后端分页在实训6 再补"。（仓库 `实训3/工程/element-plus/src/views/Components.vue:189-192` 就是修正版。）
- **【影响程度】** 高：这是本讲"表格+分页"的完整示例，照抄出来的功能是坏的；而且它传递了一个错误认知——"分页组件会自动分数据"（见勘误 13）。

## 勘误 2（中）`pageSize4 = ref(100)` 与 `:page-sizes="[5,10,15,50]"` 不自洽：下拉框初始显示 100，但 100 不在候选里

- **【讲义原文】** 同上：`const pageSize4 = ref(100)` + `:page-sizes="[5, 10, 15, 50]"`（十、十一两处都一样）。
- **【问题】** 初始每页条数 100 不在候选数组里：① 下拉框显示 "100" 但展开后没有任何一项被选中，学生以为组件坏了；② 100 大于总条数 → 永远只有一页。
- **【实测证据】** 上文 `pageSizeShown: "100"`，`pagerPageNumbers: ["1"]`；把每页条数改成 5 后页码变成多页（此时才暴露"不切片"的问题）。
- **【正确写法】** `const pageSize4 = ref(5)`，或把 `100` 加进 `:page-sizes`。
- **【影响程度】** 中：与勘误 1 叠加，让分页看起来"彻底不可用"。

## 勘误 3（中）`:background` 写成了绑定写法：Vue 3.4+ 会把它当**同名简写** `:background="background"` → `undefined` → 页码没有底色 + 控制台告警

- **【讲义原文】** 十、十一共 3 处 `<el-pagination … :background … />`（每处前面有冒号）。
- **【问题】** `background` 是 **Boolean 类型 prop**，正确写法是**裸属性** `background`；写成 `:background` 后，Vue 3.4+ 的"同名简写"规则把它解释成 `:background="background"`，而 `<script setup>` 里没有名为 `background` 的变量 → 取到 `undefined`（falsy）→ prop 为 `false`，且控制台报一条 warn。这是 Vue 3.4 才引入的新坑，讲义（以及大多数老教程）都没意识到。
- **【实测证据】**
  1. 编译产物（本次用项目自带 `@vue/compiler-sfc` 编译讲义原样模板）：
     ```
     讲义版 :background   →  background: _ctx.background,
     修正版 裸 background →  background: "",
     ```
  2. 浏览器 `/comp-orig` 实测（讲义原样）：
     ```
     .el-pagination class : "el-pagination"        // 没有 is-background
     页码按钮背景色       : rgb(255, 255, 255)      // 白底
     console : [Vue warn]: Property "background" was accessed during render but is not defined on instance.
     ```
  3. 对照 `/comp`（仓库修正版，裸 `background`）：
     ```
     .el-pagination class : "el-pagination is-background"   // 有
     页码按钮有蓝色/灰底色
     ```
- **【正确写法】** 去掉冒号：`<el-pagination … background … />`（只写属性名，不写值）。
- **【影响程度】** 中：功能不致命，但"照着讲义配的分页没底色"，且控制台一直挂 warn，会干扰学生排查别的错误。

## 勘误 4（中）`interval="3000"` 是字符串：**有类型告警，但轮播仍然 3 秒一切**——不要写成"不生效"

- **性质**：讲义类型错误（可跑，但语义不严谨 + 告警）。
- **【讲义原文】** 七、Carousel 走马灯（普通版与卡片式两处）：
  ```html
  <el-carousel height="400px" style="width: 550px" autoplay interval="3000" pause-on-hover>
  ```
- **【问题】** `interval` 是 **Number** 类型 prop（单位毫秒）：`interval="3000"` 传的是字符串 `"3000"`，控制台报 `Invalid prop`；Element Plus 内部 `setInterval(() => playSlides(), props.interval)` 会把字符串**隐式转数字**，所以**轮播照常工作**。问题是语义/类型不符合组件契约，将来换实现方式、开 TS 严格校验、单元测试断言类型时就会暴露。
- **【实测证据】**
  1. 编译产物：`interval="3000"` → `interval: "3000"`；` :interval="3000"` → `interval: 3000`。
  2. 控制台（`/comp-orig`）：
     ```
     [Vue warn]: Invalid prop: type check failed for prop "interval".
       Expected Number with value 3000, got String with value "3000".
     ```
  3. **行为实测**（200ms 采样 8.4 秒，记录 `.is-active` 下标）：
     ```
     interval="3000"（字符串） 切换时刻(ms): 630, 3571, 6726    → 周期 ≈ 2.9s / 3.2s
     :interval="3000"（数字）   切换时刻(ms): 630, 3571, 6726    → 完全一致
     ```
     即字符串版**确实每 3 秒切一张**，与数字版无差别。对照 `/comp`（`:interval="2000"`）控制台干净、无告警。
- **【正确写法】** `:interval="3000"`（数字）；讲义自己在"二、文本域"就强调过"写数字要加 `:`"，这里正好可以互相印证。
- **【影响程度】** 中：不修也能用，但控制台告警 + 类型错误；**文档不能写成"不加冒号就不轮播"（那是错的）**。

## 勘误 7（低）表格列宽混用 `width="180"` 与 `width="100px"`：**两种都能用**，但 `width="20%"` 会被当成 **20 像素**

- **性质**：讲义前后风格不统一（不是错误），但"百分比列宽"是坑。
- **【讲义原文】** 九、（表格）用 `width="180"`；十一、（弹窗）用 `width="100px"` / `width="230px"` / `width="660px"`。
- **【问题】** Element Plus 表格的 `parseWidth` 是 `Number.parseInt(width, 10)`：`"100px"` → 100（能用）；`"20%"` → **20**（被当成 20px，而不是 20%）。所以"带 px 能用"这一点旧勘误已经更正过，本次再确认；真正会错的是百分号。
- **【实测证据】** 隔离工程 `#tbl-width` 三列（180 / 100px / 20%）：
  ```
  colgroup col style : ["180px", "100px", "20px", ...]
  th 实际宽度        : [{180}, {100}, {20}]
  ```
  → `width="20%"` 解析成了 20px，**不是** 20%。源码依据 `element-plus/es/components/table/src/util.mjs:110-116`：
  ```js
  function parseWidth(width) {
    if (width === "") return width;
    if (!isUndefined(width)) {
      width = Number.parseInt(width, 10);   // "100px"→100, "20%"→20
      if (Number.isNaN(width)) width = "";
    }
    return width;
  }
  ```
- **【正确写法】** 统一写不带单位的数字（`width="180"`）最省心；要按比例请用 `min-width` 或 `flex` 布局，别用 `%`。
- **【影响程度】** 低：讲义自身没有用 `%`，只是风格不统一；但学生容易自己"创新"写 `%` 然后踩坑。

## 勘误 9（低）Checkbox/Radio 的 `label`、`value` 语义在 2.14.x 里要说清楚（讲义只写了"版本会影响用法"）

- **【讲义原文】** 五、Checkbox："注意，EL 的版本号会影响具体的用法，我的版本号是 `^2.14.2`"；组内用 `<el-checkbox v-for=… :label="item.label" :value="item.name" />`；基本用法只用 `label="冬虫"`。
- **【问题】** 讲义没说明"哪个是显示文字、哪个是绑定值"，学生换版本/组内漏写 `value` 时行为会变。本次查 `element-plus@2.14.6` 源码确认：
  - `checkbox/src/composables/use-checkbox-status.mjs:10-13`：`actualValue = isPropAbsent(props.value) ? props.label : props.value`（**value 优先，label 兜底当值**）；
  - `use-checkbox.mjs` / `use-radio.mjs` 里 `useDeprecated({ from: "label act as value", replacement: "value", version: "3.0.0" })`，触发条件是 **在 group 里且没有 value**。
  - 即：讲义组示例同时写了 `:label` 和 `:value` → 正确、**无告警**；基本用法单选框（不在组里）只写 `label` → 也正确。
- **【实测证据】** 隔离工程实测：4 个单独 checkbox 正常渲染出"冬虫/人参/鹿茸/枸杞"；多选框组点第一个后显示 `你的选择是：[ "阿胶1" ]`（绑定的是 `:value="item.name"`，显示的是 `label`）；控制台**无任何 deprecation 告警**。
- **【正确写法】** 补一句："`label` 是显示文字（组内不写 `value` 时会被当成值，2.14 起会告警）；`value` 是绑定值。2.x 建议两者都写，3.0 起 `label` 不再当值。"
- **【影响程度】** 低：讲义代码本身对；说明不充分，换版本易踩。

## 勘误 13（中·新增）"当数据量过多时，使用分页分解数据"——**错，分页组件不分解数据**

- **【讲义原文】** 十、分页组件 开头第一句："当数据量过多时，使用分页分解数据"。
- **【问题】** 这句话是本讲"假分页"的认知根源。`el-pagination` 只提供 UI 状态（当前页、每页条数）和页码按钮，**不会碰你的数组**；数据切分必须自己写（`computed` + `slice`，或交给后端 `limit`）。把它讲成"分页组件负责分解数据"，学生就写不出正确代码。
- **【实测证据】** 见勘误 1：`:total` 写对了（"共 23 条"），但表格始终 23 行；只有把 `:data` 换成切片结果后，第 1 页才只显示 3 行。
- **【正确写法】** "分页组件是**页码遥控器**，只告诉我们'要看第几页、每页几条'；真正切片要自己用 `computed + slice` 做，或把 `currentPage/pageSize` 发给后端由后端分页。"
- **【影响程度】** 中：一句话的概念错误，直接导致示例功能失效。

## 勘误 16（低·新增）表格数据 `tableData` 是普通数组（非响应式），讲义删除示例只用 `alert()` —— 学生改成"真删除"会不生效

- **【讲义原文】** 九、十、十一 都写 `const tableData = [ … ]`（普通 `const` 数组，没有 `ref`/`reactive`）；十一的 `del` 只 `alert(...)`。
- **【问题】** 普通数组不是响应式的：学生如果把 `alert` 改成 `tableData.splice(...)`，页面**不会更新**（必须 `reactive([...])` 或 `ref([...])`），会以为"删除功能坏了"。
- **【实测证据】** 仓库修正版把数据改成 `const tableData = reactive([...])`（`Components.vue:179`），删除用 `tableData.splice(...)`（`:230`）——响应式数组的 `splice` 会触发视图更新，这是 Vue 响应式的基本行为；lab-runner-a 实测 `/comp` 的删除确认框可用（`frontend-a.md` §4）。对照之下，讲义那份普通 `const` 数组没有响应式能力，`splice` 后表格不会重画。
- **【正确写法】** 讲义表格示例统一改用 `const tableData = reactive([...])`（或 `ref([...])` + `.value`），并说明"要动态增删必须响应式"。
- **【影响程度】** 低：本讲示例本身不删数据，但这是学生最容易自己加功能的地方。
