## 0. 这一讲在整门课里的位置

实训3 你把 Element Plus 装进了工程（`main.js` 里 `app.use(ElementPlus)`、中文语言包、图标全局注册），但页面上只放了几颗按钮。这一讲是把那个"组件仓库"真正打开：输入框、下拉、单选、多选、图片、轮播、日期、表格、分页、弹窗——**这十样东西，后面每一讲的页面都是它们拼出来的**。你去翻 `07/xm-pro/vue/src/views/Detail.vue`，那个"药材管理"页就是本讲的表格 + 分页 + 输入框换了个皮肤而已。

所以这一讲不是"认十一个组件"，而是认三件更底层的事：**① `v-model` 把组件和你的变量接在一起；② 属性该不该加冒号，取决于组件声明这个 prop 是什么类型；③ 组件只负责"显示得好看"，数据怎么切、怎么算，永远是你自己写 JS 的事**——这一讲被扣最多分的地方就在第 ③ 条。

## 2. 知识点精讲

### 2.1 Input 输入框

**① 讲义怎么说** —— 讲义"一、Input 输入框"只给了官网那一行 `<el-input v-model="input" style="width: 240px" placeholder="Please input" />`，加一句"稍作修改，如下图所示"。它默认你会 `v-model`，但没说它绑在哪、绑的是什么。

**② 一句话讲透** —— **`el-input` 是一个"被包装过的输入框"**：它在原生 `<input>` 外面套了一层 `div`，这样才有可能统一加边框、图标、尺寸、错误提示。包装的代价是它不再是一个裸标签，值不能靠 DOM 的 `value` 属性取，只能靠 `v-model` 这条传送带。就像对讲机：**两边同时说、同时听**，而不是一个人念稿子。

**③ 示例代码** ——

```vue
<template>
  <el-input v-model="data.input" style="width: 240px" placeholder="请输入单行文本" />
  <p>你输入的是：{{ data.input }}</p>
</template>

<script setup>
import { reactive } from 'vue'
const data = reactive({ input: '安中医' })
</script>
```

**④ 逐行拆解** ——
- `v-model="data.input"`：它是 `:model-value="data.input"` 加 `@update:model-value="data.input = $event"` 的**语法糖**。写成 `:value="data.input"` 就只剩"变量 → 输入框"单向，**你在页面上打字，变量不会变**——而且不报错，只是静默失效。
- `data.input` 必须来自 `reactive({...})` 或 `ref()`。写成 `const data = { input: '' }`（普通对象），打字时变量会变，但**页面不会重新渲染**，因为 Vue 只跟踪响应式对象。
- `style="width: 240px"`：`el-input` **没有** `width` 这个 prop，宽度只能给 CSS。它**默认宽度是 100%**（块级），不写就撑满整行——"我明明设了宽度却没用"多半是这里。
- `placeholder="请输入单行文本"`：String，不加冒号，透传给内部原生 `<input>`。
- `<p>你输入的是：{{ data.input }}</p>`：讲义没有这一行。**没有它，你无法证明 `v-model` 通了**，截图也说明不了数据同步。

**⑤ 在你仓库里** —— `03/element-plus/src/views/Components.vue:7` 就是输入框那一行；绑定变量 `data.input` 的初值 `'安中医'` 在 `:158`。

**⑥ 常见坑** ——
- 现象：打字时页面上的 `{{ data.input }}` 一动不动。原因：写成了 `:value`，或压根没绑。怎么改：改成 `v-model`。
- 现象：输入框撑满整行。原因：默认 `width: 100%`。怎么改：`style="width: 240px"`。
- 现象：抄了官网那行 `<el-input v-model="input" ... />`，报 `input is not defined`。原因：官网的 `input` 是它自己页面里的 `const input = ref('')`。怎么改：换成你自己定义过的变量，比如 `data.input`。

**⑦ 自测** —— `v-model="data.input"` 展开成哪两个绑定？只写前一半会怎样？

<details><summary>看答案</summary><br>

展开成 `:model-value="data.input"` 和 `@update:model-value="data.input = $event"`。只写前一半就是**单向**的：变量能影响输入框，输入框影响不了变量，页面上打什么字 `data.input` 都不变——而且不报错，最难查。

</details>

### 2.2 文本域 textarea

**① 讲义怎么说** —— 讲义"二、文本域"给了 `<el-input type="textarea" v-model="data.textarea" style="width: 240px" :rows="2" placeholder="Please input" />`，并说：**"其中 `:rows="2"`：显示 2 行高度；写数字要加`：`，代表是 JS 数字。"**

**② 一句话讲透** —— **同一个组件换一件外套。** `type="textarea"` 让它内部不渲染 `<input>` 而渲染 `<textarea>`，外面写的 `v-model`、`placeholder`、`style` 全部照旧生效——这就是"包装成组件"的好处。而那个冒号是**"后面这串是 JS 代码，不是字符串"的开关**：`rows="2"` 交出去的是两个字符组成的文本，`:rows="2"` 交出去的是**数字 2**。

**③ 示例代码** ——

```vue
<template>
  <el-input type="textarea" v-model="data.textarea" style="width: 240px" :rows="2" placeholder="Please input" />
  <p>你输入了 {{ data.textarea.length }} 个字（换行也算一个）</p>
  <!-- 想看出 :rows 的效果，把 2 改成 6 -->
  <el-input type="textarea" v-model="data.big" style="width: 240px" :rows="6" placeholder="6 行的文本域" />
</template>

<script setup>
import { reactive } from 'vue'
const data = reactive({ textarea: '', big: '' })
</script>
```

**④ 逐行拆解** ——
- `type="textarea"`：`el-input` 的 `type` 默认 `'text'`（单行），等于 `'textarea'` 时才走多行分支。**忘了写它，你得到的就是个普通单行框，而且不报错。**
- `:rows="2"`：源码里是 `rows: { type: Number, default: 2 }`——**它本来就是 Number，而且默认值就是 2**。所以你把 `:rows="2"` 整段删掉，页面**一模一样**；想看出差别得写 `:rows="6"`。讲义说"显示 2 行高度"没错，但没告诉你这正好是默认值。
- **加不加冒号的实测差别**（本机 element-plus 2.14.6 + vue 3.5.43 实测）：`:rows="2"` 收到数字 `2`，控制台干净；`rows="2"` 收到字符串 `"2"`，控制台出现
  `[Vue warn]: Invalid prop: type check failed for prop "rows". Expected Number with value 2, got String with value "2".`
  **但页面上看不出区别**——DOM 属性最终都是字符串。
- 所以这条规则的价值不在这个组件上，而在于那条更一般的判断：**拿到一个属性，先想"组件声明的这个 prop 是什么类型"。是数字 / 布尔 / 数组 / 对象 → 加冒号；是字符串（`240px`、`large`、`男` 这种字面量）→ 不加。** 2.7 节的 `:interval`、2.10 节的 `background` 全是这条规则的应用。
- （讲义没提）更常用的替代是 `:autosize="{ minRows: 2, maxRows: 6 }"`，让高度跟着内容长。

**⑤ 在你仓库里** —— `03/element-plus/src/views/Components.vue:11` 就是这一行；`data.textarea` 的初值 `''` 在 `:159`。

**⑥ 常见坑** ——
- 现象：多行框变成单行。原因：`type="textarea"` 漏写或拼错（大小写敏感，必须全小写）。怎么改：补上，**不加冒号**（它是字符串枚举）。
- 现象：改了 `:rows` 的数字高度没变。原因：你改的是 `2`，而 2 就是默认值。怎么改：改成 `:rows="6"`。
- 现象：控制台一堆 `Invalid prop ... Expected Number ... got String`。原因：数字型 prop 漏冒号。怎么改：加冒号——**别因为"页面看起来正常"就放着不管**。
- 现象：敲的回车用 `{{ }}` 显示出来变成一行。原因：HTML 折叠连续空白。怎么改：外面套 `style="white-space: pre-wrap"`。

**⑦ 自测** —— `:rows="2"` 和 `rows="2"` 在页面上看起来有区别吗？那为什么还要强调加冒号？

<details><summary>看答案</summary><br>

**页面上没区别**：DOM 属性最终都是字符串，浏览器不区分。区别在控制台——`rows="2"` 会打印 `Invalid prop: type check failed for prop "rows". Expected Number with value 2, got String with value "2".`

真正要记的是规则本身：**prop 是什么类型就传什么类型**。`rows` 只是碰巧"字符串也能被浏览器接受"，换成参与比较的 `interval`、要读 `.minRows` 的 `autosize`，传错类型就是真出错。

</details>

### 2.3 Select 选择器（下拉框 el-select）

**① 讲义怎么说** —— 讲义"三、Select 选择器"给了完整代码：`el-select` 里放 `v-for` 生成的 `el-option`，`:key="item.id"`、`:label="item.name"`、`:value="item.name"`，下面用 `你的选择：{{data.value}}` 显示结果。

**② 一句话讲透** —— **下拉框是"菜单 + 一本隐藏的登记本"。** 你眼睛看到的是菜单上印的字（`label`），登记本上记下来的却是另一样东西（`value`）。就像点菜：你念的是菜名（"宫保鸡丁"），后厨收到的是菜号（"07 号"）。**菜名可以随便改，菜号不能变**——所以真实项目里 `:value` 几乎永远绑 `item.id`。

**③ 示例代码** ——

```vue
<template>
  <el-select v-model="data.value" placeholder="请选择中药" style="width: 230px">
    <el-option v-for="item in data.options" :key="item.id" :label="item.name" :value="item.id" />
  </el-select>
  <span> 你的选择：{{ data.value }}（类型：{{ typeof data.value }}）</span>
</template>

<script setup>
import { reactive } from 'vue'
const data = reactive({
  value: '',
  options: [
    { id: 1, name: '虫草' }, { id: 2, name: '人参' },
    { id: 3, name: '鹿茸' }, { id: 4, name: '牛黄' }
  ]
})
</script>
```

**④ 逐行拆解** ——
- `<el-select v-model="data.value">`：接住的**不是显示出来的文字，而是选中项 `:value` 的值**。所以上面这段选中"人参"后，右边打印的是 `2`。
- 初值 `''`：空串匹配不到任何选项的 value，就退回显示 `placeholder`。写成 `null` 效果一样；写成 `'1'` 或 `1` 就会一进来就选中那一项。
- `<el-option>` 必须写在 `el-select` 的**默认插槽**里——`el-select` 靠"收集子 option"才知道有哪些可选项，写在外面它什么都不知道。
- `v-for="item in data.options"`：把数组渲染成 4 个 option。**不要手写四遍** `<el-option>`：加一味药就得改模板，这是"数据和视图分家"的反面教材。
- `:key="item.id"`：Vue 做列表 diff 的**身份标记**，必须稳定且唯一。**不能用 `index`**——列表中间增删一项时 index 会整体漂移，Vue 复用错节点，出现"删了 A 结果 B 没了"这类怪现象。
- `:label="item.name"`：**下拉菜单里显示的文字**。`:value="item.id"`：**选中后写回变量的值**。
- 讲义把两者都写成 `item.name`：能跑，但演示不出区别，右边永远显示中文名。**亲手改一次 `:value="item.id"`，右边立刻从"人参"变成 `2`。**
- `style="width: 230px"`：和 `el-input` 一样默认宽度 100%，不写就撑满。

**⑤ 在你仓库里** —— 选择器在 `03/element-plus/src/views/Components.vue:15-18`；`data.options` 在 `:168`（4 味药）；`data.value` 在 `:160`。**仓库保留的是讲义原写法**：`:16` 是 `:label="item.name" :value="item.name"`，两个都绑名字。想验证 `label`/`value` 的区别就自己改一下。

**⑥ 常见坑** ——
- 现象：能选，但后台收到的是一串中文名。原因：`:value` 绑了 `item.name`。怎么改：`:value="item.id"`。
- 现象：下拉点开是空的。原因：`options` 是空数组、变量名拼错，或 `v-for` 写了 `item in options` 而 `options` 没定义。怎么改：先 `{{ data.options.length }}` 打一下。
- 现象：`{{ data.value }}` 一直是 `undefined`。原因：`el-option` 漏了 `:value`，选中就是把 `undefined` 写进变量。怎么改：补 `:value`。
- 现象：控制台 `Duplicate keys encountered`。原因：`:key` 用了会重复的字段。怎么改：`:key="item.id"`。
- 现象：变量名叫 `data.value`，读代码时和 `ref` 的 `.value` 撞车。怎么改：叫 `data.selected`。

**⑦ 自测** —— 我写成 `:label="item.id" :value="item.name"` 会怎样？

<details><summary>看答案</summary><br>

菜单里显示的是 `1`、`2`、`3`、`4`，而选中后 `data.value` 里存的是 `"虫草"`。功能不报错，但页面很怪、后台也拿不到 id。

这说明 **`:label` 给**人**看、`:value` 给**程序**存，两者彼此独立，绑什么完全由你决定。**

</details>

### 2.4 单选按钮与单选按钮组

**① 讲义怎么说** —— 讲义"四、单选按钮和单选按钮组"给了两段：`el-radio-group` + 两个 `el-radio`（男/女）；`el-radio-group` + 三个 `el-radio-button`（我发布/点赞/收藏），并用了 `size="large"`。

**② 一句话讲透** —— **一组单选按钮就是一道考试选择题：整道题共用一张答题卡（`v-model` 写在 `el-radio-group` 上），每个选项只是"一个候选答案"（`value` 写在每个 `el-radio` 上）。** 答题卡只有一张，所以 `v-model` 只能写一次、必须写在外层 group 上。这就是"我给每个 radio 都写了 v-model"必然出错的原因。

**③ 示例代码** ——

```vue
<template>
  <!-- 圆点式：value 是选项代表的值，标签中间的文字是显示内容 -->
  <el-radio-group v-model="data.sex">
    <el-radio value="男">男</el-radio>
    <el-radio value="女">女</el-radio>
  </el-radio-group>
  <span> 你的选择是：{{ data.sex }}</span>

  <!-- 按钮式：没写插槽文字，按钮上的字由 label 兜底 -->
  <el-radio-group v-model="data.tag" size="large">
    <el-radio-button label="我发布的内容" value="1" />
    <el-radio-button label="我点赞的内容" value="2" />
    <el-radio-button label="我收藏的内容" value="3" />
  </el-radio-group>
  <span> 你的选择是：{{ data.tag }}</span>
</template>

<script setup>
import { reactive } from 'vue'
const data = reactive({ sex: '女', tag: '3' })
</script>
```

**④ 逐行拆解** ——
- `<el-radio-group v-model="data.sex">`：**唯一的一张答题卡**，负责"现在谁被选中"；子项自己不存状态。
- `<el-radio value="男">男</el-radio>` 里有两样容易混的东西：`value="男"` 是这个选项**代表的值**（选中后写回 `data.sex`）；`>男<` 是**默认插槽**，也就是显示出来的文字。本例两者恰好都是"男"，**把插槽文字改成 `>男性<`、`value` 不动**，就会看到页面显示"男性"而 `data.sex` 还是 `"男"`。
- **2.14 的关键规则**：源码里子项的取值是 `actualValue = props.value ?? props.label`——**有 `value` 用 `value`，没有就退回用 `label`**，退回的同时打印
  `[el-radio] [API] label act as value is about to be deprecated in version 3.0.0, please use value instead.`
  所以 `<el-radio label="男" />` 在 2.14 能跑，但这是**要淘汰的写法**（`el-checkbox` 同理，见 2.5）。**这就是"版本会影响用法"的真相**：老版本里 `label` 就是值。
- `<el-radio-button label="我发布的内容" value="1" />`：按钮样式，**没写默认插槽**，源码的兜底是"插槽没内容就拿 `label` 当文字"，所以按钮上显示文字、选中后写回 `"1"`，分工清清楚楚。
- `size="large"`：写在 group 上会传给组内所有子项（子项 size 优先取 group 的）。**它是字符串枚举，不加冒号**，可选 `large` / `default` / `small`——正好和 2.2 的 `:rows="2"` 形成对照。
**⑤ 在你仓库里** —— 圆点单选在 `03/element-plus/src/views/Components.vue:22-26`；按钮组在 `:29-34`；`data.sex = '女'`、`data.tag = '3'` 在 `:161-162`。仓库去掉了讲义那两个 `margin-left`，其余一致。

**⑥ 常见坑** ——
- 现象：点哪个都选不中，或三个能同时亮。原因：`v-model` 写到了每个 `el-radio` 上或没写。怎么改：group 上写 `v-model`，子项只写 `value`。
- 现象：一进页面没有任何一项选中。原因：初值和 `value` 不相等——**特别注意类型**，`:value="1"`（数字）配 `tag: '1'`（字符串），`1 !== '1'`，看起来"明明一样"就是不选中。
- 现象：控制台出现 `label act as value ... deprecated`。原因：组里的选项只写了 `label`。怎么改：补 `value`。
- 现象：`:size="large"` 报 `large is not defined`。原因：冒号让它去找一个叫 `large` 的变量。怎么改：`size="large"`。

**⑦ 自测** —— 为什么 `v-model` 要写在 `el-radio-group` 上，不能每个 `el-radio` 各写一个？

<details><summary>看答案</summary><br>

因为**"当前选中了谁"只可能有一个答案**，这个答案必须存在一个地方。`el-radio-group` 就是那个地方：它把 `v-model` 的值和每个子项的 `value` 逐个比对，相等的显示为选中；点击某个子项时，把那个子项的 `value` 写回 group 的 model。

每个 `el-radio` 各写一个 `v-model`，就变成三个互不相干的独立开关（源码里会走"非 group"分支）——单选组直接退化。

</details>

### 2.5 Checkbox 多选框

**① 讲义怎么说** —— 讲义"五、Checkbox 多选框"分两小节：① 基本用法（单个 `el-checkbox` 绑 `ref(true/false)`）；② 多选框组（`el-checkbox-group` + `v-for`）。讲义自己提醒：**"注意，EL 的版本号会影响具体的用法，我的版本号是 `"element-plus": "^2.14.2"`"**。另外第二个 `<div>` 上用了 `class="mt-2"`。

**② 一句话讲透** —— **单个 checkbox 是"一个问题的是/不是"，一组 checkbox 是"一个收集筐"。** 前者只回答"勾没勾"（`true`/`false`），后者回答"勾了哪几个"（数组）。**同一个标签，外面套不套 `el-checkbox-group`，`v-model` 绑的类型完全不同**——把单个的当数组用、把组里的当布尔用，是这一讲最容易翻车的地方。

**③ 示例代码** ——

```vue
<template>
  <!-- ① 单个：v-model 绑布尔，label 只当显示文字 -->
  <el-checkbox v-model="checked1" label="冬虫" size="large" />
  <el-checkbox v-model="checked2" label="人参" size="large" />
  <el-checkbox v-model="checked3" label="鹿茸" size="small" />
  <el-checkbox v-model="checked4" label="枸杞" size="small" />
  <p>冬虫：{{ checked1 ? '已勾选' : '未勾选' }}　人参：{{ checked2 ? '已勾选' : '未勾选' }}</p>
  <p>鹿茸：{{ checked3 ? '已勾选' : '未勾选' }}　枸杞：{{ checked4 ? '已勾选' : '未勾选' }}</p>

  <!-- ② 多选框组：v-model 绑数组，label 显示 / value 存值 -->
  <el-checkbox-group v-model="data.checkList">
    <el-checkbox v-for="item in data.cols" :key="item.id" :label="item.name" :value="item.name" />
  </el-checkbox-group>
  <div>你的选择是：{{ data.checkList }}</div>
</template>

<script setup>
import { ref, reactive } from 'vue'

// ① 单个：四个独立的布尔
const checked1 = ref(true)
const checked2 = ref(false)
const checked3 = ref(false)
const checked4 = ref(false)

// ② 组：一个数组
const data = reactive({
  cols: [{ id: 1, name: '阿胶' }, { id: 2, name: '陈皮' }, { id: 3, name: '茯苓' }],
  checkList: []
})
</script>
```

**④ 逐行拆解** ——
- **单个**：
  - `v-model="checked1"` 配 `ref(true)`：**绑的是布尔**，勾上 `true`、取消 `false`。
  - `label="冬虫"`：单独使用时 `label` **只当显示文字**（源码 `hasOwnLabel = !!slots.default || !isPropAbsent(actualValue.value)`，`actualValue` 取 `value ?? label`），不参与绑定，所以这里写 `label` 是安全的。
  - `{{ checked1 ? '已勾选' : '未勾选' }}`：**这一行是验证 `v-model` 类型的手段**。不加它只能靠肉眼猜布尔值。讲义写了这一行，值得学。
- **组**：
  - `<el-checkbox-group v-model="data.checkList">`：**必须是数组**。源码判断"我勾没勾"用的是 `value.includes(actualValue)`——数组里有这个值就显示勾选。
  - `v-model` **不在子项上写**（和 `el-radio-group` 同一个道理，源码里 `model = isGroup ? checkboxGroup.modelValue : props.modelValue`）。
  - `:label` 显示、`:value` 存值，**两个都要写**。**版本真相**：子项取值同样是 `props.value ?? props.label`，没有 `value` 就退回 `label`，并打印 `label act as value is about to be deprecated in version 3.0.0`。旧版本 `label` 即值，新版本 `label` 管显示——**这就是讲义那句"版本会影响用法"的具体含义。**
  - 讲义的数据其实是**演示 `label ≠ value` 的好材料**：`[{id:1,label:'阿胶',name:'阿胶1'}, {id:2,label:'陈皮',name:'陈皮'}, {id:3,label:'阿胶',name:'阿胶2'}, {id:4,label:'茯苓',name:'茯苓'}]`——第 1 和第 3 项**显示文字一模一样**，但勾上后进数组的分别是 `'阿胶1'` 和 `'阿胶2'`。仓库为了方便把数据简化成 `cols: [{id:1,name:'阿胶'}, ...]`、`label`/`value` 都取 `name`，能跑但看不出区别——想通这一层，就自己改数据做一次对照。
  - `checkList: []` 初值必须是数组；写 `''` 或 `null`，勾选时 `push` 直接报错。
- `class="mt-2"`：**`mt-2` 是 Tailwind CSS 的工具类，本项目根本没装 Tailwind**，这个类名等于白写，间距不会出现。仓库改成了 `style="margin-top: 8px"`。要间距就老老实实写内联 `style`。

**⑤ 在你仓库里** —— 单个多选框在 `03/element-plus/src/views/Components.vue:39-46`，四个 `ref` 定义在 `:173-176`；多选框组在 `:50-53`，`data.cols` 在 `:169`、`data.checkList` 在 `:163`。仓库把讲义的 `class="mt-2"` 换成了内联 `style`（`:42`），并去掉了重复的"阿胶"数据。

**⑥ 常见坑** ——
- 现象：组里勾选后 `{{ data.checkList }}` 一直是 `[]`。原因：`v-model` 绑的是普通数组（`const checkList = []` 没放进 `reactive`/`ref`）。怎么改：放进 `reactive({ checkList: [] })`。
- 现象：控制台告警 `label act as value ... deprecated`，或数组里是 `undefined`。原因：子项只写了 `label` 没写 `value`。怎么改：两个都写。
- 现象：单个 checkbox 勾上后变量变成数组。原因：它被无意中包进了 `el-checkbox-group`——**一旦进组，子项自己的 `v-model` 会被忽略**。怎么改：挪出 group。
- 现象：`class="mt-2"` 没效果。原因：Tailwind 的类名。怎么改：`style="margin-top: 8px"`。
- 现象：升级 element-plus 后老的多选框全乱。原因：`label` 语义变了。怎么改：锁定版本（`package.json:13` 是 `"element-plus": "^2.14.6"`），统一写 `label` + `value`。

**⑦ 自测** —— 单个 `el-checkbox` 和放进 `el-checkbox-group` 里的 `el-checkbox`，`v-model` 绑的类型分别是什么？

<details><summary>看答案</summary><br>

单个绑 **布尔**；组里绑 **数组**。

原因在源码：子项拿到的 `model` 是"有 group 就用 group 的 modelValue，没有才用自己的"；而判断"我勾没勾"时会先看 model 是不是数组——**是数组就用 `includes(actualValue)`，是布尔就直接用布尔值**。同一个组件，因为父级不同而走了两条完全不同的分支。

</details>

### 2.6 Image 图片

**① 讲义怎么说** —— 讲义"六、Image 图片"分三小节：① 基础用法，循环渲染 5 个区块对比 `fill / contain / cover / none / scale-down`；② 懒加载，`lazy` + 外层 400px 高容器；③ 预览缩放，用了 `:preview-src-list`、`:zoom-rate="1.2"`、`:max-scale="7"`、`:min-scale="0.2"`、`:initial-index="0"`、`fit="cover"`、`show-progress`，并把 `show-progress` 解释成**"加载进度显示"**。图片全部用外链。

**② 一句话讲透** —— **`el-image` 是一个固定大小的相框，`fit` 决定那张照片怎么塞进相框。** 照片和相框比例往往不一样，于是只有五种态度：暴力拉伸、整个装进去留白、盖满相框裁掉边、原样摆着只看一角、以及"只许缩小不许放大"的折中。`lazy` 则是"相框滚进视野了才去取照片"。**记住相框这个比喻，五种 fit 一辈子不会忘。**

**③ 示例代码** —— 三段，放在同一个页面里依次看：

```vue
<template>
  <!-- ① 同一张图、五种 fit 对比 -->
  <span v-for="fit in fits" :key="fit" style="display: inline-block; text-align: center; margin-right: 10px">
    {{ fit }}<br />
    <el-image style="width: 100px; height: 100px" :src="img" :fit="fit" />
  </span>

  <!-- ② 懒加载：外层必须限高 + 出滚动条 -->
  <div style="height: 240px; overflow-y: auto; border: 1px solid #eee">
    <el-image v-for="(u, i) in lazyList" :key="i" :src="u" lazy style="display: block; height: 150px; margin-bottom: 8px" />
  </div>

  <!-- ③ 预览：点缩略图弹全屏，可滚轮缩放、左右切换 -->
  <el-image
    style="width: 100px; height: 100px" :src="img" :preview-src-list="imgs" :initial-index="0"
    :zoom-rate="1.2" :max-scale="7" :min-scale="0.2" show-progress fit="cover"
  />
  <span>点缩略图打开全屏预览器（右下角显示"第几张 / 共几张"）</span>
</template>

<script setup>
// 4 张本地图，放在工程的 public/img/ 下，用根路径引用，不依赖外部图床
const imgs = ['/img/shihu.jpg', '/img/baishao.jpg', '/img/mugua.jpg', '/img/juhua.jpg']
const img = imgs[0]
const lazyList = [...imgs, ...imgs] // 8 张才看得出"滚到才加载"
const fits = ['fill', 'contain', 'cover', 'none', 'scale-down']
</script>
```

**④ 逐行拆解** ——
- **`fit` 的五个值**（源码 `values: ['', 'contain', 'cover', 'fill', 'none', 'scale-down']`，**必须全小写**）：

  | 值 | 效果 | 会变形吗 | 看得见全图吗 |
  |---|---|---|---|
  | `fill`（默认） | 拉伸铺满，比例不管 | **会** | 全图，但被拉扁/拉长 |
  | `contain` | 等比缩到**能完整装下**，装不满处留白 | 不会 | 全图，四周留白 |
  | `cover` | 等比放大到**完全盖住**，超出部分裁掉 | 不会 | **不是全图**，边缘被裁 |
  | `none` | 不缩放，原图像素尺寸直接摆 | 不会 | 只露出相框那一块 |
  | `scale-down` | 在 `none` 和 `contain` 里取**更小的那个** | 不会 | 图比相框大→同 contain；比相框小→同 none |

  记忆法：**fill 暴力 / contain 装下 / cover 盖满 / none 原样 / scale-down 只缩不放。**
- **`lazy`**：布尔属性，裸写即 `true`。原理是"监听滚动容器，图片进入可视区才去设 `src`"（源码还有个 `scroll-container` prop 可指定监听哪个容器，默认找最近的可滚动祖先）。
  - **必须给外层容器限高**（示例里 `height: 240px; overflow-y: auto`），否则所有图一进页面就在可视区里，你会以为"懒加载没生效"。
  - 为什么要懒加载：一张手机拍的照片几 MB，10 张就是几十 MB，不懒加载就等着全部下完才好看。**懒加载 = 用到了才要。**
  - 验证方法：F12 → Network → 筛 `Img` → 勾 `Disable cache` → 慢慢往下滚，请求会**一批一批**冒出来。
- **预览属性**：
  - `:preview-src-list="imgs"`：给一个**数组**（注意是 `list`，复数）。有几张就能左右切几张。**只写 `:src` 不会出现预览**。
  - `:initial-index="0"`：打开时定位到第几张，**下标从 0 开始**；源码默认值就是 `0`。
  - `:zoom-rate="1.2"`：每次滚轮/点按钮的缩放倍率；**源码默认就是 1.2**。
  - `:min-scale="0.2"` / `:max-scale="7"`：缩放下限/上限；**源码默认就是 0.2 和 7**。
  - → **讲义这三个数字全是默认值，写不写完全一样**。想玩就改成 `:max-scale="2"`（不许放太大）或 `:zoom-rate="1.5"`。
  - `fit="cover"`：它管的是 **100×100 那张缩略图**的填充方式，**不管预览器里的大图**。
  - **`show-progress` 的真相（讲义这里讲错了）**：源码里它就是一个计算属性，拼出来的字符串是"当前下标 + 1、一个斜杠、图片总数"，模板里 `v-if="$slots.progress || showProgress"` 才渲染它。所以它显示的是**"当前第几张 / 共几张"的序号**（如 `3 / 11`），**不是加载进度条，跟加载百分比毫无关系**。另有一个 `#progress` 插槽可自定义内容，插槽参数是 `active-index` 和 `total`。
- **外链图床的问题**：讲义用的图来自 `fuss10.elemecdn.com`（Element 老 demo CDN）和 `www.ahtcm.edu.cn`（学校站点）。前者是多年前的资源，后者可能要校内网——**图裂了一般不是你的代码错，是图没了。**
  正确做法：把图片放进工程的 `public/img/`，用**根路径**引用（`/img/shihu.jpg`）。`public` 下的文件 Vite 会原样输出到网站根路径，**不需要 `import`**；换图同名覆盖即可，页面代码一行都不用改。

**⑤ 在你仓库里** —— 五种 fit 对比在 `03/element-plus/src/views/Components.vue:56-62`；懒加载在 `:64-67`；预览缩放在 `:69-71`；图片数组在 `:151`、`fits` 在 `:155`、`lazyList` 在 `:154`。四张图真实存在于 `03/element-plus/public/img/`：`shihu.jpg`、`baishao.jpg`、`mugua.jpg`、`juhua.jpg`。**仓库的预览示例没有写 `show-progress`**（`:70` 只给了 `:preview-src-list` 和 `:initial-index`）——想验证上面的结论，自己加上它，点开预览看右下角是不是 `1 / 4` 这样的序号。

**⑥ 常见坑** ——
- 现象：一片灰底小破图。原因：外链图床挂了/要校内网。怎么改：换成 `public/img/` 里的本地图。
- 现象：懒加载看不出效果。原因：外层容器没限高，图本来就在视口里。怎么改：`height: 240px; overflow-y: auto`，图至少 8 张。
- 现象：点图片没反应。原因：只写了 `:src`，没写 `:preview-src-list`。怎么改：补数组。
- 现象：预览打开黑屏/一直转圈。原因：列表里混进了失效地址。怎么改：每条都先在地址栏打开确认能访问。
- 现象：`fit` 写了没效果。原因：写成了大写 `COVER`——它是**值校验枚举**。怎么改：全小写。

**⑦ 自测** —— `contain` 和 `scale-down` 什么时候效果一样，什么时候不一样？

<details><summary>看答案</summary><br>

原图**比相框大**时两者一样：都缩到能完整装下（等同 `contain`）。
原图**比相框小**时不一样：`contain` 会把小图**放大**到刚好装下相框，`scale-down` 保持原尺寸（`none` 的行为）周围留白。

因为 `scale-down` 的定义就是"在 `none` 和 `contain` 里取更小的那个"——**它只缩不放**。

</details>

### 2.7 Carousel 走马灯

**① 讲义怎么说** —— 讲义"七、Carousel 走马灯"先把两个标签的分工讲得挺清楚（"`el-carousel`：外层大盒子……`el-carousel-item`：每一张轮播内容的单独容器"），然后给基础版和 `type="card"` 卡片版两段代码，两段都写：
`<el-carousel height="400px" style="width: 550px" autoplay interval="3000" pause-on-hover>`。

**② 一句话讲透** —— **`el-carousel` 是一本会自动翻页的相册，`el-carousel-item` 是相册里的一页。** 外壳负责"相册多大、几秒翻一页、怎么翻"，每页里放什么随你。关键点在于：**相册必须给定高度**——不告诉它多大，它的高度就是 0，你什么都看不见。

**③ 示例代码** ——

```vue
<template>
  <!-- 普通轮播：:interval 绑数字 2000（2 秒） -->
  <el-carousel height="200px" style="width: 460px" :interval="2000" arrow="hover">
    <el-carousel-item v-for="(u, i) in imgs" :key="i">
      <img style="width: 100%; height: 100%; object-fit: cover" :src="u" alt="轮播图片" />
    </el-carousel-item>
  </el-carousel>

  <!-- 卡片式：只多一个 type="card" -->
  <el-carousel height="200px" style="width: 640px" type="card" :interval="2000">
    <el-carousel-item v-for="(u, i) in imgs" :key="i">
      <img style="width: 100%; height: 100%; object-fit: cover" :src="u" alt="轮播图片" />
    </el-carousel-item>
  </el-carousel>
</template>

<script setup>
// 本地图，不依赖外链图床
const imgs = ['/img/shihu.jpg', '/img/baishao.jpg', '/img/mugua.jpg', '/img/juhua.jpg']
</script>
```

**④ 逐行拆解** ——
- `height="200px"`：源码是 `height: { type: String, default: "" }`——**String 类型、带单位，所以不加冒号**。默认是空串，也就是"没高度"。**忘了写它，轮播区高度塌成 0，页面上什么都看不到**，这是这一节最常撞的墙。
- `autoplay`：布尔属性，裸写 = `true`。**源码默认值本来就是 `true`**——写不写都在自动播，写出来只是"自解释"，别以为你打开了什么开关。
- `pause-on-hover`：布尔属性，裸写 = `true`，**源码默认值也是 `true`**。"鼠标移上去暂停、移开继续"是**默认行为**；真想"移上去也不停"，得写 `:pause-on-hover="false"`。
- **`:interval="3000"`（讲义这里漏了冒号，是错的）**：源码是 `interval: { type: Number, default: 3000 }`——**Number 类型，单位毫秒**。写成字符串 `"3000"`，控制台必然出现：
  `[Vue warn]: Invalid prop: type check failed for prop "interval". Expected Number with value 3000, got String with value "3000".`
  - **有一件事必须说准**：它并不会真的"不轮播"。源码判断是 `if (props.interval <= 0 || !props.autoplay || timer.value) return`，`"3000" <= 0` 会隐式把字符串转成数字比较，`setInterval(fn, "3000")` 也会把延迟转成数字——**所以功能上碰巧还能跑**。
  - 这恰恰最危险：**告警被你忽略、规则被你学歪**。等你写 `:max-scale="'7'"`，或者写 `autoplay="false"`（字符串 `"false"` 是**真值**，轮播反而停不下来）就真出事。**凡是 Number / Boolean 类型的 prop，一律加冒号。**
  - 而且讲义自己在"二、文本域"里刚强调过"写数字要加`：`"，这里打了自己脸（勘误第 1 条）。
  - 顺带：`:interval="3000"` 也正好是默认值，想看出它在工作就改成 `:interval="1000"`。仓库用的是 `:interval="2000"`。
- `type="card"`：卡片模式，源码 values 是 `['', 'card']`——**小写**。开启后当前这张居中，左右各露出一部分并缩小，比例由 `card-scale` 控制（默认 `0.83`）。**图少于 3 张时看不出效果**。
- `<img style="object-fit: cover">`：这里的 `object-fit` 是**原生 CSS 属性**，和 2.6 节 `el-image` 的 `fit` 说的是同一件事（都是 `object-fit`），只是一个自己写 CSS、一个组件帮你写。轮播框固定高度、图片比例不一，必须用 `cover` 才不拉变形。

**⑤ 在你仓库里** —— 普通轮播在 `03/element-plus/src/views/Components.vue:75-79`（已修正为 `:interval="2000"`、`arrow="hover"`）；卡片式在 `:82-86`；图片数组在 `:151`。
**讲义原版那句错代码被刻意保留在对照页**：`03/element-plus/src/views/ComponentsOriginal.vue:7` 就是 `autoplay interval="3000" pause-on-hover`，专门用来复现控制台告警；路由 `/comp-orig` 定义在 `03/element-plus/src/router/index.js:9`，访问 http://localhost:5173/comp-orig 就能亲眼看到那条 `Invalid prop`。

**⑥ 常见坑** ——
- 现象：轮播区一片空白/高度成一条细线。原因：`el-carousel` 没写 `height`。怎么改：`height="400px"`。
- 现象：控制台 `Invalid prop: type check failed for prop "interval"`。原因：漏冒号。怎么改：`:interval="3000"`。
- 现象：写 `autoplay="false"` 想让它停，结果照播不误。原因：布尔 prop 传了**字符串** `"false"`，非空字符串在 JS 里是真值。怎么改：`:autoplay="false"`。**这条比 interval 那条更狠，它会让你的意图完全反掉。**
- 现象：卡片模式看起来和普通模式一样。原因：只有 1~2 张图。怎么改：至少 3 张。
- 现象：图片被压扁/拉长。原因：忘了 `object-fit: cover`。

**⑦ 自测** —— `autoplay="false"` 和 `:autoplay="false"` 效果一样吗？

<details><summary>看答案</summary><br>

**完全不一样。**

- `:autoplay="false"` → 传进去布尔 `false` → 轮播**停止**。
- `autoplay="false"` → 传进去字符串 `"false"`。Vue 对布尔 prop 的处理是"只要值存在就当 `true`"；而且就算不转换，`Boolean("false")` 在 JS 里也是 **`true`**——**非空字符串永远是真值**。

所以 `autoplay="false"` 的实际效果是**一直在播**，和你想的正好相反。

</details>

### 2.8 DatePicker 日期选择器

**① 讲义怎么说** —— 讲义"八、DatePicker 日期选择器"分四小节：① `type="date"`；② `type="datetime"`；③ `el-time-picker`；④ `type="daterange"`（并说明"data.daterange 是一个数组，数组里面有 2 个值"）。前三节都同时写了 `format` 和 `value-format`，讲义自己解释：**"`format` 是展示日期格式，`value-format` 是指定绑定值的格式，也就是后台拿到的数据格式"**——这句讲义讲对了。但 datetime 那节的注释是从上一节复制的（勘误第 11 条）。

**② 一句话讲透** —— **`format` 是"给人看的样子"，`value-format` 是"交给程序的样子"。** 同一份日期，挂在墙上给客人看的是"2026年10月16日"，写进账本给会计的是"2026-10-16"。**不管你写不写 `format`，人看到的那份永远在变；但变量里存的那份，你不写 `value-format` 就是一个 `Date` 对象**——丢给后台会变成带时区的 UTC 字符串，日期还可能少一天。这是本节唯一必须记死的一条。

**③ 示例代码** ——

```vue
<template>
  <!-- ① 日期：format 和 value-format 可以不一样 -->
  <el-date-picker v-model="data.date" type="date" format="YYYY年MM月DD日" value-format="YYYY-MM-DD" placeholder="请选择日期" />
  <span> 变量里的值：{{ data.date }}（类型 {{ typeof data.date }}）</span>

  <!-- ② 日期时间 -->
  <el-date-picker v-model="data.datetime" type="datetime" format="YYYY-MM-DD HH:mm:ss" value-format="YYYY-MM-DD HH:mm:ss" placeholder="请选择日期时间" />

  <!-- ③ 只选时间 -->
  <el-time-picker v-model="data.time" placeholder="选择时间" />
  <span> {{ data.time }}</span>

  <!-- ④ 日期范围：绑的是两元素数组，模板里取属性要带 ?. -->
  <el-date-picker v-model="data.daterange" type="daterange" range-separator="至" start-placeholder="开始日期"
    end-placeholder="结束日期" format="YYYY-MM-DD" value-format="YYYY-MM-DD" />
  <span> 你选的日期范围是：{{ data.daterange?.length ? data.daterange[0] : '' }} 到 {{ data.daterange?.length ? data.daterange[1] : '' }} </span>
</template>

<script setup>
import { reactive } from 'vue'
const data = reactive({ date: '', datetime: '', time: '', daterange: [] })
</script>
```

**④ 逐行拆解** ——
- `type="date"` / `"datetime"` / `"daterange"`：决定"选到哪一级""要不要双日历"，源码里 `type` 默认就是 `'date'`。还有 `year`、`month`、`week`、`dates`、`monthrange` 等值。
- **`format`**：只影响**输入框里显示成什么样**，写 `"YYYY年MM月DD日"` 完全没问题。
- **`value-format`**：只影响 **`v-model` 里存什么**。源码注释原文是
  `format of binding value. If not specified, the binding value will be a Date object`
  ——**不写它，绑的就是一个 `Date` 对象**。后果：`{{ data.date }}` 打印出 `Fri Oct 16 2026 00:00:00 GMT+0800 (中国标准时间)`；发请求 `JSON.stringify` 后变成 `"2026-10-15T16:00:00.000Z"`——**变成了前一天**（UTC 和东八区差 8 小时）。**只要这个日期要交给后台，`value-format` 就必须写。**
- **格式串大小写不能乱写**：Element Plus 用 day.js 的 token，`YYYY`（年）、`MM`（月）、`DD`（日）、`HH`（24 小时）、`mm`（**分**）、`ss`（秒）。写小写 `yyyy-mm-dd`，`yyyy` 和 `dd` 不是 token 会原样输出字母、`mm` 会被当成分钟——你会得到 `yyyy-00-dd` 这种鬼东西。**一律大写。**
- `el-time-picker`：只选时间。它和 `el-date-picker` 共用同一套 `format` / `value-format`（源码注释一模一样），"不写 `value-format` 就是 Date 对象"对它同样成立。
- **`type="daterange"`**：
  - `range-separator="至"`、`start-placeholder`、`end-placeholder`：纯文案。
  - 绑定值是**两元素数组** `[开始, 结束]`，所以取 `[0]` 和 `[1]`。
  - **`?.` 是可选链，这里不是装饰，是保命的**：① 初值若写成 `daterange: null`（很常见），`data.daterange.length` 直接抛 `TypeError: Cannot read properties of null (reading 'length')`，**整个组件渲染失败、页面一片空白**；② 更关键的是——**用户点一下清空（×），Element Plus 会把 `v-model` 设成 `null`**。源码里 picker 用的是 `useEmptyValues(props, null)`，`valueOnClear` 默认值就是 `null`。所以哪怕你初值规规矩矩写了 `[]`，用户点一下 × 就变 `null`，模板立刻炸。
  - `?.` 的语义：左边是 `null` / `undefined` 时**整个表达式短路成 `undefined`**，不再往下取 `.length`，所以不报错。
- 讲义 datetime 那节的注释是**复制上一节没改**的（代码已是 `HH:mm:ss`，注释还写着 `YYYY-MM-DD`），写作业别照抄。

**⑤ 在你仓库里** —— 日期在 `03/element-plus/src/views/Components.vue:90-91`；日期时间在 `:93-95`；时间选择器在 `:97-98`；日期范围在 `:100-102`，其中 `?.` 出现在 `:102`。四个变量在 `:164-167`（`date: ''`、`datetime: ''`、`time: ''`、`daterange: []`）。

**⑥ 常见坑** ——
- 现象：后台收到的日期是 `2026-10-15T16:00:00.000Z`，比选的少一天。原因：没写 `value-format`。怎么改：`value-format="YYYY-MM-DD"`。
- 现象：格式串写了小写 `yyyy-mm-dd`，显示成 `yyyy-00-dd`。原因：day.js 的 token 大小写敏感。怎么改：`YYYY-MM-DD`。
- 现象：点了一下清空按钮，页面白屏，控制台 `Cannot read properties of null (reading 'length')`。原因：清空后 `v-model` 变成 `null`。怎么改：取属性处加 `?.`，或外面套 `v-if="data.daterange"`。
- 现象：想把范围拆成"开始/结束"两个变量却拿不到。原因：它是**一个数组**。怎么改：`const [start, end] = data.daterange ?? []`。
- 现象：`el-time-picker` 选完时间，变量变成看不懂的对象。原因：同"没写 `value-format`"。

**⑦ 自测** —— `format` 和 `value-format`，哪一个决定 `{{ data.date }}` 打出来的东西？

<details><summary>看答案</summary><br>

**`value-format`。** `{{ }}` 打印的是变量本身，变量存什么由 `value-format` 决定；`format` 只管输入框里显示给人看的那一串。

反过来：输入框显示"2026年10月16日"、变量里存 `"2026-10-16"`，是完全合法的组合——这正是两个属性分开存在的意义。

</details>

### 2.9 数据表格 el-table

**① 讲义怎么说** —— 讲义"九、数据表格 el-table"给了 `el-table :data="tableData"` + 三个 `el-table-column`，分别绑 `prop="name"` / `"date"` / `"address"`，加了 `stripe`，数据是 4 条中药材。这一段和官网标准写法一致，**讲义没错**。

**② 一句话讲透** —— **表格就是"把数组翻译成一行行"。** `:data` 是你交给它的数组，每一个 `el-table-column` 是"一列的取数规则 + 表头文字"。它不管你有多少数据、也不管该显示第几页——**你给它 22 条它就画 22 行，给它 3 条就画 3 行**。记住这句，2.10 节"分页看着有、其实没生效"就一目了然了。

**③ 示例代码** ——

```vue
<template>
  <el-table :data="tableData" style="width: 100%" stripe>
    <el-table-column prop="name" label="名称" width="180" />
    <el-table-column prop="date" label="日期" width="180" />
    <el-table-column prop="address" label="主产地" />
  </el-table>
</template>

<script setup>
import { reactive } from 'vue'
const tableData = reactive([
  { id: 1, name: '人参', date: '2028-05-03', address: '吉林长白山山脉' },
  { id: 2, name: '三七', date: '2028-06-02', address: '云南省文山州' },
  { id: 3, name: '当归', date: '2028-09-07', address: '甘肃省定西市岷县' },
  { id: 4, name: '山药', date: '2028-11-26', address: '河南焦作，俗称「怀山」' }
])
</script>
```

**④ 逐行拆解** ——
- `:data="tableData"`：**必须加冒号**，因为要的是一个**数组变量**，不是字符串 `"tableData"`。
- `prop="name"`：**不要加冒号**。它要的是**字段名的字符串**，表格拿它去行对象里查 `row['name']`。
  - 写成 `:prop="name"`，Vue 会去 setup 里找一个叫 `name` 的变量，找不到 → `undefined` → **那一列全空白，而且不报错**（开发环境只有一句 `Property "name" was accessed during render but is not defined on instance.`）。这是表格最难查的问题之一。
  - **"什么时候加冒号"到这里形成闭环**：`:data` 要对象所以加，`prop` 要字符串所以不加，`width` 是数字但字符串也能解析，所以加不加都行（见下）。
- `label="名称"`：表头文字，字符串，不加冒号。
- `width="180"`：列宽。源码是 `width: { type: [String, Number], default: "" }`，内部走 `parseWidth`，实现是 `Number.parseInt(width, 10)`。
  - `width="180"`（数字字符串）和 `:width="180"`（数字）都对。
  - **`width="100px"` 也是能用的**：`parseInt("100px", 10)` 得到 `100`，单位被自动剥掉。所以勘误第 5 条说的"带 px 可能不被正确解析"，**实际是能解析的**，这条要更精确一点。
  - **真正会踩的是百分号**：`width="20%"` → `parseInt("20%")` 得到 `20` → 表格把它当 **20 像素**，而不是"占 20%"。想按比例分配宽度要用 `min-width`（源码里 `parseMinWidth` 默认给 80）。
  - 结论：**统一写不带单位的数字最省心**（`width="180"`），但别把"带 px 会失效"当事实记住。
- `stripe`：斑马纹，布尔属性，**裸写 = true**，不要写 `:stripe`（同 2.10 节的 `background`）。
- 不写 `width` 的那一列（`prop="address"`）自动吃掉剩余宽度。
- `const tableData = reactive([...])`：**数据源必须是响应式的**。写成普通数组，之后 push / splice 页面不会刷新——这是 2.11 节删除功能的隐形前提。
- 数据里带 `id` 但没有对应的列：**数据里有、列里没写就不显示**，很正常，`id` 是留给操作列用的。

**⑤ 在你仓库里** —— 表格在 `03/element-plus/src/views/Components.vue:110-120`（注意 `:data` 绑的是 `pagedData` 而不是原始数组，那是 2.10 节的修正）；数据 `tableData`（6 条，带 `id`）在 `:179-186`。
同一套写法的实战版还有两处：`05/admin-layout/src/views/Detail.vue:20-24`、`07/xm-pro/vue/src/views/Detail.vue:26-30`（后者就是实训7 那个"药材管理"页的表格）。

**⑥ 常见坑** ——
- 现象：某一列整列空白，控制台有 `Property "xxx" was accessed during render but is not defined on instance.`。原因：`prop` 前面多写了冒号。怎么改：`prop="name"`。
- 现象：一行都不显示。原因：`:data` 不是数组（写成了对象/`undefined`）或变量名拼错。怎么改：先 `{{ tableData.length }}` 看看。
- 现象：push 了数据页面不动。原因：数据源不是 `reactive`/`ref` 包起来的。怎么改：`reactive([...])`。
- 现象：字段名大小写不一致（`prop="Name"` vs 数据里 `name`）→ 列空白且**不报错**。怎么改：复制粘贴字段名，别手打。
- 现象：`width="20%"` 出来是一列 20 像素宽。原因：`parseInt` 把 `%` 之后的丢了。怎么改：用 `min-width`。

**⑦ 自测** —— 为什么 `:data` 前面要加冒号，而 `prop` 前面不要？

<details><summary>看答案</summary><br>

因为**冒号的意思是"引号里是一段 JS 代码"**。

- `:data="tableData"` → 把 `tableData` 这个**变量（数组）**传进去。
- `prop="name"` → 把**字符串 `"name"`** 传进去；写成 `:prop="name"` 就等于让 Vue 去找一个叫 `name` 的变量，找不到就是 `undefined`，那一列全空白。

判断依据永远只有一条：**这个 prop 声明的是什么类型**（`data` 是 Array，`prop` 是 String）。

</details>

### 2.10 分页 el-pagination

**① 讲义怎么说** —— 讲义"十、分页组件 el-pagination"开头四行把四个属性的意思讲对了（"`v-model:current-page`：当前的页码……`total`：总共的数据个数……`layout` 是分页的各种组件的表现集合"），但代码有三处问题：① `:background` 带了冒号；② `pageSize4 = ref(100)` 不在 `:page-sizes="[5, 10, 15, 50]"` 里；③ **表格的 `:data` 直接绑整份 `tableData`，没按页切片，所以翻页根本不生效**——分页在这里纯粹是摆设。勘误第 2、7、8 条。

**② 一句话讲透** —— **分页组件不是"帮你把数据分成几页"的，它只是一个"页码遥控器"。** 它只干两件事：告诉你"用户想看第几页、每页几条"，以及把页码 1 2 3 画出来。**真正把数组切成那一页该有的几条，是你自己必须写的一行 JS。** 不写切片，分页就是墙上的假按钮——这是整讲最大的认知差。

**③ 示例代码** —— 一个"真分页"完整可跑的版本：

```vue
<template>
  <el-table :data="pagedData" style="width: 100%" stripe>
    <el-table-column prop="name" label="名称" width="180" />
    <el-table-column prop="date" label="日期" width="180" />
    <el-table-column prop="address" label="主产地" />
  </el-table>

  <el-pagination v-model:current-page="currentPage" v-model:page-size="pageSize" :page-sizes="[3, 5, 10]"
    background layout="total, sizes, prev, pager, next, jumper" :total="tableData.length" style="margin-top: 12px" />
</template>

<script setup>
import { reactive, ref, computed } from 'vue'

const tableData = reactive([
  { id: 1, name: '人参', date: '2028-05-03', address: '吉林长白山' },
  { id: 2, name: '三七', date: '2028-06-02', address: '云南文山' },
  { id: 3, name: '当归', date: '2028-09-07', address: '甘肃岷县' },
  { id: 4, name: '山药', date: '2028-11-26', address: '河南焦作' },
  { id: 5, name: '黄精', date: '2029-12-26', address: '池州九华山' },
  { id: 6, name: '石斛', date: '2028-05-12', address: '六安霍山' }
])

const currentPage = ref(1)
const pageSize = ref(3) // 初值一定要在 :page-sizes 的候选里

// 真分页的关键就这三行
const pagedData = computed(() => {
  const start = (currentPage.value - 1) * pageSize.value
  return tableData.slice(start, start + pageSize.value)
})
</script>
```

**④ 逐行拆解** ——
- `v-model:current-page="currentPage"`：**具名 v-model**，等于 `:current-page` 加 `@update:current-page`。
  - 为什么必须用 `v-model:` 而不是 `:current-page`：后者是**单向**的。你在分页条上点"第 2 页"，组件内部页码变了，但你的 `currentPage` 还是 1 → 切片不重算 → **表格纹丝不动**。这是"点了没反应"的另一个来源。
- `v-model:page-size="pageSize"`：同理，绑每页条数。用户在下拉框选"5 条/页"，`pageSize` 会被写回 5。
- `:page-sizes="[3, 5, 10]"`：每页条数的**候选数组**（所以有冒号），渲染成 `sizes` 那一段的下拉框。
- **`background`（裸属性，不要冒号）**：裸写 → `true` → 页码有底色方块。写成 `:background`，Vue 3.4+ 有个"同名简写"规则——`:` 后面不写值就等于 `:background="background"`，**去找一个叫 `background` 的变量**；setup 里没有 → 取到 `undefined` → falsy → **底色没了**，控制台还有 `Property "background" was accessed during render but is not defined on instance.`
  - 勘误第 7 条方向是对的（"会去绑定一个未定义的变量，结果是 false"），这里补一句机理：**准确说取到的是 `undefined`（falsy），不是 `false`**；`false` 是"明确传了 false"或"根本没传这个属性"时的值。
- `layout="total, sizes, prev, pager, next, jumper"`：分页条上有哪些"零件"、从左到右什么顺序。源码就是 `props.layout.split(',').map(item => item.trim())` 再逐个渲染。

  | 段 | 是什么 | 数据从哪来 |
  |---|---|---|
  | `total` | "共 6 条" | 读 `:total` |
  | `sizes` | 每页条数下拉框 | 读 `:page-sizes` |
  | `prev` / `next` | 上一页 / 下一页按钮 | 内部 |
  | `pager` | 页码数字块（1 2 3 …） | `:total` ÷ `page-size` 算出的页数 |
  | `jumper` | "前往 __ 页"输入框 | 内部 |
  | `->` | "后面的零件推到右边"的分隔符 | — |

  **不写 `sizes` 就没有下拉框，不是坏了**；默认 layout 是 `prev, pager, next, jumper, ->, total`（**默认没有 `sizes`**）。
- `:total="tableData.length"`：总条数。**它唯一的用途是让分页组件算出"一共几页"**，和表格显示哪几行**毫无关系**——这就是讲义那个例子"看着有、其实没生效"的根因。
  - 讲义写成 `:total=tableData.length`（**没有引号**）。实测编译结果是 `total: _ctx.tableData.length`，和加引号版**完全一样**，能跑。但这是坏习惯：HTML 属性值里不能有空格，你哪天写 `:total="a + b"` 再顺手去掉引号，就会解析成 `:total=a` 外加一个名叫 `+` 的怪属性。**统一加引号。**（勘误第 3 条判断准确。）
- **真分页三件套（本节核心）**：
  - `computed`：`currentPage` 或 `pageSize` 一变，`pagedData` **自动重算**、表格自动重画。
  - `(currentPage.value - 1) * pageSize.value`：第 1 页要从下标 0 开始，所以**先减 1**。忘了减 1，第 1 页会从第二条开始，而且永远少一条。
  - `tableData.slice(start, start + pageSize.value)`：**左闭右开**（含头不含尾），`slice(0, 3)` 得到下标 0、1、2 三条。`slice` **不改原数组**（`splice` 会）。
  - 最后把表格 `:data` 从 `tableData` 改成 `pagedData`——**这一行才是分页生效的开关**。
- **`pageSize4 = ref(100)` vs `:page-sizes="[5, 10, 15, 50]"`（讲义的不自洽）**：初值 100 不在候选数组里，现象是**每页条数那个下拉框一开始显示空白/对不上**。改法二选一：初值改成候选里的值，或把 `100` 加进 `:page-sizes`。
  - 仓库两边是自洽的：`:page-sizes="[3, 5, 10]"` 配 `pageSize = ref(3)`（`Components.vue:124`、`:188`）。
  - 另一处现成对照是 `05/admin-layout/src/views/Detail.vue:29,56`：`[5, 10, 15, 20]` 配 `pageSize: 10`，也在候选里。
  - 顺带：**讲义那个 `100` 比它表格里的 22 条还多**，所以永远只有一页，页码根本点不动——这是"两个 bug 叠在一起"的典型。

**⑤ 在你仓库里** —— 分页在 `03/element-plus/src/views/Components.vue:121-129`（`background` 裸属性在 `:125`、`:total="tableData.length"` 带引号在 `:127`）；`currentPage`/`pageSize`/`pagedData` 在 `:187-192`；表格绑的是 `pagedData`（`:110`）。
**讲义原版的问题写法被完整保留在对照页**：`ComponentsOriginal.vue:14` 是没切片的 `:data="tableData"`、`:23` 是 `:background`、`:25` 是 `:total=tableData.length`。跑 http://localhost:5173/comp-orig 就能看到"每页条数选了 5、表格还是全显示"的现象。

**⑥ 常见坑** ——
- 现象：**点页码、改每页条数，表格内容一动不动。** 原因：`:data` 还绑着整份数组。怎么改：写 `computed` 切片，表格绑切片结果。**本讲最高频的失分点。**
- 现象：分页条页码没有底色方块。原因：写成了 `:background`。怎么改：`background`。
- 现象：分页组件自己变了，表格没跟着变。原因：用了 `:current-page` 单向绑定。怎么改：`v-model:current-page`。
- 现象：每页条数下拉框初始是空的/对不上。原因：`page-size` 初值不在 `page-sizes` 里。怎么改：两边对齐。
- 现象：只有一页，页码点不动。原因：`pageSize` 比总条数还大（讲义那个 `ref(100)`）。怎么改：改小。
- 现象：删掉一条数据后页码停在空页上。原因：`currentPage` 不会自动回退。怎么改：删除后判断 `if ((currentPage.value - 1) * pageSize.value >= tableData.length) currentPage.value = 1`。
- 现象：接上后端以后分页又不对了。原因：前端切片只适合"数据已经全在手上"。真接后端要把 `currentPage`/`pageSize` 当参数发给后台、由后台 `LIMIT`；那时 `:total` 用后台返回的总数，`pagedData` 换成后台返回的列表，**`computed` 切片就该删掉**。

**⑦ 自测** —— `total` 是给谁用的？它和表格里显示几行有关系吗？

<details><summary>看答案</summary><br>

`total` 只给**分页组件自己**用：它拿 `total ÷ page-size` 算出"一共几页"，好决定页码块上画几个数字。

**它和表格显示几行没有任何关系。** 表格显示什么完全由 `:data` 决定。所以"`total` 写对了"不等于"分页生效了"——你必须自己按 `currentPage`/`pageSize` 切数组，再把切片结果交给表格。

</details>

### 2.11 弹窗与操作列

**① 讲义怎么说** —— 讲义"十一、弹窗"**标题叫弹窗，正文里却一个 `el-dialog` 都没有**。它给的是两段：① 表格最后一列用 `<template #default="scope">{{scope.row}}</template>` 把整行数据打出来；② "添加删除功能"，用 `<el-button type="danger" @click="del(scope.row.id)">删除</el-button>` 配原生 `alert("删除id = " + id + "的数据")`。**名不副实**（勘误第 12 条）。所以要拆成两半讲：**前半段真正讲的是"作用域插槽"（讲义没给它名字）；后半段要补真正的 `el-dialog`。**

**② 一句话讲透** ——
- **作用域插槽**：普通插槽是"我把位置给你"；**作用域插槽是"我把位置给你，同时把我知道的数据也塞给你"**。表格知道"现在画的是第几行、那行数据是什么"，但它不知道你想在这一格里放什么——于是把那一行的数据递出来，你在自己的模板里接住。**两边的活分着干，所以叫"作用域"。**
- **`el-dialog`**：原生 `alert()` 是浏览器自带的"原始人弹窗"——丑、不能放表单、按钮文字改不了，而且**会阻塞整个页面**（脚本跑不动、自动化截图截不到）。`el-dialog` 只是页面里的一块普通 DOM，显隐由一个布尔变量说了算。

**③ 示例代码** —— 一份完整的"表格 + 操作列 + 真弹窗 + 真删除"：

```vue
<template>
  <el-button type="primary" @click="openAdd">新增</el-button>

  <el-table :data="tableData" style="width: 100%" stripe>
    <el-table-column prop="name" label="名称" width="180" />
    <el-table-column prop="date" label="日期" width="180" />
    <el-table-column prop="address" label="主产地" />
    <!-- 这一列没有 prop：不是从行数据里取字段，而是自己画 -->
    <el-table-column label="操作" width="200">
      <template #default="scope">
        <el-button size="small" @click="view(scope.row)">查看</el-button>
        <el-button type="danger" size="small" @click="del(scope.row.id)">删除</el-button>
      </template>
    </el-table-column>
  </el-table>

  <!-- 真弹窗：显隐完全由 dialogVisible 说了算 -->
  <el-dialog v-model="dialogVisible" title="新增中药材" width="420px">
    <el-form label-width="70px">
      <el-form-item label="名称"><el-input v-model="form.name" placeholder="如：大别山天麻" /></el-form-item>
      <el-form-item label="日期"><el-date-picker v-model="form.date" type="date" format="YYYY-MM-DD" value-format="YYYY-MM-DD" style="width: 100%" /></el-form-item>
      <el-form-item label="主产地"><el-input v-model="form.address" placeholder="如：六安金寨、霍山" /></el-form-item>
    </el-form>
    <template #footer>
      <el-button @click="dialogVisible = false">取消</el-button>
      <el-button type="primary" @click="save">保存</el-button>
    </template>
  </el-dialog>
</template>

<script setup>
import { reactive, ref } from 'vue'
import { ElMessage, ElMessageBox } from 'element-plus'

const tableData = reactive([
  { id: 1, name: '人参', date: '2028-05-03', address: '吉林长白山' },
  { id: 2, name: '三七', date: '2028-06-02', address: '云南文山' },
  { id: 3, name: '当归', date: '2028-09-07', address: '甘肃岷县' }
])

// ① 新增弹窗
const dialogVisible = ref(false)
const form = reactive({ name: '', date: '', address: '' })
let nextId = 100
const openAdd = () => {
  form.name = ''; form.date = ''; form.address = ''
  dialogVisible.value = true
}
const save = () => {
  if (!form.name) { ElMessage.warning('名称不能为空'); return }
  tableData.push({ id: nextId++, name: form.name, date: form.date, address: form.address })
  dialogVisible.value = false
  ElMessage.success('已新增：' + form.name)
}

// ② 查看：函数式弹框
const view = (row) => {
  ElMessageBox.alert(`名称 ${row.name}　日期 ${row.date}　主产地 ${row.address}`, '第 ' + row.id + ' 行', { confirmButtonText: '关闭' })
}

// ③ 删除：先确认，再真删
const del = (id) => {
  const row = tableData.find((x) => x.id === id)
  ElMessageBox.confirm(`确定删除【${row.name}】这条数据吗？`, '删除确认', {
    type: 'warning', confirmButtonText: '确定', cancelButtonText: '取消'
  })
    .then(() => {
      tableData.splice(tableData.findIndex((x) => x.id === id), 1)
      ElMessage.success('已删除 id = ' + id)
    })
    .catch(() => ElMessage.info('已取消删除'))
}
</script>
```

**④ 逐行拆解** ——
- **操作列（作用域插槽）**：
  - `<el-table-column label="操作" width="200">`：**这一列没有 `prop`**，因为它的内容不是从行数据里取字段，而是你自己画。有插槽内容时，列就渲染插槽而不是渲染字段值。
  - `<template #default="scope">`：`#default` 是 `v-slot:default` 的简写；`="scope"` 是**接收子组件递出来的数据**，会打包成一个对象。
  - 递出来的对象里常用的三项：`scope.row` 是**当前这一行的数据对象**（就是 `tableData` 里的元素）；`scope.column` 是当前列的配置对象；`scope.$index` 是这一行**在当前页数据里**的下标（从 0 开始，**不是 id，也不是全局行号**）。
  - **`scope` 只是个变量名**，写 `s`、`item` 都行。更常见的写法是直接解构 `<template #default="{ row }">`，里面用 `row.name`。仓库和讲义都用 `scope`。
  - 讲义这里写 `{{scope.row}}`——把整个对象丢给 Vue 显示，页面上是一坨 `{ "id": 1, "name": "人参", ... }`。**仓库改成了传给 `view()` 用 `ElMessageBox` 展示**（`:116`）。
  - `@click="del(scope.row.id)"`：传的是 **`scope.row.id`（一个数字）**，不是整个 `scope.row`。传什么由你 `del` 的签名决定——如果 `del` 写的是 `(row) => {}`，那就该传 `scope.row`。
  - `#default` 里可以放**任何东西**：按钮、开关、标签、进度条。这就是操作列的通用套路，后面每一讲的增删改查都用它。
- **`el-dialog`**：
  - `v-model="dialogVisible"`：**绑一个布尔**（`ref(false)`），`true` 弹出、`false` 关闭。
  - **为什么必须 `v-model` 而不是 `:model-value`**：弹窗的关闭入口不止你的按钮——右上角 ×、按 ESC、点遮罩，都会触发"我要关了"。这些事件必须能**反向写回你的变量**。写成单向绑定，就会出现"点 × 关了，但 `dialogVisible` 还是 `true`，下次点新增它自己又弹出来"。
  - `title="新增中药材"`：标题文字（也可用 `#header` 插槽自定义）。`width="420px"`：字符串，带单位，不加冒号。
  - `<template #footer>`：**底部按钮区插槽**，不写就没有底部按钮（不是 bug）。仓库把"取消/保存"放在这里（`:138-141`）。
  - `el-dialog` 默认会传送到 `<body>` 下渲染（`teleported`），所以不会被父元素的 `overflow: hidden` 裁掉；手动关掉它又碰上父级 CSS `transform`，弹窗位置就会错乱。
- **`ElMessage` / `ElMessageBox`**：
  - 先 import：`import { ElMessage, ElMessageBox } from 'element-plus'`（`Components.vue:148`）。它们是**函数式**调用，不写标签、不进模板。
  - `ElMessage.success('已新增')`：右上角飘一条消息，自动消失。
  - `ElMessageBox.confirm(...)` **返回 Promise**：点"确定"走 `.then()`，点"取消/关闭"走 `.catch()`。删除的真实逻辑写在 `then` 里，取消提示写在 `catch` 里。`ElMessageBox.alert(...)` 同理，只是只有一个按钮。
  - **这就是为什么不能再用 `alert()`**：原生 `alert` 会**阻塞整个 JS 线程**，页面卡住等人工点掉，自动化截图脚本直接挂。仓库为了能稳定截图，专门加了 `?open=add` / `?open=view` / `?open=del` 三个 URL 参数（`Components.vue:238-245`），访问时自动弹出对应弹窗。**写作业时如果用原生 `alert`，你的截图会很痛苦。**
- **删除为什么这么写**：
  - `tableData.find(x => x.id === id)`：先按 id 找到那一行，为了拿名字拼提示语。
  - `tableData.splice(tableData.findIndex(x => x.id === id), 1)`：**`splice(下标, 1)` 是"从数组里真删掉"**（会改原数组），和 2.10 取切片用的 `slice` 正好相反。
  - 删完为什么表格自动更新了：因为 `tableData` 是 `reactive` 的，**一处数据变了，所有读它的地方一起变**。这就是响应式的价值。
  - 顺带：删除后如果当前页空了，页码不会自动回退（见 2.10 最后一条坑）。

**⑤ 在你仓库里** —— 操作列在 `03/element-plus/src/views/Components.vue:114-119`；`el-dialog` 在 `:132-142`（`#footer` 插槽在 `:138-141`）；显隐变量 `dialogVisible` 在 `:195`、表单 `form` 在 `:196`、`openAdd`/`save` 在 `:198-212`；`view` 在 `:215-219`；`del`（`ElMessageBox.confirm` + Promise）在 `:222-234`；`import { ElMessage, ElMessageBox }` 在 `:148`；演示用的 URL 参数逻辑在 `:238-245`。
讲义原版只有操作列、没有真弹窗：对照页 `03/element-plus/src/views/ComponentsOriginal.vue:14-27` 整页都没有 `el-dialog`。

**⑥ 常见坑** ——
- 现象：点按钮没反应，控制台说 `scope is not defined`。原因：`<template #default>` **忘了写接收参数**，里面却在用 `scope.row`。怎么改：`<template #default="scope">`。
- 现象：弹窗关了又自己弹出来。原因：用了 `:model-value` 单向绑定。怎么改：`v-model="dialogVisible"`。
- 现象：`scope.$index` 拿去当 id 用，翻到第 2 页就全乱。原因：`$index` 是**当前页数据里的下标**，每页都从 0 开始。怎么改：用 `scope.row.id`。
- 现象：保存成功后弹窗不关。原因：`save()` 里忘了写 `dialogVisible.value = false`。改法：加上（不用手动"销毁"弹窗，`el-dialog` 自己管）。
- 现象：用原生 `alert()` 做提示，无头浏览器截图失败。原因：`alert` 阻塞 JS 线程。怎么改：`ElMessage` / `ElMessageBox`。
- 现象：删除点了页面不动。原因：`tableData` 是普通数组。怎么改：`reactive([...])`。
- 现象：控制台报 `ElMessage is not defined`。原因：忘了从 `'element-plus'` import（**组件是全局注册的，但 `ElMessage` 这类函数式 API 不会自动注册**）。

**⑦ 自测** —— `<template #default="scope">` 里的 `scope` 是谁传给谁的？如果写成 `<template #default>`，里面还能用 `scope.row` 吗？

<details><summary>看答案</summary><br>

**是 `el-table-column` 传给"你写在它里面的这段模板"的。** 表格渲染每一行时知道这行的数据（`row`）、列配置（`column`）、在当前页里的下标（`$index`），于是打包成对象作为插槽参数递出来。你的模板接住它，叫它 `scope`（名字随你起）。

写成 `<template #default>` 就等于**不要这份数据**，里面的 `scope` 是个从没声明过的变量 → `undefined` → 访问 `scope.row` 直接抛 `TypeError: Cannot read properties of undefined`，表格渲染失败。**这就是"作用域插槽"这个名字的来源：数据的作用域在子组件那边，你必须显式接过来。**

</details>

## 6. 讲义勘误速查（本讲）

| 讲义原文 | 问题 | 正确写法 |
|---|---|---|
| `<el-carousel ... interval="3000" ...>`（七，两处） | `interval` 是 **Number** 类型 prop，不加冒号传的是字符串，控制台报 `Invalid prop: type check failed for prop "interval". Expected Number with value 3000, got String with value "3000".`；且与讲义自己在"二、文本域"强调的"写数字要加`：`"自相矛盾 | `:interval="3000"`。**补充说准**：因为 `"3000" <= 0` 和 `setInterval(fn, "3000")` 都会隐式转数字，它"碰巧还能跑"——所以更不能放着不管，规则学歪了换个组件就真出事 |
| 分页示例 `<el-table :data="tableData" ...>`（十、十一） | 整份 `tableData` 交给表格，从未按 `currentPage4/pageSize4` 切片，**翻页、改每页条数都不生效**；且 `pageSize4 = ref(100)` 比总条数还大 | 用 `computed` 切片：从 `(currentPage.value - 1) * pageSize.value` 起，`tableData.slice(start, start + pageSize.value)`，表格改绑切片结果（见 2.10"真分页三件套"） |
| `:total=tableData.length`（十、十一，三处，无引号） | 实测编译结果与加引号版**完全一样**（`total: _ctx.tableData.length`），能跑；但属性值一旦出现空格就会解析错，且与全篇风格不一致 | 统一写 `:total="tableData.length"` |
| 分页里写 `:background`（十、十一） | `:background` 是"绑定一个变量"；Vue 3.4+ 把它当 `:background="background"` 的同名简写，setup 里没有 `background` → 取到 `undefined`（falsy）→ **没有底色**，并有 `Property "background" was accessed during render but is not defined on instance.` | 去掉冒号：`background` |
| `pageSize4 = ref(100)` 配 `:page-sizes="[5, 10, 15, 50]"`（十、十一） | 初值 100 不在候选数组里，每页条数下拉框初始显示对不上；且 100 > 总条数，永远只有一页 | 初值改成候选里的值（如 `ref(5)`），或把 `100` 加进 `:page-sizes`。仓库用的是 `[3, 5, 10]` 配 `ref(3)` |
| `<div class="mt-2">`（五） | `mt-2` 是 **Tailwind CSS** 的工具类，本项目没装 Tailwind，这个类名等于白写 | 换内联 `style="margin-top: 8px"`（仓库写法），或自己在 `<style scoped>` 里定义 |
| 预览一节把 `show-progress` 说成"加载进度显示"（六、3） | **说错了**。源码里它就是个计算属性，拼出来的是"当前下标 + 1、一个斜杠、图片总数"，显示的是**"当前第几张 / 共几张"的序号**（如 `3 / 11`），不是加载百分比 | 说成"预览时显示图片序号"；想自定义内容用它提供的 `#progress` 插槽（插槽参数 `active-index`、`total`） |
| 表格列宽 `width="180"`（九）与 `width="100px"`（十一）混用 | 勘误说"带 px 可能不被正确解析"，**实测是能解析的**：源码 `parseWidth` 用 `Number.parseInt(width, 10)`，`parseInt("100px") === 100`，单位被剥掉 | 两种都能跑，但统一写不带单位的数字最省心。**真正会出错的是 `width="20%"`**——`parseInt("20%") === 20`，会被当成 20 像素；要按比例分配请用 `min-width` |
| 多选框组同时用 `:label` 和 `:value`（五、2），只提醒"版本会影响用法" | 没说清**为什么**。源码里 `actualValue = props.value ?? props.label`：写了 `value` 用 `value`，**没写就退回用 `label`**，同时打印 `label act as value is about to be deprecated in version 3.0.0, please use value instead.`（`el-radio`、`el-radio-button` 同理） | 锁死 element-plus 2.14.x；写法固定为"`:label` 管显示、`:value` 管存值，两个都写"——这套写法在新版本里是前向兼容的 |
| `<el-checkbox v-model="checked1" label="冬虫" size="large" />`（五、1） | 写法本身没错，但**没说明单个 checkbox 的 `label` 只当显示文字**，也没提醒"一旦放进 `el-checkbox-group`，子项自己的 `v-model` 会被忽略"（源码 `model = isGroup ? checkboxGroup.modelValue : props.modelValue`） | 保留原写法；补一句"单个绑布尔、进组绑数组" |
| datetime 一节注释写 `format="YYYY-MM-DD"是展示日期时间格式`（八、2） | 注释是从上一节复制的，**与同一段代码不符**（代码是 `YYYY-MM-DD HH:mm:ss`） | 注释同步改成带 `HH:mm:ss` 的说法，别把这条错注释抄进作业 |
| 全篇 `fuss10.elemecdn.com` / `www.ahtcm.edu.cn` 外链图（六、七） | 官方老 demo CDN 与学校站点，过一两年易 404，学校站点还可能要求校内网 | 图片放工程 `public/img/`，用根路径 `/img/xxx.jpg` 引用（`public` 下的文件 Vite 原样输出到根路径，不用 `import`）。仓库已放 4 张 |
| 第十一节标题"弹窗"，正文只有操作列 + 原生 `alert()`（十一） | **名不副实**：全节没有一个 `el-dialog`；原生 `alert` 还会阻塞 JS 线程，自动化截图会被卡住 | 标题改成"表格操作列/自定义列"，或补上真正的 `el-dialog`（`v-model` 控显隐 + `title` + `#footer` 插槽）与 `ElMessageBox.confirm` 确认框。仓库两种都补了 |
| 未提：`format` 格式串的大小写（八） | Element Plus 用 day.js 的 token，`YYYY`/`MM`/`DD`/`HH`/`mm`/`ss` **大小写敏感**；写小写 `yyyy-mm-dd` 会输出 `yyyy-00-dd` 这种怪东西（`mm` 被当成"分钟"） | 一律大写：`YYYY-MM-DD`、`YYYY-MM-DD HH:mm:ss` |
| 未提：daterange 清空后变 `null`（八、4） | 讲义只给了 `data.daterange?.length`，没说**为什么需要 `?.`**。源码里 picker 用 `useEmptyValues(props, null)`，`valueOnClear` 默认是 `null`——**用户点一下清空（×），`v-model` 就从 `[]` 变成 `null`**，`data.daterange.length` 立刻抛 `Cannot read properties of null`，页面白屏 | 保留 `?.`；更稳妥是初值给 `[]` 且模板里带 `?.`，或外面套 `v-if="data.daterange"` |
| 未提：好几个属性写的都是默认值（六、七） | `autoplay`（默认 `true`）、`pause-on-hover`（默认 `true`）、`arrow="hover"`（默认 `hover`）、`:interval="3000"`（默认 3000）、`:zoom-rate="1.2"`（默认 1.2）、`:max-scale="7"`（默认 7）、`:min-scale="0.2"`（默认 0.2）、`:initial-index="0"`（默认 0）、`:rows="2"`（`rows` 默认 2）——**写和不写完全一样**，容易误以为"是我配了才生效" | 想真正看到效果就把值改掉：`:interval="1000"`、`:max-scale="2"`、`:rows="6"`、`:pause-on-hover="false"`。写默认值当"自解释"可以，但要知道它是默认值 |
