## 2. 知识点精讲

### 2.1 Element Plus 是什么，为什么要用组件库

**讲义怎么说**
开头第一段：Element Plus 是饿了么前端团队开源、持续维护的 **Vue3 专属企业级桌面端 UI 组件库**，是 Vue2 时代 **Element UI 的官方升级继任版本**；给了官网 `https://element-plus.org` 和国内镜像 `https://cn.element-plus.org/`。

**一句话讲透**
自己写组件叫"造轮子"，用组件库叫"买现成的家具"。你要一张桌子，可以自己锯木头（写 `<div>` + CSS），也可以去家具城搬一张（`<el-table>`）。家具城的代价是"你得知道他家有什么款式、每款叫什么型号"——所以**查文档**才是这一讲要练的能力，不是抄代码。

**示例代码**

```vue
<!-- 文件：03/element-plus/src/views/Home.vue 的 <template> 里 -->
<template>
  <div style="padding: 20px;">
    <!-- 手搓按钮：样式自己写，hover 也得自己处理 -->
    <button style="padding: 8px 15px; border: 1px solid #dcdfe6;
                   background: #fff; border-radius: 4px; cursor: pointer;">
      手搓按钮
    </button>

    <!-- Element Plus 的按钮：一行搞定，配色、圆角、hover、禁用态全都有 -->
    <el-button>默认</el-button>
    <el-button type="primary">主要</el-button>
    <el-button type="primary" plain>plain 朴素</el-button>
    <el-button type="success" round>round 圆角</el-button>
    <el-button type="danger" disabled>disabled 禁用</el-button>
  </div>
</template>

<script setup>
// 什么都不用写：el-button 已经在 main.js 里全局注册了
</script>
```

**逐行拆解**

- 第一个 `<button>` 是**原生 HTML 标签**，浏览器天生认识，长什么样完全由你的内联样式决定；不写 `:hover`，鼠标悬停就毫无反馈。
- `<el-button>` 是**组件标签**，浏览器根本不认识。它能显示成漂亮按钮，是因为 `main.js` 里已经把它注册进了 Vue，Vue 拿标签名去组件表里查，查到 `ElButton` 再渲染出真正的 `<button class="el-button ...">`。**没注册就是一行红字警告**（见 2.6）。
- `type`/`plain`/`round`/`disabled` 都是 `ElButton` 预先定义好的 **props**。`disabled` 只写名字不写值，等价于 `disabled="true"`，这是 HTML 的布尔属性写法。

**在你仓库里**

- `03/element-plus/src/views/Home.vue:7-17` —— 六种 `type` 加四种变体全在这里，是"装没装成功"的验证页。
- `03/element-plus/package.json:11-16` —— `"element-plus": "^2.14.6"` 就在 `dependencies` 里。

**常见坑**

- **现象**：`<el-button>` 什么都不显示，控制台红字 `Failed to resolve component: el-button`。**原因**：`main.js` 里没写 `app.use(ElementPlus)`。**怎么改**：补上 2.3 那段。
- **现象**：按钮显示出来了，但灰扑扑一片、没有圆角。**原因**：漏了 `import 'element-plus/dist/index.css'`——组件库只管"结构"，样式在另一个文件里。**怎么改**：补上 2.3 的第 2 行 import。
- **现象**：官网文档里看到的组件，抄过来报错说"没有这个属性"。**原因**：看的是 Vue2 版 Element UI 的文档，或 Element Plus 的旧版本文档。**怎么改**：认准 `https://cn.element-plus.org/zh-CN/component/xxx`，并对照 `package.json` 里实际装的版本。

**自测**
问题：为什么 `<el-button>` 在浏览器里能用，而你随便编一个 `<el-abcd>` 就不行？
<details><summary>看答案</summary>
浏览器只认识 HTML 标准里规定的那一百多个标签（`div`、`button`、`table`…）。`<el-button>` 能渲染出来，靠的是 **Vue 在编译阶段把它从"标签"改写成了"按名字查组件"**；查到了就渲染组件，查不到就警告并当成未知元素丢掉。见 2.6 的编译器实测。
</details>

### 2.2 `npm i element-plus -S`：`-S` 和 `-D` 到底差在哪

**讲义怎么说**
"一、安装Element Plus框架"第 2 步：在工程目录下输入**安装生产依赖包命令** `npm i element-plus -S`。讲义只说了"生产依赖"四个字，没解释为什么。

**一句话讲透**
`package.json` 里有两个篮子：`dependencies`（**上线要用的**）和 `devDependencies`（**只有开发时用的**）。`-S` 是 `--save`（生产篮子），`-D` 是 `--save-dev`（开发篮子）。装错篮子的后果，只有在你把项目交给别人、或者部署上线的时候才会爆炸——这正是最坑的地方。

**示例代码**

```bash
# 进工程根目录（能看到 package.json 的那一层）
cd D:\course\Javaweb\03\element-plus

npm i element-plus -S                 # 讲义写法：-S 显式声明"生产依赖"
npm install @element-plus/icons-vue   # 图标包：不写 -S 也进 dependencies
npm i element-plus -D                 # 反例：装成开发依赖，开发时看不出问题，上线缺包

# 验证两个篮子真的会被区别对待（模拟"服务器上只装生产依赖"）
npm i --omit=dev      # 实测结果：vue、element-plus 装上了；vite 没有
```

装完之后 `package.json` 应该长这样（节选自你仓库的真实内容）：

```json
{
  "dependencies": {
    "@element-plus/icons-vue": "^2.3.2",
    "element-plus": "^2.14.6",
    "vue": "^3.5.42",
    "vue-router": "^5.3.1"
  },
  "devDependencies": {
    "@vitejs/plugin-vue": "^6.0.8",
    "vite": "^8.2.2",
    "vite-plugin-vue-devtools": "^8.2.1"
  }
}
```

**逐行拆解**

- `npm i` 就是 `npm install` 的缩写。它做三件事：下载包到 `node_modules`、把名字写进 `package.json`、把精确版本写进 `package-lock.json`。
- `-S` 是 `--save` 的缩写。但在这个仓库的 **npm 11.13.0 上我实测过：不加 `-S` 也一样写进 `dependencies`**。因为 npm 5（2017 年）之后 `save` 的默认值就是 `true`，`-S` 已经是"历史遗留但无害"的写法。讲义让你写它，是为了让意图明确，照写没问题。
- 真正有区别的是 `-D`（`--save-dev`）。`vite`、`@vitejs/plugin-vue` 就该放这里——它们**只负责把你的代码编译成浏览器能跑的版本，编译完就没它们什么事**，服务器上不需要。
- 那 `element-plus` 为什么必须是 `dependencies`？因为它的代码**会被打进你最终的前端产物**：`el-button` 的组件代码和样式，是 Vite 从 `node_modules/element-plus` 里抽出来、压缩、塞进 `dist/` 的。它是"产品的一部分"，不是"工具"。上面那条 `--omit=dev` 的实测就是最好的证明。

**在你仓库里**

- `03/element-plus/package.json:11-16` —— `dependencies` 段，`element-plus` 和 `@element-plus/icons-vue` 都在里面。
- `03/element-plus/package.json:17-21` —— `devDependencies` 段，`vite` 在里面。两段对比着看，一眼就懂。

**常见坑**

- **现象**：开发时一切正常，把代码交到服务器上 `npm i`，报 `Failed to resolve import "element-plus"`。**原因**：装的时候手抖写了 `-D`，包进了 `devDependencies`，而服务器上通常只装生产依赖。**怎么改**：把 `package.json` 里那一行从 `devDependencies` 剪到 `dependencies`，重跑 `npm i`。
- **现象**：`npm i element-plus -S` 报 `ERR! code ENOENT ... package.json`。**原因**：终端当前目录不是工程根目录，npm 靠"往上找 `package.json`"确定装哪儿。**怎么改**：`cd 03/element-plus`，确认 `dir` 能看到 `package.json`。
- **现象**：装完了但 `package.json` 没变化。**原因**：执行的是 `npm i element-plus -g`（全局安装，装到了系统目录）。**怎么改**：去掉 `-g`，加上 `-S`。

**自测**
问题：你写了一个只在开发时生成假数据的包 `mockjs`，该用 `-S` 还是 `-D`？装错了会在什么阶段出问题？
<details><summary>看答案</summary>
用 `-D`。它只服务于开发调试，生产环境不需要。装错了（写成 `-S`）**不会报错**，只是最终产物里多带一份用不上的代码，让包变大、加载变慢——问题是"变胖"而不是"报错"，所以最难被发现。反过来把 `element-plus` 装成 `-D`，才是会直接报错的严重错误。
</details>

### 2.3 在 `main.js` 里引入并装配：三样东西 + `app.use` 逐行拆解

**讲义怎么说**
"一、安装ElementPlus框架"第 3 步给了四行代码，说"将下面代码放在**合适的位置**"。两个问题：① **讲义把 `app.use` 和两个 `import` 混在一起给了**，没区分"哪几行是 import、哪一行是调用"；② 那句"合适的位置"太含糊——`app` 这个变量在下一行才被 `const` 声明出来。

**一句话讲透**
`element-plus` 这个包其实是"三份东西分开卖的"：**组件代码**（告诉 Vue 怎么渲染按钮）、**CSS 样式**（告诉浏览器按钮长什么样）、**各国语言包**（告诉组件分页器上该写"共 3 条"还是 `Total 3`）。它们必须**各引各的**，少引一份就少一份能力。
而 `createApp(App)` 是"**领一张空白的营业执照**"，`app.use(...)` 是"**往执照上盖章**"——你得先有执照，才能盖章。

**示例代码**

```js
// 文件：03/element-plus/src/main.js（逐字对应你仓库里的真实文件）
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'
import './assets/global.css'
import ElementPlus from 'element-plus'                    // ① 组件库本体
import 'element-plus/dist/index.css'                      // ② 样式（没有 from，没有变量名）
import zhCn from 'element-plus/es/locale/lang/zh-cn'      // ③ 中文语言包
import * as ElementPlusIconsVue from '@element-plus/icons-vue'  // ④ 图标包（2.4 节）

const app = createApp(App)                  // ← 必须先造出 app，它是个"应用实例"

app.use(router)                             // ← 装路由插件
app.use(ElementPlus, { locale: zhCn })      // ← 装组件库，并指定中文

app.mount('#app')                           // ← 挂载到 index.html 里 id="app" 的节点
```

**逐行拆解**

- `import ElementPlus from 'element-plus'`：**有 `from`、有变量名**，说明它是**默认导出**——整个包对外只交出一个"插件对象"，形状是 `{ install(...) }`，这正是 `app.use()` 要的。名字随便改（`import EP from 'element-plus'` 也行），默认导出不靠名字匹配。
- `import 'element-plus/dist/index.css'`：**没有 `from`、没有变量名**，这叫**副作用导入**——不是"我要用这个文件里的东西"，而是"**执行一下这个文件**"，效果就是里面的样式规则被注册到页面上。漏了会怎样？组件**照样渲染、照样能点**，但样式全没了：按钮是没圆角的裸 `<button>`，表格是光秃秃的 `<table>`。
- `import zhCn from 'element-plus/es/locale/lang/zh-cn'`：实际跑起来看，它交出的是 `{ name: 'zh-cn', el: {...} }`，`el` 下面按模块分组，共 25 个模块。比如 `pagination` 里是 `{ total: '共 {total} 条', goto: '前往', pagesize: '条/页' }`。路径必须写全，`element-plus/zh-cn` 这种简写不存在。
- `const app = createApp(App)` **必须在 `app.use` 之前**：`const` 声明的变量存在**暂时性死区（TDZ）**，声明语句执行前访问会抛 `ReferenceError: Cannot access 'app' before initialization`；而且 `use` 是 `app` 上的方法，`app` 都没造出来，哪来的方法。讲义说的"合适的位置"就是：**`createApp(App)` 之后、`app.mount('#app')` 之前**。
- `app.use(ElementPlus, { locale: zhCn })`：`app.use()` 是 Vue 的**插件安装方法**——看看传进来的东西有没有 `install` 方法，有就调用它并把 `app` 自己当参数传进去。Element Plus 的 `install` 干的事就是把 `ElButton`、`ElTable` 等**全部组件**和 `ElMessage`、`ElMessageBox` 等**全部方法**注册到 `app` 上。
- 第二个参数 `{ locale: zhCn }` 是**插件选项对象**，意思是"以后要显示文字的地方，都去 `zhCn` 里查"。内部通过 Vue 的 `provide/inject` 发给所有子组件，根上设一次全局生效。不写 `locale` 就是**英语**：分页器的"共 3 条"变成 `Total 3`、"前往"变成 `Go to`；日期选择器是 `Mon Tue Wed`；表单校验、表格的"暂无数据"、确认框的"确定/取消"也全是英文。

**在你仓库里**

- `03/element-plus/src/main.js:7`、`:8`、`:9` —— 三行 import，依次是本体、样式、中文包。已确认 `node_modules/element-plus/dist/index.css` 与 `es/locale/lang/zh-cn.mjs` 真实存在。
- `03/element-plus/src/main.js:12` —— `const app = createApp(App)`；`:15-16` —— 工程自己加的注释 `// 注意：app.use(ElementPlus) 必须在 createApp 之后` 和真正的那一行；`:23` —— `app.mount('#app')`。
- `03/element-plus/src/views/Components.vue:121-129` —— 真正受 `locale` 影响的地方：`layout="total, sizes, prev, pager, next, jumper"` 里的**键名**永远是英文，但**渲染出来的文字**受 locale 控制。

**常见坑**

- **现象**：按钮/表格能显示但完全没有样式，页面上是一堆裸标签，字体还是默认衬线体。**原因**：漏了 `import 'element-plus/dist/index.css'`。**怎么改**：补上第 8 行，放在 `import ElementPlus` 紧下面，一眼看出是一对。
- **现象**：控制台第一行就是 `Uncaught ReferenceError: Cannot access 'app' before initialization`，页面白屏。**原因**：把 `app.use(ElementPlus, ...)` 抄到了 `const app = createApp(App)` **上面**。**怎么改**：顺序永远是"**造 app → 装插件 → 挂载**"。
- **现象**：分页器、日期选择器全是英文，但你确认 `zhCn` 引了。**原因**：引了但没传对，比如只写 `app.use(ElementPlus)`，或者写成 `app.use(ElementPlus, zhCn)`——少了 `{ locale: ... }` 这一层。**怎么改**：必须是 `{ locale: zhCn }`，键名 `locale` 不能改。
- **现象**：控制台报 `Failed to resolve import "element-plus/dist/index.css"`。**原因**：`element-plus` 根本没装上，或被装进了 `devDependencies` 而当前环境用了 `--omit=dev`。**怎么改**：回 2.2 检查 `package.json`，重跑 `npm i`。

**自测**
问题：把 `import 'element-plus/dist/index.css'` 注释掉，页面会变成什么样？按钮还能点吗？这说明了什么？
<details><summary>看答案</summary>
按钮变成没有圆角、没有配色、没有间距的裸 `<button>`，文字是浏览器默认字体；但它**照样能点、`@click` 照样触发**。因为 Vue 渲染出来的是真实的 `<button class="el-button el-button--primary">` 元素，点击事件绑在这个真实元素上；而 `.el-button` 那套规则住在 `dist/index.css` 里，你没引就没人给它化妆。**结构（JS）和外观（CSS）是两份东西**，这就是那行副作用导入存在的唯一理由。
</details>

### 2.4 全局注册 vs 按需引入 / 装图标包 / 那三行注册循环

> 这一节打包三个连在一起的知识点：**怎么选注册方式**（讲义没讲）、**图标包怎么装**（二、第 1 步）、**循环注册那三行每一句在干嘛**（二、第 2 步）。

**讲义怎么说**
讲义从头到尾用的都是**全局注册**：`app.use(ElementPlus, {...})` 一次注册全部组件，图标也用循环一次注册 294 个——但**没讲这种做法的代价**。图标部分只给了：

```js
import * as ElementPlusIconsVue from '@element-plus/icons-vue'
for (const [key, component] of Object.entries(ElementPlusIconsVue)) {
app.component(key, component)
}
```

外加一句"在 main.js 里引入"。**这三行里的语法一个都没解释**，而它恰好是整份讲义里语法密度最高的一段：一口气用了 `import * as`、`Object.entries`、数组解构、`for...of`、`app.component`。

**一句话讲透**
全局注册 = **把整间超市搬回家**，想吃什么伸手就有，但冰箱得装得下。按需引入 = **想吃什么买什么**，冰箱清爽，但每次出门都得跑一趟（每个文件写 import）。
至于那三行循环：它干的事等价于**手写 294 遍** `app.component('School', School)`——把包里的所有图标摊成一张清单，挨个去 Vue 那里报户口。**报完户口，标签才能用。**

**示例代码**

```bash
npm install @element-plus/icons-vue
```


**逐行拆解**

- **方案 A 的代价**：会把**整个组件库**拉进打包结果。哪怕只用了一个 `<el-button>`，最终 `dist/` 里也有表格、日期选择器、走马灯等所有组件的代码和样式，代价是**首屏体积大、加载慢**（几百 KB 级别）。图标同理——全量进包。**收益**是零心智负担，粘贴就能跑。
- **方案 B 的收益**：Vite/Rollup 会做 **tree-shaking（摇树）**，没被 import 的组件代码被整块摇掉。**代价**是每个 `.vue` 文件都要多写一两行 import，抄官网示例时经常漏。注意方案 B **仍然要引** `dist/index.css`（样式省不掉）；进阶的 `unplugin-vue-components` 自动导入超出本讲范围，知道有这回事就行。**本讲用方案 A**——讲义选它是为了让你先跑通，别在这一讲纠结体积。
- `import * as ElementPlusIconsVue from '@element-plus/icons-vue'`：`* as 名字` ="**把这个模块导出的所有东西打包成一个对象**"。图标包用的是**具名导出**（`export { School, House, ... }`），所以不能用默认导入的写法。变量名随便改（`import * as icons` 也行），改完记得循环里同步改。
- `Object.entries(ElementPlusIconsVue)`：JS 原生方法，把**对象**转成**二维数组**。我实测过：

```js
const fake = { School: 1, House: 2 }
Object.entries(fake)   // → [['School', 1], ['House', 2]]，每一项本身也是数组
```

  **为什么要转换？** 因为 `for...of` 只能遍历"可迭代对象"，而普通对象**不是**可迭代的——直接写 `for (const x of ElementPlusIconsVue)` 会报 `ElementPlusIconsVue is not iterable`。`Object.entries` 就是那座桥。
- `for (const [key, component] of ...)`：`for...of` 挨个取出数组里的每一项，第一轮取出 `['School', 组件]`；`const [key, component] = ['School', 组件]` 是**数组解构**，按位置对应。变量名随便起（`[name, comp]` 也一样），但方括号 `[]` **不能写成花括号 `{}`**——`{}` 是对象解构，用在数组上会报错。
- `app.component(key, component)`：**在全局注册一个组件**。注册完之后这个名字对应的标签在**所有** `.vue` 文件里都能直接用，不用再 import。循环跑了 294 次，294 个图标一个不漏。

**在你仓库里**

- `03/element-plus/src/main.js:10` —— `import * as ElementPlusIconsVue ...`；`:16` —— 方案 A 的 `app.use(ElementPlus, { locale: zhCn })`；`:19-21` —— 循环注册的三行，注释是 `// 全局注册所有图标组件`。

- `03/element-plus/src/views/Components.vue:148` —— 反例：`import { ElMessage, ElMessageBox } from 'element-plus'`。这两个**是函数不是标签**，没法靠全局注册使用，**必须**单独 import。
- 已确认 `node_modules/@element-plus/icons-vue/dist/types/components/` 下共 **294 个**组件文件（`school.vue.d.ts`、`house.vue.d.ts`、`menu.vue.d.ts` …）。

**常见坑**

- **现象**：报 `ElementPlusIconsVue is not iterable`。**原因**：忘了写 `Object.entries(...)`。**怎么改**：补上。记住：**对象不能直接 for...of**。
- **现象**：图标还是 `Failed to resolve component: School`，循环明明写了。**原因**：循环写在了 `const app = createApp(App)` **之前**（先报 `app` 未定义），或者写在了 `app.mount('#app')` **之后**（挂载后再注册，已渲染的组件不会回头重新解析）。**怎么改**：注册必须在 `createApp` 之后、`mount` 之前。
- **现象**：报 `TypeError: Cannot read properties of undefined (reading 'component')`。**原因**：打错成了 `App.component(...)`——大写的 `App` 是**根组件**，不是应用实例，身上没有 `component` 方法。**怎么改**：确认是小写的 `app`。
- **现象**：`ElMessage` 弹不出来，报 `ElMessage is not defined`。**原因**：以为它和 `<el-button>` 一样被全局注册过。**怎么改**：`import { ElMessage } from 'element-plus'`，用的时候直接 `ElMessage.success('保存成功')`。
- **现象**：`npm install @element-plus/icons-vue` 报 `404 Not Found`。**原因**：包名拼错，常见错法 `element-plus-icons-vue`（少了 `@`）、`@element-plus/icon-vue`（少了 `s`）。**怎么改**：去 npm 官网搜 `element-plus icons` 复制命令，别手打。

**自测**
问题：`import * as ElementPlusIconsVue` 能不能写成 `import ElementPlusIconsVue`（去掉 `* as`）？`<el-button>` 不用 import 就能用，`ElMessage` 为什么必须 import？
<details><summary>看答案</summary>
**第一问：不能。** `import X from '包'` 要求这个包有**默认导出**（`export default`）。图标包用的是**具名导出**，去掉 `* as` 会报 `does not provide an export named 'default'`。对比 2.3 节：`element-plus` 本体是默认导出，所以写 `import ElementPlus from 'element-plus'`。**同一个"引入"动作，写法取决于包里是怎么导出的。**

**第二问：** `<el-button>` 是**组件**，被注册进了 Vue 的全局组件表，模板里出现这个标签名时 Vue 会去表里查。`ElMessage` 是**普通函数**（调用它在页面上动态插入一个消息框），不走模板、不经过组件解析，组件表里根本没有它。**全局注册只覆盖"能当标签用的东西"**，函数类 API 永远要自己 import。
</details>

### 2.5 图标怎么用：`el-icon` + `:size` + `color`（含 `#6666` 错误与两层颜色的分工）

> 这一节打包讲三个知识点：**基本用法**（二、第 3 步）、**讲义写错的 `#6666`**、**外层 `span` 与 `el-icon` 两层颜色的分工**。

**讲义怎么说**
"二、全局使用 icon"第 3 步，讲义原文：

```html
<div>
<span style="margin-left: 30px; color: #6666">
<el-icon :size="60" color="#6666" style="top: 4px"><School /></el-icon> 安中医
</span>
</div>
```

两个问题：① **`#6666` 是错的**（出现两处），`03/讲义勘误_实训3.md` 第 1 条记的就是它；② 讲义没说明"为什么外层和内层都写了颜色、各管什么"。

**一句话讲透**
`<el-icon>` 是**画框**，`<School />` 是**画**。画框负责尺寸和颜色，画负责图形，两个标签缺一不可——只写画框是空的，只写画就没有统一的大小和颜色控制。
至于颜色：**十六进制颜色只有四种合法长度：3、4、6、8 位**，其中 4 位和 8 位是**带透明度**的格式。所以 `#6666` 不是"打少了几位的 `#666666`"，而是一个**语法合法、语义完全不同**的颜色：40% 不透明度的灰。你写它，浏览器一点都不报错，只是安静地把图标画淡了。

**示例代码**

```vue
<!-- 文件：03/element-plus/src/views/Home.vue:21-34（你仓库里就是这么对比的） -->
<template>
  <div style="padding: 20px; display: flex; gap: 60px;">
    <div>
      <p>老师原版 color="#6666"（4位，被当半透明，偏淡）</p>
      <span style="color: #6666">
        <el-icon :size="60" color="#6666"><School /></el-icon> 安中医
      </span>
    </div>
    <div>
      <p>修正版 color="#666666"（正常中灰）</p>
      <span style="color: #666666">
        <el-icon :size="60" color="#666666"><School /></el-icon> 安中医
      </span>
    </div>
  </div>
</template>

<script setup>
</script>
```

```vue
<!-- 补充：尺寸的几种写法和两层颜色的组合（加在 Home.vue 里试） -->
<template>
  <div style="padding: 20px;">
    <!-- ① 不写 size：图标继承外层字号（30px）和颜色（蓝）；② ③ 两种 size 写法都能用 -->
    <div style="color: #409eff; font-size: 30px;"><el-icon><House /></el-icon> 首页</div>
    <el-icon :size="60"><House /></el-icon>
    <el-icon size="60px" color="#67c23a"><House /></el-icon>

    <span style="color: #c0392b; font-size: 20px;">
      <el-icon :size="60"><School /></el-icon> 只写外层，图标照样红
    </span>

    <!-- ⑤ 两层不同色：图标用自己的，文字用外层的；⑥ 按钮里放图标要自己加 margin-right -->
    <span style="color: #c0392b; font-size: 20px;">
      <el-icon :size="60" color="#409eff"><School /></el-icon> 图标蓝、文字红
    </span>
    <el-button type="primary">
      <el-icon style="margin-right: 4px;"><Search /></el-icon> 搜索
    </el-button>
  </div>
</template>
```

**逐行拆解**

- `<el-icon>` 是**容器组件**。查源码（`node_modules/element-plus/es/components/icon/src/icon.vue_vue_type_script_setup_true_lang.mjs`）可以看到，它最终渲染出一个 `<i class="el-icon">`，里面放你塞进去的内容（`<slot>`）。所以 `<el-icon>` 里必须再写一个具体图标标签。
- `:size="60"` 前面的**冒号是 `v-bind` 的缩写**，意思是"引号里的东西按 JS 表达式算，不算字符串"。`:size="60"` 传的是**数字** `60`；`size="60"` 传的是**字符串** `"60"`。两种**都能用**，因为 `ElIcon` 声明的 size 类型是 `[Number, String]`，内部再调 `addUnit()` 补上 `px`。但**冒号的意义在于表达意图**：要传数字就加冒号。等你在实训4 写 `:total="tableData.length"` 时，冒号就是**必须**的——不加冒号，`"tableData.length"` 会被当成一串普通字符。
- `style="top: 4px"` 是**行内样式**，作用在渲染出的那个 `<i>` 上。`top` 能生效是因为 `.el-icon` 设了 `position: relative`（我核过 `node_modules/element-plus/theme-chalk/el-icon.css`）。它的用途是**微调图标和旁边文字的基线对齐**——60px 的大图标和 14px 的中文并排时往往偏低，`top: 4px` 把它抬一点。
- `size` 实际影响的是 `font-size`。为什么改字号就能改图标大小？因为 `.el-icon` 的样式里有 `width: 1em; height: 1em`——**图标永远是 1 个字号那么大**。这也是为什么外层写 `font-size: 30px` 也能控制图标大小（例 ①）。
- **`#6666` 到底算成了什么？** 四种合法写法，以及我在浏览器里逐个跑 `getComputedStyle` 得到的真实结果：

| 你写的 | 浏览器实际算出来的 | 含义 |
|---|---|---|
| `#666` | `rgb(102, 102, 102)` | 3 位简写，等价于 `#666666`，不透明 |
| `#6666` | `rgba(102, 102, 102, 0.4)` | **4 位 = `#RGBA`**，最后一位 `6` 是 alpha（6/15 ≈ 0.4） |
| `#666666` | `rgb(102, 102, 102)` | 6 位，标准写法，不透明 |
| `#66666666` | `rgba(102, 102, 102, 0.4)` | 8 位 = `#RRGGBBAA`，和 `#6666` 一个效果 |

  CSS Color 4 规定 4 位十六进制是 `#RGBA`，四位依次是红、绿、蓝、透明度的**半字节**（0~15）；`6 ÷ 15 = 0.4`。
- **`color` 是怎么走到图标上的？** `ElIcon` 源码里，你传的 `color` 被写成一个 CSS 变量 `--color`，而 `.el-icon` 的样式里写着 `color: var(--color)` 和 `fill: currentColor`。实测 `fill` 的值，`#6666` 那一侧算出的是 `rgba(102, 102, 102, 0.4)`——**灰度和正常值一模一样（都是 102），只是多了 40% 的透明度**，这就是"看起来发淡、像蒙了层灰"的全部原因。
- **正确写法**：`color="#666666"`，或更短的 `color="#666"`。**绝不要写 4 位或 8 位**，除非你真的想要半透明（比如做禁用态）。而且**同一行里外层 `<span>` 的 `color` 也要改**，否则图标旁边的"安中医"照样发淡——**要改一起改**。
- **两层颜色各管什么？** 外层 `span` 的 `color` 管**旁边的文字**，`el-icon` 的 `color` 管**图标本身**。而 `.el-icon` 的默认样式是 `--color: inherit`，也就是**从父元素继承文字颜色**——所以例 ④ 里图标不写 `color` 也照样是红的。图标自己写了 `color` 时优先级更高（`ElIcon` 把它写成**行内**的 `--color`，行内样式压过继承），所以例 ⑤ 里图标蓝、文字红，互不干扰。**`margin-left: 30px` 在外层**，是让**整个这一块**（图标 + 文字）离左边远一点；想让文字离图标远一点，得给 `el-icon` 加 `margin-right`。

**在你仓库里**

- `03/element-plus/src/views/Home.vue:24-26` —— 讲义原版（`#6666`），故意留着做对比；`:30-32` —— 修正版（`#666666`）。
- `03/element-plus/node_modules/element-plus/theme-chalk/el-icon.css` —— 全文只有一行，`position:relative`、`width:1em;height:1em`、`--color:inherit` 都在里面，可以自己打开看。
- `03/讲义勘误_实训3.md:11-21` —— 勘误第 1 条，讲的就是这一处，配了截图 `03/勘误图/icon-color.png`；`03/演示截图/03_图标颜色对比.png` 是两种写法的实际对比图。
- `03/实验过程_实训3.md:124` —— 老师记录的"`<el-icon style="top: 4px">` 这个 top 有没有用"，结论是有用。

**常见坑**

- **现象**：图标颜色对，但看起来"淡"、"灰扑扑"、"像被禁用"。**原因**：颜色值写成了 4 位或 8 位十六进制。**怎么改**：改成 6 位。**自检**：F12 选中图标，Styles 面板看 `color` 的计算值——显示 `rgba(102, 102, 102, 0.4)` 这种带小数的就是这个问题；显示 `rgb(...)` 三个数字就正常。
- **现象**：图标巨大或巨小，跟旁边文字不搭。**原因**：`<el-icon>` 不写 size 时是 `font-size: inherit`——**继承父元素的字号**，父元素是 `<h1>` 图标就那么大。**怎么改**：显式 `:size="20"`，或把父元素的 `font-size` 定下来。
- **现象**：只改了外层 `span` 的颜色，图标纹丝不动。**原因**：`el-icon` 上已经写了 `color`，行内值压过继承。**怎么改**：把 `el-icon` 上那个 `color` 删掉让它继承，或两处一起改。
- **现象**：图标位置比旁边的中文低一截；或者图标和文字粘在一起没间距。**原因**：内联元素默认按基线对齐，SVG 容易偏低；两者之间也没有默认间距（HTML 换行产生的空白被折叠）。**怎么改**：`<el-icon style="top: 4px">`（讲义的做法）抬基线；`style="margin-right: 4px"` 或 Element Plus 自带的 `.el-icon--right` 类加间距。

**自测**
问题一：`<el-icon :size="60">` 和 `<el-icon size="60">` 渲染出来一样吗？`<el-icon :size="60"></el-icon>` 和 `<el-icon :size="60"><House /></el-icon>` 呢？
问题二：在 F12 里跑 `const e=document.createElement('span'); e.style.color='#6666'; console.log(e.style.color)`，它打印什么？和 `#666666` 的区别在哪个数值上？为什么浏览器不给个错？
<details><summary>看答案</summary>
**问题一：** 前两个**效果一样**——`ElIcon` 的 size 类型是 `[Number, String]`，数字 `60` 和字符串 `"60"` 都会被 `addUnit()` 补成 `60px`；区别只在"你传的是什么类型"。后两个**完全不一样**——前者是**一个空的 60px 方框**，页面上什么都看不到（`el-icon` 只是容器，里面没东西就没东西）；后者才有图标。这也是新手最常见的困惑："我明明写了 `el-icon`，怎么是空的"，答案永远是**里面那个具体图标标签漏了**。

**问题二：** 打印 `rgba(102, 102, 102, 0.4)`；换成 `#666666` 则打印 `rgb(102, 102, 102)`。**红绿蓝三个数字完全相同（都是 102），唯一的差别是多了个 alpha = 0.4。**

浏览器不报错，是因为按 CSS 规范 `#6666` 是一个**完全合法的颜色值**（4 位 `#RGBA`），浏览器的职责是"照你写的执行"，不是"猜你想写什么"。这类 bug 最阴的地方就是：它不崩、不报错、不警告，只是长得不对——而"长得不对"往往是你最后才会怀疑的地方。
</details>

### 2.6 组件注册后才能当标签用的原理 + Vite 热更新

> 这一节讲两个"讲义没展开但必须懂"的知识点：**"注册"到底是什么**（讲义只说"就可以使用了"）、**改完要不要重启**（讲义只说"看效果"）。

**讲义怎么说**
"二、全局使用 icon"第 2 步末尾只有一句"注册完之后，就可以使用了"，**没解释"注册"是什么**。"一、安装Element Plus框架"第 4 步只说"添加按钮，测试一下是否配置成功"，**没说要不要重启**（`03/实验过程_实训3.md:53` 补上了答案：保存后 Vite 会热更新，不用重启）。

**一句话讲透**
Vue 的模板**不是 HTML**，它是一份要被**编译器翻译**的源代码。你写 `<School />`，编译器不把它当标签，而是翻译成一句 **"去组件表里查一个叫 `School` 的东西"**。全局注册（`app.component`）的作用就是**往那张表里塞一行记录**：表里有就渲染，表里没有就警告。
至于热更新：Vite 的开发服务器像个**监工**，你一保存它只把改动的那个模块重新编译、推给浏览器局部替换。**所以你几乎不用刷新，更不用重启**——但有两件事它管不了。

**示例代码**

```js
// 临时验证脚本，放在 03/element-plus/ 目录下跑（用完可以删）。名字：_verify.mjs
import { compile } from '@vue/compiler-dom'

const cases = [
  ['<School />', '大写 School'],
  ['<school />', '小写 school'],
  ['<el-button>hi</el-button>', '连字符 el-button'],
  ['<div>hi</div>', '原生 div'],
]

for (const [tpl, label] of cases) {
  const { code } = compile(tpl, { mode: 'module', prefixIdentifiers: true })
  console.log('=== ' + label + ' ===')
  console.log(code.split('\n').filter(l => l.includes('resolve') || l.includes('createElement')).join('\n'))
}
```

我跑出来的真实结果（`node _verify.mjs`）：

```text
=== 大写 School ===       const _component_School = _resolveComponent("School")
=== 小写 school ===       const _component_school = _resolveComponent("school")
=== 连字符 el-button ===   const _component_el_button = _resolveComponent("el-button")
=== 原生 div ===          return (_openBlock(), _createElementBlock("div", null, "hi"))
```

```text
# 开发服务器（npm run dev）一直开着，然后照这个顺序改一遍，把每一栏的现象记下来
① 改 Home.vue 里某个 <el-button> 的文字        → 浏览器文字立刻变，地址栏端口不变
② 在 Home.vue 里加 <el-icon><Star /></el-icon>  → 立刻出现星星图标
③ 注释掉 main.js 里的 import '.../index.css'    → 按钮瞬间变成裸样式
④ 注释掉 app.use(ElementPlus, ...)             → 图标/按钮全没了，控制台刷红字
⑤ 恢复代码，保存，看控制台                      → 红字还在！
⑥ 按 F5 刷新浏览器                              → 一切恢复正常
```

**逐行拆解**

- **编译器实测结论**：`<div>` 走的是 `createElementBlock("div", ...)`——编译器认识它。而 `<School />` 走的是 `_resolveComponent("School")`——编译器**不认识**它，于是生成一句"**运行时去查**有没有叫 `School` 的组件"。
- **`_resolveComponent` 的查找顺序**：① 当前组件的 `components` 选项（`<script setup>` 里 import 的局部组件）→ ② 一路往上找父组件的注册表 → ③ 最后到**根组件**的注册表，也就是 `app.component('School', ...)` 塞进去的那张表。查不到就**渲染成同名的原生元素（基本等于什么都不显示）+ 打一行警告**。我在 Node 里实测过没注册时的原文：

```text
[Vue warn]: Failed to resolve component: School
If this is a native custom element, make sure to exclude it from component resolution via compilerOptions.isCustomElement.
  at <App>
```

- **大小写是敏感的。** 编译结果里 `<school />` 查的是 `"school"`，而注册的是 `"School"`——**两个不同的键，查不到**。
- **`<el-button>` 为什么是连字符小写？** 因为 HTML 标签名**天生大小写不敏感**，Vue 因此约定组件标签写 kebab-case。Element Plus 内部注册的是 `ElButton`，Vue 会自动把 `el-button` 转成 `ElButton` 再查一次（camelize 匹配）。而图标是单词名、没有对应的原生标签，注册的键就是大写驼峰 `'School'`，所以直接写 `<School />` 最省事。
- **为什么改 `.vue` 不用刷新？** 改动只影响**模块的代码内容**：Vite 重新编译那个模块，推给浏览器替换旧的，Vue 自动重渲染。这就是 **HMR（Hot Module Replacement，热模块替换）**。
- **为什么 ⑤ 的红字"还在"？** 因为控制台是**只追加不清空**的日志——你恢复代码后**没再报新错**，但**旧的记录还留在屏幕上**。**判断方法**：按 F5 刷新，红字消失就说明早修好了。
- **哪些改动必须重启 `npm run dev`？** ① `npm install` 装新包之后（Vite 要重做依赖预构建）；② 改 `vite.config.js`（配置只在启动时读一次）；③ 改 `package.json` 的 `scripts`。**停止服务器**用 `Ctrl + C`；直接关窗口有时会留下"孤儿进程"占着 5173 端口，下次启动 Vite 会自动改用 5174——**一切以地址栏实际显示的端口为准**。

**在你仓库里**

- `03/element-plus/src/main.js:19-21` —— 往表里塞 294 条记录的地方；`03/element-plus/src/views/Home.vue:25` —— 表里查 `School` 的地方。
- `03/element-plus/src/main.js:14-16` —— `app.use(router)` 和 `app.use(ElementPlus)`：插件的 `install` 内部也在做同样的"注册"（路由注册 `RouterLink`/`RouterView`，组件库注册所有 `El*`）。
- `03/element-plus/package.json:7` —— `"dev": "vite"`；`src/main.js:23` —— `app.mount('#app')`。
- `03/实验过程_实训3.md:53` —— "保存后 Vite 会热更新，不用重启"；`基础补课/补基础训练营.html` 的 **L0 关卡**（第 449-467 行）专门练"起得来、关得干净、端口被占怎么查"。

**常见坑**

- **现象**：`Failed to resolve component: school`（小写的 school）。**原因**：标签名大小写和注册名对不上。**怎么改**：图标一律按官网抄**大驼峰**：`<School />`、`<House />`、`<ArrowDown />`。
- **现象**：报 `Failed to resolve component: el-buttons`（多打了个 s），或者标签原样出现在页面上。**原因**：标签名拼错了——Vue 不做模糊匹配；不认识的标签会被浏览器当"未知元素"跳过渲染，但**不报错**。**怎么改**：对着官网文档复制标签名。
- **现象**：改完代码页面没反应。**原因**：改的不是正在显示的那个页面（`/home` 显示的是 `Home.vue`，不是 `Components.vue`），或者 HMR 卡住了。**怎么改**：先 F5 刷新；还不行就 `Ctrl + C` 重启。
- **现象**：启动时提示 `Port 5173 is in use, trying another one...`。**原因**：上一次的 dev server 没关干净。**怎么改**：看地址栏实际端口（大概率 5174）直接用；或在任务管理器里收掉残留的 node 进程。

**自测**
问题：`app.component('School', component)` 的第二个参数，为什么要传"组件定义"而不是"组件实例"？讲义注释里写的"组件实例"对吗？
<details><summary>看答案</summary>
**讲义这个措辞不准确**（`03/讲义勘误_实训3.md` 第 3 条也记了）。第二个参数是**组件定义**——一个选项对象（`{ name, setup, template, ... }`）或者一个 `setup` 函数，也就是"**怎么做这个组件的图纸**"，不是"实例"（实例是图纸造出来的某一个具体的东西，带自己的 `data`、自己的生命周期）。

为什么必须是图纸？因为**同一张图纸要造很多个**：你在页面上放 3 个 `<School />`，Vue 需要按图纸造 3 个互不干扰的实例。如果注册的是实例，3 个地方就会共用同一份状态——那 Vue 的响应式体系就崩了。

**顺带记一个习惯**：控制台报错后改代码，"红字还在"多半是旧日志；**判断是不是还在报错，永远看按 F5 刷新之后的第一屏。**

</details>

## 6. 讲义勘误速查（本讲）

| 讲义原文 | 问题 | 正确写法 |
|---|---|---|
| `color="#6666"`（出现两处：外层 `span` 的 `style` 和 `el-icon` 的 `color`） | `#6666` 是 4 位十六进制，按 CSS Color 4 解析成 `#RGBA`，即 `rgba(102,102,102,0.4)`，图标和文字都会发淡。**它不是语法错误，浏览器不报任何警告**，最难自查 | `color="#666666"` 或简写 `color="#666"`。两层都要改，只改一层另一层照样淡 |
| "将下面代码放在合适的位置"（一、第 3 步，指 `app.use(ElementPlus, ...)`） | 表述含糊。`app.use` 用到了 `app` 变量，放在 `const app = createApp(App)` 之前会直接抛 `ReferenceError: Cannot access 'app' before initialization` | 明确写在 `const app = createApp(App)` **之后**、`app.mount('#app')` **之前** |
| 图注红字写"`app.component(组件名, 组件实例)`" | 措辞不准。第二个参数是**组件定义**（选项对象或 `setup` 函数），不是实例；实例是组件定义被渲染出来的结果 | 说成"`app.component(组件名, 组件定义)`"，或直接说"注册组件" |
| `<el-icon style="top: 4px">`（曾被误判为无效） | 经核 `node_modules/element-plus/theme-chalk/el-icon.css`，`.el-icon` 是 `position: relative`，`top` **生效**，用途是微调图标与文字的基线对齐 | **这条不是错，保留即可**（`03/讲义勘误_实训3.md` 已撤销该条） |
| `npm i element-plus -S` 里的 `-S` | 不算错，但在 npm 5 之后 `-S` 已是默认行为（本机 npm 11.13.0 实测：不写 `-S` 也进 `dependencies`）。真正要小心的是别误用 `-D` | 照写 `-S` 无害；关键是**别写成 `-D`** |
