## 0. 先建立地图：这个系统到底是什么

### 0.1 一句话

这是一个**前后端分离的员工信息管理系统**：

- 前端：Vue 3 + Element Plus，负责页面、表格、弹窗、分页；
- 后端：Spring Boot 3 + MyBatis，负责接收请求、写 SQL、返回 JSON；
- 数据库：MySQL 的 `xm-pro` 库，里面有一张 `employee` 表。

最终能完成：**分页查询、按姓名查询、新增、修改、删除**。

### 0.2 技术栈

| 层 | 技术 | 作用 |
|---|---|---|
| 页面 | Vue 3 | 数据绑定、组件化 |
| UI | Element Plus | 表格、按钮、弹窗、分页等现成组件 |
| 路由 | Vue Router | `/manage/employee` 对应员工管理页 |
| 请求 | axios | 浏览器发 HTTP 请求 |
| 后端 | Spring Boot 3 | 提供 REST 接口 |
| 持久层 | MyBatis | Java 方法 ↔ SQL |
| 分页 | PageHelper | 自动生成 `LIMIT` 和 `COUNT` |
| 数据库 | MySQL 8 | 存员工数据 |

### 0.3 三层架构图

```text
浏览器
  │  点击“查询/新增/编辑/删除”
  ▼
Employee.vue
  │  request.get/post/put/delete
  ▼
request.js（axios 实例，baseURL=http://localhost:8080）
  │  HTTP + JSON
  ▼
EmployeeController       ← 接收参数、返回 Result
  │
  ▼
EmployeeService          ← 业务逻辑、PageHelper 分页
  │
  ▼
EmployeeMapper           ← Java 方法
  │
  ▼
EmployeeMapper.xml / @Delete   ← 真正执行的 SQL
  │
  ▼
MySQL（xm-pro.employee）
```

一句话记住：**Controller 管入口，Service 管业务，Mapper 管 SQL，Vue 管展示。**

### 0.5 数据库表

```sql
CREATE TABLE `employee` (
  `id`          INT NOT NULL AUTO_INCREMENT,
  `name`        VARCHAR(255) DEFAULT NULL,   -- 姓名
  `sex`         VARCHAR(255) DEFAULT NULL,   -- 性别
  `no`          VARCHAR(255) DEFAULT NULL,   -- 工号
```

## 2. 后端：从 URL 到数据库

### 2.1 请求入口：EmployeeController

文件：`springboot/src/main/java/com/example/controller/EmployeeController.java`

```java
@RestController
@RequestMapping("/employee")
public class EmployeeController {

    @Resource
    private EmployeeService employeeService;

    @GetMapping("/selectPage")
    public Result selectPage(Employee employee,
                             @RequestParam(defaultValue = "1") Integer pageNum,
                             @RequestParam(defaultValue = "10") Integer pageSize) {
        PageInfo<Employee> pageInfo = employeeService.selectPage(employee, pageNum, pageSize);
        return Result.success(pageInfo);
    }
}
```

逐行理解：

- `@RestController`：这个类返回的是 JSON，不是页面。
- `@RequestMapping("/employee")`：类里所有接口都以 `/employee` 开头。
- `@GetMapping("/selectPage")`：最终地址是 `GET /employee/selectPage`。
- `Employee employee`：Spring 会拿 URL 上的 `?name=thc` 去匹配 `Employee` 的 `name` 属性。
- `@RequestParam(defaultValue = "1")`：URL 没传 `pageNum` 时默认第 1 页。
- `Result.success(pageInfo)`：统一包装成 `{code, msg, data}`。

### 2.2 统一返回：Result

文件：`common/Result.java`

```java
public class Result {
    private String code;
    private String msg;
    private Object data;

    public static Result success() { ... }
    public static Result success(Object data) { ... }
    public static Result error(String code, String msg) { ... }
}
```

为什么要有它？

- 前端只判断 `res.code === '200'`，不用关心 HTTP 细节；
- 所有接口返回格式一致，前端 `request.js` 好统一处理；
- 出错时也能返回 `{code:'500', msg:'...'}`。

### 2.3 实体：Employee

文件：`entity/Employee.java`

```java
public class Employee {
    private Integer id;
    private String name;
    private String sex;
    private String no;
    private Integer age;
    private String description;
    // getter/setter
}
```

它有三个身份：

1. 数据库一行记录的 Java 对象；
2. Controller 接收前端 JSON 的参数类型；
3. MyBatis 查询结果的映射类型（`resultType`）。

### 2.4 Service：业务层

文件：`service/EmployeeService.java`

```java
@Service
public class EmployeeService {

    @Resource
    private EmployeeMapper employeeMapper;

    public PageInfo<Employee> selectPage(Employee employee, Integer pageNum, Integer pageSize) {
        PageHelper.startPage(pageNum, pageSize);
        List<Employee> list = employeeMapper.selectAll(employee);
        return PageInfo.of(list);
    }
}
```

- `@Service`：告诉 Spring 这是一个业务类，创建对象并管理。
- `@Resource`：把 Mapper 注入进来。
- `PageHelper.startPage(...)`：只对**紧接着的下一句查询**生效。
- `PageInfo.of(list)`：把查询结果包装成包含 `total`、`list`、`pageNum` 等字段的分页对象。

### 2.5 Mapper：接口 + XML

文件：`mapper/EmployeeMapper.java`

```java
@Mapper
public interface EmployeeMapper {

    List<Employee> selectAll(Employee employee);

    @Select("SELECT * FROM employee WHERE id = #{id}")
    Employee selectById(Integer id);

    void insert(Employee employee);

    void updateById(Employee employee);

    @Delete("DELETE FROM `employee` WHERE id = #{id}")
    void deleteById(Integer id);
}
```

文件：`resources/mapper/EmployeeMapper.xml`

```xml
<select id="selectAll" resultType="com.example.entity.Employee">
    SELECT * FROM employee
    <where>
        <if test="name != null and name != ''">
            employee.name LIKE CONCAT('%', #{name}, '%')
        </if>
    </where>
    ORDER BY employee.id DESC
</select>

<insert id="insert" useGeneratedKeys="true" keyProperty="id">
    INSERT INTO employee (name, sex, no, age, description)
    VALUES (#{name}, #{sex}, #{no}, #{age}, #{description})
</insert>

<update id="updateById">
    UPDATE employee
    SET name = #{name}, sex = #{sex}, no = #{no}, age = #{age}, description = #{description}
    WHERE id = #{id}
</update>
```

重点：

- `id="selectAll"` 必须和接口方法名 `selectAll` 完全一致；
- `resultType` 写实体类的全限定名；
- `#{name}` 是预编译参数，能防止 SQL 注入；不要用 `${name}`；
- 简单的删除 SQL 可以直接用 `@Delete` 注解，不必再写 XML；
- **同一个方法不能同时在注解和 XML 里各写一份**，否则 MyBatis 会报重复映射。

### 2.6 application.yml

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/xm-pro?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai
    username: root
    password: 123456
    driver-class-name: com.mysql.cj.jdbc.Driver

mybatis:
  mapper-locations: classpath:mapper/*.xml
  configuration:
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
    map-underscore-to-camel-case: true
```

- `mapper-locations`：告诉 MyBatis 去哪里找 XML；
- `log-impl`：控制台打印 SQL，调试非常有用；
- `map-underscore-to-camel-case`：数据库 `description` 这种下划线字段能映射到 Java 驼峰属性。

### 2.7 一条 selectPage 请求的完整链路

以 `GET /employee/selectPage?pageNum=1&pageSize=10&name=thc` 为例：

1. 浏览器发出请求；
2. `CorsConfig` 先处理跨域；
3. Spring MVC 找到 `EmployeeController.selectPage`；
4. 把 `name=thc` 绑定到 `Employee.name`；
5. `pageNum=1`、`pageSize=10` 绑定到两个 `@RequestParam`；
6. Service 调用 `PageHelper.startPage(1, 10)`；
7. Service 调用 `employeeMapper.selectAll(employee)`；
8. MyBatis 执行 XML 里的 SQL，`<if>` 判断 `name` 有值，拼上 `LIKE '%thc%'`；
9. PageHelper 自动补 `LIMIT` 并执行 `COUNT`；
10. 返回 `PageInfo`；
11. Controller 用 `Result.success` 包装；
12. Jackson 转成 JSON；
13. 前端 axios 拿到 `res.data`，赋值给表格。

### 3.5 request.js

```js
const request = axios.create({
  baseURL: 'http://localhost:8080',
  timeout: 30000
})

request.interceptors.request.use(config => {
  config.headers['Content-Type'] = 'application/json;charset=utf-8'
  return config
})

request.interceptors.response.use(
  response => {
    let res = response.data
    if (typeof res === 'string') {
      res = res ? JSON.parse(res) : res
    }
    return res
  },
  error => {
    const status = error.response ? error.response.status : null
    if (status === 404) ElMessage.error('未找到请求接口')
    else if (status === 500) ElMessage.error('系统异常，请查看后端控制台报错')
    else if (status === null) ElMessage.error('无法连接后端服务，请检查后端是否启动或跨域是否配置成功')
    else console.error(error.message)
    return Promise.reject(error)
  }
)
```

- `baseURL`：之后写 `/employee/selectAll`，实际请求 `http://localhost:8080/employee/selectAll`；
- 请求拦截器：统一加 `Content-Type`；
- 响应拦截器：直接返回 `response.data`，所以页面里 `res` 就是 `{code,msg,data}`；
- 错误处理里先判断 `error.response`，避免跨域/断网时再抛 `Cannot read properties of undefined`。

### 3.6 Employee.vue 的数据和 load

```js
const data = reactive({
  name: null,
  tableData: [],
  pageNum: 1,
  pageSize: 10,
  total: 0,
  formVisible: false,
  form: {}
})

const load = () => {
  request.get('/employee/selectPage', {
    params: {
      pageNum: data.pageNum,
      pageSize: data.pageSize,
      name: data.name
    }
  }).then(res => {
    data.tableData = res.data.list || []
    data.total = res.data.total || 0
  })
}

load()
```

- `reactive`：让对象变成响应式，改值页面自动更新；
- `data.tableData`：表格数据；
- `data.total`：分页总数；
- `load()` 在页面加载时调用一次。

### 3.7 页面加载时序

1. 进入 `/manage/employee`；
2. `Manage.vue` 渲染布局和 `<router-view>`；
3. `Employee.vue` 创建，执行 `load()`；
4. axios 发 `GET /employee/selectPage`；
5. 后端返回 `PageInfo`；
6. `data.tableData` 和 `data.total` 被赋值；
7. `el-table` 自动渲染行，`el-pagination` 显示总数。

## 4. 分页查询

### 4.1 需求

- 每页显示 10 条；
- 可以切换页码、每页条数；
- 显示总条数；
- 数据从后端来，不是前端假数据。

### 4.2 后端

Controller：

```java
@GetMapping("/selectPage")
public Result selectPage(Employee employee,
                         @RequestParam(defaultValue = "1") Integer pageNum,
                         @RequestParam(defaultValue = "10") Integer pageSize) {
    PageInfo<Employee> pageInfo = employeeService.selectPage(employee, pageNum, pageSize);
    return Result.success(pageInfo);
}
```

Service：

```java
PageHelper.startPage(pageNum, pageSize);
List<Employee> list = employeeMapper.selectAll(employee);
return PageInfo.of(list);
```

PageHelper 做的事：

- 在 SQL 后面自动加 `LIMIT (pageNum-1)*pageSize, pageSize`；
- 自动执行一条 `SELECT COUNT(0)` 得到总数；
- 把结果封装成 `PageInfo`。

### 4.3 前端

```html
<el-table :data="data.tableData" stripe>
  <el-table-column label="姓名" prop="name" />
  <el-table-column label="性别" prop="sex" />
  <el-table-column label="工号" prop="no" />
  <el-table-column label="年龄" prop="age" />
  <el-table-column label="个人介绍" prop="description" />
</el-table>

<el-pagination
    v-model:current-page="data.pageNum"
    v-model:page-size="data.pageSize"
    :page-sizes="[5, 10, 15, 20]"
    :total="data.total"
    layout="total, sizes, prev, pager, next, jumper"
    @current-change="load"
    @size-change="handleSizeChange"
/>
```

`@current-change="load"`：点页码时重新请求。
`@size-change="handleSizeChange"`：改每页条数时，把页码重置到第 1 页再请求。

### 4.4 验收

- 页面显示「共 X 条」；
- 点第 2 页，表格内容变化；
- 改每页条数，表格行数变化；
- Network 里能看到 `selectPage?pageNum=...&pageSize=...`。

### 4.5 常见坑

| 现象 | 原因 |
|---|---|
| 表格没数据 | `res.data.list` 写错，或后端返回的不是 `PageInfo` |
| 总数为 0 | `res.data.total` 没取到 |
| 点页码没反应 | 忘记绑定 `@current-change` |
| 分页不生效 | `PageHelper.startPage` 后面没有紧接查询，或 Mapper 方法不是被拦截的查询 |

## 5. 姓名条件查询

### 5.1 需求

输入姓名关键字，点查询，只显示姓名包含该关键字的记录；点重置清空条件。

### 5.2 前端

```html
<el-input v-model="data.name" placeholder="请输入名称查询" clearable @keyup.enter="load" />
<el-button type="primary" @click="load">查 询</el-button>
<el-button type="warning" @click="reset">重 置</el-button>
```

`load()` 里已经把 `name` 放进 params：

```js
params: {
  pageNum: data.pageNum,
  pageSize: data.pageSize,
  name: data.name
}
```

重置：

```js
const reset = () => {
  data.name = null
  data.pageNum = 1
  load()
}
```

### 5.3 后端接收

Controller 的 `Employee employee` 参数会自动接收 `?name=thc`。

例如请求：

```text
GET /employee/selectPage?pageNum=1&pageSize=10&name=thc
```

Spring 会调用 `employee.setName("thc")`。

### 5.4 XML 动态 SQL

```xml
<select id="selectAll" resultType="com.example.entity.Employee">
    SELECT * FROM employee
    <where>
        <if test="name != null and name != ''">
            employee.name LIKE CONCAT('%', #{name}, '%')
        </if>
    </where>
    ORDER BY employee.id DESC
</select>
```

- `<where>`：如果里面没有条件，就不生成 `WHERE`；如果有条件，会自动去掉开头多余的 `AND`。
- `<if test="...">`：条件成立才拼接。
- `CONCAT('%', #{name}, '%')`：模糊查询，等价于 `LIKE '%thc%'`。

### 5.5 验收

1. 输入 `thc`，点查询；
2. Network 里请求参数应有 `name=thc`；
3. 表格只剩姓名包含 `thc` 的记录；
4. 点重置，输入框清空，表格恢复全部。

### 5.6 常见坑

| 现象 | 原因 |
|---|---|
| 查询没效果 | 前端没传 `name`，或后端参数没绑定 |
| SQL 报错 | `<if>` 里用了 `${}`，或 `name` 为空时拼出 `WHERE AND` |
| 中文查不到 | 数据库/连接字符集不是 utf8mb4 |

## 7. 修改记录

### 7.1 后端

Controller：

```java
@PutMapping("/update")
public Result update(@RequestBody Employee employee) {
    employeeService.update(employee);
    return Result.success();
}
```

Service：

```java
public void update(Employee employee) {
    employeeMapper.updateById(employee);
}
```

Mapper：

```java
void updateById(Employee employee);
```

XML：

```xml
<update id="updateById">
    UPDATE employee
    SET name = #{name},
        sex = #{sex},
        no = #{no},
        age = #{age},
        description = #{description}
    WHERE id = #{id}
</update>
```

`WHERE id = #{id}` 是关键，没有它会把整张表都改了。

### 7.2 前端：操作列

```html
<el-table-column label="操作" width="160">
  <template #default="scope">
    <el-button type="primary" @click="handleUpdate(scope.row)">编辑</el-button>
    <el-button type="danger" @click="del(scope.row.id)">删除</el-button>
  </template>
</el-table-column>
```

- `#default="scope"`：Element Plus 表格的作用域插槽；
- `scope.row`：当前这一行的完整数据对象，例如 `{id:3, name:'lisi', ...}`。

### 7.3 打开弹窗前深拷贝

```js
const handleUpdate = (row) => {
  data.form = JSON.parse(JSON.stringify(row))
  data.formVisible = true
}
```

为什么不能直接 `data.form = row`？

因为 `row` 是表格里的对象，直接赋值会让弹窗和表格共享同一个对象。你在弹窗里改值，表格会立刻跟着变；点“取消”也回不去。深拷贝会复制一份新对象，只有点“保存”才写回后端。

### 7.4 保存时区分新增/修改

```js
const save = () => {
  data.form.id ? update() : add()
}
```

- 新增：`data.form` 是 `{}`，没有 `id` → 调 `add()`；
- 编辑：`data.form` 是从行数据深拷贝来的，有 `id` → 调 `update()`。

### 7.5 验收

1. 点某一行的“编辑”；
2. 弹窗里显示该行原数据；
3. 修改姓名，点保存；
4. 提示“操作成功”，表格该行更新；
5. 刷新页面，修改还在。

## 8. 删除记录

### 8.1 后端

Controller：

```java
@DeleteMapping({"/deleteById/{id}", "/delete/{id}"})
public Result deleteById(@PathVariable Integer id) {
    employeeService.deleteById(id);
    return Result.success();
}
```

- `@DeleteMapping`：处理 DELETE 请求；
- `@PathVariable`：从 URL 路径里取 `{id}`；
- 访问 `/employee/deleteById/3` 时，`id` 就是 `3`。

Service：

```java
public void deleteById(Integer id) {
    employeeMapper.deleteById(id);
}
```

Mapper：

```java
@Delete("DELETE FROM `employee` WHERE id = #{id}")
void deleteById(Integer id);
```

这里用的是 **`@Delete` 注解**，所以 `EmployeeMapper.xml` 里不再写 `<delete>`。如果两边都写，会报重复映射。

### 8.2 前端

```html
<el-button type="danger" @click="del(scope.row.id)">删除</el-button>
```

```js
const del = (id) => {
  ElMessageBox.confirm('删除数据后无法恢复，您确认删除吗？', '删除确认', { type: 'warning' })
    .then(() => {
      request.delete('/employee/deleteById/' + id).then(res => {
        if (res.code === '200') {
          ElMessage.success('操作成功')
          load()
        } else {
          ElMessage.error(res.msg)
        }
      })
    })
    .catch(() => {})
}
```

- `ElMessageBox.confirm`：弹出确认框；
- `.catch(() => {})`：用户点“取消”时不做任何事，也不报错；
- 删除成功后 `load()` 重新加载表格。

### 8.3 验收

1. 点某一行的“删除”；
2. 弹出“删除确认”；
3. 点“确定”，提示“操作成功”，该行消失；
4. 总条数 -1；
5. 刷新页面，数据确实被删了。

## 9. 调试手册：报错怎么查

### 9.1 CORS 跨域报错

现象：

```text
Access to XMLHttpRequest at 'http://localhost:8080/employee/selectAll'
from origin 'http://localhost:5173' has been blocked by CORS policy:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

原因：前端 5173、后端 8080，浏览器同源策略拦截。

解决：

1. 后端有 `CorsConfig`：

```java
@Configuration
public class CorsConfig {
    @Bean
    public CorsFilter corsFilter() {
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        CorsConfiguration config = new CorsConfiguration();
        config.addAllowedOrigin("*");
        config.addAllowedHeader("*");
        config.addAllowedMethod("*");
        source.registerCorsConfiguration("/**", config);
        return new CorsFilter(source);
    }
}
```

2. **改完必须重启后端**。只保存文件不重启，等于没加。
3. 浏览器 Network 里看响应头有没有 `Access-Control-Allow-Origin: *`。

### 9.2 `error.response` 是 undefined

现象：

```text
TypeError: Cannot read properties of undefined (reading 'status')
```

原因：跨域、后端没启动、断网时，axios 的 `error.response` 不存在。

解决：`request.js` 里先判断：

```js
const status = error.response ? error.response.status : null
```

### 9.3 404

- 路径写错：前端 `/employee/add`，后端却是 `/employee/insert`；
- 方法写错：前端 `post`，后端却是 `@GetMapping`；
- 参数写错：`@PathVariable` 的 `{id}` 和 URL 不匹配。

看浏览器 Network 的 Request URL 和后端 Controller 的 `@RequestMapping` 是否一致。

### 9.4 500

- SQL 语法错误；
- 表名/字段名写错；
- Mapper XML 的 `id` 和方法名不一致；
- 同一个方法在注解和 XML 里重复定义；
- `resultType` 写错；
- 数据库没启动/密码错。

看后端控制台，MyBatis 会打印 `Preparing:` 和 `Parameters:`，对照 SQL。

### 9.5 表格没数据

在浏览器 Network 看 `selectPage` 的 Response：

```json
{"code":"200","msg":"请求成功","data":{"total":6,"list":[...]}}
```

然后检查前端：

```js
data.tableData = res.data.list
data.total = res.data.total
```

如果后端返回 `records` 而不是 `list`，要改成对应字段。

### 9.6 中文乱码

- 数据库/表用 `utf8mb4`；
- JDBC URL 带 `characterEncoding=utf-8`；
- 后端文件用 UTF-8；
- 前端页面 `<meta charset="UTF-8">`。

### 9.7 端口占用

```powershell
netstat -ano | findstr :8080
netstat -ano | findstr :5173
```

找到 PID 后结束进程，或改端口。

### 9.8 Vite 监听 EBUSY

IDEA 保存文件时会产生临时目录，Vite 可能报：

```text
Error: EBUSY: resource busy or locked, watch '...tmpdir...'
```

在 `vite.config.js` 里忽略临时文件：

```js
server: {
  watch: {
    ignored: ['**/*.tmpdir/**', '**/*.tmp']
  }
}
```

<details>
<summary>点击展开答案</summary>

1. `@RestController` = `@Controller` + `@ResponseBody`，方法返回 JSON；`@Controller` 默认返回页面。
2. `/employee/selectPage`。
3. `@RequestParam` 从查询字符串/表单取；`@PathVariable` 从 URL 路径取。
4. 把请求体里的 JSON 反序列化成 Java 对象。
5. 统一前后端返回格式，前端只判断 `code`，不用关心 HTTP 细节。

7. `#{}` 是预编译参数，防 SQL 注入；`${}` 是字符串拼接，不安全。
8. `<where>` 自动处理 `WHERE` 和多余的 `AND`；`<if>` 按条件决定是否拼接 SQL。
9. 插入后把数据库自增主键回填到 Java 对象的 `id` 属性。
10. 简单 SQL 用注解更简洁；但同一个方法不能同时在注解和 XML 里定义。

12. `total` 是总记录数，`list` 是当前页数据。
13. 返回 `response.data`，也就是后端 JSON；所以 `res` 是 `{code,msg,data}`。
14. 表格当前行的完整数据对象。
15. 深拷贝，避免弹窗改值直接影响表格行；取消时能恢复。
16. 有 `id` 说明是编辑，没有 `id` 说明是新增。

## 13. 讲义对照与差异

| 讲义写法 | 当前项目写法 | 说明 |
|---|---|---|
| `@PostMapping("/add")` | `@PostMapping({"/add", "/insert"})` | `/add` 与讲义一致，`/insert` 兼容旧接口 |
| `@DeleteMapping("/deleteById/{id}")` | `@DeleteMapping({"/deleteById/{id}", "/delete/{id}"})` | 同上 |
| `employeeMapper.updateById(employee)` | 一致 | Mapper 方法名按讲义 |
| `@Delete("delete from \`employee\` where id = #{id}")` | 一致 | 删除 SQL 用注解 |
| `selectAll(Employee employee)` | 一致 | 条件查询靠实体参数 |
| `selectPage(Employee employee, pageNum, pageSize)` | 一致 | PageHelper 分页 |
| 讲义前端 `load()` 传 `name` | 一致 | 另加 `clearable`、回车查询、条数切换处理 |

> 说明：讲义里的 `@PostMapping("/add")`、`@DeleteMapping("/deleteById/{id}")` 是标准写法；项目里保留 `/insert`、`/delete/{id}` 是为了兼容之前实训8的旧接口。你写报告时以 `/add`、`/deleteById/{id}` 为主即可。
