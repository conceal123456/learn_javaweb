## 一、严重问题

### 勘误 1：路由守卫会把无 `meta` 页面的标签标题设成字符串 `"undefined"`（严重，已实测复现）

**【讲义原文】** 「五、路由守卫 → 3. 代码和效果如下」（docx 第 107–128 段）：

```js
import { createRouter, createWebHistory } from 'vue-router'
const router = createRouter({
    history: createWebHistory(import.meta.env.BASE_URL),
    routes: [
        { path: '/', redirect:'/home' },
        { path: '/home', name: 'home', component: () => import('../views/Home.vue') },
        { path: '/test', name: 'test', component: () => import('../views/Test.vue') },
        { path: '/manage', name: 'manage', meta:{title:'后台管理'}, component: () => import('../views/Manage.vue'),children:[
                { path: 'user', name: 'user',meta:{title:'用户列表'}, component: () => import('../views/User.vue') },
                { path: 'goods', name: 'goods', meta:{title:'商品列表'},component: () => import('../views/Goods.vue') },
                { path: 'orders', name: 'orders',meta:{title:'订单列表'}, component: () => import('../views/Orders.vue') },
            ] }    
      ]
})
// from：将要进行跳转的当前route对象 (跳转前的一些操作)
// to: 跳转后route对象 (跳转后的一些操作)
// next(): 调用该方法后, 才能进入下一个钩子
router.beforeEach((to, from, next) => {
    document.title = to.meta.title;
    next()
})
export default router
```

**【问题】** 只有 `/manage` 及其三个子路由配了 `meta.title`；`/home`、`/test`、`/` 都没有。访问这些页面时 `to.meta` 是空对象 `{}`，`to.meta.title` 为 `undefined`，赋值给 `document.title` 会被转成**字符串 `"undefined"`**——浏览器标签页上真的显示 `undefined` 这个词，而且**不报任何错**。

**【实测证据 / 原理】**
- 讲义原版守卫 + 访问 `http://localhost:5185/home`：`document.title === "undefined"`，`typeof document.title === "string"`（不是 undefined 值，是字面量字符串）。截图：`.extract/verify/shots/lab5_home_title_undefined.png`（页面上的 `【undefined】` 是仓库 Home.vue 把 `document.title` 回显出来，便于肉眼确认）。
- 访问 `http://localhost:5185/`：先重定向到 `/home`，标题同样是 `"undefined"`。
- 访问 `/manage/goods`（有 meta）：`document.title === "商品列表"` ✅，说明守卫本身工作正常，只差兜底。
- 原理：`document.title` 的 setter 接收 DOMString，`undefined` 会被 `String(undefined)` 转成 `"undefined"`；对比 `document.title = undefined` 在不同浏览器历史上有差异，**现代 Chrome/Edge 都是写入字符串 `"undefined"`**（本次实测就是这两个内核）。

**【正确写法】**

```js
router.beforeEach((to, from, next) => {
  document.title = to.meta.title || '默认标题'   // 兜底
  next()
})
// 或者去掉第三个参数、用返回值风格（见勘误 7）：
// router.beforeEach((to) => { document.title = to.meta.title || '默认标题' })
```

**【影响程度】** ★★★ 严重。这是本讲唯一"跑起来就能看见、且答辩截图一定会被截到"的 bug；标签页显示 `undefined` 很影响观感，也容易让学生误以为路由配置整体错了。

### 勘误 2：`el-button` / Element Plus 是隐藏前置依赖，讲义一个字没提（一般，已实测）

**【讲义原文】** 「三、路由跳转 → 1. 编程式的路由」配图（docx 第 39 段配图）里，`Home.vue` 的模板是：

```html
<el-button type="primary" @click="$router.push('/test')">push跳转页面</el-button>
<el-button type="primary" @click="$router.replace('/test')">replace跳转页面</el-button>
```

全文（133 段正文 + 23 张图）**没有任何一处**出现 "Element"/"元素"/"el-button 从哪来"/"先装 Element Plus" 的说明，也没有说"本讲在你实训3/4 的工程上继续"。

**【问题】** `el-button` 来自 Element Plus，必须在 `main.js` 里 `app.use(ElementPlus)` 且引入 CSS 才有效果；这来自**实训3（Element Plus 框架）**，不是 Vue 自带的。学生若从"只做过实训1/2 的工程"起手，页面不会报错崩溃，但按钮会**退化成没有任何样式的裸标签**，控制台一片 `Failed to resolve component`。

**【实测证据 / 原理】** 实验工程 `.extract/verify/_lab5b/vue-router`：`main.js` 只 `app.use(router)`、**不注册 Element Plus**，访问 `/home`：

| 观测项 | 结果 |
|---|---|
| 页面里的按钮标签 | `<el-button type="primary">push 跳测试页</el-button>`（自定义元素原样输出） |
| `document.querySelectorAll('el-button').length` | **5** |
| `document.querySelectorAll('.el-button').length`（有样式的） | **0** |
| 控制台 | `[Vue warn]: Failed to resolve component: el-button`（每个实例一条，共 2 类） |
| 点击是否还能跳转 | **能**（`@click` 事件监听仍绑在该自定义元素上，点击后 `location.pathname` 变成 `/test`） |

截图：`.extract/verify/shots/lab5b_no_elementplus.png`。也就是说：**"功能还能点、样式全丢、控制台一堆红黄"** —— 不是"完全不生效"，别把现象说满。

仓库工程的做法（`src/main.js:6-19`）是补上 `element-plus` + `dist/index.css` + 中文 locale，并**循环全局注册所有图标**：

```js
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
import zhCn from 'element-plus/es/locale/lang/zh-cn'
import * as ElementPlusIconsVue from '@element-plus/icons-vue'
app.use(ElementPlus, { locale: zhCn })
for (const [key, component] of Object.entries(ElementPlusIconsVue)) app.component(key, component)
```

**【正确写法】** 讲义开头加一句前置说明："本讲在实训3/4 的工程上继续做，`main.js` 里已经 `app.use(ElementPlus)`；如果你是从实训1 的工程起手，先按实训3 装上 Element Plus。"

**【影响程度】** ★★ 一般。不是语法错误，但会让"照着讲义抄却跑不出同样界面"的学生卡在环境上，且现象（按钮没样式）与路由知识无关，容易被误诊。

## 三、提示 / 措辞 / 覆盖面（上一版 5 条维持原判）

### 勘误 3：对象形式传参示例里 `id` 前后对不上（2 vs 123）（提示）

**【讲义原文】** 「三、3. 路由传参」（docx 第 68–73 段）：

```html
<div>
     <el-button type="primary" @click="$router.push({ path: '/test', query: { id: 2, name: '手机' } })">路由传参</el-button>
   </div>
```
紧接着第 73 段：「这个是以对象形式配置要传递的数据，跳转后但浏览器不会传递 JS 对象，**会自动转成 URL 字符串：/test?id=123&name=手机**」

同一张配图（第 74 段）的说明表里又写的是 `{ path: '/test', query: { id: 2, name: '手机' } }`。

**【问题】** 代码里 `id` 是 **2**，说明文字里的 URL 却是 **`id=123`**（那是上一段"字符串形式"例子的值）。三处（代码/说明/表格）只有说明文字是 123。

**【实测证据 / 原理】** 点"对象形式传参"按钮后的真实地址：

```
http://localhost:5185/test?id=2&name=%E6%89%8B%E6%9C%BA
decodeURIComponent → http://localhost:5185/test?id=2&name=手机
```

目标页渲染：`id = 2 ，name = 手机`（`id=123` 不出现）。截图：`.extract/verify/shots/lab5_query_object.png`

**【正确写法】** 把第 73 段的 `/test?id=123&name=手机` 改成 `/test?id=2&name=手机`（或把代码里的 2 改成 123，两处统一）。

**【影响程度】** ★ 提示。会让学生在对照地址栏时怀疑对象传参"被改了值"。

### 勘误 4：组件内取参，`router.currentRoute.value.query` 能用但不如 `useRoute()`（提示，风格建议）

**【讲义原文】** 「三、3. 路由传参 → 参数获取」（docx 第 55、64–66 段）：

> 通过 `router.currentRoute.value.query.id` 获取 id 的值。
> `id: router.currentRoute.value.query.id,`
> `name: router.currentRoute.value.query.name,`

**【问题】** 写法**能用**（`router.currentRoute` 是 `shallowRef`，在模板/计算属性里读 `.value` 是响应式的），但更常见、更简洁的是 `const route = useRoute(); route.query.id`。讲义只教了前者，学生容易把它写成"只在 setup 里读一次"，导致切换页面后取到的还是旧值。

**【实测证据 / 原理】** 仓库 `Test.vue:25` 用 `computed(() => router.currentRoute.value.query)` 包装，实测切换 query 后能正常更新；直接在 setup 里 `const id = router.currentRoute.value.query.id` 取值则只取一次（非响应式）。

**【正确写法】**

```js
import { useRoute } from 'vue-router'
const route = useRoute()
// 模板里：{{ route.query.id }}  ← 响应式，切换路由自动更新
```

**【影响程度】** ★ 提示（非错误）。

### 勘误 5："还有一种路由传参的方式"表述不完整（提示）

**【讲义原文】** docx 第 68 段：「注意：还有一种路由传参的方式：」+ 第 70 段的对象写法 `$router.push({ path:'/test', query:{...} })`。

**【问题】** 严格说它**仍然是 query 传参**，只是把"字符串拼查询串"换成"对象写查询参数"，属于同一种传参的两种写法。真正**没被覆盖**的是 **params 动态路由传参**（`path: '/test/:id'` + `route.params.id`）。讲义没有提到 params。

**【正确写法】** 补一句对比："`query` 参数会出现在地址栏 `?` 后面；`params` 需要路由路径带 `:id` 占位符，不出现在 `?` 后。"（不必当成错误改，属覆盖面补充）

**【影响程度】** ★ 提示。

### 勘误 6："所有页面代码一开始就一次性加载完了"与懒加载相冲突（提示）

**【讲义原文】** 「一、路由的定义 → 通俗的解释（主打一个用户体验好）」（docx 第 13 段）：

> 我们平时普通网站，点菜单跳页面，浏览器会刷新、转圈，去服务器重新下载一整个新网页。但单页网站不一样，**所有页面代码一开始就一次性加载完了**。

**【问题】** 这句在"通俗解释"里，核心意思（换页不整页刷新、不向服务器重新取整页）是对的；但本讲义每个路由都用 `() => import()` **懒加载**，子页面是**访问时才**拉取的，"一开始就全加载完"与自己的代码相矛盾。

**【实测证据 / 原理】** 用 playwright 监听 `src/views/*.vue` 的模块请求：
- 首屏 `http://localhost:5185/home`：只请求了 `/src/views/Home.vue`；
- 导航到 `/test` 之后：才出现 `/src/views/Test.vue`。

**【正确写法】** 改成："单页应用的页面是组件，切换页面不会向服务器重新请求整页 HTML；**本项目页面还做了懒加载，每个页面组件第一次访问时才下载**。"

**【影响程度】** ★ 提示。概念表述，不补会让学生以为"懒加载没用"。

### 勘误 7：`next()` 在 vue-router 5 已废弃——功能仍可用，只是 dev 模式每次导航告警（提示，本次新增实测）

**【讲义原文】** docx 第 121–127 段注释与代码：

```js
// next(): 调用该方法后, 才能进入下一个钩子
router.beforeEach((to, from, next) => {
    document.title = to.meta.title;
    next()
})
```

**【问题】** 讲义按 **vue-router 4** 的三参数写法讲守卫。本工程实际装的是 **vue-router 5.3.1**（`实训5_Vue-Router实现路由跳转/工程/vue-router/node_modules/vue-router/package.json` → `"version": "5.3.1"`），`next()` 已被标记为 **deprecated**：**功能完全正常**（导航照旧完成），但开发模式每次导航都打印一条告警。讲义（以及实验报告的"问题与解决"栏）都不知道这件事。

**【实测证据 / 原理】**
- 浏览器控制台实测（每次导航一条）：

```
[VUE_ROUTER_R0025] The `next()` callback in navigation guards is deprecated.
├▶ fix: Return the value instead: `next()` becomes `return`, `next(false)` becomes `return false`,
│        `next("/path")` becomes `return "/path"`.
╰▶ see: https://router.vuejs.org/guide/advanced/navigation-guards.html#Optional-third-argument-next
```

- 源码依据：`node_modules/vue-router/dist/devtools-CN5uWJaH.js:560` 在 dev 分支里把 `next` 包成 `withDeprecationWarning(canOnlyBeCalledOnce(next, to, from))`，`withDeprecationWarning` 首次调用即触发 `VUE_ROUTER_R0025`（`useApi-BPuI6ZR9.js:231-235` 是这句文案）；
- **只在 dev 模式告警**：仓库已构建的 `dist/assets/*.js` 里搜不到这段文案，说明被 `process.env.NODE_ENV !== "production"` 剔除；
- 顺带一个坑（实测）：守卫声明了三个参数却**不调用** `next()`，导航会**永远挂住**（Promise 不 resolve、页面不切换、控制台不报错），这是比废弃更危险的情况。

**【正确写法】**

```js
router.beforeEach((to) => {
  document.title = to.meta.title || '默认标题'
  // 不返回值 = 放行；返回 false 或路径字符串 = 拦截/重定向
})
```

**【影响程度】** ★ 提示。不影响运行，但"每次导航一条废弃告警"会让学生以为自己的代码写错了。

### 勘误 8：`meta` 的定义写成了"路由参数"（提示，上一版第 6 条）

**【讲义原文】** 「五、路由守卫 → 2. 核心原理」（docx 第 102 段）：

> 在 routes 路由元信息 meta （**meta：额外补充路由参数的对象**）中定义 title 字段，标记当前页面标题

**【问题】** `meta` 是路由记录上的**自定义元信息**（title、权限标记、是否缓存等），不是"路由参数"。路由参数指 `params` / `query`。这个措辞会把两个概念混在一起，学生后面学 `params/query` 时会乱。

**【正确写法】** 改成"meta 是路由记录的**自定义附加信息**（元信息），通常放 title、权限标记等"。

**【影响程度】** ★ 提示（措辞）。

### 勘误 9：第 11 段"Vue 是专用的官方导航工具"主语写错（提示）

**【讲义原文】** 「一、路由的定义 → 通俗的解释」（docx 第 11 段）：

> 1. **Vue 是专用的官方导航工具**，不用自己写跳转逻辑，直接用它管理页面切换。

**【问题】** 主语写错了，这句描述的是 **Vue Router**，不是 Vue 本身。前一段（第 7 段）才刚说"Vue Router 是 Vue 官方的客户端路由解决方案"，两段自相矛盾。

**【正确写法】** "**Vue Router** 是 Vue 官方的路由工具，不用自己写跳转逻辑……"

**【影响程度】** ★ 提示。概念混淆，不致命。
