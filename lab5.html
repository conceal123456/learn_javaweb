2. 知识点精讲

2.1

客户端路由与 SPA：点菜单为什么不刷新页面

①讲义要点

讲义"一、路由的定义"第 1~3 条：Vue Router 是 Vue 官方的客户端路由方案，"将浏览器的 URL 和用户看到的内容绑定起来……URL 会随之更新，但页面不需要从服务器重新加载"。通俗解释里说：普通网站点菜单会"刷新、转圈，去服务器重新下载一整个新网页"，单页网站则"所有页面代码一开始就一次性加载完了"。

②核心讲解

浏览器是一台电视，URL 是频道号。传统网站换台要换一台新电视（整页 HTML 重新下载：白屏、转圈、表单内容全丢）；SPA 是同一台电视换台。技术上就一句：第一次把 HTML 和 JS 下载完，之后改地址栏靠 history.pushState()——它只改地址栏，不发网络请求。 顺带给讲义那句"一次性加载完"打补丁：本工程每条路由都用了懒加载（2.4），启动时只加载入口那份代码，Test.vue 是大家第一次点进去才下载的。

③示例演示

打开 http://localhost:5173/home，F12 → Console，粘贴运行：

js5 行
1 2 3 4 5
console.log('① 现在的地址：', location.href)
history.pushState({}, '', '/test')                 // 只改地址栏，不发请求
console.log('② pushState 之后：', location.href)    // 已经变成 /test
// ③ 看页面：内容还是 Home；看 Network：一条新请求都没有
// ④ 按浏览器后退：地址变回 /home，页面内容依然没变
④代码解读
  • location.href 是完整地址，location.pathname 只有路径；Vue Router 匹配路由表看的就是路径加查询串。
  • history.pushState(state, title, url)：state 是跟着这条历史记录一起存的数据（Vue Router 用它存内部状态，刷新后能从 history.state 读回）；title 所有浏览器都忽略（传空串）；url 是要显示在地址栏的新地址。
  • pushState() 不发请求、不加载页面、也不触发 popstate——它只做两件事：改地址栏、往历史记录压一条。
  • history.back() 等价于点浏览器后退按钮；popstate 只在"历史记录指针移动"时触发，所以是 back() 触发的它。
  • 只有地址栏敲 URL、按 F5、点原生 <a href> 这三种情况浏览器才真的请求服务器——这就是 SPA 部署后刷新子页面容易 404 的根源。
⑤工程对照
  • 实训5_Vue-Router实现路由跳转/工程/vue-router/src/App.vue:2 —— 整个文件只有 <RouterView />，它就是那块"屏幕"：URL 匹配到谁就往这个洞里塞谁。
  • 实训5_Vue-Router实现路由跳转/工程/vue-router/src/router/index.js:4 —— createWebHistory(import.meta.env.BASE_URL)，选中的就是 pushState 这套机制。
⑥易错提醒
  • 点链接整页闪一下、Home.vue 里填的字没了 → 写的是原生 <a href="/test"> 或 location.href= → 页面内跳转一律用 <RouterLink> / router.push()。
  • 部署后刷新子页面 404（本地不会）→ /manage/user 在服务器上没有对应文件 → 服务器配 history fallback（Vite dev server 已配好，所以本地感觉不到）。
⑦课堂思考
展开解析

为什么按 F5 之后"不刷新"就失效了？

F5 是浏览器级的"重新加载当前 URL"，会真的向服务器发请求。pushState 那套只在"大家已经站在页面上、由 JS 改地址"时成立；本地没事，是因为 Vite 对任何路径都返回同一份 index.html。

2.2

URL 与组件的映射表

①讲义要点

通俗解释第 3 点原话："大家提前写一份对照表：网址 /home → 显示首页组件，网址 /mine → 显示个人中心组件。Vue Router 会盯着地址栏，网址一变，就对照这份表，把对应的组件放到页面上展示出来。"

②核心讲解

这张表就是大家手机里的通讯录——名字（URL）→ 号码（组件），大家拨号（改地址栏），它去查表。背后是一条重要约定："当前在哪一页"永远以地址栏为准，不是大家代码里的某个变量，因为地址栏是用户唯一能复制、收藏、发群里、按 F5 还能回来的东西。

③示例演示

表本身就是 实训5_Vue-Router实现路由跳转/工程/vue-router/src/router/index.js:5-14 的 routes 数组：

  { path: '/manage', name: 'manage', meta: { title: '后台管理' }, component: () => import('../views/Manage.vue'), children: [
    { path: 'user', name: 'user', meta: { title: '用户列表' }, component: () => import('../views/User.vue') },

④代码解读
  • path 是主键，从上往下匹配、先命中先用；同一个 path 写两条：先写的赢，且不报错（本机实测）。
  • name 也要求唯一，重复更阴：实测后写的赢、控制台一句警告都没有，会莫名跳到别的页面。
  • component 是 value，懒加载写法见 2.4；meta 是挂在记录上的自定义信息，2.13 讲。
  • 两条"如果以为会踩、其实不会"的规则先说清：路径默认不区分大小写（实测 /Test、/TEST 都能匹配 path:'/test'），尾斜杠被忽略（/test/ 能匹配 path:'/test'）——这是默认选项 sensitive: false、strict: false 的效果。

2.3

createRouter / createWebHistory / BASE_URL

①讲义要点

讲义"五"贴出的 index.js 第 78~79 行是 const router = createRouter({ history: createWebHistory(import.meta.env.BASE_URL),，只给代码没解释；实验内容 1 要求"熟悉 createRouter、createWebHistory 创建路由实例"。

②核心讲解

createRouter 是造一台导播台——把频道表（routes）交给它，它盯地址栏、决定播谁；createWebHistory 是选地址栏长相——正常路径 /home（History 模式，好看，部署要服务器配合）还是带井号的 /#/home（Hash 模式，丑，但扔哪都能跑）；括号里的 BASE_URL 回答"我这个前端最终放在服务器哪个子文件夹里"。

③示例演示

实训5_Vue-Router实现路由跳转/工程/vue-router/src/router/index.js 的头尾（中间是 2.2 那张表）：

js8 行
1 2 3 4 5 6 7 8
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [ /* 见 2.2 */ ],
})

export default router

BASE_URL 是什么，在任意组件的 <script setup> 里 console.log(import.meta.env) 就能看到。本机实测 Vite 塞进去的对象是：{"BASE_URL": "/", "DEV": true, "MODE": "development", "PROD": false, "SSR": false}。想让它不是 /，在 vite.config.js 里加 base: '/shop/'，重启后首页地址变成 http://localhost:5173/shop/home；想切 Hash 模式，把第 1 行改成导入 createWebHashHistory、第 4 行改成 createWebHashHistory()，地址就变成 /#/home。

④代码解读
  • import { createRouter, createWebHistory } from 'vue-router' —— 具名导入，花括号里的名字必须和 vue-router 导出的完全一致（回顾训练营 L3）。
  • createRouter({ history, routes }) —— 只认这两个必填项：history 决定地址栏长相和历史记录怎么存，routes 就是那张对照表。
  • createWebHistory(import.meta.env.BASE_URL) —— 不传也能跑（默认就是 /），所以本地看不出差别，部署到子目录才炸：所有链接都少一层 /shop/。
  • export default router 把实例给 main.js 用；真正让它生效的是 main.js:14 的 app.use(router)，不加这步 <RouterLink> 会被 Vue 当成不认识的组件。
  • import.meta.env 是 Vite 在编译时替换进去的（不是浏览器自带，也不是 Node 的 process.env）；BASE_URL 一定以 / 开头、以 / 结尾，正好是 createWebHistory() 要的格式。
⑤工程对照
  • 实训5_Vue-Router实现路由跳转/工程/vue-router/src/router/index.js:1（导入）、:3-4（造实例）、:23（导出）。
  • 实训5_Vue-Router实现路由跳转/工程/vue-router/src/main.js:14 —— app.use(router)，路由生效的开关；实训5_Vue-Router实现路由跳转/工程/vue-router/vite.config.js:8-18 没配 base，所以实测 BASE_URL 是 /。

展开解析

2.4

路由懒加载

①讲义要点

讲义正文所有路由都写成 component: () => import('../views/Test.vue') 却没解释为什么；实验目的 2 要求"掌握路由懒加载写法"，实验内容 2 要求"使用路由懒加载导入组件"。

②核心讲解

懒加载是点菜现做，不是开业前把整本菜单全做好。import('../views/X.vue') 是动态导入，返回值是 Promise；写成 () => import('../views/X.vue') 的意思是"先别导入，等真要进这个页面再调用这个函数"；Vite 见到这种写法，会自动把该组件单独打成一个文件。

③示例演示
js2 行
1 2
{ path: '/test', name: 'test', component: () => import('../views/Test.vue') }   // ✅ 对
{ path: '/bad',  name: 'bad',  component: import('../views/Test.vue') }         // ❌ 错：给的是 Promise

漏写箭头函数时，本机实测控制台原文：[VUE_ROUTER_R0028] Component "default" in record with path "/bad" is a Promise instead of a function that returns a Promise. This will break in production if not fixed.，它的 fix 就写着 write "() => import('./MyPage.vue')", not "import('./MyPage.vue')"。

懒加载到底省了什么？在本工程跑 npm run build，看 实训5_Vue-Router实现路由跳转/工程/vue-router/dist/assets/ 的真实产物：首屏 index-DyAGkxy8.js 是 1157.96 kB（含 Element Plus），而 Home-CyA3qOY1.js 只有 2.01 kB、Test-DESMPkk4.js 1.34 kB、Manage-C0Q7KZCd.js 0.77 kB、User/Goods/Orders 各约 0.3 kB——每个懒加载页面都是一个独立文件，首屏不用下载它们。

④代码解读
  • 箭头函数是一层包装：vue-router 拿到它并不调用，等 URL 真要进 /test 时才调用、拿到 Promise 再 await，成功了才渲染。
  • 直接写 component: import('../views/X.vue')，这行代码在模块加载时就执行——"懒"字没了，首屏反而更慢，而且 vue-router 拿到的是 Promise 不是函数（就是上面那条 R0028）。
  • '../views/Test.vue' 是相对当前文件（src/router/index.js）算的；写 '@/views/Test.vue' 也行，别名配在 vite.config.js:13-17。
  • 开发环境不打包，懒加载表现为"访问时才发一个 /src/views/Test.vue 请求"。想看效果：F12 → Network → 筛 JS → 清空 → 点"去测试页 Test"。
⑤工程对照
  • 实训5_Vue-Router实现路由跳转/工程/vue-router/src/router/index.js:7-12 —— 六条路由全是懒加载，一条静态导入都没有。
  • 实训5_Vue-Router实现路由跳转/工程/vue-router/dist/assets/ —— 上面那张产物清单就是从这里抄的（dist/ 已被 .gitignore 忽略，不入库）。
⑥易错提醒
  • 漏写箭头函数：本地好好的、上线白屏 → 开发环境 vue-router 帮大家兜住了 Promise，生产构建不兜底（R0028 原文就是这么说的）→ 写成 component: () => import('../views/X.vue')。
  • 点进某页面才报"Failed to fetch dynamically imported module" → 懒加载把错误推迟了：路径写错、文件名大小写不对（Windows 不报错、Linux 服务器炸）都要等点击进去才发现 → 按报错里的路径核对文件名，别指望本地试出来。
⑦课堂思考
展开解析

为什么懒加载的路径写错了，启动时看不出来，点进去才炸？

() => import('../views/X.vue') 只是一个等待被调用的函数，模块加载阶段谁也不会去检查那个文件在不在。只有 URL 真匹配到这条路由、vue-router 调用它时才去下载——错误在那一刻才产生。这就是懒加载的代价：把编译期能发现的错误推到了运行期。

2.5

定义一个新路由（含 name 的作用）

①讲义要点

讲义"二、定义一个新的路由"：以前能访问 Home，是"在 index.js 中定义了 Home.vue 这个路由"；现在"给 Test.vue 配上路由，也就是设置一个导航，让页面进行跳转"（配视频"新建一个路由 01.mp4"）。实验内容 2 给出四步：views 新建 Test.vue → routes 配置规则 → 懒加载导入 → 用 <RouterLink> 从 Home 跳过去。

2.8

push 与 replace 的区别

①讲义要点

讲义"三、1"只有一句"push 和 replace 两者区别，看视频 push 和 replace 两者区别 02.mp4"——正文没有文字说明。这一节就是把那个视频讲清楚。

②核心讲解

浏览器维护一个历史记录栈（一摞盘子）：push = 往最上面再放一个（多一条记录），随时能拿走（点后退）；replace = 把最上面那个换掉（数量不变），换走的再也回不来。后退按钮干的事就是"把最上面那个拿走"，所以区不要只有一句：大家换掉的那一页，还能不能退回去。

  • 判断标准："用户会不会想回到这一页？" 会 → push；不会（登录页、支付结果页、临时中转页）→ replace。

①讲义要点

路由守卫 beforeEach + meta

①讲义要点

讲义"五、路由守卫"：好处是"集中管理、全局统一规则、路由切换必更新、和权限逻辑放一起"；核心原理是"在 routes 路由元信息 meta 中定义 title 字段……使用前置守卫 router.beforeEach，每次路由跳转时读取 meta.title，赋值给 document.title"。讲义原文注释保留如下（换成好记的话：from 是大家现在待着的页面，to 是大家正要去的那页面，next() 是"放行"）：

js3 行

// from：将要进行跳转的当前route对象 (跳转前的一些操作)
// to: 跳转后route对象 (跳转后的一些操作)
// next(): 调用该方法后, 才能进入下一个钩子
②核心讲解

守卫就是小区门口的保安：不管大家从哪栋楼出来、要去哪栋楼，每次都得先过他。他手上有一张表（to.meta），写着"这栋楼叫什么名"，他顺手把门口大屏（document.title）改成新名字。好处是把"改标题"从 N 个页面挪到 1 个地方：各页面自己写一遍 document.title = '首页'，改规则要改 N 处；写在守卫里只改 1 处，新加的页只要配了 meta 就自动有标题。

  • to 是正要去的路由对象，from 是当前所在的路由对象（首次进入应用时 from 是初始空白路由）。
  • to.meta 是路由记录上的自定义元信息对象。讲义把它说成"额外补充路由参数的对象"是不准的：路由参数指 params/query，meta 是自己挂上去的任意附加信息（title、requiresAuth 都常见）。

  • 声明了三个参数却忘了调 next()：实测导航永久挂住，页面不切换，控制台连报错都没有，那个 push() 的 Promise 永远不 resolve。这是最难查的一种卡死。

  • 控制台每条导航都刷一遍 [VUE_ROUTER_R0025] The next() callback in navigation guards is deprecated. → 守卫用了第三个参数 next → 去掉它，改 return 风格。
  • 点链接没反应、页面不动、也不报错 → 守卫声明了 next 但某个分支忘了调用它 → 要么保证每条分支都调 next()，要么改写成 return 风格（推荐）。
⑦课堂思考
展开解析

父路由配了 meta: { title: '后台管理' }，子路由没配 meta。访问子路由时标签显示什么？

显示 "后台管理"——to.meta 会把父子 meta 合并，子级没写就继承父级（实测）。所以"标签变成 undefined"只发生在整条匹配链都没配 meta 的顶级路由上（本工程的 /home、/test）。
