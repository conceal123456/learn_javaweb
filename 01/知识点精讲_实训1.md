## 2. 知识点精讲

### 2.1 Node.js 是什么、为什么前端要装它

**① 讲义怎么说** —— "Node.js部分"开头直接让你双击 `node-v20.15.1-x64.msi` 一路 Next，**没解释 Node 是干什么的**，属于只给动作不给原理。

**② 一句话讲透** —— Node.js 不是一门新语言，**它就是 JavaScript**，只是配了个"离开浏览器也能跑的发动机"（V8 引擎 + 文件读写 + 网络能力）。前端非装不可的原因：浏览器只认 HTML/CSS/普通 JS，而你写的 `.vue`、`import`、ES6+ 它一个都不认识，必须先在本地编译；干这活儿的 Vite 是 JS 程序，得靠 Node 跑。类比：**Node 是灶台，Vite 是厨师，`.vue` 是生食材**——没灶台，厨师再厉害也做不出菜。

**③ 示例代码**

```js
// hello-node.js —— 存到 D:\course\Javaweb\基础补课\js练习\ 下，用 node hello-node.js 跑
const os = require('node:os')   // Node 内置模块，浏览器里没有这个东西
const fs = require('node:fs')

console.log('我在 Node 里跑，版本：' + process.version)
console.log('这台机器叫：' + os.hostname())

fs.writeFileSync('hello-node-output.txt', '这行字是 Node 写进硬盘的\n', 'utf8')
console.log('已经把结果写进 hello-node-output.txt 了')
```

```bash
node hello-node.js
```

**④ 逐行拆解**
- `require('node:os')`：`require` 是 Node 的取模块语法；`node:` 前缀表示内置模块，**不用 `npm install`**。不写这行就用不了 `os`，直接 `ReferenceError`。
- `process.version`：`process` 是 Node 自动给的全局对象。**浏览器里根本没有 `process`**，写了就是 `process is not defined`——这也是判断"这段代码在哪跑"最快的办法。
- `fs.writeFileSync(...)`：`Sync` 结尾＝同步，这一行不返回程序就在这等着。**浏览器里的 JS 永远没权限直接写硬盘**，Node 有。这就是"前端要装 Node"的根。
- 最后的 `console.log` 一定在文件写完之后才执行。换成 `fs.writeFile`（异步）就可能先打印——异步到训练营 L4 专门练。

**⑤ 在你仓库里** —— `01/hello-vue/package.json:20-22` 的 `"engines": { "node": "^20.19.0 || >=22.12.0" }` 就是工程对 Node 的约束。本机实测 `node -v` → `v24.17.0`，`node -p "process.execPath"` → `D:\software\nodejs\node.exe`。

**⑥ 常见坑** —— **现象**：`node -v` 报"不是内部或外部命令"。**原因**：装的时候没勾 Add to PATH，或者装了没重开命令行窗口（旧窗口拿的是旧 PATH）。**怎么改**：重装勾上 Add to PATH，或手动把 `D:\software\nodejs` 加进 Path 后**关掉所有命令行窗口重开**。另一坑：装了讲义的 `20.15.1` 后 `npm install` 报 `EBADENGINE`，因为 20.15 < 20.19 下限——装 20.19+ 或 22.x/24.x。

**⑦ 自测** —— Node.js 和 JavaScript 是什么关系？为什么"前端开发"反而要先装一个"服务端运行时"？

<details><summary>看答案</summary>

Node.js 不是新语言，是 JavaScript 的**运行时**（执行环境），用和 Chrome 同一个 V8 引擎，额外给了文件读写、网络、进程能力。

前端要装它，是因为 `.vue`、`import`、ES6+ 浏览器都不认识，必须先编译；干这活儿的 Vite 是 JS 程序，只能在 Node（或浏览器）里跑。所以 **Node 不是给浏览器装插件，而是给构建工具提供落脚点**，顺带兼任依赖下载器（npm）和本地服务器。

</details>

### 2.2 npm 是什么、和 Node 什么关系

**① 讲义怎么说** —— 第3条原话："nodejs 里面默认的会带一个 npm……它会跟随这个 NodeJS 一起安装的，**不需要单独安装**，它是在 NodeJS 里面内置的"。**这个说法是对的，讲义这里没讲错。**

**② 一句话讲透** —— npm = **N**ode **P**ackage **M**anager，仓库管理员＋搬运工：去 registry 把别人写好的包下下来放进 `node_modules`，并记住版本。"内置"的意思是**装不了单独的 npm，也不需要装**。类比：手机自带的应用商店——你不会"再装一个商店来装应用"，它是系统的一部分。你可以升级它，但不能让它脱离 Node 存在。

**③ 示例代码**

```bash
npm -v                              # 看 npm 自己的版本
where npm                           # 看它躺在哪（Windows 的 which）
npm config get registry             # 看它从哪个仓库下单
npm view create-vue version engines # 只问价不下载，看包要求的 Node 版本
npm install --dry-run               # 模拟装一遍，只报告不动硬盘
```

**④ 逐行拆解**
- `npm -v` → 本机 `11.13.0`，验证的是"npm 的启动脚本在不在 PATH 里"。
- `where npm` → 会列出 `D:\software\nodejs\npm` 和 `npm.cmd`。**它们躺在 Node 安装目录里，这就是"npm 是 Node 附属品"最直接的证据。**
- `npm view create-vue version engines` → 实测 `version = '3.21.0'`、`engines = { node: '^20.19.0 || >=22.12.0' }`。`view` 是只读查询，**不下载不安装**，用它不必瞎猜自己的 Node 够不够。
- `npm install --dry-run` → 报告"会装什么"，一个文件都不动。

**⑤ 在你仓库里** —— `01/hello-vue/package-lock.json:25` 是 `"resolved": "https://registry.npmmirror.com/@babel/code-frame/-/code-frame-7.29.7.tgz"`，**这条 URL 就是镜像源真生效的铁证**；`:1` 是 `lockfileVersion: 3`；`:2598`/`:2787`/`:2808` 分别锁住 vite / vue / vue-router 的实际版本。

**⑥ 常见坑** —— **现象**：`node -v` 正常但 `npm -v` 报错。**原因**：Node 在 PATH 里，npm 的 `npm.cmd` 不在（多半有多个 Node 安装，被 nvm 或旧版覆盖）。**怎么改**：`where node` 看 node 在哪个目录，`npm.cmd` 必须和它在同一个目录；不在就卸掉多余的 Node，或调 PATH 顺序。

**⑦ 自测** —— 讲义说"npm 不需要单独安装"，为什么？把 Node 卸了 npm 还能用吗？

<details><summary>看答案</summary>

npm 的代码就在 Node 安装目录里（`D:\software\nodejs\node_modules\npm`），`npm` 命令只是个调用它的批处理脚本，它是 Node 发行包的一部分，不是独立软件。

卸掉 Node，脚本和代码一起被删，npm 自然也没了。而且 npm 本身就是 JS 写的、靠 `node.exe` 执行——**没有 node，npm 连启动都启动不了**。

</details>

### 2.3 `node -v` / `npm -v` 验证的到底是什么

**① 讲义怎么说** —— "打开命令提示符，输入 `node -v`，看是否输出版本号"，以及"检测一下 npm 有没有安装好"。**只说了做什么，没说验证的到底是什么。**

**② 一句话讲透** —— `-v` 是 `--version` 的缩写，"报版本号然后退出"。它验证的**不是"文件在不在硬盘上"，而是"系统能不能按名字把程序叫起来"**——这两件事完全不同。类比：**书在图书馆里（文件存在）≠ 你能按书名一次借到（PATH 里有它）。**

**③ 示例代码**

```bash
node -v          # v24.17.0
npm -v           # 11.13.0，注意 npm 不打印 v 前缀
node --version   # 和 node -v 完全等价
where node       # 真正定位问题的诊断命令
where npm
```

**④ 逐行拆解**
- `node -v` 输出的那个 `v`（`v24.17.0`）**是版本号的一部分，不是命令的一部分**，别写成 `node -v v24.17.0` 去搜。
- `npm -v` 输出 `11.13.0`，**没有 `v` 前缀**。
- `where node` 返回 `D:\software\nodejs\node.exe` 说明 PATH 配对了；返回"信息: 用提供的模式无法找到文件"说明 PATH 没配好。**`node -v` 只是最终结论，`where` 才是诊断工具。**
- 两个命令的组合意义：`node -v` 成功只证明 Node 本体 OK；`npm -v` 成功才证明"Node + npm 这一对"都就位。

**⑤ 在你仓库里** —— 本机实测 `node -v` → `v24.17.0`、`npm -v` → `11.13.0`、`node -p "process.execPath"` → `D:\software\nodejs\node.exe`；与 `01/实验过程_实训1.md:10-11` 环境表里记的值一致。

**⑥ 常见坑** —— **现象**：系统 cmd 里正常，IDEA 内置终端里 `node -v` 报错。**原因**：IDEA 是在你改 PATH **之前**启动的，继承的是旧环境变量。**怎么改**：完全退出 IDEA（File → Exit，不是关窗口）再打开。**现象**：版本号和以为装的不一样。**原因**：机器上有多个 Node。**怎么改**：`where node` 按 PATH 顺序列出所有候选，**排最前面的才真正生效**。

**⑦ 自测** —— `node -v` 正常但 `where node` 无输出，可能吗？为什么？

<details><summary>看答案</summary>

几乎不可能同时成立。`where` 和 `node` 都靠 PATH 查目录，只是 `where` 是独立程序（`C:\Windows\System32\where.exe`）。如果 `where` 自己不在 PATH 里，那它压根跑不起来（报"不是内部或外部命令"），而不是"无输出"。

真正会遇到的是反过来：`where node` 能列出路径，但 `node -v` 报错——那说明文件在 PATH 目录里，但**文件本身坏了或被安全软件拦了**。所以诊断顺序是：先 `where` 看找没找到 → 再 `node -v` 看能不能跑。

</details>

### 2.4 PATH 环境变量

**① 讲义怎么说** —— "同时观察环境变量，会有下图所示"。**只让你看一眼截图**，没说 PATH 是什么、为什么必须有它。

**② 一句话讲透** —— PATH 是系统的"**程序搜索通讯录**"。你敲 `node`，系统不知道去哪找，就拿这个名字去 PATH 里列的目录**一个一个试**，找到第一个叫 `node.exe` 的就执行；全找完还没有，就报那句经典错误。类比：**你打电话找"张伟"，通讯录里没这个人就打不出去——不是张伟不存在，是通讯录里没他。**

**③ 示例代码**

```bash
echo %PATH%          # cmd：打印整份"通讯录"，分号分隔
where node           # 比上面更好用：直接告诉你最终命中的是哪个文件
```

```powershell
$env:Path -split ';'  # PowerShell：按分号切成一行一条，便于逐行检查
```

**④ 逐行拆解**
- `echo %PATH%` 里 `%NAME%` 是 cmd 读环境变量的语法。你会在输出里看到 `D:\software\nodejs\`——**这一条就是 `node` 命令能被找到的全部原因**，删掉它 `node -v` 立刻失效。
- `where node` 省得你在一堆路径里肉眼比对。
- **PATH 分"用户变量"和"系统变量"两份**：改用户变量只影响当前用户，改系统变量影响所有用户。装 Node 时一般写系统变量。

**⑤ 在你仓库里** —— 本机 `where node` 命中 `D:\software\nodejs\node.exe`，说明 `D:\software\nodejs` 在 PATH 中。对照 `01/实验过程_实训1.md:51`："是 PATH 没写上，重装时勾上 Add to PATH，或手动把 Node 安装目录加进环境变量后**重开命令行窗口**"——最后这半句是最容易漏、也最容易白折腾半小时的一步。

**⑥ 常见坑** —— **现象**：明明加进 PATH 了，`node -v` 还报错。**原因**：加完没重开窗口——已经开着的 cmd / IDEA 终端在启动那一刻就拍了个 PATH 快照，后续改了它不知道。**怎么改**：关掉所有命令行和 IDEA 重开，在新窗口 `echo %PATH%` 确认能看到刚加的目录。**另一坑**：`where node` 列出两条、排第一的是个不认识的旧目录——那是以前装过 Node 或 nvm，**要去删掉旧的那条或把它下移，而不是把新目录再加一遍**（加两遍不改变顺序）。

**⑦ 自测** —— 装 Node 时没勾 Add to PATH，但双击 `D:\software\nodejs\node.exe` 能打开。这时 cmd 里敲 `node -v` 会怎样？

<details><summary>看答案</summary>

会报"`node` 不是内部或外部命令，也不是可运行的程序或批处理文件。"

因为**双击是你亲手告诉系统"运行这个文件"**，路径是你给的；而**敲 `node` 是让系统自己猜文件在哪**，它只能查 PATH，查不到就找不到。

一个是"走直接路径"，一个是"走搜索"，完全不是一回事。

</details>

### 2.5 npm 镜像源 registry 的作用

**① 讲义怎么说** —— "因为 NPM 默认是从国外的下载依赖的，速度很慢，所以呢，要配置一个国内的淘宝镜像"，命令写的是 `npm config set registry http://registry.npmmirror.com`。**注意讲义用的是 `http`，勘误第 2 条已指出应改成 https。**

**② 一句话讲透** —— registry 就是 npm 的"**进货地址**"。默认的 `https://registry.npmjs.org` 在美国，国内经常几十 KB/s 甚至超时；npmmirror 是国内把同一份包**完整同步**了一份的副本服务器，换过去就是"从隔壁仓库拿货"。**关键认知：镜像是只读副本，不是另一个世界**——内容逐字节相同（靠哈希校验），所以换源是**纯速度优化**，不改变工程行为。

**③ 示例代码**

```bash
npm config set registry https://registry.npmmirror.com
npm config get registry        # 回显和刚设的一模一样才算成功
```

**④ 逐行拆解**
- `config set` 是"写配置"，**不下载任何东西**，只往一个配置文件里写一行。
- 地址必须写全 `https://`。漏掉协议头只写 `registry.npmmirror.com`，npm 会当相对路径解析，报 `Invalid registry` 之类的错。
- 讲义的 `http://` 现在会被 301 跳转到 https，多一次往返，**改成 `https://registry.npmmirror.com`**。本机实测 `npm config get registry` 回显 `http://registry.npmmirror.com`（历史设置，能用，只是多一跳）。
- 换源后不用重装 Node，但建议删掉 `node_modules` 和 `package-lock.json` 再 `npm install`，让锁文件里的 `resolved` 地址统一到新源。

**⑤ 在你仓库里** —— `01/hello-vue/package-lock.json:25` 的 `resolved` 指向 npmmirror，实证生效。`01/实验过程_实训1.md:50` 也记了"用 https 更稳妥，http 会多一次重定向"。

**⑥ 常见坑** —— **现象**：设完了 `npm install` 还是慢，锁文件里仍出现 `registry.npmjs.org`。**原因**：旧锁文件里已写死 `resolved` 地址，npm 优先按锁文件下载，**你的 registry 配置被锁文件"越过"了**。**怎么改**：删掉 `node_modules` 和 `package-lock.json` 重新 `npm install`。**另一坑**：公司/学校内网要走代理，`npm config set proxy http://地址:端口`，排查完记得 `npm config delete proxy` 清掉，否则回家又连不上。

**⑦ 自测** —— 换淘宝镜像会不会导致你装到的 Vue 和别人装的不一样（被改过、少文件）？

<details><summary>看答案</summary>

不会。npmmirror 是官方 registry 的**完整只读同步镜像**，内容逐字节相同。

校验靠 `package-lock.json` 里每个包的 `integrity` 字段（sha512 哈希）。npm 下载完算一遍哈希去比对，**对不上直接报错拒绝安装**。镜像站想偷偷改内容是不可能的——哈希一变，全世界的安装都会失败。

这正是 `package-lock.json` 必须提交进 Git 的原因之一。

</details>

### 2.6 `npm config set registry` 改的是哪个文件

**① 讲义怎么说** —— "输入 `npm config set registry ...` 按回车，直接跳到下一行代表执行正确"。**完全没说这行命令写了哪个文件**——这是本讲最容易被跳过、排查问题时又最要命的一环。

**② 一句话讲透** —— 它默认写的是**你用户主目录下的 `.npmrc`**，一个纯文本键值对配置，相当于 npm 的"**个人设置本**"，和具体某个工程无关，所以在任何目录下执行都生效。类比：**这不是改教室黑板上的课表（项目配置），而是改你自己手机里的默认铃声（用户配置）。**

**③ 示例代码**

```bash
npm config get userconfig     # 看用户级配置文件在哪
npm config get globalconfig   # 看全局级配置文件在哪
npm config get prefix         # 看全局安装目录
type %USERPROFILE%\.npmrc     # 看这个文件里到底写了什么
```

**④ 逐行拆解**
- `npm config get userconfig` → 本机实测 `C:\Users\15156\.npmrc`。**这就是 `npm config set registry` 实际改的那个文件**，换台机器用户名不同、路径也不同。
- `npm config get globalconfig` → 本机 `D:\nodejs\npm_global\etc\npmrc`（本机把 npm 全局目录挪到了 D 盘）。这个文件所有用户共享。
- `type %USERPROFILE%\.npmrc` → 本机实测内容：

```text
prefix=D:\nodejs\npm_global
cache=D:\nodejs\npm_cache
registry=http://registry.npmmirror.com
```

  **看到 `registry=` 那一行，你就掌握了"改的是哪个文件"的实锤。**
- npm 读配置的优先级（高→低）：**命令行参数 → 项目里的 `.npmrc`（和 `node_modules` 同级）→ 用户 `.npmrc` → 全局 `.npmrc` → 内置默认值**。"我明明设了镜像却没用"往往是被优先级更高的项目级 `.npmrc` 覆盖了。

**⑤ 在你仓库里** —— `01/hello-vue/` 根目录下**没有** `.npmrc`（已用 `Get-ChildItem -Force` 确认），所以它用的是用户级 `C:\Users\15156\.npmrc`，registry 就是那行 `http://registry.npmmirror.com`，和 `package-lock.json:25` 里的 npmmirror 地址吻合。

**⑥ 常见坑** —— **现象**：`npm config set` 执行完没报错，但 `npm config get` 还是老值。**原因**：环境变量 `NPM_CONFIG_REGISTRY` 存在，优先级高于任何 `.npmrc`。**怎么改**：`set NPM_CONFIG_REGISTRY=` 清掉（只对当前窗口有效），再去环境变量设置里删掉这条。**另一坑**：A 工程走镜像、B 工程不走——B 目录里有自己的 `.npmrc` 覆盖了用户级配置，用 `Get-ChildItem -Force` 看一眼（点开头的文件资源管理器默认不显示）。

**⑦ 自测** —— 你在 `01/hello-vue` 里执行 `npm config set registry https://registry.npmmirror.com`，这会影响你新建的另一个工程 `D:\other\demo` 吗？

<details><summary>看答案</summary>

**会。** 因为不带 `--location=project` 时写的是**用户级** `C:\Users\你的用户名\.npmrc`，和当前目录无关，跑到任何目录都生效。

如果只想让某一个工程用特定源，正确做法是**手动在那个工程根目录建一个 `.npmrc`**，里面写 `registry=https://registry.npmmirror.com`——只影响这个工程，也不污染全局设置。

</details>

### 2.7 `npm create vue@3.21.0` 脚手架做了什么

**① 讲义怎么说** —— "打开官网 `https://cn.vuejs.org/`，找到这条命令，并进行复制"，然后在 `xm-pro` 目录里"输入命令：`npm create vue@3.21.0` 按回车"。**没说这条命令背后发生了什么。**

**② 一句话讲透** —— 脚手架就是"**毛坯房 + 标准水电**"：不用从零一砖一瓦搭目录、写配置文件，一条命令下来整套能跑的骨架就躺在你目录里了。它具体干三件事：**① 去 registry 查 `create-vue` 的 3.21.0 版本；② 下载到 npm 临时缓存；③ 用 npx 的方式临时执行它。** 它**不会**把 `create-vue` 装进全局环境，干完活就走人。

**③ 示例代码**

```bash
# 在你想放工程的目录里执行（讲义用的是 D:\my-project\xm-pro）
npm create vue@3.21.0

# 等价写法
npm init vue@3.21.0
npx create-vue@3.21.0
npm create vue@3.21.0 vue        # 项目名直接跟在后面，就不再问名字

# 完全不问答、一条命令生成"只带 Router + 跳过示例"的骨架（本机实测可用）
npx create-vue@3.21.0 vue --router --bare
```

**④ 逐行拆解**
- **`npm create` 是 `npm init` 的别名**，完全等价。别被 `init` 误导，它不是"初始化空工程"，而是"**执行一个生成器**"。
- **`vue@3.21.0` 里 `vue` 不是包名**。npm 的约定是 `npm create <X>` 去找 **`create-<X>`**，所以 `npm create vue` = 下载运行 `create-vue`。同理 `npm create vite` 找 `create-vite`。
- `@3.21.0` 是**这个包的版本**。不写就默认 `@latest`——本机实测 latest 已是 `3.24.0`，要求 Node `^22.18.0 || >=24.12.0`，比 3.21.0 苛刻得多。**所以讲义写死版本号是有道理的。**
- `--` 后面的参数才是传给 `create-vue` 自己的（不是给 npm 的）。`create-vue` 认这些参数：`--router`（要路由）、`--bare`（**跳过示例代码**，就是问答里的"跳过"那一项）、`--ts`、`--pinia`、`--eslint` 等，含义和问答界面的勾选项一一对应。
- **目录必须先是空的或不存在**，否则它会问你要不要覆盖/合并，别乱按。非交互模式下要加 `--force` 才会覆盖。

**⑤ 在你仓库里** —— 本机实测 `npm view create-vue@3.21.0 version engines` → `version = '3.21.0'`、`engines = { node: '^20.19.0 || >=22.12.0' }`，**这是"3.21.0 是 create-vue 的版本"最硬的证据**。仓库里还有个真实脚手架产物样品：`vue/初识_vue/vue_1/`，里面有 `.vscode/`、`.gitignore`、`index.html`、`jsconfig.json`、`package.json`、`vite.config.js`、`public/favicon.ico`、`src/main.js`、`src/App.vue`——**这些全是脚手架一运行就铺好的，一个都不用手写。**

**⑥ 常见坑** —— **现象**：命令跑完当前目录还是空的。**原因**：`create-vue` 是**在当前目录下新建一个以项目名命名的子目录**，不是把文件直接铺在当前目录。**怎么改**：`cd vue` 进去看（这也是讲义第三条命令第一条就是 `cd vue` 的原因）。**另一坑**：跑出 `EBADENGINE`——`create-vue@3.21.0` 要求 `^20.19.0 || >=22.12.0`，讲义的 `node-v20.15.1` 低于下限。**怎么改**：升到 20.19+ 或 22.12+。

**⑦ 自测** —— `npm create vue@3.21.0` 里的 `vue@3.21.0`，下载的到底是哪个包？

<details><summary>看答案</summary>

下载的是 **`create-vue@3.21.0`**，不是 `vue@3.21.0`。

npm 有个命名约定：`npm create <X>` 自动去找 **`create-<X>`** 这个包。所以 `vue` 在这里只是"生成器名字"，npm 在它前面补上 `create-` 前缀。

真正的 `vue` 包（框架本体）**不在这里下载**——它是脚手架根据模板生成 `package.json`，等你 `npm install` 时才真正下载的。这就是为什么 `3.21.0` 和 Vue 的版本号毫无关系。

</details>

### 2.8 版本号 `3.21.0` 是脚手架的版本，不是 Vue 的版本

**① 讲义怎么说** —— 正文写 `npm create vue@3.21.0`，截图里却出现 `npm create vue@latest`，前后不统一；**两处都没解释这个 `3.21.0` 到底是什么的版本**（勘误第 6 条已指出）。

**② 一句话讲透** —— 一条命令里有**两个完全独立的版本号**：`create-vue@3.21.0` 是"发模板的生成器"的版本，你只在建工程那一刻用一次，**用完就和工程再无关系**；`vue@3.5.x` 是框架本体的版本，由生成器**写进 `package.json`**，之后跟着工程一辈子。类比：**`3.21.0` 是装修公司的工牌号，`3.5.x` 是你家墙漆的品牌型号**——工牌号变了不代表墙漆换牌子。

**③ 示例代码**

```bash
npm view create-vue version engines                                # 生成器的版本（3.24.0 / 3.21.0）
npm ls vue                                                          # 已安装的 vue 版本
node -p "require('./node_modules/vue/package.json').version"        # 最直接的证据
npm pkg get dependencies.vue                                        # package.json 里声明的区间
```

**④ 逐行拆解**
- `npm view create-vue version` → 本机实测指定版本时 `3.21.0`、latest 是 `3.24.0`。**这是生成器的版本。**
- `npm ls vue` → 列出 **`node_modules` 里实际装着**的版本。
- `node -p "require('./node_modules/vue/package.json').version"` → 在 `01/hello-vue` 下实测输出 **`3.5.43`**。**这就是"Vue 的版本"。**
- `npm pkg get dependencies.vue` → 读到 `"vue": "^3.5.27"`。**注意这是区间不是固定值**：`^3.5.27` ＝ "3.5.27 及以上、不跨到 4.0.0"，所以实际装成 3.5.43 完全合规。对比 `~3.5.27` 只允许升到 `<3.6.0`。

**⑤ 在你仓库里** —— `01/hello-vue/package.json:12` 是 `"vue": "^3.5.27"`，`:13` 是 `"vue-router": "^5.0.1"`，`:17` 是 `"vite": "^7.3.1"`；`package-lock.json:11-12` 记的声明区间和它一致。安装后的真实版本（读 `node_modules` 实测）：**vue 3.5.43、vue-router 5.3.1、vite 7.3.6**。运行时打印的 `VITE v7.3.6 ready in ...` 就是 vite 的版本，**和 create-vue 版本无关**。

**⑥ 常见坑** —— **现象**：照着讲义输 `npm create vue@3.21.0`，界面上问的题和讲义截图对不上。**原因**：讲义截图是老版 `create-vue` 的界面。**怎么改**：**以实际跑出来的界面为准**，核心不变——只保留 Router，其余全 No；别为了"对上截图"去装旧版本。**另一坑**：把 `3.21.0` 改成 `@latest` 后报 `EBADENGINE`——latest 现在要 Node `^22.18.0 || >=24.12.0`。**怎么改**：要么保持 `@3.21.0`，要么先把 Node 升到 24.12+。**第三坑**：`npm ls vue` 显示 3.5.43 而 `package.json` 写 3.5.27，怀疑装错了——那是 `^` 允许升级，正常行为；真要锁死用 `npm install vue@3.5.27 --save-exact`。

**⑦ 自测** —— 你同学执行 `npm create vue@3.24.0`，你执行 `3.21.0`，最后装的 Vue 版本会不一样吗？

<details><summary>看答案</summary>

**可能一样也可能差一点，但跟 `3.21.0`/`3.24.0` 没有直接因果关系。**

create-vue 的模板里写的是**区间**（`^3.5.x`），具体装到哪个版本由"你执行 `npm install` 那一刻 registry 上的最新版"决定。所以两个人哪怕用同一个生成器版本，隔一周跑也可能装到不同的 Vue。

想和同学完全一致，要对照的不是 `create-vue` 版本，而是 **`package-lock.json`**——它锁死了每个包的确切版本和哈希。**这也是它必须提交进 Git 的原因：它才是"版本一致性"的唯一保证。**

</details>

### 2.9 交互式问答的每一项是什么意思

**① 讲义怎么说** —— 讲义给的是一张"四问式"截图（先问项目名、再单独问是否用 TypeScript、末尾问是否跳过示例代码），并说"做如下选择"。但实测 `create-vue@3.21.0` 出来的是**功能多选清单**，和截图对不上（勘误第 3 条）。

**② 一句话讲透** —— 这一屏问的都是同一件事：**"这个工程要预装哪些能力？"** 每勾一个，它就多生成几个文件、多写几条依赖。**勾得越多工程越重，初学时越容易被看不懂的文件吓到。** 判断标准：**"这门课后面会用到吗？会 → 勾；不确定 → 不勾，以后随时能加。"** 这些能力都是后加的，不会因为当初没勾就做不了。

**③ 示例代码**

```text
✔ Project name: … vue
✔ Add TypeScript? … No
✔ Add JSX Support? … No
✔ Add Vue Router for Single Page Application development? … Yes   ← 只勾这一个
✔ Add Pinia for state management? … No
✔ Add Vitest for Unit testing? … No
✔ Add an End-to-End Testing Solution? … No
✔ Add ESLint for code quality? … No
✔ Add Prettier for code formatting? … No
```

| 选项 | 中文 | 勾上会发生什么 | 本讲 |
|---|---|---|---|
| TypeScript | JS 加类型检查 | 生成 `tsconfig.json`、`env.d.ts`，代码要写 `.ts` 并标类型 | 不要 |
| JSX Support | 在 JS 里写 HTML | 允许 `render()` 里直接写标签 | 不要 |
| Vue Router | 单页应用路由 | 生成 `src/router/index.js`，加 `vue-router` 依赖 | **要** |
| Pinia | 全局状态管理 | 生成 `src/stores/`，加 `pinia` 依赖 | 不要 |
| Vitest | 单元测试 | 生成 `src/components/__tests__/` | 不要 |
| E2E Testing | 端到端测试 | 生成 `e2e/` 与 Cypress/Playwright 配置 | 不要 |
| ESLint | 代码质量检查 | 写错格式就报红 | 不要 |
| Prettier | 代码格式化 | 统一缩进引号风格 | 不要 |

**④ 逐行拆解**
- `Project name: … vue`：**这是文件夹名，也是 `package.json` 里 `name` 的来源。** 本仓库 `01/hello-vue/package.json:2` 是 `"name": "01"`，因为父目录叫 `01`。名字只能用小写字母、数字、`-`、`_`，**不能有大写字母和中文**。
- **操作方式是空格键勾选，不是回车。** 回车是"这题答完了、下一题"。**最常见的手滑就是一路回车，最后什么都没勾上。**
- `Add TypeScript? No` 这条最关键：选 Yes 之后全课程代码都要标类型、`main.js` 变 `main.ts`，和老师讲义完全对不上。
- `Add Pinia?` → 它解决"很多页面共享同一份数据"（比如登录用户），本课程六讲都没这需求。
- **"跳过示例代码"**：新版把它合成到清单里（或紧跟其后再问一句），**本讲必须选"跳过"**。跳过之后得到的是最简骨架——`App.vue` 只有一段脚手架占位文字、**`router/index.js` 的 `routes` 是一个空数组 `[]`**，而且**不存在** `assets/`、`components/`、`views/` 三个目录。**所以讲义第四部分那 7 条手工操作是必做项，不是锦上添花。**

  本机实测（非交互等价命令 `npx create-vue@3.21.0 probe --router --bare`，`--bare` 就是那个"跳过示例代码"）生成出来的 `src/router/index.js` 原文：

  ```js
  import { createRouter, createWebHistory } from 'vue-router'

  const router = createRouter({
    history: createWebHistory(import.meta.env.BASE_URL),
    routes: [],
  })

  export default router
  ```

  **`routes: []` 就是"页面全白"的直接原因，也正是讲义第 4 条要你填的那一项。**

**⑤ 在你仓库里** —— 真实产物对照 `vue/初识_vue/vue_1/`：它的 `src/` 下**只有 `App.vue` 和 `main.js` 两个文件**（已用 `Get-ChildItem -Recurse` 确认），`package.json:2` 是 `"name": "vue_1"`。**这就是"只勾必要项 + 跳过示例"之后的最小骨架**，也正是 `01/hello-vue` 手工补目录之前的形态。对照 `01/hello-vue/src/` 下的实际内容（`App.vue`、`main.js`、`assets/global.css`、`assets/logo.svg`、`router/index.js`、`views/Home.vue`）——比 `vue_1` 多出来的全是讲义第四部分手工加的。

**⑥ 常见坑** —— **现象**：一路回车后 `src/` 下多出 `HelloWorld.vue`、`TheWelcome.vue` 等一堆文件。**原因**：没选"跳过示例代码"。**怎么改**：删掉多余组件，把 `App.vue` 换成只留 `<RouterView />`；或换个空的新目录重跑脚手架（最省事）。**另一坑**：手滑选了 TypeScript，现在满屏红线。**怎么改**：**别试图改回去，直接删目录重跑**——改造一个 TS 工程回 JS 花的时间多得多。

**⑦ 自测** —— 第二天老师让你加上 Pinia，需要重新建工程吗？

<details><summary>看答案</summary>

**不需要。** 两条命令即可：

```bash
npm install pinia
```

然后在 `src/main.js` 里加两行：

```js
import { createPinia } from 'pinia'
app.use(createPinia())
```

这说明脚手架那些勾选项的本质是"**帮你提前写好配置**"，而不是"只有当初勾了才能用"。**这也是"不确定就不勾"是安全策略的原因。**

</details>

### 2.10 `npm install` 与 `npm run dev` 分别干了什么

**① 讲义怎么说** —— "接着我们要依次执行 1、2、3 个命令：`cd vue` / `npm install` / `npm run dev`"。**没解释两条命令各自的职责，也没说为什么必须按这个顺序。**

**② 一句话讲透** —— 这是**两个完全不同阶段**的事：`npm install` 是**照菜谱买菜**——读 `package.json` 的依赖清单，去 registry 把 `vue`、`vite`、`vue-router` 等所有包（连同它们的依赖）下下来塞进 `node_modules`，并生成 `package-lock.json`，**和你的业务代码毫无关系**；`npm run dev` 是**下锅炒菜**——启动 Vite 开发服务器，读 `vite.config.js` 和 `index.html`，实时编译 `src/` 下的代码，起一个本地 HTTP 服务等你访问。**顺序不能颠倒：没有 `node_modules` 就没有 Vite。**

**③ 示例代码**

```bash
cd vue           # 进工程目录（脚手架把文件放在子目录里）
npm install      # 装依赖
npm run dev      # 启动开发服务器
```

**④ 逐行拆解**
- `cd vue` 为什么必须？因为 `npm install` **在当前目录里找 `package.json`**。你站在 `xm-pro` 敲而它下面没有 `package.json`，npm 会一路向上找父目录，最后报 `ENOENT: no such file or directory, open '...\package.json'`。
- `npm install`（简写 `npm i`）四步：① 读 `package.json` 的 `dependencies` 和 `devDependencies`；② **有 `package-lock.json` 就严格按它锁定的版本装**（保证和别人一致），没有就按 `^` 区间解析最新可用版并**生成**锁文件；③ 下载解压到 `node_modules`；④ 执行有 `postinstall` 脚本的包。
- 本机实测：`01/hello-vue/node_modules` 下最终有 **3262 个文件**，而 `package.json` 里你只声明了 **5 个包**——**这就是"依赖树"的直观体量。**
- `npm run dev` 会去找 `scripts.dev` 的值 `"vite"` 并执行。终端里回显的 `> 01@0.0.0 dev` / `> vite` 就是 npm 在告诉你"我实际跑的是这个"。`01@0.0.0` 来自 `package.json:2-3`。
- `VITE v7.3.6 ready in 8839 ms`：Vite 完成启动准备（读配置、预构建依赖）耗时 8839 毫秒。**第一次慢是正常的**，之后会快很多。

**⑤ 在你仓库里** —— `01/hello-vue/package.json:6-10` 是 `scripts` 三条；`package-lock.json:1-22` 头部的 `""` 条目记录直接依赖，和 `package.json` 一一对应；`node_modules/` 已存在（说明本机装过）。另外注意 `dist/` 里是 `index.html`、`assets/Home-CKU-tvrx.js`、`assets/index-CZ19N2H0.js`、`assets/index-lNEktN1b.css`——**这是 `npm run build` 的产物，不是 `npm run dev` 的**：dev 不产出 dist，build 才产出。

**⑥ 常见坑** —— **现象**：`npm run dev` 报 `'vite' 不是内部或外部命令`。**原因**：没先跑 `npm install`，`node_modules/.bin/vite` 不存在。**怎么改**：先装；装过还报就删 `node_modules` 重装。**现象**：`npm install` 刷一堆 `npm warn deprecated`。**原因**：正常现象，包多、有些包作者已停止维护。**怎么改**：`deprecated` 是**警告不是错误**，只要最后没有 `npm ERR!` 就是成功。

**⑦ 自测** —— `npm install` 之后你改了一行 `src/App.vue`，需要重新 `npm install` 吗？需要重新 `npm run dev` 吗？

<details><summary>看答案</summary>

**两个都不需要。**

`npm install` 管的是"第三方包"，你改自己的业务代码它完全不关心。

`npm run dev` 起的 Vite 服务器带**热更新（HMR）**：保存 `App.vue` 的瞬间 Vite 只把改动的那个模块推给浏览器，页面**自动刷新且不丢状态**（这是它比 webpack 快的原因——按需编译，不是全量重编）。

**唯一必须重跑 `npm run dev` 的情况是改了 `vite.config.js`**——那是服务器自己的配置，得重启才生效。

</details>

### 2.11 `package.json` 里 scripts 的作用

**① 讲义怎么说** —— 只说要"依次执行 1、2、3 个命令"，**把 `npm run dev` 当成一个要背的咒语，没提 `scripts` 这个字段的存在，也没说 `dev` 是谁定义的**。

**② 一句话讲透** —— `scripts` 是 `package.json` 里的"**快捷键定义表**"：把又长又难记的命令起个短名字。`npm run dev` 的真实身份就是"**帮我执行 `scripts.dev` 那一行**"。类比：**微波炉面板上的"解冻"按钮，按下去实际执行的是"中火 3 分钟间歇加热"。** 好处：命令短、全组统一（不管底层是 vite 还是 webpack 都敲 `npm run dev`）、可组合。

**③ 示例代码**

`01/hello-vue/package.json` 的 scripts 段（真实内容）：

```json
{
  "name": "01",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

自己加两条试试：

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "hello": "node -e \"console.log('scripts 生效了，当前目录是：' + process.cwd())\"",
    "show-vue": "node -p \"require('./node_modules/vue/package.json').version\""
  }
}
```

```bash
npm run hello
npm run show-vue
```

**④ 逐行拆解**
- `"dev": "vite"`：`dev` 是**你自己起的名字**，`vite` 是**真实命令**。能直接写 `vite` 而不是一长串路径，是因为 npm 执行脚本前会**临时把 `node_modules/.bin` 加到 PATH 最前面**——这是 npm 很贴心的设计，也是脚本里能直接写 `vite`、`eslint` 的原因。
- `"build": "vite build"`：把 `src/` 编译打包成可部署的静态文件输出到 `dist/`。本仓库 `01/hello-vue/dist/` 里那几个文件就是它的产物。
- `"preview": "vite preview"`：本地预览 `dist/` 里的构建产物，**端口是 4173 不是 5173**。
- `"type": "module"`（`package.json:5`）：很容易被忽略但很重要，它让 `.js` 按 **ES Module** 规范解析，即允许 `import ... from '...'`。**没有这一行，`import` 会报 `Cannot use import statement outside a module`。**
- `"private": true`（`:4`）：防止手滑把课程作业 `npm publish` 上去。
- **`npm run` 不带参数**会列出所有可用脚本，忘了名字时很有用。另外 `start`/`test`/`stop`/`restart` 四个可以省掉 `run`，其余一律要写 `npm run xxx`。

**⑤ 在你仓库里** —— `01/hello-vue/package.json:6-10` 就是上面那段，逐字核对过；`:2` 的 `"name": "01"` 就是回显 `> 01@0.0.0 dev` 里那个 `01` 的出处；`:5` 是 `"type": "module"`。对照 `vue/初识_vue/vue_1/package.json:6-10`，scripts 段**一模一样**——脚手架生成的工程都是这三条。

**⑥ 常见坑** —— **现象**：`npm run dev` 报 `Missing script: "dev"`。**原因**：当前目录的 `package.json` 里没这条，或站错目录了（比如站在父目录 `xm-pro`）。**怎么改**：`npm run` 列一下有哪些脚本。**现象**：在 scripts 里改了 `"dev": "vite --port 3000"`，运行没反应。**原因**：改动 `package.json` 需要**重启**进程。**怎么改**：`Ctrl + C` 停掉再跑。**现象**：直接敲 `vite` 报"不是内部或外部命令"但 `npm run dev` 正常。**原因**：`node_modules/.bin` 只在**通过 npm 执行脚本时**才进 PATH。**怎么改**：用 `npm run dev` 或 `npx vite`。

**⑦ 自测** —— `npm run build` 和 `npm run dev` 的产物分别在哪？为什么 `npm run dev` 之后找不到 `dist`？

<details><summary>看答案</summary>

`npm run build` → 在工程根生成 **`dist/`**，里面是压缩、合并、带内容哈希文件名的静态文件，可直接丢给 Nginx 部署。本仓库 `01/hello-vue/dist/` 里有 `index.html`、`assets/index-CZ19N2H0.js`、`assets/index-lNEktN1b.css`、`assets/Home-CKU-tvrx.js`。

`npm run dev` → **不在硬盘上产出任何文件**。它是"按需编译 + 内存里提供 + 通过 HTTP 推给浏览器"：浏览器请求哪个模块，Vite 才现场编译那一个。好处是启动几乎不花时间、改一行只重编一行。

所以 `npm run dev` 之后找不到 `dist` 是**完全正常的**，它压根就不该有。

</details>

### 2.12 Vite 开发服务器：为什么关掉命令行窗口就打不开了

**① 讲义怎么说** —— "此时是在命令行打开的项目，**如果把命令行关闭，则 `http://localhost:5173` 无法访问。**"——现象说出来了，**但没解释为什么**。

**② 一句话讲透** —— 因为 `http://localhost:5173` 这个网站**根本不在互联网上，它就在你自己的电脑里**。`npm run dev` 在你机器上起了一个小程序（Vite 开发服务器），它监听 5173 端口、随时把编译好的文件发给浏览器。**关掉命令行窗口就等于把这个程序杀了，网站自然就没了。** 类比：**你在家里开了个小型展览，门牌号是"我家 5173 房间"；你人走了、门锁了，别人拿这个门牌号当然进不去**——这个地址从来没对全世界公开过。

**③ 示例代码**

```bash
npm run dev                      # 前台阻塞运行，窗口不能关
```

```bash
# 另开一个窗口，验证"服务是自己电脑上的进程"
netstat -ano | findstr :5173
```

```bash
# 直接向开发服务器要文件，看它到底返回了什么
curl http://localhost:5173/
curl http://localhost:5173/src/main.js
```

```bash
# 想让它对局域网其它机器开放（手机调试用）
npm run dev -- --host
```

**④ 逐行拆解**
- `npm run dev` 是**前台阻塞**的：终端停在 `ready in xxx ms` 不再返回提示符，**这不是卡住，是服务器在工作**。它占着这个窗口，所以窗口不能关。
- `netstat -ano | findstr :5173` → 会看到 `TCP [::1]:5173 [::]:0 LISTENING 7432`。**`LISTENING` 表示"有进程正在这个端口等连接"，最后那个数字就是 node 的 PID**——这就是"网站住在你电脑里"的实锤。
- `curl http://localhost:5173/src/main.js` **很关键**：返回的**不是**你写的原文件，而是 Vite 编译后的版本（`import` 被改写成带时间戳的 URL、`.vue` 被拆成 JS）。**这直观证明了"开发服务器在实时编译你的源码"，浏览器拿到的从来不是你的原始文件。**
- `npm run dev -- --host` 里那个 `--` 是**必须的**：它把参数和 npm 自己隔开，后面的才是传给 vite 的。`--host` 让 Vite 监听 `0.0.0.0`，同一 WiFi 下的手机就能用 `http://你的IP:5173` 访问。**公共 WiFi 下别乱开。**
- 正常停服务：在终端按 **`Ctrl + C`**（有时要按两次），或直接关窗口。

**⑤ 在你仓库里** —— 本机实测：在 `01/hello-vue` 下跑 `npm run dev`，`netstat` 能看到 `[::1]:5173 LISTENING` 指向 node 进程；杀掉该进程后 5173 立刻从 `netstat` 消失。`01/实验过程_实训1.md:85` 也点出了原因："服务器是命令行里跑着的进程。" 对照 `01/hello-vue/dist/`——那是**另一条路线**的产物（`npm run build` 出的静态文件），拷到任何机器的 Nginx 下，那时候关不关窗口就无所谓了。**dev 服务器只用于开发，永远不用于部署。**

**⑥ 常见坑** —— **现象**：浏览器提示"`localhost` 拒绝了我们的连接请求"。**原因**：开发服务器已经停了。**怎么改**：回工程目录重新 `npm run dev`，**看终端实际给出的端口号**再访问。**现象**：同桌在他电脑上打不开你的 `http://localhost:5173`。**原因**：`localhost` 在**每台电脑上都指自己**，不是指你。**怎么改**：用 `npm run dev -- --host`，让他访问你终端里 `Network:` 那一行给出的局域网地址。

**⑦ 自测** —— 关掉 `npm run dev` 的窗口后，双击 `01/hello-vue/dist/index.html`，页面还能看到内容吗？

<details><summary>看答案</summary>

**大概率打不开或白屏，但原因不是"服务器没了"。** `dist/` 是 `npm run build` 产出的**静态文件**，双击就是用 `file://` 协议直接读本地文件，**不需要服务器**——这正好反证了"dev 服务器只是个分发工具，不是网站本身"。

但会有两个问题：① `dist/index.html` 里的资源路径是 `/assets/index-xxx.js` 这种**以 `/` 开头的绝对路径**，在 `file://` 下会解析成磁盘根目录，导致 404 白屏；② `createWebHistory` 用 HTML5 History API，`file://` 下路由不工作。

**正确的验证方式是跑 `npm run preview`**（即 `vite preview`），它起一个真正的 HTTP 服务器（**端口 4173**）来伺服 `dist/`。这也解释了 `scripts` 里为什么要专门放一条 `preview`。

</details>

### 2.13 端口被占会自动 +1

**① 讲义怎么说** —— "复制地址：`http://localhost:5173/`，在浏览器中打开"——**把 5173 写死了**。而 `01/实验过程_实训1.md:83` 里就真实遇到了这个情况（5173 被占，实际跑在 5171）。

**② 一句话讲透** —— 端口是"**同一台电脑上的房间号**"：IP 负责找到"哪栋楼"，端口负责找到"楼里哪个房间"。5173 是 Vite 约定俗成的默认房间号。如果房间已经有人住了（另一个 `npm run dev` 还在跑），Vite 不会撞门，而是**自动去隔壁敲门**：5173 不行就试 5174、5175…… 类比：**酒店前台给你 5173 房，发现有人了直接给你 5174，不会把你赶出去，也不会把里面的人赶出来。** 所以**永远不要背端口号，看终端输出**。

**③ 示例代码**

```bash
# 先跑一个占住 5173，别关它；另开一个窗口在同一个目录再跑一次
npm run dev
```

第二个窗口会打印（本机实测原文）：

```text
Port 5173 is in use, trying another one...

  VITE v7.3.6  ready in 8839 ms

  ➜  Local:   http://localhost:5174/
```

想让它别自动换、直接报错：

```bash
npm run dev -- --port 5173 --strictPort
```

```js
// 或者写进 vite.config.js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    port: 5173,
    strictPort: true  // 端口被占就直接失败，不自动 +1
  }
})
```

查是谁占了端口：

```bash
netstat -ano | findstr :5173
taskkill /PID 进程号 /F
```

**④ 逐行拆解**
- **`Port 5173 is in use, trying another one...` 就是"自动 +1"的官方声明**，本机实测原文一字不差。看到它你就知道端口变了。
- `➜ Local: http://localhost:5174/`：**最终地址以这一行为准**。讲义写的 5173 只是"没有冲突时的默认值"。
- 找下一个端口的规则是 **`port + 1` 依次递增**，不是随机。所以第二次跑通常是 5174、第三次 5175。
- `--strictPort`：开了它，5173 被占时 Vite **直接退出并报错**而不换端口。适合"前端要配代理、端口必须固定"的场景。
- `taskkill` 的 `/F` 是强制结束，**`/PID` 后面的数字必须是 `netstat` 最后一列那个，别抄错行**。

**⑤ 在你仓库里** —— 本机实测（同时启动两个 `01/hello-vue` 的 dev 服务器）：一个拿到 `http://localhost:5173/`，另一个打印 `Port 5173 is in use, trying another one...` 并拿到 `http://localhost:5174/`，`netstat` 里 5173 和 5174 同时 `LISTENING`。`01/实验过程_实训1.md:79-83` 记录里实际跑出来的是 **5171**（当时 5173、5172 都被别的工程占了），并写明"端口不同不影响结果"。训练营 [L0](../基础补课/补基础训练营.html) 第 2 条任务专门写了"注意端口会不会自动 +1"，第 466 行还提醒"以地址栏实际显示的为准，别照着讲义写死的端口"。

**⑥ 常见坑** —— **现象**：照讲义复制 `http://localhost:5173/` 打开，显示的是**另一个工程**的页面。**原因**：5173 被别的工程占着，你的工程跑在 5174，你访问的是别人的。**怎么改**：**永远看你这个终端的 `Local:` 那一行。** **现象**：端口一路涨到 5178，关了窗口重开也没降回来。**原因**：之前几次的 node 进程都没死透，各自占着一个端口。**怎么改**：`netstat -ano | findstr :517` 把所有相关 PID 找出来逐个 `taskkill`，或重启电脑。

**⑦ 自测** —— 你同时开了 `01/hello-vue` 和 `05/admin-layout` 两个工程的 `npm run dev`，两个浏览器标签页都填 `http://localhost:5173`，会发生什么？

<details><summary>看答案</summary>

**两个标签页会打开同一个工程**（先启动那个，它占住了 5173），另一个工程的页面**根本打不开**——你必须去看它那个终端的 `Local:` 行，多半是 5174。

原因是"端口是全局唯一的"：一台电脑同一个端口同一时刻只能被一个进程监听。后启动的 Vite 发现 5173 被占，自动换到 5174，但它**不会去通知浏览器**，只能靠你自己看输出。

这正是训练营 L0 第 1、2 条要你"记下地址栏真实端口"的原因——**这个坑几乎每个人都会踩一次。**

</details>

### 2.14 `index.html` / `src/main.js` / `src/App.vue` 三者关系

**① 讲义怎么说** —— 三个文件都提到了（`index.html` 在"运行项目"的截图里，`main.js` 在第四部分第 7 条，`App.vue` 在第 5 条），**但从头到尾没把它们串成一条链路讲**。

**② 一句话讲透** —— 用盖房子打比方，这是三个完全不同的层次：

| 文件 | 角色 | 一句话 |
|---|---|---|
| `index.html` | **门牌 + 地基** | 浏览器真正打开的那个文件，里面有一个空壳 `<div id="app">` |
| `src/main.js` | **总指挥（入口）** | 唯一被 html 直接引入的脚本，负责"造应用、装插件、挂上去" |
| `src/App.vue` | **根组件** | main.js 挂上去的那个"顶层组件"，里面装什么页面就显示什么 |

**关键点：`index.html` 里那个 div 是空的。** 你右键"查看网页源代码"永远看不到"欢迎来到安徽中医药大学…"，因为那句话是**运行起来之后**由 JS 现场画进去的——这就是**单页应用（SPA）**和传统网页最本质的区别。

**③ 示例代码**

按顺序连起来读一遍，链路就清楚了。

`index.html`（工程根目录，**不在 src 下**）：

```html
<!DOCTYPE html>
<html lang="">
  <head>
    <meta charset="UTF-8">
    <link rel="icon" href="/favicon.ico">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Vite App</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

`src/main.js`：

```js
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'
import '@/assets/global.css'

const app = createApp(App)

app.use(router)

app.mount('#app')
```

`src/App.vue`：

```vue
<template>
  <RouterView />
</template>
```

`src/router/index.js`：

```js
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      name: 'home',
      component: () => import('../views/Home.vue')
    }
  ],
})

export default router
```

`src/views/Home.vue`：

```vue
<template>
  <div>
    欢迎来到安徽中医药大学信工院JavaWeb课堂！
  </div>
</template>

<script setup>

</script>
```

**④ 逐行拆解**
- `index.html:10` → `<div id="app"></div>`：**一个空容器、一个 id，就这么多**。整个页面的内容将来都长在这个 div 里。这个 id 必须和 `mount('#app')` 的字符串**一模一样**。
- `index.html:11` → `<script type="module" src="/src/main.js"></script>`：**整个工程只有这一处直接引入 JS**。`type="module"` 让浏览器按 ES Module 解析（允许 `import`）；`src` 以 `/` 开头表示"从网站根目录算起"，对 Vite 来说就是工程目录。

- `main.js:4` → `import '@/assets/global.css'`：**没有 `from`，是副作用导入**——只为执行这个文件（把样式塞进页面），不接收导出值。
- `main.js:6` → `const app = createApp(App)`：造出应用实例，并告诉它"你的根组件是 App"。
- `main.js:10` → `app.mount('#app')`：把应用挂到页面上那个空 div 上。**挂载那一刻 Vue 才真正开始渲染。**

**⑤ 在你仓库里** —— 全部逐字核对过：`index.html:10-11`；`src/main.js:1-10`；`src/App.vue:1-3`；`src/router/index.js:1-14`；`src/views/Home.vue:1-9`。**特别值得看的对比**：`01/hello-vue/dist/index.html:10-12` 里 `<div id="app"></div>` 保留了，但 `src="/src/main.js"` 被换成了 `<script type="module" crossorigin src="/assets/index-CZ19N2H0.js"></script>`——**这一对比直接说明"开发时的源码路径"和"部署时的产物"是两回事。**

**⑥ 常见坑** —— **现象**：页面全白，控制台报 `Failed to mount app: mount target selector "#app" returned null`。**原因**：html 里 div 的 id 和 `mount()` 的选择器对不上（比如 html 写 `id="root"`），或 `<script>` 写在了 div **前面**（执行时 div 还不存在）。**怎么改**：两边字符串一致，且 `<script>` 保持在 div **之后**。**现象**：右键"查看网页源代码"看不到自己的内容，以为代码没生效。**原因**：SPA 的内容是 JS 运行时生成的，"查看源代码"看到的是**服务器返回的原始 html**，不是渲染后的 DOM。**怎么改**：用 F12 的 **Elements** 面板看。**这是理解 SPA 最直观的一课。**

**⑦ 自测** —— 只清空 `src/App.vue`，和只删掉 `index.html` 里的 `<div id="app"></div>`，分别是什怎么个白屏法？

### 2.15 讲义把 App.vue 叫"入口文件"不准

**① 讲义怎么说** —— 第四部分第 5 条原文："精简 App.vue，**App.vue 是作为项目的入口文件**"。**这个说法是错的**（勘误第 5 条已指出）。

**② 一句话讲透** —— **入口（entry）的定义是"构建工具从这里开始往上爬依赖树"的那个文件。** 在你这个工程里是 `src/main.js`——因为 `index.html` 里 `<script src="/src/main.js">` 直接指向它。`App.vue` 是 **main.js 引用进来的一个组件**，身份是"**组件树的根**"，不是"程序的入口"。类比：**`main.js` 是开机键（按下去机器才开始转），`App.vue` 是默认桌面壁纸（开机后你看到的东西）**——讲义的说法等于说"壁纸是开机键"。考试按讲义口径写没问题，但面试问到"Vue 工程入口在哪"答 App.vue 是要扣分的。

**③ 示例代码**

把 `src/main.js` 改成下面这样——**完全不引入 App.vue**，直接内联一个组件当根组件：

```js
import { createApp } from 'vue'
import '@/assets/global.css'

// 不 import App.vue，直接在这里写一个组件对象
const Root = {
  template: '<h1>我是内联的根组件，App.vue 根本没参与</h1>'
}

createApp(Root).mount('#app')
```

保存后浏览器显示"我是内联的根组件，App.vue 根本没参与"。

**④ 逐行拆解**
- 删掉 `import App from './App.vue'` 之后，**`App.vue` 彻底变成"死文件"**——它还在硬盘上，但没人 import 它，Vite 根本不会去读它。
- `const Root = {...}`：一个最朴素的组件对象，只有 `template` 一个属性。**组件本质上就是个普通 JS 对象**，`.vue` 文件只是它的"编译前写法"。
- `createApp(Root)`：`createApp` 的参数**只要求"是一个组件"**，不要求是 App.vue。**传谁进来，谁就是根组件。**
- **这个实验说明两件事**：① 入口必然在 `main.js`（删掉它整个页面就没了）；② App.vue 的地位来自"main.js 恰好引用了它"，而不是某种目录约定。
- **反向验证**：把 `main.js` 整个删掉，`index.html` 那行 `<script>` 立刻 404，页面**必然报错**；而删掉 `App.vue` 只会让 main.js 报 `Failed to resolve import "./App.vue"`。**哪个更致命，哪个就更"入口"。**

**⑤ 在你仓库里** —— `index.html:11` 的 `<script type="module" src="/src/main.js"></script>` **就是"入口是 main.js"的铁证**（html 只认这一个 JS 文件）；`src/main.js:2` 的 `import App from './App.vue'` 说明 App.vue 的身份是"**被 main.js 引入的模块**"；`:6` 的 `createApp(App)` 里 App 是作为**参数**传进去的。勘误原文：`01/讲义勘误_实训1.md` 问题 5——"工程入口是 `main.js`……App.vue 是**根组件**"。

**⑥ 常见坑** —— **现象**：面试/答辩被问"Vue 工程的入口文件是哪个"，答 `App.vue` 被判错。**原因**：把"根组件"和"入口"混为一谈。**怎么改**：标准答案分三句说：**`index.html` 是页面入口（HTML 层面），`src/main.js` 是脚本入口（JS 层面），`src/App.vue` 是根组件。** **另一坑**：把 `App.vue` 改名成 `app.vue`，Windows 上照跑，交到别人电脑上报 `Failed to resolve import "./App.vue"`——Windows 文件系统**大小写不敏感**，Linux/Mac 敏感。**严格保持大小写一致。**

**⑦ 自测** —— 用一句话分别说清 `index.html`、`main.js`、`App.vue` 的角色。

<details><summary>看答案</summary>

- **`index.html`**：浏览器加载的**唯一真实网页**，里面只有一个空容器 `<div id="app">` 和一个指向 main.js 的 `<script>`。它是**页面入口**。
- **`src/main.js`**：**脚本入口 / 装配车间**。造应用实例、装路由插件、引全局样式、挂载到 `#app`。Vite 从这里开始分析整个依赖树。
- **`src/App.vue`**：**根组件**，是 main.js 引用的顶层组件、组件树的根，页面内容由它里面的 `<RouterView />` 决定。

一句话串起来：**html 提供一个空壳 → main.js 把 Vue 应用装配好塞进这个壳 → App.vue 是这个应用的最外层组件。**

</details>

### 2.16 `createApp(App)` / `app.use(router)` / `app.mount('#app')` 逐行拆解

**① 讲义怎么说** —— 第四部分第 7 条只给了 `main.js` 的代码，**一行解释都没有**。可这三行是整个 Vue 应用的生命线，不讲透后面全讲不通。

**② 一句话讲透** —— 这三行是"**造 → 装 → 挂**"：`createApp(App)` 造一个 Vue 应用实例并指定根组件；`app.use(router)` 给它装插件（路由就是插件）；`app.mount('#app')` 把它塞进页面上那个空 div。类比：**造一辆车 → 装上导航仪 → 把车开上路。** 三步顺序不能换，少一步都不行。

**③ 示例代码**

`01/hello-vue/src/main.js`（真实内容，逐行加注释）：

```js
// ① 从 vue 包里取出 createApp（裸模块名，Vite 解析到 node_modules/vue）
import { createApp } from 'vue'

// ② 引入根组件。./ 相对当前文件，所以是 src/App.vue
import App from './App.vue'

// ③ 引入路由实例。./router 指向 src/router/ 目录，自动解析 index.js
import router from './router'

// ④ 引入全局样式，只为产生副作用，不接收导出值
import '@/assets/global.css'

// ⑤ 造应用：创建实例，指定 App.vue 作为根组件
const app = createApp(App)

// ⑥ 装插件：把路由装进应用，RouterView / RouterLink 才能用
app.use(router)

// ⑦ 挂载：渲染到 index.html 里 id="app" 的那个 div 上
app.mount('#app')
```

**④ 逐行拆解**
- **`import { createApp } from 'vue'`**：`{ }` 是**解构导入**，`vue` 包导出了很多成员，你只取一个。写成 `import createApp from 'vue'`（不带花括号）是取 `default` 导出，在 `vue` 包里**不存在**，会得到 `undefined`，一调用就报 `createApp is not a function`。**花括号必须和包实际的导出方式匹配。**
- **`const app = createApp(App)`**：接收一个组件对象作为根组件，返回**应用实例**（带 `use`、`mount`、`component`、`directive`、`provide` 等方法）。用 `const` 是因为 app 这个引用从头到尾不变，只是往它上面加东西。**不写这行**，后面 `app.use` 直接 `ReferenceError: app is not defined`。
- **`app.use(router)`**：`use` 是"安装插件"，插件是一个**带 `install` 方法的对象**（或函数）。router 实例就是标准插件，它的 `install` 干两件事：① **全局注册 `<RouterView>` 和 `<RouterLink>`**；② **注入 `$router` / `$route`**。**不写这行的后果最阴险**：`<RouterView />` 变成未识别的自定义元素，Console 报 `Failed to resolve component: RouterView`，**页面白屏但 `npm run dev` 一点错都不报**。**必须在 `mount` 之前**——已经 mount 之后再 use，Vue 会警告 `Plugin must be applied before mounting`，且对已渲染的组件无效。
- **`app.mount('#app')`**：接收 **CSS 选择器字符串**或真实 DOM 元素。Vue 用它去 `document.querySelector`，把根组件渲染进去并**清空原有内容**。这是唯一真正碰 DOM 的一步。**选择器对不上**就报 `Failed to mount app: mount target selector "#app" returned null`。`#` 是 id 选择器，写成 `'app'` 会去找 `<app>` 标签。
- **`import '@/assets/global.css'` 的位置**：它是副作用导入，放 `createApp` 前或后都行，只要在 `mount` 之前执行到就可以。**惯例是放在所有 import 的最后**，一眼能看出"这是全局配置区"。

**⑤ 在你仓库里** —— `src/main.js:6` 是 `const app = createApp(App)`，`:8` 是 `app.use(router)`，`:10` 是 `app.mount('#app')`；`index.html:10` 的 `<div id="app"></div>` 必须和 `mount('#app')` 一致；`src/App.vue:2` 的 `<RouterView />` **就是 `app.use(router)` 存在的理由**。训练营对照：[补基础训练营.html](../基础补课/补基础训练营.html) 第 568 行要求"能解释 `07/xm-pro/vue/src/main.js` 和 `router/index.js` 第 1 行在 import 什么"。

**⑥ 常见坑** —— **现象**：白屏，Console 一行红字 `Failed to resolve component: RouterView`。**原因**：漏了 `app.use(router)`。**怎么改**：补上；**注意 `npm run dev` 的终端里什么都不会报，一定要开 F12 看 Console。** **现象**：报 `createApp is not a function`。**原因**：import 花括号写错了。**怎么改**：`import { createApp } from 'vue'`。**现象**：报 `mount target selector "#app" returned null`。**原因**：id 不是 `app`，或 `<script>` 写在了 div 前面。**怎么改**：对齐 id，`<script>` 移到 `<body>` 末尾。**现象**：警告 `Plugin must be applied before mounting`。**原因**：`use` 写在 `mount` 后面了。

**⑦ 自测** —— 把 `app.use(router)` 注释掉，`npm run dev` 会报错吗？浏览器里会看到什么？

<details><summary>看答案</summary>

**`npm run dev` 完全不报错**，终端照样显示 `ready in xxx ms` 和 `Local: http://localhost:5173/`。**这是这个坑最坑的地方。**

浏览器里：**页面全白**，那个空 div 还在但里面什么都没有。F12 Console 会有警告：

```text
[Vue warn]: Failed to resolve component: RouterView
```

原因是 `<RouterView>` 既不是原生标签、也没被注册成组件，Vue 只能把它当"未知标签"按原样渲染一个空元素；而 `app.use(router)` 的 `install` 方法里干的正好就是"全局注册 RouterView 和 RouterLink"。

**记住教训：白屏先看 Console，不要只看终端。**

</details>

### 2.17 `assets` / `components` / `views` 三个目录各自放什么

**① 讲义怎么说** —— 第四部分第 1、2 条：在 src 下"新建目录，命名 `assets`，然后复制 `logo.svg` 图片到 assets 下"、"新建目录，命名 `components`"、"新建目录，命名 `views`，粘贴 `home.vue`"。**只给了动作。**

**② 一句话讲透** —— 这三个目录是 **Vue 社区约定俗成的分工，不是语法规定**。你把 `Home.vue` 放进 `assets` 工程照样跑，但没人看得懂你的工程。

| 目录 | 放什么 | 判断标准 | 本工程实例 |
|---|---|---|---|
| `assets` | **素材**：图片、字体、全局 CSS | 它不是代码，是被代码引用的资源 | `logo.svg`、`global.css` |
| `components` | **零件**：可复用的局部组件 | 它需要在多个页面里被拼装使用 | 本讲精简后**为空** |
| `views` | **整页**：一个路由一个页面 | 它能跟一个路由路径对上号 | `Home.vue`（对应 `/`） |

最好记的判据：**能和 `router/index.js` 里某条 `path` 对上号的放 `views`，对不上号的放 `components`。** 类比：`views` 是**整道菜**（一盘端上桌），`components` 是**食材半成品**（按钮、卡片、表格），`assets` 是**调料餐具**（不单独吃，但每道菜都用）。

**③ 示例代码**

本工程精简后的真实目录结构：

```text

├── index.html
├── package.json
├── vite.config.js
├── jsconfig.json
├── public/
│   └── favicon.ico
└── src/
    ├── main.js
    ├── App.vue
    ├── assets/
    │   ├── global.css
    │   └── logo.svg
    ├── components/       ← 本讲为空，实训2 起往里放东西
    ├── views/
    │   └── Home.vue
    └── router/
        └── index.js
```

练习用零件 `src/components/HelloCard.vue`（自己新建）：

```vue
<template>
  <div class="hello-card">
    <img :src="logo" alt="logo" width="60">

    <p><slot /></p>
  </div>
</template>

import logo from '@/assets/logo.svg'

  title: {
    type: String,

  }

</script>

<style scoped>
.hello-card {
  border: 1px solid #ddd;
  border-radius: 8px;
  padding: 12px;
  margin: 12px;

</style>
```

改 `src/views/Home.vue` 用上这个零件：

```vue
<template>
  <div>
    欢迎来到安徽中医药大学信工院JavaWeb课堂！

    <HelloCard title="我是从 components 里来的零件">
      这一行文字通过插槽塞进了零件内部。
    </HelloCard>

    <HelloCard title="同一个零件用了第二次" />
  </div>

<script setup>
```

**④ 逐行拆解**
- `import HelloCard from '@/components/HelloCard.vue'`：**跨目录引用就用 `@` 别名**，不用写 `../components/...`。
- `import logo from '@/assets/logo.svg'`：**assets 里的图片要用 import 引入，不能直接写路径字符串**。Vite 会处理这个导入并返回最终可访问的 URL。写成 `<img src="@/assets/logo.svg">` **不行**——`@` 别名在模板属性字符串里不生效。
- `<script setup>` 里 import 进来的组件**自动注册**，不用再写 `components: { HelloCard }`。
- `<style scoped>` 让样式**只作用于当前组件**（Vue 给元素加一个唯一属性并据此生成选择器）。`global.css` 则相反。**能加 `scoped` 就加**，否则组件一多样式必然互相打架。
- `<slot />` 是插槽，让使用方往零件内部"填空"。第二个 `<HelloCard />` 没有内容，插槽就是空的。
- **`components` 目录本讲是空的，这不是疏漏**——讲义第四部分只要求"新建目录"，实训1 还没有可复用的零件。
- **`public` 和 `assets` 的区别**：`public` 下的文件**原样拷贝**到 dist 根目录，用绝对路径 `/favicon.ico` 直接引用，**不经过 Vite 处理**（不压缩、不哈希）；`assets` 下的文件**要 import、会被处理**（小图内联成 base64、大文件带内容哈希）。`index.html:5` 的 `<link rel="icon" href="/favicon.ico">` 就是绝对路径引用，因为它来自 `public`。

**⑤ 在你仓库里** —— 用 `Get-ChildItem -Recurse` 逐项确认：`src/assets/global.css`（6 行）、`src/assets/logo.svg`、`src/views/Home.vue`（9 行）、`public/favicon.ico` **都存在**；**`src/components/` 这个目录也存在，但里面一个文件都没有**（脚手架自带的示例组件被删掉了，目录本身留了下来）。要跟着本节练手，直接在已有的 `components` 目录里新建 `HelloCard.vue` 就行，不用再建目录。

**⑥ 常见坑** —— **现象**：`<img src="@/assets/logo.svg">` 图片裂开，404 找不到 `/@/assets/logo.svg`。**原因**：`@` 别名只在 **JS 的 `import` 语句**里生效，模板属性字符串里不认。**怎么改**：先在 `<script setup>` 里 `import logo from '@/assets/logo.svg'`，模板里用 `:src="logo"`。**现象**：`<style>` 里写的样式影响到别的页面。**原因**：没加 `scoped`。**怎么改**：加 `<style scoped>`；真需要全局的（比如 `body`）放 `global.css`。**现象**：`components` 目录建了但 Git 提交后别人拉下来没有。**原因**：**空目录 Git 不跟踪。怎么改**：等有组件了再提交，或放个 `.gitkeep` 占位。

**⑦ 自测** —— 一个"用户信息卡片"会在"个人中心""后台首页""修改资料"三个页面各出现一次，它该放 `views` 还是 `components`？

<details><summary>看答案</summary>

**放 `components`。**

判据是"**它能跟 `router/index.js` 里的某条 path 对上号吗**"。那三个页面各有各的 path（`/profile`、`/admin`、`/profile/edit`），而"用户信息卡片"**不对应任何 path**——它是被那三个页面**当零件拼装使用**的。

放进 `views` 会有实际麻烦：`views` 天然是"一个路由一个文件"，混进一个零件，别人会以为它是个可跳转的页面，去找它的路由却发现没有。

**补充判据**：一个东西只要是"页面里的一块"并且**在多处复用**，就一定是 `components`。哪怕只用在一个页面里，只要它不是"整页"，放 `components` 也不算错——**`views` 的标准比 `components` 严格。**

</details>

### 2.18 `router/index.js` 精简路由

**① 讲义怎么说** —— 第四部分第 4 条："修改 `index.js`，也就是精简路由"。**只给了动作，没给代码，也没解释 `createRouter` / `createWebHistory` / `routes` / `() => import()` 分别是什么。**

**② 一句话讲透** —— 路由就是"**地址 → 显示哪个组件**"的对照表。以前做一个 `.html` 对应一个网址、点链接整页刷新；Vue 路由是**地址变了但不重新加载页面，只把页面里某一块内容换掉**，这就是单页应用。类比：**路由是电视台总控台**——`path: '/'` 是"1 频道"，`component` 是"1 频道播哪个节目"；按遥控器换台时，**电视机（页面）本身没换，换的只是画面**。

**③ 示例代码**

`01/hello-vue/src/router/index.js`（真实内容，逐行加注释）：

```js
// ① 从 vue-router 取出两个函数：一个造路由器，一个选历史模式
import { createRouter, createWebHistory } from 'vue-router'

// ② 造路由器
const router = createRouter({
  // ③ HTML5 History 模式，地址栏是 /about 而不是 /#/about
  history: createWebHistory(import.meta.env.BASE_URL),

  // ④ 路由表：地址 → 组件 的对照清单
  routes: [
    {
      path: '/',                                    // 浏览器地址是 /
      name: 'home',                                 // 给这条路由起名
      component: () => import('../views/Home.vue')  // 懒加载：用到时才下载
    }
  ],
})

// ⑤ 导出，给 main.js 用
export default router
```

再加一条验证它真在工作。新建 `src/views/About.vue`：

```vue
<template>
  <div>
    <h2>关于本课程</h2>
    <p>这是实训1 的路由演示页面。</p>
  </div>
</template>

<script setup>

</script>
```

`routes` 改成两条：

```js
const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      name: 'home',
      component: () => import('../views/Home.vue')
    },
    {
      path: '/about',
      name: 'about',
      component: () => import('../views/About.vue')
    }
  ],
})
```

`src/App.vue` 加两个链接就能点着跳：

```vue
<template>
  <nav>
    <RouterLink to="/">首页</RouterLink>
    <RouterLink to="/about">关于</RouterLink>
  </nav>
  <hr>
  <RouterView />
</template>
```

**④ 逐行拆解**
- **`from 'vue-router'`**：`vue-router` 是**独立包，不是 vue 的一部分**。所以 `package.json` 的 `dependencies` 里必须能看到它（本工程 `:13` 是 `"vue-router": "^5.0.1"`）。**如果 `npm create vue` 时 Router 选了 No，这一行直接报 `Failed to resolve import "vue-router"`。**
- **`createRouter({...})`**：接收配置对象返回**路由器实例**，也就是 `main.js` 里 `app.use(router)` 装的那个插件。它内部会：建匹配表、监听地址变化、提供 `install` 方法。
- **`history: createWebHistory(import.meta.env.BASE_URL)`** 决定地址栏长什么样：`createWebHistory()` → `http://localhost:5173/about`，**干净好看**，代价是**部署时必须在服务器配 `try_files $uri $uri/ /index.html;`**，否则刷新 `/about` 会 404；`createWebHashHistory()` → `http://localhost:5173/#/about`，丑但**部署零配置**（`#` 后面的内容不发给服务器）。`import.meta.env.BASE_URL` 来自 `vite.config.js` 的 `base` 配置，**默认 `'/'`**，作用是支持部署到子目录。本工程用默认值，等价于 `createWebHistory('/')`。
- **`path: '/'`**：**以 `/` 开头**表示从根算起的绝对路径。**写成 `''` 或 `'home'` 都匹配不上。** 默认是精确匹配，`/` 不会匹配 `/about`。
- **`name: 'home'`**：可选但强烈建议。好处是**跳转时不用写死路径**（`router.push({ name: 'home' })`），将来路径从 `/` 改成 `/index`，用名字的地方一行都不用改。**名字必须全局唯一。**
- **`component: () => import('../views/Home.vue')`（懒加载，本讲最重要的细节）**
  - **不懒加载**：顶部 `import Home from '../views/Home.vue'` + `component: Home`，会让 `Home.vue` 和 `main.js` 一起**在首屏就被下载**，页面一多首屏体积就爆炸。
  - **懒加载**：`() => import(...)`。`() =>` 是函数，**`import()` 在函数被调用前不会执行**——用户访问 `/` 之前 `Home.vue` 根本不会被下载。
  - **真实证据**：本工程 build 产物里 `dist/assets/` 下有**独立的** `Home-CKU-tvrx.js`。**它能被单独打包成一个文件，正是懒加载起作用的铁证**；没有懒加载的话所有代码会挤在 `index-CZ19N2H0.js` 一个文件里。
  - **`../views/Home.vue` 是相对谁的？** 相对**当前文件** `src/router/index.js`。`../` 回到 `src/` 再进 `views/`，**不是相对工程根目录**。
  - **代价**：路径写错时**启动不报错**，要等用户点进那条路由才报 `Failed to fetch dynamically imported module`。所以每个路径都要仔细核对。
- **`export default router`**：让 `main.js` 的 `import router from './router'` 能接住。**`./router` 会自动补成 `./router/index.js`。**

**⑤ 在你仓库里** —— 全部逐字核对过：`src/router/index.js:1`、`:4`、`:5-11`、`:9`（`component: () => import('../views/Home.vue')`）、`:14`；`src/App.vue:2` 的 `<RouterView />` 是渲染位置；`src/main.js:3` 和 `:8`；`package.json:13` 是 `"vue-router": "^5.0.1"`（装好后实际 5.3.1）。**懒加载的实证产物**：`dist/assets/Home-CKU-tvrx.js`（单独 chunk）和 `dist/assets/index-CZ19N2H0.js`（主包，含 vue、vue-router、main.js）。

**⑥ 常见坑** —— **现象**：启动正常，点进新加的路由 Console 报 `Failed to fetch dynamically imported module: .../src/views/About.vue`。**原因**：`import()` 里路径写错（大小写不对、目录写错、漏扩展名）。**怎么改**：核对相对路径；**Windows 大小写不敏感，`about.vue` 也能跑，但交到 Linux 服务器就炸**。**现象**：地址栏变成 `/about` 但刷新就 404。**原因**：`createWebHistory` 下刷新时浏览器真的去问服务器要 `/about`，dev 服务器能处理、生产 Nginx 不能。**怎么改**：Nginx 配 `try_files`，或改用 `createWebHashHistory()`。**现象**：`routes` 是空数组，页面全白。**原因**：`create-vue` 选了"跳过示例代码"后 `routes` 默认就是空的，**这不是 bug，是要你手填**——这就是讲义那几步是"必做项"的原因。**现象**：`import.meta.env.BASE_URL` 报 `Cannot read properties of undefined`。**原因**：写成了 `process.env.BASE_URL`，**浏览器里没有 `process`**。**怎么改**：必须是 `import.meta.env.XXX`。

**⑦ 自测** —— `component: () => import('../views/Home.vue')` 和顶部先 import 再 `component: Home`，运行结果看起来一样，差在哪？

<details><summary>看答案</summary>

**差在"什么时候下载这个文件的代码"。**

- **顶部 import（静态导入）**：`Home.vue` 和 `main.js` 一起在**首屏就被打进主包并下载**，用户只看首页也已经把所有页面的代码下完了。
- **`() => import(...)`（动态导入/懒加载）**：`import()` 写在箭头函数里，**函数不调用就不执行**，Vite 也就能把 `Home.vue` **单独打包成一个 chunk**。

**证据就在你的仓库里**：`01/hello-vue/dist/assets/` 里有独立的 `Home-CKU-tvrx.js`。如果没用懒加载，这个文件根本不会存在，所有代码只会挤在 `index-CZ19N2H0.js` 里。

**代价**：多一次网络往返（点进去才下载，有极短暂等待），以及"路径写错时不报错、点进去才发现"。**对页面多的工程，这个代价远小于首屏变慢，所以是官方推荐写法。**

</details>

### 2.19 `App.vue` 只保留 `<RouterView />` 的意义

**① 讲义怎么说** —— 第四部分第 5 条："精简 App.vue，App.vue 是作为项目的入口文件"——**动作给了（精简成只留路由视图），但"为什么"和"入口文件"的说法都不对。**

**② 一句话讲透** —— `<RouterView />` 是一个**占位符**：它自己不产生任何画面，就是一块**留给路由的屏幕**。当前地址匹配到哪个组件，那个组件就显示在这块屏幕的位置上。把 `App.vue` 精简成只剩它，等于让根组件**退化成一块纯屏幕**：**页面显示什么，100% 由地址决定**。类比：`App.vue` 是**电视机**，`RouterView` 是**屏幕上的显示区域**，路由是**遥控器**——以前电视机自带开机广告（脚手架生成的欢迎页），现在广告去掉了，**屏幕上只有当前频道的内容**。

**③ 示例代码**

`01/hello-vue/src/App.vue`（精简后的真实内容，全文 3 行）：

```vue
<template>
  <RouterView />
</template>
```

**实战：给所有页面加统一的顶部导航**——这才是 `RouterView` 之外还该放东西的那一类内容：

```vue
<template>
  <nav class="top-nav">
    <RouterLink to="/">首页</RouterLink>
    <span> | </span>
    <RouterLink to="/about">关于</RouterLink>
  </nav>

  <main class="page-body">
    <RouterView />
  </main>
</template>

<style scoped>
.top-nav {
  background: #f5f5f5;
  padding: 10px 16px;
  border-bottom: 1px solid #ddd;
}
.page-body {
  padding: 16px;
}
</style>
```

**④ 逐行拆解**
- **`<RouterView />` 为什么不用 import？** 因为它**已经在 `app.use(router)` 的时候全局注册过了**，模板里直接写标签名即可。既然本工程 `App.vue` 只有这一行，**不加 `<script>` 也能跑**——`src/App.vue` 全文就 3 行，**真的没有 `<script>` 块**。反过来说，显式写 `import { RouterView } from 'vue-router'` **也完全合法**，两种写法都对。
- **自闭合写法**：Vue 模板允许 `<RouterView />`（不像原生 HTML），写成 `<RouterView></RouterView>` 效果一样。
- **标签名大小写**：`<RouterView />`（帕斯卡）和 `<router-view />`（短横线）**都可以**。
- **为什么"只留 RouterView"是对的**：上面的导航栏例子说明 `App.vue` **可以有** RouterView 之外的东西——**前提是"所有页面都需要它"**。判据就一句话：**所有页面都要 → 放 App.vue；只有某些页面要 → 放对应 view。**
- **`<style scoped>` 里不能用 `body` 选择器**：`scoped` 只作用于当前组件模板里的元素，`body` 不在其中，写了不生效。

**⑤ 在你仓库里** —— `01/hello-vue/src/App.vue` **全文 3 行，只有 `<template>` 和 `<RouterView />`，没有 `<script>` 块**（已用 `read` 逐行确认）；`src/router/index.js:9` 匹配 `/` 的是 `Home.vue`，它会被渲染进这个 `<RouterView />` 的位置；`src/main.js:6` 的 `createApp(App)` 说明 App.vue 是根组件。**对照说明**：`vue/初识_vue/vue_1/src/App.vue` 里是 `<img :src="imgPath">` 和 `:style` 绑定的示例内容——**那是老师手改的练习文件，不是脚手架的默认内容**，别拿它当"精简前"的参照。

**⑥ 常见坑** —— **现象**：`App.vue` 里保留着脚手架的 `<HelloWorld />`，页面永远显示欢迎组件，加了路由也看不到变化。**原因**：根组件里的固定内容和 `<RouterView />` 并存。**怎么改**：**精简成只留 `<RouterView />`**。**现象**：`<RouterView />` 写在 `<RouterLink>` 前面，链接跑到页面最下面。**原因**：模板显示顺序就是代码顺序。**怎么改**：调整顺序。**现象**：`App.vue` 只留 `<template>`，IDEA 报语法警告。**原因**：某些检查器期望至少有个 `<script>` 或 `<style>`。**怎么改**：忽略即可，**Vue 完全允许只有 `<template>` 的 SFC**，本仓库就是这样跑的。

**⑦ 自测** —— "欢迎来到安徽中医药大学信工院JavaWeb课堂！"为什么该放在 `views/Home.vue` 而不是 `App.vue`？

<details><summary>看答案</summary>

因为这句话**只属于首页**。

`App.vue` 是根组件，它的模板会出现在**每一个页面**上。放进 `App.vue`，等实训2 加了 `/about`、实训3 加了 `/list` 之后，**每个页面顶部都会顶着这句欢迎语**，而且你还得回头去 `App.vue` 删掉它。

放进 `views/Home.vue` 就干净了：只有地址是 `/` 时路由才匹配到它，它才会被渲染进 `<RouterView />` 的位置，**加新页面完全不影响它**。

**推广判据**：想要"所有页面都有"的（导航栏、页脚、全局提示条）放 `App.vue`；只属于某个页面的放对应 `views/*.vue`。讲义第 8 条跑出来的效果图里，文字紧贴浏览器左上角、上面没有任何导航栏——**这正是"App.vue 里除了 RouterView 什么都没有"的直接视觉证据。**

</details>

### 2.20 `global.css` 全局样式 + 在 main.js 里 import 的顺序

**① 讲义怎么说** —— 第四部分第 6 条："在目录 assets 下新建一个全局样式表文件：`global.css`，同时写上代码"。第 7 条："在 main.js 里面引入全局的 css"。**同样只给动作，没讲"什么是全局样式"和"为什么要在 main.js 里引"。**

**② 一句话讲透** —— **全局样式 = 不 scoped 的样式 = 影响整个页面**，管的是"所有页面都一样的底色"：`body` 的外边距、默认字号、默认字体色。这些属性**在组件里根本写不了**（组件模板里没有 `body` 这个元素），所以必须有个地方专门管。类比：**全局样式是房子的水电总闸和统一墙面漆，组件样式是每个房间自己的家具摆放**——总闸得在整栋楼的总控室（`main.js`）合上，不能塞进某一个房间里。

**③ 示例代码**

`src/assets/global.css`（真实内容）：

```css
body {
    margin: 0;
    padding: 0;
    font-size: 14px;
    color: #333;
}
```

练习用：写得更完整一点，逐条看懂：

```css
/* 1. 清除浏览器默认的 body 外边距 */
/*    不写这两行，页面四周会有约 8px 白边，文字不会紧贴左上角 */
body {
    margin: 0;
    padding: 0;
    font-size: 14px;
    color: #333;
    font-family: "Microsoft YaHei", "PingFang SC", Arial, sans-serif;
}

/* 2. 盒模型统一成 border-box，让 width 包含 padding 和 border */
* {
    box-sizing: border-box;
}

/* 3. 去掉链接默认的下划线和蓝色 */
a {
    color: inherit;
    text-decoration: none;
}

/* 4. 所有图片默认不超出容器宽度 */
img {
    max-width: 100%;
}
```

`src/main.js`（引入位置）：

```js
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'
import '@/assets/global.css'

const app = createApp(App)

app.use(router)

app.mount('#app')
```

**④ 逐行拆解**
- **`body { margin: 0; padding: 0; }`**：浏览器给 `body` 的**默认样式**是 `margin: 8px`，不清掉页面内容四周就有一圈白边。**讲义第 8 条验收效果"文字紧贴浏览器左上角"就是靠这两行实现的**——删掉它，文字立刻向右下各退 8px。
- **`font-size: 14px; color: #333;`**：`font-size` 和 `color` 是**继承属性**，会被所有后代元素继承，所以整个网站的默认字号字色在这里一次定好，组件里不用重复写。`#333` 是深灰，比纯黑柔和，是通用做法。
- **`import '@/assets/global.css'` 为什么放 `main.js`？** 因为 `main.js` 是**唯一必然被执行到的入口脚本**，在这里引一次全站生效。放 `App.vue` 里也行，但那样"全局配置"就散落在组件里了。
- **为什么没有 `from`？** 这是**副作用导入**——CSS 没有"导出值"可接，import 它只是为了让 Vite 处理它、把样式插进页面。写成 `import styles from '...css'` 会得到一个莫名其妙的值，纯属画蛇添足。
- **样式生效顺序到底由什么决定？** 这是最容易混的一条，分两层：
  1. **先看选择器权重**。`body { color: red }`（元素选择器，权重 0-0-1）**永远打不过**组件里的 `.my-text { color: blue }`（类选择器，权重 0-1-0），**跟写在哪儿、谁先谁后毫无关系**。
  2. **权重相同时才看源码顺序，后写的赢。**
  所以 `global.css` 和组件样式的顺序**只在权重打平时才有意义**。而 `main.js:4` 这行 import 位置靠前（在所有组件被 import 之前），意味着**它的 CSS 排在组件 CSS 前面**——这是好设计：**全局打底，组件覆盖它**。
- **Vite 怎么把 CSS 弄进页面的？** 开发时它把 CSS 转成 JS 模块，执行到 `import` 那行就把 `<style>` 动态插进 `<head>`；构建时抽成独立 CSS 文件——**证据就在 `dist/assets/index-lNEktN1b.css`，内容正是那 6 行压缩后的结果。**

**⑤ 在你仓库里** —— `src/assets/global.css:1-6` 逐字核对过；`src/main.js:4` 的 `import '@/assets/global.css'` 位于三个 import 的**最后**、`createApp` 之前；`dist/assets/index-lNEktN1b.css` 内容是 `body{margin:0;padding:0;font-size:14px;color:#333}`，**说明这个全局样式确实被打包进去了**；`dist/index.html:8` 的 `<link rel="stylesheet" crossorigin href="/assets/index-lNEktN1b.css">` 就是构建后加载它的方式。`01/实验过程_实训1.md:215` 也记了"文字紧贴浏览器左上角（说明 `margin: 0; padding: 0` 生效了）"。

**⑥ 常见坑** —— **现象**：`global.css` 写好了也 import 了，样式没生效。**原因**：① 路径写错（Vite 会报 `Failed to resolve import`）；② **改完 CSS 没保存**（IDE 标签页上的小圆点还在）；③ 那行 import 被注释掉了。**怎么改**：看 **F12 → Network** 有没有 `global.css` 请求，或 F12 选中 `<body>` 看 Styles 里有没有你的规则。**现象**：`body` 的 margin 清了还有白边。**原因**：白边来自 `html` 或别的容器（比如 `App.vue` 里 `.page-body { padding: 16px }`）。**怎么改**：F12 选中那个有白边的**具体元素**，看是哪条规则给的间距，**别盲猜**。**现象**：组件里写 `body { color: red }` 不生效。**原因**：`scoped` 把选择器改写成 `body[data-v-xxxxxxx]`，而 `body` 上没有这个属性。**怎么改**：全局样式一律放 `global.css`。

**⑦ 自测** —— `global.css` 里写 `body { background: pink }`，`Home.vue` 里写 `<style scoped> body { background: green } </style>`，页面背景什么颜色？

<details><summary>看答案</summary>

**粉色（`global.css` 里的 pink）。**

原因：`scoped` 会把选择器改写成 `body[data-v-1a2b3c4d]`。Vue 只给它自己渲染出来的元素打上 `data-v-1a2b3c4d`，而 `<body>` 是 `index.html` 里的元素、**不归 `Home.vue` 管**，身上没这个属性，选择器匹配不到任何元素，**这条样式等于没写**。

如果去掉 `scoped` 就变成真正的全局样式了，两条规则都是 `body`、权重相同，这时才看源码顺序——`main.js:4` 的 import 在组件 import 之前，所以 `global.css` 在前，**绿色（组件里的）会赢**。

**记住：`<style scoped>` 作用不到 `body`、`html` 这类不属于本组件的元素。全局底色必须写在 `global.css`。**

</details>

### 2.21 `@` 路径别名的来历、和 `./` 的区别

**① 讲义怎么说** —— 第四部分第 7 条下方说明："`@` 是指向 `src` 的路径别名，在 `vite.config.js` 的 `resolve.alias` 里配好了，所以 `@/assets/global.css` 等价于 `./assets/global.css`"。**这个说明是对的**，但"等价"只在**当前这层目录**下成立，跨目录就不等价了（见 ④）。

**② 一句话讲透** —— `@` 是"**工程内部门牌号**"：不管你现在站在 `src` 下第几层，写 `@/xxx` 找的都是**从 `src` 出发**的路径；而 `./xxx` 是"**从我旁边找**"，你人一挪指向就变了。类比：**`@` 是公司内部分机号**——公司搬到哪层楼，拨"财务部"都能通；**`./` 是"我隔壁那间"**——你换个工位，隔壁就换人了。为什么需要它？在 `src/views/a/b/c/Detail.vue` 里引用 `src/assets/global.css`，相对路径要写 `../../../assets/global.css`，**数几个 `..` 是最容易数错的事**，而且一移动文件就要重数。

**③ 示例代码**

`vite.config.js`（`@` 别名的**定义处**，真实内容）：

```js
import { fileURLToPath, URL } from 'node:url'

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueDevTools from 'vite-plugin-vue-devtools'

// https://vite.dev/config/
export default defineConfig({
  plugins: [
    vue(),
    vueDevTools(),
  ],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    },
  },
})
```

`jsconfig.json`（别名的**编辑器端声明**，真实内容）：

```json
{
  "compilerOptions": {
    "paths": {
      "@/*": ["./src/*"]
    }
  },
  "exclude": ["node_modules", "dist"]
}
```

同一个文件的两种写法对照——在 `src/views/Home.vue` 里引用 `src/assets/logo.svg`：

```js
// 相对路径：从当前文件（src/views/）出发
import logo from '../assets/logo.svg'

// @ 别名：从 src 出发 —— 推荐
import logo from '@/assets/logo.svg'
```

在 `src/router/index.js` 里引用 `src/views/Home.vue`：

```js
// 相对路径：从当前文件（src/router/）出发
component: () => import('../views/Home.vue')

// @ 别名：移动 router 目录时不用改
component: () => import('@/views/Home.vue')
```

**④ 逐行拆解**
- **`import { fileURLToPath, URL } from 'node:url'`**：从 Node 内置模块取两个工具。`URL` 是**全局类的一个引用**（不是新东西），`fileURLToPath` 把 `file:///D:/...` 转成 `D:\...`。
- **`'@': fileURLToPath(new URL('./src', import.meta.url))`** 的意图是"**算出 `src` 的绝对路径**"，拆开看：`import.meta.url` 是**当前这个配置文件自己的 URL**（形如 `file:///D:/course/Javaweb/01/hello-vue/vite.config.js`）；`new URL('./src', import.meta.url)` 以它为基准解析出 `file:///D:/course/Javaweb/01/hello-vue/src`；`fileURLToPath` 转成 `D:\course\Javaweb\01\hello-vue\src`。**为什么要这么绕？因为 `resolve.alias` 要的是绝对路径**——写死 `'D:/course/Javaweb/01/hello-vue/src'` 的话，换台电脑、换个目录就废了。**注意这里是 `./src` 不是 `../src`**，因为基准是 `vite.config.js` 自己（它在工程根）。
- **改别名练手**：把 `'@'` 改成 `'@@'`，`main.js` 里的 `@/assets/global.css` 立刻报 `Failed to resolve import`。**这证明 `@` 不是 Vue 或 JavaScript 的内置语法，纯粹是 Vite 的配置。**
- **`jsconfig.json` 和 Vite 的 alias 是两件独立的事**：`vite.config.js` 的 alias 让**编译器**能找到文件（影响能不能跑）；`jsconfig.json` 的 `paths` 让 **IDEA / VS Code 的智能提示**能找到文件（只影响补全和跳转，**不影响运行**）。**两边必须同步改**——只改 Vite 能跑但 IDE 报红；只改 jsconfig 不报红但一运行就 `Failed to resolve import`。
- **`@` 和 `./` 哪里不等价？** 讲义说"`@/assets/global.css` 等价于 `./assets/global.css`"，**这句只在 `src/main.js` 这一个文件里成立**，因为 `main.js` 恰好就在 `src` 下，两者起点重合。换到 `src/views/Home.vue` 里，`./assets/global.css` 指的是 `src/views/assets/global.css`（**不存在**），而 `@/assets/global.css` 指的是 `src/assets/global.css`，**完全不同**。**正确说法：`@/xxx` 恒等于「`src` 目录下的 `xxx`」；`./xxx` 等于「当前文件旁边目录下的 `xxx`」。**
- **`@` 能用在哪些地方？** 只在 **JS 的 `import` 语句**里可靠生效。写在模板属性字符串里（`<img src="@/assets/a.png">`）**不生效**，见 2.17 的坑。

**⑤ 在你仓库里** —— 全部逐字核对过：`vite.config.js:1` 和 `:13-17`（`resolve.alias` 里的 `'@': fileURLToPath(new URL('./src', import.meta.url))`）；`jsconfig.json:3-5`（`"paths": { "@/*": ["./src/*"] }`）；`src/main.js:4` 是**工程里唯一一处实际使用 `@` 别名的代码**；`src/router/index.js:9` 用的是 `'../views/Home.vue'` **相对路径**——两种写法都合法，讲义给的就是相对路径版，**知道它们指向同一个文件比纠结用哪种更重要**。

**⑥ 常见坑** —— **现象**：报 `Failed to resolve import "@/assets/global.css" from "src/main.js". Does the file exist?`。**原因**：① alias 没配或被删；② 路径拼错（`assets` 写成 `asset`）；③ **改完 `vite.config.js` 没重启开发服务器**。**怎么改**：核对配置；**改 `vite.config.js` 必须 `Ctrl+C` 重跑 `npm run dev`**（这是少数必须重启的情况）。**现象**：代码能跑但 IDEA 里 `@/xxx` 有红波浪线。**原因**：`jsconfig.json` 的 `paths` 没配或 IDEA 没重新加载。**怎么改**：确认内容正确后 `File → Invalidate Caches / Restart`，或右键 `jsconfig.json` → `Reload project`。**现象**：别人 clone 后报 `Failed to resolve import` 而你本机是好的。**原因**：`vite.config.js` 没提交。**怎么改**：确认 `vite.config.js`、`jsconfig.json` 都在版本控制里。

**⑦ 自测** —— 在 `src/router/index.js` 里，`'../views/Home.vue'` 和 `'@/views/Home.vue'` 是同一个文件吗？把 `src/router/` 改名成 `src/routes/`，哪个要改？

<details><summary>看答案</summary>

**是同一个文件**，都指向 `D:\course\Javaweb\01\hello-vue\src\views\Home.vue`。

- `'../views/Home.vue'`：从 `src/router/index.js` 出发，`../` 回到 `src/` 再进 `views/`。
- `'@/views/Home.vue'`：`@` 就是 `src`，直接就是 `src/views/Home.vue`。

**改名成 `src/routes/` 之后：**
- `'../views/Home.vue'` —— `../` 依然回到 `src/`，所以**碰巧还是对的**（只改了父目录名字，层级没变）。
- 但如果把文件从 `src/router/index.js` 挪到 `src/router/admin/index.js`（**多了一层**），`'../views/...'` 就变成指 `src/router/views/...` 了，**必须改成 `'../../views/...'`**；而 `'@/views/Home.vue'` **一个字都不用改**。

**这就是 `@` 别名的真正价值：让路径和"当前文件在哪一层"解耦。** 相对路径不是不能用（Vue 官方脚手架生成的就是相对路径），但**层级一深，相对路径就是 bug 温床。**

</details>

## 6. 讲义勘误速查（本讲）

| 讲义原文 | 问题 | 正确写法 |
|---|---|---|
| `npm create vue@3.21.0` 配 `node-v20.15.1` | 版本不自洽：实测 `create-vue@3.21.0` 的 `engines` 是 `^20.19.0 \|\| >=22.12.0`，20.15.1 低于下限，会报 `EBADENGINE` | 装 Node 20.19 以上，或直接 22.x / 24.x（本机 Node 24.17.0 全流程正常） |
| `npm config set registry http://registry.npmmirror.com` | 用了 http，会被 301 重定向到 https，多一次往返 | `npm config set registry https://registry.npmmirror.com` |
| "App.vue 是作为项目的入口文件" | **说法错误**。入口是 `index.html`（页面入口）和 `src/main.js`（脚本入口），App.vue 是**根组件** | "App.vue 是根组件，main.js 才是入口" |
| 交互式问答截图是"四问式"，末尾问"是否跳过示例代码" | 截图与命令版本不匹配。实测 `create-vue@3.21.0` 是**功能多选清单**（TypeScript/JSX/Router/Pinia/Vitest/E2E/ESLint/Prettier 一屏勾选） | 以**实际跑出来的界面**为准；核心不变：**只保留 Vue Router，其余全不勾** |
| 正文写 `npm create vue@3.21.0`，截图里是 `npm create vue@latest` | 命令不统一；且 `latest` 要求更高 Node（实测 `create-vue@3.24.0` 要求 `^22.18.0 \|\| >=24.12.0`） | 统一写 `npm create vue@3.21.0`；**别盲目改成 `@latest`**，装 Node 20 的人一改就报 `EBADENGINE` |
| 反复出现 `http://localhost:5173` | 把端口写死了。Vite 在 5173 被占时会**自动 +1**（实测打印 `Port 5173 is in use, trying another one...`） | 端口以**终端里 `Local:` 那一行**为准。实验记录里实际跑出来的是 5171 |
| 讲义目录里放了 `jdk-21_windows-x64_bin.exe` | 本讲是纯前端（Node + Vue），**用不到 JDK**，放着容易让初学者误以为要先装 JDK | JDK 是给后续 SpringBoot 后端实训准备的，**实训1 不需要安装** |
| "同时观察环境变量，会有下图所示" | 只给截图不讲原理，学生不知道 PATH 是什么、为什么改了要重开窗口 | PATH 是系统的"程序搜索目录列表"（见 2.4 节）。**改完必须重开命令行窗口**才生效 |
| "精简 App.vue"、"修改 index.js，也就是精简路由" | 只给动作不给代码、不给解释 | 完整可粘贴的代码见 2.18 / 2.19 节 |

**最后提醒一句**：讲义正文里那些不准确的地方（尤其是"App.vue 是入口文件"），**考试答题时可以按讲义口径写**——但你自己心里必须清楚正确说法。这是两件事。
