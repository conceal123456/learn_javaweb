## 勘误 1（中）讲义让装 Node 20.15.1，但脚手架与 Vite 都要求 Node ≥ 20.19——**讲义自己的截图里就印着这两条警告**

- **性质**：讲义过时（版本差异），不是笔误。
- **【讲义原文】** 第一部分"Node.js部分"第 1 条："Nodejs20+版本、IntelliJIDEA2025版本"；"双击 `node-v20.15.1-x64.msi`"；第三步"验证是否安装成功…输入 `node -v`"。
- **【问题】** `npm create vue@3.21.0` 这个包（以及它生成的 Vite 7 工程）官方支持的最低 Node 是 **20.19.0**，20.15.1 低于下限。讲课截图里已经出现了警告，但正文没有任何解释，学生看到满屏黄色警告会以为装错了。
- **【实测证据】**
  1. registry 侧（决定 `npm install` 会不会 EBADENGINE）：
     ```
     $ npm view create-vue@3.21.0 engines
     { node: '^20.19.0 || >=22.12.0' }
     ```
  2. **讲义自己的截图**（`img01/image13.png`，第二部分"输入命令：`npm create vue@3.21.0`"那张）原文：
     ```
     D:\my-project\xm-pro>npm create vue@3.21.0
     npm warn EBADENGINE Unsupported engine {
     npm warn EBADENGINE   package: 'create-vue@3.21.0',
     npm warn EBADENGINE   required: { node: '^20.19.0 || >=22.12.0' },
     npm warn EBADENGINE   current: { node: 'v20.15.1', npm: '10.7.0' }
     npm warn EBADENGINE }
     ```
  3. **讲义自己的截图**（`img01/image18.png`，第四部分第 8 条"`npm run dev`"那张）原文：
     ```
     You are using Node.js 20.15.1. Vite requires Node.js version 20.19+ or 22.12+. Please upgrade your Node.js version.
     VITE v7.3.5  ready in 4317 ms
     ➜  Local:   http://localhost:5173/
     ```
  4. 本次用**真实 Node 20.15.1** 复跑仓库工程（不是推断）：
     ```
     $ npx --yes node@20.15.1 -v
     v20.15.1
     $ npx --yes node@20.15.1 node_modules/vite/bin/vite.js --port 5182 --strictPort
     [stderr] You are using Node.js 20.15.1. Vite requires Node.js version 20.19+ or 22.12+. Please upgrade your Node.js version.
     VITE v7.3.6  ready in 1299 ms
     ➜  Local:   http://localhost:5182/
     ```
     即：**只警告，不退出**。源码依据 `node_modules/vite/dist/node/cli.js:496`：`if (!checkNodeVersion(...)) console.warn(...)`（没有 `process.exit`）。
  5. 仓库里实训1 工程的 `package.json` 里 `"engines": { "node": "^20.19.0 || >=22.12.0" }` 与上述一致。
- **【正确写法】** 讲义应改成："装 **Node 20.19 以上**（推荐 22.x / 24.x）；Node 20.15.1 会触发 npm `EBADENGINE` 与 Vite 的黄色警告，虽然当前还能跑，但不在官方支持范围。"
- **【影响程度】** 中：不阻塞建工程，但初学者第一次跑就吃两条警告；若换成 `@latest`（3.24.0）要求 `^22.18.0 || >=24.12.0`，20.x 全线不达标。

## 勘误 2（中）"做如下选择"的截图不是 `create-vue@3.21.0` 的界面，而是 **@latest（3.22.0+）** 的界面——学生按讲义敲 3.21.0，会找不到"是否使用 TypeScript 语法？"这一问

- **性质**：讲义版本混乱（两张截图来自两个不同版本）。
- **【讲义原文】** 第二部分第 2 条："输入命令：`npm create vue@3.21.0` 按回车" → 图 `img01/image13.png`（命令行里确实是 `npm create vue@3.21.0`）；紧接着："做如下选择：" → 图 `img01/image14.png`（命令行标题却是 `npm create vue@latest`，界面是"四问式"：**是否使用 TypeScript 语法？No** → 请选择要包含的功能（空格选择）Router → 选择要包含的试验特性 none → **跳过所有示例代码？** Yes）。
- **【问题】** 讲义让跑 `3.21.0`，但"照这个选"的截图是另一个版本（`@latest`）的界面。`create-vue@3.21.0` 的交互是：项目名 → **功能多选（TypeScript 就在这个列表里，没有独立的是/否提问）** → 选择要包含的试验特性 → 跳过所有示例代码。学生看着截图找"是否使用 TypeScript 语法？"会找不到；反过来也可能在功能多选里误勾 TypeScript。
- **【实测证据】** 本次 `npm pack create-vue@<版本>` 后逐个读 `locales/zh-Hans.json` 与 `bundle.js` 的问答流程：
  ```
  create-vue 3.21.0 : needsTypeScript = "TypeScript"（并入功能多选）  | 有"跳过所有示例代码"
  create-vue 3.22.0 : needsTypeScript = "是否使用 TypeScript 语法？"  | 有"跳过所有示例代码"
  create-vue 3.23.0 : needsTypeScript = "是否使用 TypeScript 语法？"  | 有"跳过所有示例代码"
  create-vue 3.24.0 : needsTypeScript = "是否使用 TypeScript 语法？"  | 有"跳过所有示例代码"
  create-vue 3.14.0 : needsTypeScript = "是否使用 TypeScript 语法？"  | 无"跳过所有示例代码"
  ```
  `bundle.js` 里 3.21.0 的流程为 `projectName → features(multiselect) → experimentFeatures(multiselect) → needsBareboneTemplates`；3.24.0 为 `projectName → needsTypeScript(confirm) → features(multiselect) → experimentFeatures → needsBareboneTemplates`。**image14 的界面（独立 TS 问 + 功能多选 + 试验特性 + 跳过示例）只有 3.22.0+ 才有**，与 image14 顶部命令行 `npm create vue@latest` 完全吻合（当前 latest = 3.24.0）。
- **【正确写法】** 两条路选一条并保持图文一致：
  - 想锁 3.21.0：把"做如下选择"的截图换成 3.21.0 的真实界面，说明"**TypeScript 在功能多选列表里，不选它**；只按空格勾 `Router（单页面应用开发）`；试验特性直接回车；`跳过所有示例代码` 选 **Yes**"。
  - 想用 @latest：正文命令改成 `npm create vue@latest`，并明确"当前 latest=3.24.0，要求 Node ≥22.18"。
- **【影响程度】** 中：最终生成的工程结构一样（JS + Router + 跳过示例），但过程与截图对不上，学生会卡在"找不到这一步"。

> 旧勘误第 3 条的两处错误：① 把该截图说成"**旧版**界面"——实际是**新版**（≥3.22）；② 说 3.21.0"**没有**跳过示例这一问"——实际**有**（`needsBareboneTemplates`，"跳过所有示例代码，创建一个空白的 Vue 项目？"）。本文件以此为准。

## 勘误 3（中-低）正文写 `npm create vue@3.21.0`、官网截图却是 `npm create vue@latest`：两条命令生成**两套不同**的工程

- **性质**：讲义版本混乱 + 没解释版本差异。
- **【讲义原文】** 第二条第 1 步："打开官网 https://cn.vuejs.org/ …找到这条命令，并进行复制" → 图 `img01/image9.png` 是官网给的 `npm create vue@latest`；第 2 步却让"输入命令：`npm create vue@3.21.0`"。
- **【问题】** 学生"照着官网复制"或"照讲义敲"会得到不同代际的脚手架：3.21.0 → Vite 7 / vue-router 5.0.1 / engines `^20.19.0 || >=22.12.0`；3.24.0 → **Vite 8.2.2 / vue-router 5.3.1 / engines `^22.18.0 || >=24.12.0`**。后续讲义的截图（Vite 7）与目录结构都是 3.21.0 代的。
- **【实测证据】** 本次分别真实生成两个工程，读 `package.json`：

  ```jsonc
  // npm create vue@3.21.0 tmp-app --router --bare
  { "dependencies": { "vue": "^3.5.27", "vue-router": "^5.0.1" },
    "devDependencies": { "@vitejs/plugin-vue": "^6.0.3", "vite": "^7.3.1" },
    "engines": { "node": "^20.19.0 || >=22.12.0" } }

  // npm create vue@3.24.0 tmp-latest --router --bare
  { "dependencies": { "vue": "^3.5.42", "vue-router": "^5.3.1" },
    "devDependencies": { "@vitejs/plugin-vue": "^6.0.8", "vite": "^8.2.2" },
    "engines": { "node": "^22.18.0 || >=24.12.0" } }
  ```
  仓库内也复现了这种"代际不统一"：`实训1/工程/hello-vue` 是 3.21.0 代（vite ^7.3.1），而 `实训2/工程/vue-syntax`、`实训3/工程/element-plus` 是 3.24.0 代（vite ^8.2.2、engines `^22.18.0`）——**同一门课三讲用了两个脚手架代际**，同学之间按不同文档建工程会互相不一致。
- **【正确写法】** 全文统一一条命令、并把版本号含义写出来：`@` 后面是**脚手架 create-vue 的版本**（3.21.0 / 3.24.0），不是 Vue 的版本；Vue 版本由模板写进 `package.json`（3.21.0 给 `^3.5.27`，3.24.0 给 `^3.5.42`）。若统一用 3.21.0，请把官网截图替换或标注"官网默认给 latest，本课固定用 3.21.0"。
- **【影响程度】** 中-低：能建出来，但和后续截图/依赖版本对不上；`@latest` 对 Node 20 用户更不友好。

## 勘误 4（低）npm 镜像命令用 `http://`，实测会 301 跳转到 `https://`

- **性质**：讲义不够新（可用但多一跳）。
- **【讲义原文】** 第一部分第 4 条："输入：`npm config set registry http://registry.npmmirror.com`"。
- **【问题】** npmmirror 早已只认 https，http 会 301。
- **【实测证据】**
  ```
  $ curl -s -o NUL -w 'http=%{http_code} redirect=%{redirect_url}' http://registry.npmmirror.com
  http=301 redirect=https://registry.npmmirror.com/
  $ curl -s -o NUL -w 'http=%{http_code}' https://registry.npmmirror.com
  http=200
  ```
- **【正确写法】** `npm config set registry https://registry.npmmirror.com`
- **【影响程度】** 低：npm 会跟随 301，装包不会失败；只是每次多一次跳转，个别网络环境下 http 会被拦。

## 勘误 5（低）"App.vue 是作为项目的入口文件"——概念错，入口是 `main.js`

- **【讲义原文】** 第四部分第 5 条："5.精简 App.vue，App.vue 是作为项目的入口文件"。
- **【问题】** 真正的入口是 `src/main.js`（`index.html` 里 `<script type="module" src="/src/main.js">`，main.js 里 `createApp(App).mount('#app')`）。App.vue 是**根组件**，负责放 `<RouterView />`。讲义后文"精简 App.vue"的操作本身没错，错的是"入口文件"这个定性。
- **【实测证据】** 仓库 `实训1/工程/hello-vue/index.html` 只加载 `/src/main.js`；`src/main.js` 里 `const app = createApp(App)`；`src/App.vue` 全文只有 `<template><RouterView /></template>`（与讲义 `img01/image36.png` 一致）。
- **【正确写法】** "App.vue 是**根组件**（页面最外层容器）；`main.js` 才是**入口**，`createApp(App).mount('#app')` 在那里。"
- **【影响程度】** 低：不影响操作，但概念错误会在实训5（路由）、实训7（前后端联调）追问"谁先执行"时暴露。

## 勘误 6（低）"看不见运行绿色三角形"的原因归到了"IDEA 没激活 / 没以管理员身份启动"——**未证实，且不合常理**

- **性质**：讲义归因可疑（无法在本机复现/验证）。
- **【讲义原文】** 第三部分末尾："注意：如果看不见运行的绿色三角形，可能的情况有：Idea2025旗舰版没有激活；Idea2025旗舰版没有用管理员身份启动。"
- **【问题】** IntelliJ IDEA 能否在 `package.json` 的 `scripts` 旁显示绿色三角（npm 运行配置的 gutter 图标），取决于 **Node.js 插件 / JavaScript 插件是否启用、项目是否被识别为 npm 项目、package.json 是否在项目根**；与"是否激活/是否管理员启动"没有因果关系（管理员启动 IDEA 反而常导致文件权限混乱，不是推荐做法）。
- **【实测证据】** 本机没有 IDEA，**无法实测**；本条只能标"未证实"。可确证的是：仓库工程 `package.json` 里 `"scripts": { "dev": "vite", ... }` 存在，命令行 `npm run dev` 可正常起服务（见勘误 1 第 4 条实测）——即"工程本身没问题"。
- **【正确写法】** 改为排查清单："① 确认装了 Node.js 插件并在 Settings → Node.js 里选对解释器；② 确认 `package.json` 在项目根目录；③ 右键 `package.json` → `Show npm Scripts`；④ 仍不行就直接在 Terminal 里 `npm run dev`。"
- **【影响程度】** 低：多数学生不会遇到；遇到的人按讲义排查会白折腾。

## 勘误 8（低）正文写"粘贴 `home.vue`"，截图与实际文件是 `Home.vue`（大小写不一致）

- **【讲义原文】** 第四部分第 3 条："在 src 文件夹右键 → 新建目录，命名 views，粘贴 home.vue"；而讲义目录里提供的文件是 `讲义/Home.vue`，截图 `img01/image34.png` 里也是 `Home.vue`，路由里写的是 `import('../views/Home.vue')`。

## 勘误 9（低）"删除不需要的文件"里删掉了 `.gitignore`——讲义没提副作用

- **【讲义原文】** 第三部分"删除不需要的文件"图 `img01/image25.png`，红字"删除这三个文件"：`.vscode`、`.gitignore`、`README.md`。
- **【问题】** 删 `.vscode`、`README.md` 无所谓；**删 `.gitignore` 会让 `node_modules/`、`dist/` 不再被 Git 忽略**。本课程后续要提交仓库（本仓库 `.gitignore` 里就有 `**/node_modules/`、`**/dist/`），学生若在自己工程里 `git init` 提交，会把几百 MB 的 node_modules 一起提交。
- **【实测证据】** 仓库根 `.gitignore` 明确列了 `**/node_modules/`、`**/dist/`；而 `实训1/工程/hello-vue` 目录下确实没有 `.gitignore`（按讲义删掉了），其 `node_modules` 目前靠**仓库根**的 `.gitignore` 兜底。
- **【正确写法】** 只删 `.vscode`、`README.md`，保留 `.gitignore`；或说明"删了以后自己补一个忽略 node_modules 的 .gitignore"。
- **【影响程度】** 低（本仓库有根级 .gitignore 兜底；学生独立建仓时会踩）。
