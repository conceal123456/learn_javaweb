## 勘误 1（中）`color="#6666"` 写了两处：它是合法的 4 位 `#RGBA`（半透明灰），不是作者想要的 `#666666`

- **性质**：讲义笔误（不报错、不崩，只是颜色不对——最难发现的那种）。
- **【讲义原文】** 二、全局使用 icon 第 3 步"在浏览器就可以发现图标已经可以使用了"：
  ```html
  <div>
    <span style="margin-left: 30px; color: #6666">
      <el-icon :size="60" color="#6666" style="top: 4px"><School /></el-icon> 安中医
    </span>
  </div>
  ```
  两处 `#6666`：外层 `span` 的 `color` 一处、`el-icon` 的 `color` 属性一处。
- **【问题】** 十六进制颜色合法长度只有 3/4/6/8 位。**4 位 = `#RGBA`**，`#6666` = R=6,G=6,B=6,A=6 → `rgba(102,102,102,0.4)`（40% 不透明）。所以图标和"安中医"三个字都会**发淡**，而不是讲义想要的实色中灰。浏览器完全合法、不报错。
- **【实测证据】**（`errata_a_browser.mjs`，真实 Chrome 打开 `/home`）
  ```
  spanInline   : "color: rgba(102, 102, 102, 0.4);"     // #6666
  spanColor    : "rgba(102, 102, 102, 0.4)"
  iconColorProp: "rgba(102, 102, 102, 0.4)"              // el-icon 的 color 也走 CSS 变量
  svgFill      : "rgba(102, 102, 102, 0.4)"              // svg 的 fill 跟随 currentColor
  --- 对照（#666666）---
  spanInline   : "color: rgb(102, 102, 102);"
  iconColorProp: "rgb(102, 102, 102)"
  svgFill      : "rgb(102, 102, 102)"
  ```
  即：`#6666` 与 `#666666` 的 RGB 三个分量**完全相同**，差别只在 alpha=0.4。lab-runner-a 的截图 `.extract/verify/shots/03_shiXun3_home.png` 也是"左浅右深"。
- **【正确写法】** 两处都改成 `#666666`（或 `#666`）；**外层 span 与 el-icon 要一起改**，否则"安中医"三个字仍然是淡的。若真想要半透明，写 `#66666666`（8 位）更不容易误读。
- **【影响程度】** 中：不影响功能，但这是"照讲义做出来的配色和预期不一样"的一个典型；讲师若把它当"正常现象"会传递错误认识。

## 勘误 2（中）`app.use(ElementPlus, …)` 讲义只说"放在合适的位置"——放错位置（`createApp` 之前）会**整个页面白屏报错**

- **【讲义原文】** 一、安装 Element Plus 第 3 步："在 main.js 里面引入，将下面代码放在合适的位置："，随后列出 `import ElementPlus… / import 'element-plus/dist/index.css' / import zhCn… / app.use(ElementPlus, { locale: zhCn })`。二、全局使用 icon 第 2 步："在 main.js 里引入"（图标注册循环）。
- **【问题】** 这两段都依赖变量 `app`，必须在 `const app = createApp(App)` **之后**（且 `app.mount('#app')` 之前）。讲义没有把顺序讲死，学生"按直觉"贴在文件顶部（那里正好是 import 区）就会报错白屏。
- **【实测证据】**
  - JS 语义（本次实跑）：
    ```
    $ node -e "try{ app.use(1) }catch(e){ console.log(e.constructor.name+': '+e.message) }; const app={use(){}}"
    ReferenceError: Cannot access 'app' before initialization
    ```
  - 讲义自己的截图 `img03/image8.png`（改完后的 main.js）顺序是对的：`const app = createApp(App)`（第 10 行）→ `app.use(router)`（12）→ `app.use(ElementPlus,{locale:zhCn})`（13-15）→ 图标循环（16-20）→ `app.mount('#app')`（21）。仓库 `实训3/工程/element-plus/src/main.js:12-21` 也精确照此执行，`/home` 实测无任何 console 报错、按钮与图标正常（本次浏览器采到的 console 只有 Vite 的 `[vite] connected`）。
- **【正确写法】** 明确写死："`app.use(...)` 与图标注册循环必须放在 `const app = createApp(App)` 之后、`app.mount('#app')` 之前。"
- **【影响程度】** 中：顺序错就是运行时报错、白屏；这是本讲最容易"抄漏一行就卡住"的地方。

## 勘误 3（低-中）`讲义/资源/main.js` 是"装完 Element Plus、**还没注册图标**"的中间版本——学生拿它覆盖 main.js，会把第二步的图标注册冲掉

- **性质**：讲义配套资源与讲义步骤不同步。
- **【讲义原文/证据】** 讲义目录里的实体文件 `实训3_前端ElementPlus框架/讲义/资源/main.js`（356 字节）全文：
  ```js
  import { createApp } from 'vue'
  import App from './App.vue'
  import router from './router'
  import ElementPlus from 'element-plus'
  import 'element-plus/dist/index.css'
  import '@/assets/global.css'
  import zhCn from 'element-plus/es/locale/lang/zh-cn'

  const app = createApp(App)

  app.use(router)
  app.use(ElementPlus, { locale: zhCn })

  app.mount('#app')
  ```
  文件里**没有** `import * as ElementPlusIconsVue …`，也没有 `for (const [key, component] of Object.entries(...))` 循环。
- **【问题】** 这份资源对应的是"一、安装 Element Plus"完成后的状态。学生如果把它当成"最终版 main.js"去覆盖，第二步辛苦加的图标全局注册就没了，第二章 `<School />` 立刻报 `Failed to resolve component: School`。
- **【实测证据】** 逐字比对：`讲义/资源/main.js` 与 `img03/image4.png`（红字"原先的 main.js"）一致；讲义 `img03/image8.png`（"修改后"）比它多出**图标 import + 注册循环**整整 5 行。仓库的 `src/main.js` 按 image8 写全，`/home` 实测 `<School />` 渲染出 60×60 的 svg（含 3 个 `<path>`）。
- **【正确写法】** 资源文件改名为 `main_step1.js`（或补齐图标注册为最终版）；讲义里注明"这是第 1 步后的版本，第 2 步还要再加图标注册"。
- **【影响程度】** 低-中：照抄"资源"文件夹会丢功能，且报错信息（组件未解析）与图标注册距离较远，不好排查。

## 勘误 4（低）"`app.component(组件名, 组件实例)`"用词不准：第二个参数是**组件定义**，不是实例

- **【讲义原文】** 二、全局使用 icon 截图 `img03/image8.png` 红字："`app.component(组件名, 组件实例)` 是 Vue3 全局注册组件的核心方法。通过这个方法注册后的组件，项目内所有页面、子组件都可以直接使用，不需要单独 import 引入。"
- **【问题】** `app.component(name, definition)` 的第二个参数是**组件定义**（SFC 导出的组件选项对象 / `setup` 函数），不是"组件实例"；实例是 `createApp` 之后由 Vue 创建的。用词错了不影响使用，但概念会糊，后面讲 `ref` 拿组件实例（`ref` + `$refs`）时容易混淆。
- **【实测证据】** 讲义代码本身 `app.component(key, component)` 中 `component` 来自 `Object.entries(ElementPlusIconsVue)`，即图标包导出的**组件定义对象**；仓库同款代码在 `main.js:19-21`，运行正常。
- **【正确写法】** "第二个参数是**组件定义**（图标包导出的组件对象），注册后任意模板可直接写 `<School />`，不用再 import。"
- **【影响程度】** 低：措辞问题，不影响运行。

## 勘误 5（低）"全量引入 Element Plus + 全量注册约 300 个图标"的产物体积代价，讲义没提

- **性质**：不是错误，是"讲义做法"的客观代价，建议补一句知情说明。
- **【讲义原文】** 一、"import ElementPlus from 'element-plus'" + 二、全局注册全部图标。
- **【问题】** 全量 `app.use(ElementPlus)` + 全量注册图标，构建产物很大；本仓库构建实测 **主 chunk 1.16 MB、CSS 约 360 KB，并触发 Vite 的 `chunk > 500 kB` 警告**（lab-runner-a 实测：`.extract/verify/frontend-a.md` §1、§4；本次未重复 build，引用该证据）。
- **【正确写法】** 课堂照旧全量引入没问题（简单），但补一句："生产项目可改用按需引入（`unplugin-vue-components`）或只注册用到的图标，能显著减小体积。"
- **【影响程度】** 低：教学阶段可接受，不是讲义错误。
