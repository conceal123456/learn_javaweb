## 2. 知识点精讲
### 2.1 插值表达式 `{{ }}`
**讲义怎么说**：讲义开头写着"`{{ }}` 双大括号：Vue 插值表达式（文本插值），作用：专门在 Vue 的 `<template>` 模板里，渲染 JS 变量、表达式到页面文本，把数据转换成普通文字展示"。

**一句话讲透**：`{{ }}` 是模板上唯一一个"把 JS 的值印到屏幕上"的洞口。它像打印机的出纸口：塞进去的必须是**算好的结果**（变量、算式、三元、函数调用），不能是**操作指令**（`if`、`for` 这类"要干什么"的句子，打印机不认）；而且它只印字——塞一段 HTML 进去，尖括号也照样印出来。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { reactive, ref } from 'vue'

const name = ref('安徽中医药大学')
const score = ref(72)
const info = reactive({ colleges: ['信工院', '药学院'] })

const level = () => (score.value >= 60 ? '及格' : '不及格')
</script>

<template>
  <p>变量：{{ name }}</p>
  <p>算术表达式：{{ score + 8 }}，{{ score / 2 }}</p>
  <p>三元表达式：{{ score >= 60 ? '及格' : '不及格' }}</p>
  <p>方法调用：{{ level() }}</p>
  <p>字符串拼接：{{ name + ' · ' + info.colleges.length + ' 个学院' }}</p>
  <p>布尔值与数组：{{ score > 60 }}，{{ info.colleges }}</p>
</template>
```
**逐行拆解**：
- `{{ name }}` → `安徽中医药大学`：放变量名。`name` 是 `ref`，模板里**不要写** `.value`，Vue 会自动解包。
- `{{ score + 8 }}` → `80`：表达式可以算。写成 `{{ score.value + 8 }}` 也能跑，但模板里 `.value` 是多余的。
- `{{ score >= 60 ? '及格' : '不及格' }}`：三元是**表达式**，可以放；`{{ if (score >= 60) {} }}` 是**语句**，编译直接报 `Error parsing JavaScript expression`（实测）。
- `{{ level() }}`：函数调用也行，但每次重新渲染都会调用一次；别在里面改数据，会无限触发更新。
- `{{ info.colleges }}` → `[ "信工院", "药学院" ]`、`{{ score > 60 }}` → `true`：数组会被转成 JSON 字符串（想显示"信工院、药学院"要自己 `join('、')`），布尔值显示成字符串 `true`，不是打勾也不是隐藏。

**在你仓库里**：`src/views/Home.vue:6` 一行插了三个字段（`data.school`、`data.no`、`data.ok`）；`:13` 插一个 `ref`（`{{ score }}`）；`:24` 在插值里做加法（`{{ index + 1 }}. {{ item }}`）；`:34` 与 `:57` 在插值里放 `||` 兜底。

**常见坑**：
- 页面白屏 + 控制台 `Error parsing JavaScript expression` → 你往 `{{ }}` 里写了 `if`/`for`/`const` 这类语句 → 改成三元，或把逻辑搬进 `<script setup>` 写成函数再调用。
- 属性里写 `src="{{ url }}"`，图片裂 → `{{ }}` 只在**标签内容**里生效，写在属性里会原样变成字符串（实测编译结果就是 `src: "{{ url }}"`）→ 属性值来自 JS 一律用冒号：`:src="url"`。
- 插值里的 HTML 变成源码文字 → 插值只输出文本，转义是故意的 → 真要渲染 HTML 用 `v-html`；但内容是用户填的就别用，会 XSS。

**自测**：`{{ }}` 里能不能写 `{{ list.filter(x => x > 2) }}` 这种带箭头函数的表达式？
<details><summary>看答案</summary>

能。插值里放的是**表达式**，`list.filter(...)` 是一次求值，箭头函数是它的参数。两点注意：结果是数组，会显示成 JSON 字符串，通常还要 `.join('、')`；`filter` 每次重新渲染都会重跑，数据量大时该改用 `computed` 缓存。

</details>

### 2.2 数据绑定总述：两块黑板与"响应式"
**讲义怎么说**：讲义"一、数据绑定"打了个比方——第一块黑板是 JS（`<script setup>`），放你的数据；第二块黑板是页面（`<template>`），给用户看；"数据绑定 = 把两块黑板粘在一起，自动同步"。

**一句话讲透**：数据绑定就是**只擦一块黑板，另一块自己跟着变**。但这个"自动"有前提——你擦的那块必须是**响应式**的。普通变量（`let plain = '...'`）像写在便利贴上：改了 Vue 根本不知道，页面不动；`ref`/`reactive` 包出来的数据才连着一条通知线，改一下就喊 Vue 重画用到它的那一小块。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { ref } from 'vue'

const mood = ref('开心')     // 响应式：值一变，页面自己跟着变
let plain = '普通变量'        // 不是响应式：改了页面不会动

function changeReactive() {
  mood.value = '被按钮改成：非常开心'
}
function changePlain() {
  plain = '普通变量被改了'
  console.log('控制台里 plain 已经变成：', plain)
}
setTimeout(() => { mood.value = '3 秒到了，这行字是 JS 改数据后自己变的' }, 3000)
</script>

<template>
  <p>mood（ref）＝ {{ mood }}</p>
  <p>plain（let）＝ {{ plain }}</p>
  <button @click="changeReactive">改响应式数据</button>
  <button @click="changePlain">改普通变量</button>
</template>
```
**逐行拆解**：
- `const mood = ref('开心')`：`ref` 把值包成一个带通知线的盒子；盒子里一变，用到它的地方就重画。
- `let plain = '普通变量'`：普通变量。实测点"改普通变量"后，控制台打印出了新值，**页面一个字没变**。
- 再点"改响应式数据"：页面重新渲染，`plain` 的新值"普通变量被改了"**跟着冒出来了**（实测）——因为它不是响应式，只是被顺带重读一次。这种"时好时坏"最坑人，所以数据一律用 `ref`/`reactive`。
- `setTimeout(...)`：整段代码没碰过一次 DOM，3 秒后那行字自己变了，这就是"数据驱动视图"；`<script setup>` 与 `<template>` 是同一个文件里的两块黑板，上面写数据和方法，下面写"长什么样"，桥由 Vue 搭。

**在你仓库里**：`src/views/Home.vue:61-107` 是 `<script setup>` 黑板（数据、函数、生命周期都在这里）；`:1-59` 是 `<template>` 黑板，里面没有一个 `document.xxx`；`src/main.js:10` 的 `app.mount('#app')` 是 Vue 接管页面的起点；`src/router/index.js:9` 把路由 `/` 指向 Home.vue。

**常见坑**：
- 改了变量页面纹丝不动，`console.log` 却有新值 → 变量是普通 `let`/`const`，不是响应式 → 用 `ref` 包起来，改的时候写 `.value`。
- 数据改了，页面要等下一次别的操作才更新 → 你改的是普通变量，正好赶上别的响应式变化触发重渲染 → 同上，别依赖"凑巧刷新"。
- 手写 `document.getElementById(...).innerText = x` 也能显示 → 那是绕开数据绑定直接改 DOM，数据和页面从此两套 → 页面上的东西一律由数据决定。

**自测**：为什么 Vue 能做到"改一行 JS，页面对应那块自动更新"，而不是整页刷新？
<details><summary>看答案</summary>

渲染时 Vue 记录了"哪块 DOM 用到了哪个响应式数据"（依赖收集）。你改 `mood.value` 时它收到通知，只把用到 `mood` 的那部分重新执行、和上次结果比对（diff），有差异才动真实 DOM——既不刷新整页，也不碰无关节点。

</details>

### 2.3 `ref` 与 `reactive`
**讲义怎么说**：讲"一、数据绑定"末尾只给了两行结论——"`ref`：基础类型（数字、字符串、布尔）"、"`reactive`：对象 / 数组（复杂数据）"，没说为什么。

**一句话讲透**：`ref` 是**带通知线的快递柜**，什么都能装，但拿东西要先开盖（`.value`）；`reactive` 是**给整个房间装监控**，家具随便挪（属性直接读写，不用 `.value`），但你不能把整个房间搬走（不能整体替换）。选哪个只看一条：要整体换掉就用 `ref`，只是改里面的字段就用 `reactive`。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { reactive, ref } from 'vue'

const count = ref(0)                     // 基础类型 → ref

const student = reactive({               // 对象 → reactive
  name: '张三',
  age: 20,
  hobbies: ['八段锦', '认中药']
})

function change() {
  count.value++          // ref 在 JS 里必须写 .value
  student.age += 1       // reactive 直接改属性，没有 .value
  student.hobbies.push('写代码')
}

function resetStudent() {
  // reactive 不能整体替换，要一次覆盖多个字段就用 Object.assign
  Object.assign(student, { name: '李四', age: 21, hobbies: ['针灸'] })
}
</script>

<template>
  <p>count（模板里不写 .value）：{{ count }}</p>
  <p>学生：{{ student.name }}，{{ student.age }} 岁，爱好：{{ student.hobbies.join('、') }}</p>
  <button @click="change">改一改</button>
  <button @click="resetStudent">重置学生</button>
</template>
```
**逐行拆解**（括号里是实测数据）：
- `const count = ref(0)`：`ref` 返回的是个对象（控制台里长得像 `RefImpl { value: 0 }`），数字装在 `.value` 里。
- `count.value++`：JS 里**必须** `.value`。忘了写，`count + 10` 得到 `"[object Object]10"`（实测），页面也不变。
- `{{ count }}`：模板里**不能**写 `.value`，Vue 自动解包；写了 `{{ count.value }}` 也能出结果，纯属多余。
- `student.age += 1` / `student.hobbies.push('写代码')`：reactive 的嵌套对象、数组同样是响应式的，`push` 一样触发更新。
- `Object.assign(student, {...})`：reactive **不能整体替换**。实测 `student = {...}` 之后 `isReactive(student)` 变成 `false`，再改它谁也不通知；用 `const` 声明时更直接，抛 `TypeError: Assignment to constant variable`。

**在你仓库里**：`src/views/Home.vue:65-72` 用 `reactive` 装了一组数据（字符串、数字、布尔、数组、空字符串各一个）；`:75`、`:78`、`:99` 是三个 `ref`（`score`、`count`、`mountedAt`，都是基础类型）；`:81-86` 用 `reactive` 装样式对象 `box`；`:88`、`:93` 直接改属性（`box.backgroundColor = ...`、`data.imgUrl = ...`）；`:102` 写 `.value`（`mountedAt.value = ...`）。

**常见坑**：
- 点按钮数字不变，控制台看 `count` 是个对象 → `ref` 忘了 `.value` → JS 里统一写 `.value`，模板里不写。
- `data = { school: '新学校' }` 之后页面死了 → `reactive` 被整体替换，代理被扔掉 → 逐字段改，或 `Object.assign(data, newObj)`，或改用 `ref({...})` 再 `data.value = newObj`。
- `const { school } = data` 之后改 `school` 页面不动 → 解构出来的是**当时的死值** → 用 `toRefs(data)` 解构（实测：`toRefs` 出来的引用改一下 `watch` 正常触发，直接解构则不触发）。

**自测**：一个组件的学生信息（姓名、年龄、爱好数组）你会用 `ref` 还是 `reactive`？
<details><summary>看答案</summary>

看你要不要"整体替换"。用 `reactive({...})` 模板里写 `student.name` 更顺、改属性方便，但不能 `student = 新对象`；用 `ref({...})` 能整体替换（`student.value = res.data`），从后端拿到一整条数据要赋值时特别顺手——实训7 里的 `data.value = json.data` 就是这个用法。要选一个：**表单/多条字段用 reactive，整块数据来自接口用 ref**。

</details>

### 2.4 `v-model` 双向绑定
**讲义怎么说**：讲义"二、双向数据绑定 v-model"只有一句："实现表单双向数据绑定：JS 变量改了 → 页面输入框内容自动变。用户在输入框输入内容 → JS 变量同步更新。"

**一句话讲透**：普通数据绑定是**单行道**（数据 → 页面），`v-model` 修了一条**回程路**（页面 → 数据）。它像双向对讲机：你在页面上打字，变量里立刻有了；你在代码里改变量，输入框里的字跟着变。它不是新魔法，本质就是 `:value`（把值送进去）+ `@input`（把输入捞回来），Vue 把这两件事打包成了一个指令。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { ref } from 'vue'

const text = ref('')
const agree = ref(false)
const gender = ref('女')
const city = ref('')
const hobbies = ref([])
const age = ref(null)

const cities = ['合肥', '亳州', '黄山']
const hobbyList = ['八段锦', '认中药']
</script>

<template>
  <p>文本框：<input v-model="text" /> 实时回显：{{ text }}</p>
  <p>单个复选框（绑布尔）：<input type="checkbox" v-model="agree" /> 我已阅读</p>
  <p>单选按钮（一组共用 gender）：
    <label><input type="radio" value="男" v-model="gender" /> 男</label>
    <label><input type="radio" value="女" v-model="gender" /> 女</label>
  </p>
  <p>复选框组（绑数组，每个框写 :value）：
    <label v-for="h in hobbyList" :key="h"><input type="checkbox" :value="h" v-model="hobbies" /> {{ h }}</label>
  </p>
  <p>下拉框：
    <select v-model="city">
      <option value="">请选择</option>
      <option v-for="c in cities" :key="c" :value="c">{{ c }}</option>
    </select>
  </p>
  <p>数字框加 .number：<input type="number" v-model.number="age" /></p>
  <p>汇总：{{ text }}｜{{ agree }}｜{{ gender }}｜{{ city || '（未选）' }}｜{{ hobbies.join('、') || '（未选）' }}｜{{ age }}（{{ typeof age }}）</p>
</template>
```
**逐行拆解**（括号里是实测数据）：
- `<input v-model="text">`：打字时 `text` 立刻变（输入"我手打的字"，旁边 `<p>` 同步显示）；代码里改 `text`，输入框内容也跟着变；`<textarea v-model="...">` 写法完全一样，只是换行会一起带进变量。
- `type="checkbox"` + `v-model="agree"`：绑**布尔**，勾上 `true`、取消 `false`。这里**不能**写 `:value`，写了就变成绑值了。
- 一组 `radio` 绑同一个 `gender`：每个框必须有 `value`（**不带冒号**，它就是固定值"男"/"女"）；不写 `value`，选中后变量会变成 `null`。
- 复选框组绑 `hobbies`：数组元素来自每个框的 `:value`，所以这里**必须**带冒号；不带冒号只会收到 `true`/`false`。
- `<select v-model="city">`：选中的 `<option>` 的 `value` 写回 `city`，第一个 `value=""` 表示"没选"；汇总里那个 `||` 就是给"没选"用的兜底。
- `v-model.number="age"`：输入 `25` 得到的是 `25（number）`，不加修饰符是 `"25"（string）`（实测）。

**在你仓库里**：`src/views/Home.vue:9` 是 `<input v-model="data.school" />`（改字时第 6 行的插值立刻跟着变）；`:29-32` 是 `<select v-model="data.myCollege">` 配 `v-for` 生成的 `<option :value="c">`；`:34` 用 `||` 显示未选状态；`:65-72` 的 `school`、`myCollege` 就是被绑着的两个字段。

**常见坑**：
- 打字时输入框内容被"弹回去" → 绑的不是可写数据（常量、普通变量、没写 setter 的 computed）→ 绑 `ref`/`reactive` 里的字段。
- 复选框组选中后拿到一堆 `true` → 每个框没写 `:value` → `<input type="checkbox" :value="h" v-model="hobbies">`。
- 下拉框选完变量里是空字符串 → `<option>` 忘了写 `value`，或把 `v-model` 写到了 `<option>` 上 → `value` 在 `<option>` 上，`v-model` 在 `<select>` 上。
- 数字框算加法变成字符串拼接（`1` + `1` = `11`）→ 表单取回来的一律是字符串 → 加 `.number`，或自己 `Number(age.value)`（还有 `.trim`、`.lazy`）。

**自测**：`v-model="x"` 到底等价于哪两段代码？试着改写 `<input v-model="text" />`。
<details><summary>看答案</summary>

等价于 `:value="text" @input="text = $event.target.value"`。`$event` 是原生事件对象，`target` 就是那个输入框，`.value` 是框里的当前文字。

</details>

### 2.5 `v-if` / `v-else-if` / `v-else`
**讲义怎么说**：讲义"三、Vue3 条件语句"："在 Vue 3 中，你可以在模板中使用多种条件语句来控制组件的渲染。主要的条件语句有 v-if、v-else-if 和 v-else。"（没提和 `v-show` 的区别，而作业里两种都会碰到。）

**一句话讲透**：`v-if` 是**拆装式**的——条件不成立，这块标签压根不往页面上放（DOM 里没有它）；`v-show` 是**遮布式**的——标签一直在页面上，只是被加了一句 `display: none`。要不要"留个空位"，决定你选哪个。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { ref } from 'vue'

const score = ref(55)
const showTip = ref(true)
</script>

<template>
  <p>当前分数：{{ score }}</p>

  <p v-if="score >= 90" style="color: green">优秀</p>
  <p v-else-if="score >= 60" style="color: orange">及格</p>
  <p v-else style="color: red">不及格</p>

  <button @click="score += 10">加 10 分</button>
  <button @click="score = 55">重置</button>
  <hr />

  <p>下面两句只差一个指令，打开 F12 的 Elements 面板对比：</p>
  <p v-if="showTip">我是 v-if：为 false 时整个标签从 DOM 里消失</p>
  <p v-show="showTip">我是 v-show：为 false 时标签还在，只是被加了 display:none</p>
  <button @click="showTip = !showTip">切换显示</button>
</template>
```
**逐行拆解**（括号里是实测数据）：
- `v-if="score >= 90"`：条件为真才渲染。初值 55，所以页面上只有"不及格"那一个 `<p>`。
- `v-else-if="score >= 60"`：必须**紧挨着**上一个 `v-if`。中间夹了别的元素会编译报错 `v-else/v-else-if has no adjacent v-if or v-else-if`（实测）。
- `v-else`：收尾分支，同一时刻三个分支只活一个；中间只放注释是允许的（实测能正常编译，注释会挂在 `v-else` 的分支里）。
- `@click="score += 10"`：改 `ref`，页面立刻重算分支：55→65 红变橙，90 以上变绿。
- `v-show` 那一行：实测点掉之后，`v-if` 的 `<p>` 在 DOM 里**查不到**了；`v-show` 的还在，`style="display: none;"`。

**在你仓库里**：`src/views/Home.vue:14-16` 是三分支条件渲染（`>= 90` 绿"优秀"、`>= 60` 橙"及格"、否则红"不及格"）；`:17-18` 是改分数的两个按钮；`:75` 是 `const score = ref(55)`，所以打开页面看到的是红色"不及格"。

**常见坑**：
- 编译报 `v-else/v-else-if has no adjacent v-if or v-else-if` → `v-if` 和 `v-else` 之间夹了兄弟元素（`<hr>`、一句说明文字）→ 把分支之间的东西挪出去，或整段包进一个 `<div>`。
- 三个分支同时显示/同时消失 → 每段都写成了独立的 `v-if` → 只让第一个用 `v-if`，后面严格用 `v-else-if` / `v-else`。
- 切来切去很卡 → 用 `v-if` 反复销毁重建 → 切换频繁就用 `v-show`。
- 输入框里打的字，`v-if` 一关一开就没了 → `v-if` 把 DOM 拆了重建，DOM 里的临时状态自然丢 → 需要保留就用 `v-show`，或把值存进 `ref`。

**自测**：一个频繁开关、里面带表单的弹窗，用 `v-if` 还是 `v-show`？
<details><summary>看答案</summary>

容器本身建议 `v-if`：不显示时不该白白渲染里面的内容，关闭时顺手销毁内部状态（重开是干净的）。如果它在同一页里被反复开关、还希望留着用户填过的内容，就用 `v-show`。关键其实在里面的数据：无论哪种，表单值都应该存在 `ref`/`reactive` 里，这样即使 DOM 被销毁重建，值也还在。

</details>

### 2.6 `v-for` 与 `:key`
**讲义怎么说**：讲义"四、Vue3 循环语句"："在 Vue 中，循环语句主要通过 v-for 指令来实现，用于遍历数组或对象生成对应数量的元素。"

**一句话讲透**：`v-for` 是"按数据造标签"的模具——数组里有几条就压出几个元素；`:key` 是**给每个元素发一张身份证**，数据一变，Vue 靠它判断"哪个还是原来那个、哪个是新来的、哪个该搬走"。证件发错了（拿手写序号 `index` 当证件），Vue 就会认错人：该跟着数据走的状态，留在了原地。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { reactive } from 'vue'

const colleges = reactive(['信工院', '中医学院', '药学院', '针灸学院'])

const students = reactive([
  { id: 101, name: '张三', score: 88 },
  { id: 102, name: '李四', score: 59 },
  { id: 103, name: '王五', score: 75 }
])

const person = reactive({ name: '张三', age: 20, city: '合肥' })
</script>

<template>
  <p>① 遍历数组；② 值和下标（第二个参数是下标，从 0 开始）：</p>
  <ul>
    <li v-for="c in colleges" :key="c">{{ c }}</li>
    <li v-for="(item, index) in colleges" :key="item">{{ index + 1 }}. {{ item }}</li>
  </ul>

  <p>③ 对象数组（key 用唯一的 id）：</p>
  <table border="1" cellpadding="6">
    <tr v-for="s in students" :key="s.id">
      <td>{{ s.id }}</td>
      <td>{{ s.name }}</td>
      <td :style="{ color: s.score >= 60 ? 'green' : 'red' }">{{ s.score }}</td>
    </tr>
  </table>

  <p>④ 遍历对象（值、键、下标）与数字（从 1 数到 3）：</p>
  <p v-for="(value, key, i) in person" :key="key">{{ i }} - {{ key }}：{{ value }}</p>
  <p><span v-for="n in 3" :key="n">第 {{ n }} 名　</span></p>
</template>
```
**逐行拆解**：
- `v-for="c in colleges"`：数组用 `in` 遍历，`c` 是元素。reactive 数组模板里直接写名字，不用 `.value`。
- `v-for="(item, index) in colleges"`：第一个是元素、第二个是**下标**（从 0 开始），顺序固定不能反，所以显示序号要写 `index + 1`。
- `v-for="s in students"`：元素是对象——表格每行、列表每项都是这个形态，最常用。
- `v-for="(value, key, i) in person"`：遍历对象时是**值在前、键在后**，最后还有下标；`v-for="n in 3"` 是"循环 3 次"，**从 1 开始**（1、2、3）而不是从 0。
- `:key="c"` / `:key="s.id"`：必须写，而且要**唯一**——业务主键（`s.id`）最合适，字符串数组用元素本身也行（`c`）；用 `:key="index"` 能跑，但下标不是身份证（见坑 2）。

**在你仓库里**：`src/views/Home.vue:24` 是 `<li v-for="(item, index) in data.colleges" :key="index">{{ index + 1 }}. {{ item }}</li>`（用下标做 key，演示够用，学完这节你知道更好的写法是 `:key="item"`）；`:31` 是 `<option v-for="c in data.colleges" :key="c" :value="c">{{ c }}</option>`（同一个数组被遍历第二次）；`:69` 是被遍历的数据本体。

**常见坑**：
- 编辑器右上角一直有黄色告警（讲义截图里的"⚠2"）→ `v-for` 没写 `:key`（IDEA、Volar、ESLint 的 `vue/require-v-for-key` 都会报）。注意：**Vue 3 的运行时已经不打印** Vue 2 那句 "should have explicit keys" 了（在你工程的 `vue@3.5.43` 全文搜不到），别指望控制台提醒你。
- 列表每项有勾选框，往数组**前面**插一条，新那条"自带"了勾选状态 → `:key="index"`：Vue 按下标复用 DOM 节点，节点上的勾选状态归浏览器管，Vue 不会替你清 → key 换成唯一 id。实测（两种写法都先勾第一项、再往前面插一条）：`index` 版 → `[✓] 新任务3 ｜ [ ] 背方歌 ｜ [ ] 写作业`；`id` 版 → `[ ] 新任务3 ｜ [✓] 背方歌 ｜ [ ] 写作业`。
- 控制台报 `Property "item" was accessed during render but is not defined`，整块列表不渲染 → `v-if` 和 `v-for` 写在了**同一个标签**上：Vue 3 里 `v-if` 优先级更高，会在循环外面求值，那个 `item` 根本还不存在（实测报 `Cannot read properties of undefined (reading 'ok')`）→ 要筛选就在数据上做（`computed`），或用 `<template v-for>` 包一层；另外循环里的按钮要写 `@click="del(s.id)"`，只写方法名拿到的是事件对象。

**自测**：待办列表每项前面有勾选框，新增项插到最前面。为什么 `:key="index"` 会出 bug，`:key="t.id"` 不会？
<details><summary>看答案</summary>

`index` 做 key 时，key 是"第 0 个、第 1 个……"，插入新项后所有项下标都往后挪了一位，Vue 却认为"第 0 个还是第 0 个"，于是**复用**原 DOM 节点、只改里面的文字；而勾选框的勾选状态是浏览器自己记的，不属于 Vue 管的数据，就留在了原节点上，看起来像"新条目被勾上了"。用 `:key="t.id"` 时身份证跟着数据走，Vue 认出"背方歌还是 1 号"，把整个节点搬过去，勾选状态跟着一起走。

</details>

### 2.7 `v-on` / `@click`
**讲义怎么说**：讲义"五、Vue3 事件处理方法 → 单击事件 click"："我们可以使用 v-on 指令来监听 DOM 事件，从而执行 JavaScript 代码。v-on 指令可以缩写为 @ 符号。"

**一句话讲透**：`v-on` 就是给元素装一只"听到声音就做事"的耳朵——原生 JS 里要写 `addEventListener('click', fn)`，现在一句话绑上；`@` 只是 `v-on:` 的简写，一个字符都不少干。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
const msg = ref('还没点')

function addOne() { count.value++ }
function addStep(step) { count.value += step }
function sayHi(name, event) { msg.value = `你好 ${name}，事件类型是 ${event.type}` }
function onOuter() { msg.value = '外层 div 收到了点击' }
function onInner() { msg.value = '内层按钮收到了点击（.stop 挡住了冒泡）' }
</script>

<template>
  <p>count = {{ count }}</p>
  <p>① 内联语句：<button @click="count++">count++</button></p>
  <p>② 只写方法名（自动收到 event）：<button @click="addOne">addOne</button></p>
  <p>③ 调用并传参：<button @click="addStep(10)">addStep(10)</button></p>
  <p>④ 传参同时拿 event：<button @click="sayHi('张三', $event)">sayHi</button></p>
  <p>⑤ 缩写与完整写法等价：<button v-on:click="count = 0">v-on:click</button> <button @click="count = 0">@click</button></p>
  <p>⑥ 修饰符：<a href="https://cn.vuejs.org" @click.prevent="msg = '链接被拦住了'">点我不跳转（.prevent）</a></p>
  <div style="border: 1px solid #999; padding: 8px" @click="onOuter">
    外层 div
    <button @click.stop="onInner">内层按钮（.stop）</button>
  </div>
  <p>{{ msg }}</p>
</template>
```
**逐行拆解**（括号里是实测的实参）：
- `@click="count++"` → 编译成 `onClick: $event => (count++)`：内联语句，写表达式就行。
- `@click="addOne"` → 编译成 `onClick: addOne`：函数本身就是监听器，调用时把**事件对象**当第一个参数传进去（实测收到 `event:click`）。
- `@click="addStep(10)"` → 编译成 `onClick: $event => addStep(10)`：只传 `10`，事件对象**丢了**（实测第一个参数就是 `10`）。
- `@click="sayHi('张三', $event)"`：`$event` 是固定写法，用来把事件对象手动传进去（实测收到 `event:click`）。
- `v-on:click` 与 `@click`：完全等价；只有需要动态事件名（`v-on:[evt]`）时才必须写全。
- `@click.prevent` / `.stop`：自动调用 `preventDefault()` / `stopPropagation()`——`.prevent` 拦住默认行为（链接不跳转），`.stop` 拦住冒泡（点内层不动外层）；事件名就是原生事件名，`@input`、`@change`、`@keyup`、`@submit` 都能用。

**在你仓库里**：`src/views/Home.vue:17-18` 是 `@click="score += 10"`、`@click="score = 55"`（内联语句改 `ref`）；`:39` 是 `@click="count++"`（点赞 +1）；`:46`、`:53` 是只写方法名的 `@click="toggleColor"`、`@click="toggleImg"`；`:87-89`、`:92-94` 是那两个箭头函数本体。

**常见坑**：
- 点了没反应 → 函数没定义在 `<script setup>` 里，或改的是普通变量（不是 `ref`）→ 检查名字拼写，确认改的是响应式数据。
- 事件触发了两次 → 外层也绑了同类型事件，冒泡上去又跑一次 → 内层加 `.stop`。
- 表单一点提交，整页刷新了 → `<form>` 的默认提交行为 → `@submit.prevent="onSubmit"`。
- 想拿事件对象却是 `undefined` → 写成了 `@click="fn()"`，参数被丢掉 → 写 `@click="fn"`，或显式 `@click="fn($event)"`。

**自测**：`@click="addOne"` 与 `@click="addOne()"` 有什么不一样？什么时候必须用后者？
<details><summary>看答案</summary>

前者函数本身就是监听器，会收到原生事件对象；后者 Vue 会包一层 `$event => addOne()`，参数被丢掉，函数收到 `undefined`（实测）。所以**只有要传参时**才写括号，比如 `@click="addStep(10)"`；要同时拿事件就写 `@click="fn(10, $event)"`。

</details>

### 2.8 `v-bind` / `:`
**讲义怎么说**：讲义"五、Vue3 事件处理方法 → 动态绑定 v-bind"："普通写标签属性是写固定的格式……用 v-bind 就能把属性值绑定成 JS 变量 / 表达式，变量一变，页面属性立刻跟着变，这就叫动态绑定。"

**一句话讲透**：HTML 属性默认是**刻在石头上的字**（`color="blue"` 永远蓝），`:属性` 把它换成**贴在白板上的便签**——便签内容由 JS 决定，JS 一改，属性立刻跟着变。判断标准只有一条：**这个属性值是不是来自 JS？是，就必须加冒号。**

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { ref } from 'vue'

const imgUrl = ref('/img/shihu.jpg')
const fontSize = ref(20)
const active = ref(true)
const big = ref(false)

function flipImg() {
  imgUrl.value = imgUrl.value === '/img/shihu.jpg' ? '/img/juhua.jpg' : '/img/shihu.jpg'
}
</script>

<template>
  <p>1) 普通属性：<img :src="imgUrl" :alt="'当前图片：' + imgUrl" width="160" /></p>
  <p>当前 src：{{ imgUrl }} <button @click="flipImg">换一张图</button></p>

  <p>2) class 对象写法（值为 true 才加这个类）：</p>
  <p :class="{ active: active, big: big }">看我的 class</p>
  <button @click="active = !active">切换 active</button> <button @click="big = !big">切换 big</button>

  <p>3) class 数组写法，静态 class 不会被覆盖：</p>
  <p class="base" :class="[active ? 'active' : '', 'big']">静态 + 动态一起用</p>

  <p>4) style 对象写法：<span :style="{ color: 'red', fontSize: fontSize + 'px' }">红字 {{ fontSize }}px</span>
    <button @click="fontSize += 2">字号 +2</button></p>
  <p>5) style 数组写法：<span :style="[{ color: 'blue' }, { fontWeight: 'bold' }]">蓝粗字</span></p>
  <p>6) 布尔属性也要绑定：<button :disabled="!active">active 为 false 时我点不动</button></p>
</template>

<style scoped>
.active { color: #b4472f; font-weight: 700; } .big { font-size: 20px; }
.base { padding: 4px 8px; background: #f4f4f4; }
</style>
```
**逐行拆解**：
- `:src="imgUrl"`：加冒号才是 JS 表达式。写成 `src="imgUrl"`，浏览器会去请求一个叫 `imgUrl` 的文件，图片必裂；同理 `:href="link"` 少冒号会被当**相对路径**（跳到 `localhost:5173/link`）。
- `:alt="'当前图片：' + imgUrl"`：值也可以是表达式，字符串字面量要带引号，否则会被当成变量名。
- `:class="{ active: active, big: big }"`：对象写法，**键是类名、值是开关**，值为 `true` 才加。别写成 `{ active: 'active' }`（那判断的是字符串 `'active'`，永真）。
- `class="base" :class="[...]"`：静态 class 和动态 `:class` 可以并存，实测渲染成 `class="base active big"`，**不会被覆盖**；数组里还能放三元，用来动态挑类名。
- `:style="{ color: 'red', fontSize: fontSize + 'px' }"`：样式对象的键是 CSS 属性名（**小驼峰**，`font-size` 要写 `fontSize`），值一般带单位字符串。
- `:style="[{...}, {...}]"`：数组写法依次合并，后写的覆盖先写的，适合"基础样式 + 覆盖样式"。
- `:disabled="!active"`：布尔属性"真就有、假就没有"。写成 `disabled="false"` 反而会让按钮变灰（非空字符串是真值）。

**在你仓库里**：`src/views/Home.vue:45` 是 `<div :style="box"></div>`，把整个 reactive 对象当样式对象；`:81-86` 是 `box` 的内容（`width`、`height`、`backgroundColor`、`marginTop`，全是小驼峰）；`:88` 改数据即改样式；`:51` 是 `<img :src="data.imgUrl" ...>`，`:93` 在三元里切换图片路径；图片本体在 `public/img/shihu.jpg`、`public/img/juhua.jpg`（`public` 里的文件用 `/img/xxx.jpg` 直接访问，不用 `import`）。

**常见坑**：
- 图片 404，`src` 那栏显示 `data.imgUrl` → 少了冒号，被当字面路径 → 改成 `:src="data.imgUrl"`。
- `:class="{ active: 'yes' }"` 永远生效 → 字符串 `'yes'` 是真值 → 值必须是布尔量：`:class="{ active: isActive }"`。
- `:style="{ 'background-color': 'red' }"` 不生效 → 对象键不支持中划线写法 → 写小驼峰 `backgroundColor`。
- 按钮明明 `:disabled="false"` 还是灰的 → 其实写成了 `disabled="false"`（没冒号），非空字符串为真 → 加冒号，或整段删掉。
- `:src="@/assets/logo.svg"` 不生效 → 别名和模块导入是 JS 语法，属性值只当表达式求值 → 图片放 `public` 用 `/img/x.jpg`；放 `src/assets` 就先 `import url from '@/assets/logo.svg'` 再 `:src="url"`。

**自测**：`:class="{ active: active }"` 和 `:class="active ? 'active' : ''"` 结果一样吗？
<details><summary>看答案</summary>

最终 class 一样，语义不同：对象写法里"类名"是写死的、"开关"是活的；三元写法里类名和开关都能算。只是"加不加这个类"，用对象写法最清楚；**类名本身也要动态挑**时，用三元或数组写法更合适。

</details>

### 2.9 `onMounted` 生命周期
**讲义怎么说**：讲义"五、Vue3 事件处理方法 → onMounted"："就是在页面元素完全加载完成之后触发，页面元素加载需要时间的。"**⚠️ 这句不严谨，别照抄**：准确时机是**组件的 DOM 挂载（插入页面）完成**，此时图片、字体、外链脚本这些**子资源往往还在下载中**；想等"所有资源都加载完"，那是浏览器原生的 `window.onload`。这也是 `讲义勘误_实训2.md` 的第 4 条。

**一句话讲透**：`onMounted` 是组件"**搬进新家、家具摆好**"的那一刻——你可以开始摸家里的东西了（读真实 DOM、量宽高、发请求），但**快递可能还在路上**（图片没下载完）。它在组件的一生里只跑一次。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { nextTick, onMounted, onUpdated, ref } from 'vue'

const boxRef = ref(null)
const textRef = ref(null)
const width = ref('还没量')
const tick = ref(0)
const log = ref([])

onMounted(() => {
  width.value = boxRef.value.offsetWidth + 'px'
  log.value.push('① onMounted 触发，量到 div 宽度 = ' + width.value)
  log.value.push('② 此刻图片等子资源可能还没下载完，要等资源用 window.onload')
})

onUpdated(() => {
  // 千万别在这里改响应式数据，否则会一直触发更新（Vue 会报 Maximum recursive updates exceeded）
  console.log('onUpdated：数据变了、DOM 重新渲染完成')
})

async function readDom() {
  tick.value++
  log.value.push('③ 刚改完 tick 就立刻读 DOM：' + textRef.value.textContent + ' ← 还是旧值')
  await nextTick()
  log.value.push('④ await nextTick() 之后再读：' + textRef.value.textContent + ' ← 才是新值')
}
</script>

<template>
  <div ref="boxRef" style="width: 240px; background: #eef; padding: 8px">量我的宽度：{{ width }}</div>
  <p ref="textRef">tick = {{ tick }}</p>
  <button @click="readDom">改 tick 并读 DOM</button>
  <ul>
    <li v-for="(line, i) in log" :key="i">{{ line }}</li>
  </ul>
</template>
```
**逐行拆解**：
- `const boxRef = ref(null)`：要用"模板引用"先声明一个 `ref`，初值给 `null`。
- `<div ref="boxRef">`：名字必须和变量名一致；挂载后 Vue 会把它的 `.value` 指向真实 DOM 元素（编译结果里直接就是 `ref: boxRef`）。
- `onMounted(() => { ... })`：`<script setup>` 里直接调用即可，不用 `export default`；挂载完成后**只跑一次**。
- `boxRef.value.offsetWidth`：只有挂载后 `.value` 才有元素；写在 `onMounted` 外面会报 `Cannot read properties of null`。
- `onUpdated(...)`：数据变了、DOM 重新渲染完成后触发。**别在里面改响应式数据**，否则"改数据 → 触发 onUpdated → 又改数据"会无限循环；另外两个常用钩子是 `onUnmounted`（销毁时清定时器、取消订阅）和 `onBeforeMount`（更早，DOM 还没有）。
- `tick.value++` 后立刻读 DOM、再 `await nextTick()` 读：实测改完立刻读是**旧值**，`await nextTick()` 之后才是新值——Vue 把更新攒到微任务里批量做。

**在你仓库里**：`src/views/Home.vue:62` 从 vue 里引入 `onMounted`；`:99` 是 `const mountedAt = ref('')`（用来在页面上留一条"钩子跑过"的证据）；`:100-106` 是钩子本体（打日志、写时间、弹 `alert`）；`:103-105` 用 `new URLSearchParams(location.search).has('noalert')` 判断是否跳过弹窗；`:57` 用插值把 `mountedAt` 显示出来，刷新页面就能看到时刻被填上。

**常见坑**：
- 报 `Cannot read properties of null (reading 'offsetWidth')` → 在 `onMounted` 外面读了模板 ref → 把读 DOM 的代码放进 `onMounted`（或 `await nextTick()` 之后）。
- `onMounted` 里量到的宽度是 0 → 元素本身 `display: none`（被 `v-if` 关掉了），或父容器还没布局 → 先让元素显示再量。
- 图片尺寸/数量读到的是"还没加载"的状态 → `onMounted` ≠ 所有资源加载完（讲义这里说错了）→ 要等资源用 `window.addEventListener('load', ...)`，或给图片加 `@load`。
- 控制台刷屏 `Maximum recursive updates exceeded` → 在 `onUpdated` 里改了响应式数据 → 那里只做只读操作。
- `alert` 一弹页面就卡住，自动化截图也卡 → 原生 `alert` 是阻塞式的 → 真实项目用 `ElMessage`；仓库里的做法是用 `?noalert=1` 跳过。

**自测**：为什么"在 `onMounted` 里发请求"是标准做法，而不是在 `<script setup>` 顶层直接发？
<details><summary>看答案</summary>

顶层直接发也能拿到数据（请求不依赖 DOM），放 `onMounted` 里语义更清楚——"组件已就位，开始拉数据"，也保证要用到的模板引用、子组件都就绪了。更该注意的是另一半：请求是异步的，数据回来时组件可能已被销毁，所以要在 `onUnmounted` 里做收尾，而不是只关心"什么时候发"。

</details>

### 2.10 顺带用到的三件小事
**讲义怎么说**：没有单独小节，但这三样在你仓库代码里都出现了——`reactive` 装一组数据（一、数据绑定）、模板里 `||` 兜底（`Home.vue:34`、`:57`）、`v-model` 绑 `select`（二、双向数据绑定 + 四、循环语句）。

**一句话讲透**：这三样是胶水：`Object.assign` 让 reactive 也能"整体重置"；`||` 让空值有个好看的说法；`select` 不过是 `v-model` 的又一种表单形态。

**示例代码**（整段覆盖 `src/views/Home.vue` 即可）：
```vue
<script setup>
import { reactive } from 'vue'

const data = reactive({
  school: '安徽中医药大学',
  colleges: ['信工院', '中医学院', '药学院', '针灸学院'],
  myCollege: ''
})

function resetAll() {
  // reactive 不能整个换掉（data = {...} 会失效），要改就用 Object.assign
  Object.assign(data, { school: '安徽中医药大学', myCollege: '' })
}
</script>

<template>
  <p>学校：{{ data.school }}</p>
  <p>选学院：
    <select v-model="data.myCollege">
      <option value="">请选择</option>
      <option v-for="c in data.colleges" :key="c" :value="c">{{ c }}</option>
    </select>
  </p>
  <p>当前选中：{{ data.myCollege || '（还没选）' }}</p>
  <button @click="resetAll">恢复初始状态</button>
</template>
```
**逐行拆解**：
- `const data = reactive({...})`：一个对象装下整页要用的数据；模板里要写 `data.xxx`，`v-for` 里也必须带 `data.` 前缀（写成 `c in colleges` 会找不到变量）。
- `Object.assign(data, {...})`：只覆盖列出的字段，其它字段不动；比"重新造一个对象"安全，因为保住了响应式代理。
- `<select v-model="data.myCollege">`：`v-model` 写在 `select` 上，选中的 `option` 的 `value` 写回这个字段。
- `<option value="">请选择</option>` / `<option v-for="c in data.colleges" :key="c" :value="c">`：用空字符串表示"没选"；`v-for` 那行的 `:value` 是表达式写法（绑 `c` 的值），`:key` 保证唯一。
- `{{ data.myCollege || '（还没选）' }}`：空字符串是假值，未选时显示提示文字；选中后显示的就是选中的学院。

**在你仓库里**：`src/views/Home.vue:29-32` 是完整的 select 双向绑定 + `v-for` 生成 option；`:34` 与 `:57` 是两处 `||` 兜底；`:65-72` 是 reactive 数据块本体（`v-for` 用的就是它的 `colleges`）。

**常见坑**：
- `v-for="c in colleges"` 报未定义 → 数据在 `data` 下面，模板里不能省前缀 → 写 `data.colleges`。
- 选中下拉框后一直显示"（还没选）" → `<option>` 没写 `:value`，或写了 `value` 却当成 JS 变量 → 用 `:value="c"`，并确认文本与值对得上。
- `Object.assign` 重置不干净 → `assign` 只覆盖你列出的键 → 明确列出需要复原的字段，或先存一份初始值再展开。

**自测**：显示"（还没选）"时，`data.myCollege` 的真实值是什么？为什么能触发 `||` 右边？
<details><summary>看答案</summary>

真实值是空字符串 `''`（第一个 `option` 的 `value`）。JS 里 `''`、`0`、`null`、`undefined`、`NaN` 都是假值，所以 `||` 取右边的提示文字。注意：如果将来这个值可能是数字 `0`（比如数量），`||` 会误判成"没值"，那时应该用 `??`。

</details>
