## 勘误 1（中）循环示例 `v-for` 没写 `:key`——讲义截图自己都在报 `⚠2`

- **性质**：讲义写法不规范（不报错，但违反 Vue 官方推荐；IDEA/ESLint 会一直告警）。
- **【讲义原文】** 四、Vue3 循环语句 截图（`img02/image8.png`）：
  ```html
  <select style="width: 200px">
    <option v-for="item in data.schools">{{ item }}</option>
  </select>
  ```
  ```js
  const data = reactive({
    schools: ["安徽中医药大学", "安徽师范大学", "中国科学技术大学"]
  })
  ```
- **【问题】** `v-for` 必须配 `:key`（`vue/require-v-for-key` 规则）；截图里 IDEA 右上角黄色 `⚠2` 就是这条告警。课堂演示"能跑"会让学生以为不写也行——这正是 Vue 2 时代的老习惯。
- **【实测证据】**
  - 讲义截图 `image8.png`：代码第 4 行即上面那行 `<option v-for=...>`，编辑器右上角 `⚠2`；
  - 讲义截图右侧浏览器确实正常渲染出下拉框（选中"安徽师范大学"）——**功能能跑**，问题是不规范/后续列表增删会出复用 bug；
  - 仓库同一示例已补 key：`实训2/工程/vue-syntax/src/views/Home.vue:31` 是 `<option v-for="c in data.colleges" :key="c" :value="c">{{ c }}</option>`（lab-runner-a 实测 9 个语法点全部正常、无告警）。
- **【正确写法】** `<option v-for="item in data.schools" :key="item">{{ item }}</option>`
- **【影响程度】** 中：不影响本次演示，但"key 决定节点复用"是后面所有列表/表格的基础，且编辑器告警会一直挂着。

## 勘误 2（低）`onMounted` 说成"所有页面元素都加载完成才触发"——实际是"组件 DOM 挂载完成"

- **【讲义原文】** 五、事件处理方法 末节："onMounted 就是在页面元素完全加载完成之后触发，页面元素加载需要时间的。"；截图 `img02/image14.png` 红字："这个弹窗就是，当所有的页面元素都加载完成就触发 onMounted 方法"。
- **【问题】** `onMounted` 的触发点在**组件首次挂载、DOM 插入文档之后**；此时图片等子资源**往往还没下载完**（`<img>` 的 `load` 才代表图片加载完），"所有资源加载完"对应的是 `window.onload`。学生用它去读已加载图片的尺寸会取到 0 而困惑。
- **【实测证据】** 仓库 `实训2/工程/vue-syntax/src/views/Home.vue:99-106` 用 `onMounted` 打印触发时刻并 `alert`；lab-runner-a 实测钩子确实触发（弹 alert）、页面正常，即"挂载完成"即触发，不等图片等子资源。`onMounted` 语义本身是"组件 DOM 已插入"，Vue 文档明确它**不保证**子资源加载完成（"所有资源加载完"是 `window.onload`）。
- **【正确写法】** "组件挂载完成（DOM 已插入页面）后触发；要等图片/外部资源加载完，用 `window.onload` 或图片自身的 `load` 事件。"
- **【影响程度】** 低：概念性，但影响后面"进页面就调接口/量尺寸"的写法。

## 勘误 4（低）`v-bind` 语法示意绑的是 `color` 属性，在 `<span>` 上**没有任何渲染效果**——照抄会以为"v-bind 没用"

- **【讲义原文】** 五、"动态绑定 v-bind / 基础语法" 截图（`img02/image11.png`）：
  ```html
  <!-- 完整写法 -->
  <span v-bind:color="colorVal">文字</span>
  <!-- 简写（开发最常用），冒号 : 等价 v-bind: -->
  <span :color="colorVal">文字</span>
  ```
- **【问题】** `color` 不是 `<span>` 的合法属性，绑上去只是给标签加了个 `color="..."` 属性，浏览器不渲染；学生照抄后"变量改了页面没变化"，会误以为 v-bind 失效。紧接着的 `image12/13` 才演示了有效果的 `style`/`src`，但前一张已经埋坑。
- **【实测证据】** HTML 里 `<span color="red">文字</span>` 不影响文字颜色（颜色要么用 `style="color:..."`，要么用已废弃的 `<font>`）；本仓库工程用 `:style="box"`（`Home.vue:45`）与 `:src="data.imgUrl"`（`:51`）演示，lab-runner-a 实测"改 JS 变量，方块颜色/图片立刻变"，这才是有可见效果的 v-bind。
- **【正确写法】** 语法示意改成 `:title="msg"`、`:style="{ color: colorVal }"` 这类**真有渲染效果**的属性；或明确注释"这一行只演示语法，`color` 属性本身不会让文字变色"。
- **【影响程度】** 低：属于示例选择不当，会浪费学生排查时间。

## 勘误 5（低）讲义没讲"脚本里取 `ref` 要 `.value`"，而截图里 `ref` 与 `reactive` 混用容易踩坑

- **【讲义原文】** 一、数据绑定：截图 `image2.png` 用 `const a = ref(168)`、`const b = ref("信工院！")`、`const c = ref(true)`，模板里写 `{{a}} {{b}}{{c}}`；截图 `image6.png` 的 `v-model` 示例却改用 `reactive`（`data.a`）。
- **【问题】** 模板里 `{{a}}` 会自动脱壳（等价 `a.value`），但**脚本里**写 `a++`、`if (a)` 就是错的（要用 `a.value`）。讲义两处示例都在模板里用，没点破"脚本里必须 `.value`"这条规则——学生课后一写 `count++` 就静默不生效。
- **【实测证据】** 仓库 `实训2/工程/vue-syntax/src/views/Home.vue` 是正确示范：模板里 `{{ count }}`、`{{ score }}` 直接写，脚本里 `@click="count++"`（模板表达式，编译到组件上下文，等价 `count.value++`）；而 `Home.vue:88` 的 `box.backgroundColor = ...` 是 `reactive`，两种写法的差别讲义没讲。
- **【正确写法】** 补一句"模板里自动 `.value`；`<script setup>` 里赋值/读取必须 `.value`（`reactive` 对象除外）"。
- **【影响程度】** 低-中：初学者最高频的"改了没反应"来源之一。
