## 2. 知识点精讲

### 2.1 `article` 表：五个字段扛起一个新闻模块

**① 讲义怎么说** —— 本讲没有独立讲义。讲义 12《账号管理》给的是同一套顺序："后端先判断 username 是否重复，重复返回 400 提示；不重复插入 user 表。"先有表、再有 Mapper、最后才有页面。仓库的新闻模块照这个顺序落地，建表脚本在 `springboot/sql/article.sql`，字段就五个：标题、封面、简介、正文、时间。

**② 一句话讲透** —— 建表像给仓库划货架：`title`、`img`、`description`、`content`、`time` 五个格子，每个格子先想清楚"装什么、装多大、能不能空"。`img` 存的是**门牌号不是房子**——图片本体躺在磁盘上，数据库里只留一行 URL；`content` 必须用 `longtext`，因为富文本转成 HTML 后动辄几十 KB，`varchar(500)` 一秒就撑爆；`time` 用 `datetime` 而不是字符串，将来按时间排序、按月统计都靠它。表设计错了，后面 Controller、Service、页面每一层都要跟着改。

**③ 示例代码** ——

```sql
USE `xm-pro`;

CREATE TABLE IF NOT EXISTS `article` (
  `id`          int NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `title`       varchar(255) DEFAULT NULL COMMENT '标题',
  `img`         varchar(500) DEFAULT NULL COMMENT '封面图地址',
  `description` varchar(500) DEFAULT NULL COMMENT '简介',
  `content`     longtext     COMMENT '正文（富文本 HTML）',
  `time`        datetime     DEFAULT NULL COMMENT '发布时间',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='新闻文章表';
```

**④ 逐行拆解** ——
- `USE \`xm-pro\``：库名带横线，必须加反引号；漏了就是 `You have an error in your SQL syntax`，而且报错行指向 `xm`，很容易看错。
- `id int NOT NULL AUTO_INCREMENT`：自增主键，插入时不用给值；后面 `useGeneratedKeys` 才能把新 id 写回实体。
- `img varchar(500)`：**存 URL 不存二进制**。图片塞进数据库（BLOB）会让备份、查询、缓存全部变重，工业做法是文件放磁盘或对象存储、库里只留地址。
- `content longtext`：TEXT 家族里最大的一档（约 4GB），给富文本留足余量；换成 `varchar(500)` 后，稍长一点的正文插入就报 `Data too long for column 'content'`。
- `time datetime`：注意它和 MySQL 的 `TIME` 类型同名，后面每条 SQL 都要写反引号（见 2.2）。
- `utf8mb4`：一个汉字 3 字节、一个 emoji 4 字节，旧的 `utf8` 存 emoji 会直接报错，新闻里带表情太常见，所以统一 utf8mb4。

**⑤ 在你仓库里** —— 建表语句在 `D:\my-project\xm-pro\springboot\sql\article.sql` 第 7~15 行；第 17~19 行有一条注释掉的示例 `INSERT`，先插一条能立刻看到列表效果。字段与 `springboot/src/main/java/com/example/entity/Article.java` 第 8~23 行一一对应，顺序也一致。

**⑥ 常见坑** —— ① 把 `content` 写成 `varchar(500)` → 正文一保存就 500，控制台 `Data too long` → 改成 `longtext`。② 建表时 `USE` 了别的库 → 后端连 `xm-pro`，报 `Table 'xm-pro.article' doesn't exist` → 在正确库上执行脚本，或改 `USE` 那一行。③ 库名 `xm-pro` 与 yml 里 `xm_pro` 不一致 → 启动即 `Unknown database` → 两处必须一字不差。

**⑦ 自测** —— 如果新闻正文要支持插图，`content` 里该存什么？为什么不是把图片本身存进去？

<details><summary>展开解析</summary>

存的是**一段 HTML 字符串**，图片以 `<img src="http://.../files/download/xxx.png">` 的形式被引用；图片本体由 `FileController` 落到 `springboot/files/` 目录。把图片存进数据库会让单行数据膨胀到几 MB，`SELECT *` 变慢、备份变大，而且浏览器还是得通过 HTTP 才能显示——绕一圈没有收益。

</details>

### 2.2 Article 实体与 `time` 这个"关键字"

**① 讲义怎么说** —— 讲义 12 的"一、后端代码"只列了四个文件名：`Mapper/UserMapper.java`、`Mapper/UserMapper.xml`、`service/UserService.java`、`controller/UserController.java`，没讲实体怎么写。仓库按同样的分层补了 `entity/Article.java`，类注释只有一句："字段与 article 表一一对应"。

**② 一句话讲透** —— 实体类是**表在 Java 里的一张身份证**：列名 `img` 对字段 `img`，getter/setter 成对出现，MyBatis 查出来的 ResultSet 全靠"列名 → 属性名"反射赋值，名字差一个字母就是 null。`time` 这一列最阴：它和 MySQL 的类型名同名，写 SQL 时不加反引号，解析器有可能把它当类型而不是列名，报错信息还很难懂。仓库的策略是**凡出现 `time` 一律加反引号**，一次写对。另外实体里 `time` 声明成 `String` 而不是 `LocalDateTime`，是为了让前后端直接传 `"2026-11-26 17:35:33"`，省掉 Jackson 的日期格式配置。

**③ 示例代码** ——

```xml
<insert id="insert" useGeneratedKeys="true" keyProperty="id">
    INSERT INTO article (title, img, description, content, `time`)
    VALUES (#{title}, #{img}, #{description}, #{content}, #{time})
</insert>
```

**④ 逐行拆解** ——
- `id="insert"`：必须和 `ArticleMapper.java` 第 18 行的方法名**完全一致**，MyBatis 靠"接口方法名 = SQL id"配对，写错会在启动时报 `Invalid bound statement`。
- `useGeneratedKeys="true"`：告诉 MyBatis 用 JDBC 的 `getGeneratedKeys()` 取回自增主键。
- `keyProperty="id"`：取回来的主键塞到实体哪个属性上；少了这一句，新增完 `article.getId()` 仍是 null，前端拿不到新 id。
- 列名列表里 `` `time` `` 带反引号、`title` 等不带：不是风格问题，是与关键字重名的列必须保护。
- `#{title}`：预编译占位符，值走 `setString`，SQL 注入进不来；`${}` 是字符串拼接，绝不能用在用户输入上。
- 插入语句**没写 id 列**：自增列交给数据库，写了反而可能和自增值打架。

**⑤ 在你仓库里** —— 实体在 `springboot/src/main/java/com/example/entity/Article.java` 第 6~23 行（六个字段）与第 25~71 行的 getter/setter；SQL 在 `springboot/src/main/resources/mapper/ArticleMapper.xml` 第 24~28 行。`application.yml` 第 18 行 `map-underscore-to-camel-case: true` 打开了驼峰映射，本讲字段都是单词所以用不上，但第 9 讲的多单词列名靠它。

**⑥ 常见坑** —— ① 启动报 `Invalid bound statement (not found): com.example.mapper.ArticleMapper.insert` → XML 的 id 和方法名不一致，或 `mapper-locations` 没扫到 → 对照 `ArticleMapper.java` 第 18 行改 id。② 新增成功但返回的 `data` 里 `id` 是 null → 漏了 `useGeneratedKeys`/`keyProperty` → 两行一起补。③ 报 `You have an error in your SQL syntax ... near 'time'` → 列名没加反引号 → 所有出现 `time` 的地方都补上。

**⑦ 自测** —— 为什么返回给前端的 `time` 用 `String` 比 `LocalDateTime` 省事？

<details><summary>展开解析</summary>

`LocalDateTime` 默认会被 Jackson 序列化成 `[2026,11,26,17,35,33]` 这样的数组（或需要额外配置 `JavaTimeModule` 与 `@JsonFormat`），前端还得再拼一次。用 `String` 时后端 `DateUtil.now()` 直接给 `yyyy-MM-dd HH:mm:ss`，MyBatis 写进 `datetime` 列、读出来也是这个格式，前端 `el-table` 直接显示，全链路零配置。

</details>

### 2.3 正文为什么要用富文本编辑器

**① 讲义怎么说** —— 讲义 12 的"功能说明 1"只写了"前端填写账号、密码、姓名，弹窗提交"，全是短文本；新闻模块第一次遇到长内容，仓库在 `vue/package.json` 第 13~14 行引入了 `@wangeditor/editor` 与 `@wangeditor/editor-for-vue`。

**② 一句话讲透** —— `<textarea>` 是**记事本**，只能存纯文本：换行是 `\n`，加粗、列表、插图全靠用户自己敲 HTML，没人会敲。wangEditor 是**带工具栏的 Word**：用户点"B"就加粗、点图片按钮就插图，编辑器负责把这些操作**翻译成一串 HTML** 交给 Vue。所以真正存进数据库的不是"富文本"，而是**那段 HTML 字符串**；页面显示时再把 HTML 交给浏览器渲染。理解了"编辑器 = HTML 生成器"，后面所有问题——为什么 `content` 要 longtext、为什么回显要用 `v-html`、为什么要防 XSS——全都顺理成章。

**③ 示例代码** ——

```bash
cd D:\my-project\xm-pro\vue
npm install @wangeditor/editor@^5.1.23 @wangeditor/editor-for-vue@^5.1.12
```

**④ 逐行拆解** ——
- 两个包分工不同：`@wangeditor/editor` 是内核（工具栏、菜单、HTML 序列化），`@wangeditor/editor-for-vue` 是 Vue 外壳（导出 `Editor`、`Toolbar` 两个组件）。
- 版本必须 5.x：4.x 的 `editor-for-vue` 只支持 Vue 2，装错版本页面一片空白，控制台报 `Cannot read properties of undefined`。
- 命令要在 `vue` 目录下执行：在 `springboot` 目录里跑会生成一个毫无用处的 `node_modules`，前端仍然报模块找不到。
- 装完看 `package.json` 的 `dependencies` 有没有这两行，没有就说明装错了位置。
- 装完必须**重启** `npm run dev`：Vite 的依赖预构建在启动时完成，热更新不会重新扫描新装的包。
- 不需要 `app.use()` 全局注册，两个组件是按需 `import` 的（见 2.4）。

**⑤ 在你仓库里** —— 版本锁定在 `D:\my-project\xm-pro\vue\package.json` 第 13~14 行；实际引用在 `vue/src/views/Article.vue` 第 121~122 行，第一行就是 `import '@wangeditor/editor/dist/css/style.css'`——**这行样式漏了，工具栏会变成一排没排版的按钮**。

**⑥ 常见坑** —— ① 编辑器区域只有一条细线、按钮全挤在左上角 → 忘了引 CSS → 在 `<script setup>` 顶部补 `import '@wangeditor/editor/dist/css/style.css'`。② 启动报 `Failed to resolve import "@wangeditor/editor-for-vue"` → 装在错目录或装了 4.x → 回到 `vue` 目录重装 5.x。③ 不写版本号直接 `npm i`，npm 可能解析到 4.x 的兼容包 → 组件渲染空白 → 明确写 `@5.1.12`。

**⑦ 自测** —— 富文本编辑器最终交给后端的到底是什么？格式和图片去哪儿了？

<details><summary>展开解析</summary>

交给后端的是一段 **HTML 字符串**。格式变成了标签（`<strong>`、`<ul>`、`<h2>`），图片变成了 `<img src="...">` 引用，图片本体早就被上传接口单独存成文件了。所以后端完全不懂"富文本"，它只是原样收下一个长字符串并写进 `longtext`。

</details>

### 2.4 wangEditor 在 Vue 3 里怎么接

**① 讲义怎么说** —— 讲义 12 前端第一部分要求"新建 views/UserManage.vue 【管理员信息页面】"；新闻页同样是**一个 `.vue` 文件**，仓库 `Article.vue` 把编辑器放进了新增/编辑弹窗的 `el-form-item` 里（第 89~105 行）。

**② 一句话讲透** —— wangEditor 在 Vue 里是**两个组件配一个遥控器**：`<Toolbar>` 是按钮面板，`<Editor>` 是编辑区，它们彼此不认识，只认同一个 `editorRef`——`@onCreated` 把真实编辑器实例交给你，Toolbar 拿着这个实例才知道该指挥谁。像电视和遥控器：`Editor` 是电视，`Toolbar` 是遥控器，`editorRef` 是那束对准的红外线，没有它按钮按下去谁也不动。另外编辑器是**有生命的**（绑了 DOM、监听器、定时器），组件卸载时必须 `destroy()`，否则下次打开弹窗会出现两个实例抢同一块区域。

**③ 示例代码** ——

```vue
<template>
  <div class="editor-wrap">
    <Toolbar :editor="editorRef" :defaultConfig="toolbarConfig" mode="default" class="editor-toolbar" />
    <Editor v-model="form.content" :defaultConfig="editorConfig" mode="default"
            class="editor-body" @onCreated="handleCreated" />
  </div>
</template>

<script setup>
import { onBeforeUnmount, reactive, shallowRef } from 'vue'
import '@wangeditor/editor/dist/css/style.css'
import { Editor, Toolbar } from '@wangeditor/editor-for-vue'

const toolbarConfig = {}
const editorConfig = { placeholder: '请输入正文内容...' }
const editorRef = shallowRef()
const form = reactive({ content: '' })

const handleCreated = (editor) => { editorRef.value = editor }

onBeforeUnmount(() => {
  const editor = editorRef.value
  if (editor && !editor.isDestroyed) editor.destroy()
})
</script>
```

**④ 逐行拆解** ——
- `:editor="editorRef"`：Toolbar 的唯一输入，必须是 `shallowRef` 包着的实例。用 `ref` 会把编辑器对象深度代理，wangEditor 内部拿到的不是原对象，报 `Cannot use 'in' operator`。
- `v-model="form.content"`：双向绑定正文 HTML，存的就是这段字符串，不用手动 `getHtml()`。
- `:defaultConfig`：只在创建时读一次，之后改对象不会生效；要动态改得调 `editor.setConfig()`。
- `mode="default"`：默认模式（有表格、视频）；`simple` 是极简模式，新闻正文用 default。
- `@onCreated`：编辑器实例创建完成的回调，**在这里存 ref**；存早了拿到的是 undefined。
- `onBeforeUnmount` 里 `destroy()`：释放 DOM 监听和内部状态；弹窗加了 `destroy-on-close` 时 DOM 可能先没，`isDestroyed` 判断能避免重复销毁报错。

**⑤ 在你仓库里** —— 模板在 `D:\my-project\xm-pro\vue\src\views\Article.vue` 第 89~105 行；脚本在第 138~153 行（`editorRef`、`toolbarConfig`、`editorConfig`、`handleCreated`、`onBeforeUnmount`）；弹窗上的 `destroy-on-close` 在第 56 行。编辑区高度不在组件里，而在 `vue/src/assets/view.css` 第 24~39 行——`.editor-body { height: 320px }`，不设就只有一行高。

**⑥ 常见坑** —— ① 打开弹窗编辑区空白，控制台 `Cannot read properties of null (reading 'init')` → 用 `ref()` 存实例或没写 `@onCreated` → 换 `shallowRef` 并补回调。② 关掉弹窗再打开，正文串到上一条数据里 → 没销毁或 `emptyForm()` 忘了重置 `content` → 参考 `Article.vue` 第 173~176 行的 `openAdd`。③ 编辑区只有一行高、滚动条挤在一起 → 没设 `.editor-body` 高度 → 在 `view.css` 里给 320px。

**⑦ 自测** —— Toolbar 怎么知道该操作哪一个编辑器？为什么一定要 `destroy()`？

<details><summary>展开解析</summary>

通过 `:editor="editorRef"` 拿到**同一个实例**——两者不通信，只共享这个引用。`destroy()` 会解绑 DOM 事件、清空内部状态；不调的话旧实例仍挂在内存里，弹窗反复开关就会多个实例抢同一块区域，出现"输入没反应""内容跳来跳去"这类玄学问题。

</details>

### 2.5 正文存的是 HTML：v-model、longtext 与回显

**① 讲义怎么说** —— 讲义 12 反复强调："返回格式全部复用项目自带 Result 统一返回类，成功 code=200，业务错误 code=400，前端用 ElMessage 弹窗提示。"新闻模块把这套返回用在整段 HTML 上——`add` 收到的 `Article.content` 就是那段 HTML，服务端不解析、不转义，原样入库。

**② 一句话讲透** —— 把 `content` 想成**一封信**：编辑器写信（HTML），数据库是**信箱**（longtext），列表页只读信封上的"标题/简介"（不拆信），详情页才拆信并把信纸原样贴到墙上（`v-html`）。要害在于：**这封信是用户写的，里面可以夹带 `<script>`**——直接 `v-html` 等于把陌生人写的 JS 请进自己家执行，这就是 XSS。所以"存 HTML"本身没错，错的是"存了就直接渲染"。仓库目前只展示简介、没有渲染正文，恰好绕开了这个坑；作业里做详情页时，要么只渲染可信来源，要么用 DOMPurify 过滤一遍。

**③ 示例代码** ——

```js
const form = reactive({ id: null, title: '', img: '', description: '', content: '' })

const save = () => {
  const task = form.id
      ? request.put('/article/update', form)
      : request.post('/article/add', form)
  task.then(res => {
    if (res.code === '200') { ElMessage.success('保存成功'); load() }
    else ElMessage.error(res.msg || '保存失败')
  })
}
```

**④ 逐行拆解** ——
- `content: ''`：wangEditor 的 `v-model` 只认字符串，初值给 `null` 会报警告；`openAdd` 时用 `emptyForm()` 重置成空串。
- `request.post('/article/add', form)`：axios 把整个对象序列化成 JSON（`request.js` 第 11 行强制 `application/json`），HTML 里的引号、换行会被自动转义，不用自己 encode。
- `res.code === '200'`：**字符串比较**。`Result` 里 `code` 是 `String`，写成 `=== 200` 永远不成立，业务成功也会走失败分支。
- `res.msg`：字段名是 `msg` 不是 `message`，取错就是 `undefined` 提示。
- 成功后 `load()` 重新拉列表：不要手动往 `tableData` push，服务端生成的 id 和时间只有重查才拿得到。
- 失败分支必须有 `else`：业务 400 走的是 HTTP 200 + `code=400`，不判 `code` 就会被当成成功。

**⑤ 在你仓库里** —— 表单与请求在 `D:\my-project\xm-pro\vue\src\views\Article.vue` 第 134~135 行、第 196~218 行；后端 `ArticleService.add` 第 29~34 行负责在 `time` 为空时补 `DateUtil.now()`；落库 SQL 在 `ArticleMapper.xml` 第 24~28 行；字段定义在 `springboot/sql/article.sql` 第 12 行 `content longtext`。

**⑥ 常见坑** —— ① 保存后数据库里是 `<p><br></p>` 而不是空 → wangEditor 空内容也会产出占位 HTML → 判断有没有正文要用 `editor.getText().trim()`。② 详情页 `v-html` 渲染出来字号巨大、列表没圆点 → 详情页没引编辑器 CSS → 同样 `import '@wangeditor/editor/dist/css/style.css'`，或自己写 `.article-body` 样式。③ 正文里有引号就 400 → 手动拼了 JSON 或改成了表单格式 → 交给 axios 序列化对象。

**⑦ 自测** —— 如果把 `content` 从 `longtext` 改成 `varchar(2000)`，最先出问题的是哪一步？

<details><summary>展开解析</summary>

是**入库那一步**：`INSERT` 时 MySQL 直接抛 `Data too long for column 'content'`，被全局异常处理接住，前端只看到"系统错误"，而前面编辑、上传封面全都正常——所以这类问题要去看后端控制台，而不是盯着页面。2000 个字符连一篇带格式的短消息都存不下。

</details>

### 2.6 封面图上传：el-upload 三件套

**① 讲义怎么说** —— 讲义 12"功能说明 1"："前端填写账号、密码、姓名，弹窗提交"——提交的是**文字**。新闻的封面是**文件**，走的是另一条路：`el-upload` 直接把二进制 POST 给后端，拿回 URL 再当成普通字符串塞进表单，最后和标题一起提交。

**② 一句话讲透** —— 上传是**两条流水线**：文字走 axios（JSON），文件走 `el-upload`（multipart/form-data）。`el-upload` 像一个**快递柜**：`action` 是柜子地址（后端接口），`name` 是包裹上写的收件人（后端 `@RequestParam` 的名字），`on-success` 是取件码（后端返回什么你就拿什么）。三样任何一样对不上，包裹都退回来：`action` 错是 404，`name` 错是 400，`on-success` 不写则图片明明传上去了、表单里 `img` 还是空。

**③ 示例代码** ——

```vue
<el-form-item label="封面">
  <el-upload
      :action="uploadUrl"
      name="file"
      accept="image/*"
      :show-file-list="false"
      :on-success="handleUploadSuccess"
      :on-error="handleUploadError"
  >
    <img v-if="form.img" :src="form.img" class="cover-preview" alt="封面" />
    <el-button v-else type="primary" plain>点击上传封面</el-button>
  </el-upload>
</el-form-item>
```

```js
const uploadUrl = 'http://localhost:8080/files/upload'

const handleUploadSuccess = (res) => {
  if (res.code === '200') {
    form.img = res.data          // 后端返回的就是可访问的 URL
    ElMessage.success('封面上传成功')
  } else {
    ElMessage.error(res.msg || '封面上传失败')
  }
}
```

**④ 逐行拆解** ——
- `:action="uploadUrl"`：写**绝对地址**。`el-upload` 用原生 XHR，不吃 `request.js` 的 `baseURL` 和拦截器，写 `/files/upload` 会打到 5173 端口。
- `name="file"`：必须和后端 `@RequestParam("file")` 的字符串一致，否则报 `Required part 'file' is not present`。
- `accept="image/*"`：只过滤文件选择框，**不是校验**；用户仍可切"所有文件"选一个 pdf，后端也没拦类型。
- `:show-file-list="false"`：关掉默认文件列表，用下面的 `<img>` 做封面预览，界面更干净。
- `v-if="form.img"` / `v-else`：有图显示预览图、没图显示按钮，这就是"回显"的最朴素养法。
- `res.code === '200'` 后 `form.img = res.data`：`res` 是后端返回的 `Result`，`data` 里就是 URL；不赋值等于白传。
- `on-error`：网络失败或 HTTP 5xx 时才触发；业务 400 走的是成功回调，所以两个回调都要判 `code`。

**⑤ 在你仓库里** —— 模板在 `D:\my-project\xm-pro\vue\src\views\Article.vue` 第 63~78 行；`uploadUrl` 在第 126 行；两个回调在第 183~194 行；预览图样式 `.cover-preview`（160×100、`object-fit: cover`）在 `vue/src/assets/view.css` 第 10~18 行。后端接收方是 `FileController.upload`，第 48~75 行。

**⑥ 常见坑** —— ① 选完图毫无反应，控制台 400 `Required part 'file' is not present` → `name` 不是 `file` → 补 `name="file"`。② 图传上去了，保存后列表里没封面 → 回调里判断成 `res.code === 200`（数字）或忘了 `form.img = res.data` → 用 `'200'` 并赋值。③ 手机拍的图一上传就失败 → Spring Boot 默认单文件 1MB → 在 `application.yml` 配 `max-file-size: 20MB`（仓库第 10 行），前端也可加 `:before-upload` 先拦一道。

**⑦ 自测** —— 封面为什么不用 `request.js` 封装的 axios 去传？

<details><summary>展开解析</summary>

因为 `el-upload` 内部用的是**原生 XHR**，`action` 只接受一个字符串地址，`request.js` 里配的 `baseURL`、请求拦截器、响应拦截器它一概不经过。要么像仓库这样写绝对地址，要么用 `:http-request` 自定义上传函数，在函数里自己调 axios——后者更统一，但要自己处理 `FormData` 和进度。

</details>

### 2.7 FileController 上传：MultipartFile 落地成文件

**① 讲义怎么说** —— 讲义 12 的后端只列了 Controller/Service/Mapper 三个文件，没有文件上传的内容。仓库单独加了 `controller/FileController.java`，方法注释直接给了测试方式："Postman：POST http://localhost:8080/files/upload，form-data，key = file"。

**② 一句话讲透** —— 上传在 Spring 里就是**三件事**：接住（`MultipartFile`）、改名（时间戳 + 原名）、写盘（`FileUtil.writeBytes`）。改名是保命的：两个人都传 `封面.jpg`，不改名后一个把前一个覆盖，用户看到的是别人的图。写完还得**告诉前端去哪儿取**——把磁盘路径翻译成 URL，因为浏览器只认 HTTP，不认 `D:\...`。这就像存包：柜子里放包裹，给你一张**取件码**，你只认码不认柜子。

**③ 示例代码** ——

```java
@PostMapping("/upload")
public Result upload(@RequestParam("file") MultipartFile file) {
    if (file == null || file.isEmpty()) {
        throw new CustomException("400", "请选择要上传的文件");
    }
    String originalName = FileUtil.getName(file.getOriginalFilename());
    String fileName = System.currentTimeMillis() + "_" + originalName;
    File dest = new File(getFileDir(), fileName);
    try {
        FileUtil.writeBytes(file.getBytes(), dest);
    } catch (IOException e) {
        throw new CustomException("500", "文件上传失败");
    }
    String url = ServletUriComponentsBuilder.fromCurrentContextPath()
            .path("/files/download/").path(fileName).toUriString();
    return Result.success(url);
}
```

**④ 逐行拆解** ——
- `@RequestParam("file")`：表单里的 key 必须叫 `file`，和前端 `name="file"` 是一对，改一边就得改另一边。
- `MultipartFile`：Spring MVC 把 multipart 请求体逐段封装成对象，文件名、大小、字节流都在里面。
- `file.isEmpty()`：用户不选文件也会发一个空 part，只判 `null` 挡不住。
- `FileUtil.getName(...)`：去掉浏览器给的假路径 `C:\fakepath\`，只留文件名。
- `System.currentTimeMillis() + "_"`：同名不覆盖；可读性差，正式项目用 UUID，教学用时间戳够了。
- `getFileDir()`：内部是 `FileUtil.mkdir`，目录不存在会建出来，第一次上传不会失败。
- `writeBytes(file.getBytes(), dest)`：一次性读进内存再写盘，小图没问题；几百 MB 的大文件应该用 `transferTo` 流式写。
- `fromCurrentContextPath()`：取到 `http://localhost:8080`，跟着实际访问地址变，比硬编码强。

**⑤ 在你仓库里** —— `D:\my-project\xm-pro\springboot\src\main\java\com\example\controller\FileController.java` 第 34~35 行是 `@Value("${file.dir:${user.dir}/files/}")`、第 40~42 行是 `getFileDir()`、第 48~75 行是 `upload`；目录配置在 `application.yml` 第 22~23 行（`D:/my-project/xm-pro/springboot/files/`），大小限制在第 8~11 行。真实文件已经躺在 `springboot/files/` 下，例如 `1795681545712_甘草.jpg`——前面那串数字就是时间戳。

**⑥ 常见坑** —— ① 重启后旧图片全 404 → 上传目录用了 `${user.dir}` 默认值，IDEA 启动和 `java -jar` 的工作目录不同 → 在 yml 里写死 `file.dir`。② 两张新闻显示同一张图 → 没加时间戳前缀，同名文件被后传的覆盖 → 加 `System.currentTimeMillis()`。③ 换电脑后图片全部打不开 → `file.dir` 还指着上一台机器的 D 盘 → 换机器只改这一行（仓库注释特意写了这句）。

**⑦ 自测** —— 上传接口为什么返回 URL，而不是返回磁盘路径 `D:/.../files/xxx.png`？

<details><summary>展开解析</summary>

因为**浏览器只能通过 HTTP 取文件**，`D:` 路径在客户端根本不存在。URL 是"取件码"：前端把它存进 `article.img`，`<img src>` 一发请求就落到 `download` 接口，由后端读盘再吐字节。顺带的好处是磁盘目录可以随时换，只要 URL 规则不变。

</details>

### 2.8 FileController 下载：中文文件名与路径穿越

**① 讲义怎么说** —— 讲义没有这部分。仓库 `FileController.download` 的注释只有一句"浏览器直接访问 http://localhost:8080/files/download/文件名"，但方法体里有两处防御（第 83~85 行、第 88~90 行）值得单独讲。

**② 一句话讲透** —— 下载接口是**唯一一个把磁盘文件名当参数**的接口，所以它天然是个后门：传 `../../application.yml` 就可能读到配置文件。`fileName.contains("..")` 就是给这扇门装的**猫眼**，先看看来的是不是熟人。另一处是中文：HTTP 头只能放 ASCII，中文名不编码，下载下来就是 `%E7%94%98%E8%8D%89.jpg` 或者乱码，所以要 `URLEncoder.encode`，再按 RFC 5987 的 `filename*=UTF-8''` 写进响应头。

**③ 示例代码** ——

```java
@GetMapping("/download/{fileName}")
public void download(@PathVariable String fileName, HttpServletResponse response) throws IOException {
    if (fileName.contains("..")) {
        throw new CustomException("400", "文件名不合法");
    }
    File file = new File(getFileDir(), fileName);
    if (!file.exists()) {
        throw new CustomException("404", "文件不存在");
    }
    String encodeName = URLEncoder.encode(fileName, StandardCharsets.UTF_8).replaceAll("\\+", "%20");
    response.setContentType("application/octet-stream");
    response.setHeader("Content-Disposition", "attachment;filename*=UTF-8''" + encodeName);
    try (ServletOutputStream out = response.getOutputStream()) {
        out.write(FileUtil.readBytes(file));
        out.flush();
    }
}
```

**④ 逐行拆解** ——
- `@PathVariable String fileName`：URL 里的 `{fileName}` 直接进参数，**不校验就是任意文件读取**。
- `contains("..")`：挡住 `../`；生产环境还应比对 `getCanonicalPath()` 是否仍在上传目录内。
- `!file.exists()` → 404：图片被删或路径变了，这里给明确提示，而不是让 500 的堆栈淹没原因。
- `URLEncoder.encode(..., UTF_8)`：中文变成 `%E7%94%98...`；注意它会把空格编成 `+`。
- `.replaceAll("\\+", "%20")`：URL 里的空格标准写法是 `%20`，`+` 只在表单编码里表示空格，不换会在某些浏览器里出现「找不到文件」。
- `filename*=UTF-8''`：RFC 5987 写法，现代浏览器都认；只写 `filename=` 中文必乱。
- `application/octet-stream`：告诉浏览器"这是二进制，按下载处理"。
- `try (ServletOutputStream out = ...)`：try-with-resources 自动关流，不关会一直占着连接。
- 返回 `void` 不返回 `Result`：响应体已经是文件字节，再包 JSON 就成乱码了。

**⑤ 在你仓库里** —— 方法在 `D:\my-project\xm-pro\springboot\src\main\java\com\example\controller\FileController.java` 第 81~101 行；前端引用它的地方是 `Article.vue` 第 30 行与第 72 行的 `:src="row.img"`。中文样本就在本机：`springboot/files/1795681545712_甘草.jpg`，直接访问 `http://localhost:8080/files/download/1795681545712_甘草.jpg` 能下载到。

**⑥ 常见坑** —— ① `<img>` 里能显示，但在地址栏打开却变成下载 → `Content-Disposition: attachment` → 想"点开预览"就把 `attachment` 改成 `inline`。② 中文名图片下载下来文件名乱码 → 只写了 `filename=` 没编码 → 换成 `filename*=UTF-8''` + `URLEncoder`。③ 图片被手动删了，页面只剩一个灰色方块 → 这里抛 404 返回的是 JSON，`<img>` 拿到 JSON 只能裂 → 回显要有兜底（见 2.11）。

**⑦ 自测** —— 下载接口为什么不 `return Result.success(file)`？

<details><summary>展开解析</summary>

因为 `Result` 会被 Jackson 序列化成 JSON 字符串，而这里要返回的是**文件字节流**。一旦套上 JSON，浏览器收到的就是一段文本而不是图片，`<img>` 永远显示不出来。所以方法签名用 `void`，直接把字节写进 `HttpServletResponse` 的输出流——"返回 JSON"和"返回文件"是两条互斥的路。

</details>

### 2.9 文章 CRUD：五个接口与三层分工

**① 讲义怎么说** —— 讲义 12 的"一、后端代码"列了四个文件：`Mapper/UserMapper.java`、`Mapper/UserMapper.xml`、`service/UserService.java`、`controller/UserController.java`，并要求"返回格式全部复用项目自带 Result 统一返回类，成功 code=200，业务错误 code=400"。

**② 一句话讲透** —— 三层像**餐厅**：Controller 是**前台**（接待、验单，发现"标题为空"当场退回），Service 是**后厨**（补时间、算业务规则），Mapper 是**仓库管理员**（真正去数据库取货放货）。前台不会自己进仓库翻箱，后厨也不直接面对客人。分层的好处是"改一处不影响别处"：以后新增要发通知只动 Service，要换接口路径只动 Controller。新闻模块的五个接口就是这套分工的最小完整样本。

**③ 示例代码** ——

```java
@PostMapping("/add")
public Result add(@RequestBody Article article) {
    if (StrUtil.isBlank(article.getTitle())) {
        throw new CustomException("400", "文章标题不能为空");
    }
    articleService.add(article);
    return Result.success(article);
}

@PutMapping("/update")
public Result update(@RequestBody Article article) {
    if (article.getId() == null) {
        throw new CustomException("400", "文章 ID 不能为空");
    }
    articleService.update(article);
    return Result.success();
}

@DeleteMapping("/delete/{id}")
public Result delete(@PathVariable Integer id) {
    articleService.deleteById(id);
    return Result.success();
}
```

**④ 逐行拆解** ——
- `@RequestBody`：把 JSON 请求体反序列化成 `Article`；axios 发的是 `application/json`，必须用它（表单格式才用 `@ModelAttribute`）。
- `StrUtil.isBlank`：null、空串、全空格都算空；`== null` 挡不住只有空格的标题。
- `throw new CustomException("400", ...)`：不 `return Result.error()`，而是抛——交给 `GlobalExceptionHandler` 第 24~29 行统一转成 `{"code":"400","msg":...}`。
- `Result.success(article)`：新增后把带 id 的对象回给前端（靠 2.2 的 `useGeneratedKeys`）。
- `@PutMapping` / `@DeleteMapping`：分别对应 `request.put` / `request.delete`；用 GET 做删除会被浏览器预取、爬虫误触发。
- `@PathVariable Integer id`：把 `/delete/5` 里的 5 转成 int；传 `abc` 会 400，属于参数类型转换失败。
- `update` 只校验 id：业务上允许"只改封面"，但也意味着前端必须提交整行，否则没传的字段会被写成 null。

**⑤ 在你仓库里** —— `D:\my-project\xm-pro\springboot\src\main\java\com\example\controller\ArticleController.java` 第 27~65 行是五个方法；`service/ArticleService.java` 第 18~46 行（`add` 第 29~34 行补时间）；`mapper/ArticleMapper.java` 第 11~27 行；`resources/mapper/ArticleMapper.xml` 第 9~49 行共六条 SQL（多一个 `count`）。异常转 JSON 在 `exception/GlobalExceptionHandler.java` 第 24~29 行。

**⑥ 常见坑** —— ① 新增成功但列表里时间是空的 → 绕过 Service 直接调了 Mapper，`DateUtil.now()` 没执行 → 一律走 Service。② 编辑保存后发布时间变了 → `update` 会把前端传来的 `time` 原样写回，前端表单里没带 `time` 就会写成 null → 编辑时把 `time` 一起回填（`openEdit` 里整行 `Object.assign`）。③ 删除不存在的 id 也提示"删除成功" → `DELETE` 影响 0 行不报错 → 需要提示时先 `selectById` 判空。

**⑦ 自测** —— "文章标题不能为空"为什么放在 Controller，而不是 Service？

<details><summary>展开解析</summary>

参数校验属于**接口层**的职责：进来的数据先过一遍格式关，不合格立刻返回 400，不浪费后面的数据库连接。放在 Service 也能用，但那样每个调用入口都得自己记得校验；真要做强校验，标准做法是用 `@NotBlank` + `@Validated` 让框架统一处理。本讲先用 `StrUtil.isBlank` 手写，是为了让大家看清"校验 → 抛业务异常 → 全局处理"这条链路。

</details>

### 2.10 列表、模糊查询与详情

**① 讲义怎么说** —— 讲义 12 的前端三节给的是固定三步："新建 views/UserManage.vue"→"修改路由 router/index.js"→"在 Manage.vue 左侧菜单栏增加菜单项"。新闻列表照这三步落地：路由在 `router/index.js` 第 23 行，菜单在 `Manage.vue` 第 51~54 行。

**② 一句话讲透** —— 列表页的本质是**把一张表复印到浏览器**：`selectAll` 返回数组，`el-table` 按 `prop` 取字段。搜索框不是"前端过滤"，而是**把关键词带回后端重新查一遍**——数据在数据库里，前端手上只有已经查出来的那几十条。`LIKE CONCAT('%', #{title}, '%')` 是"包含"匹配：前后都带 `%`，搜"甘草"能命中"甘草片"。`<where>` 标签负责"没有关键词时别拼出 `WHERE`"，这是 MyBatis 动态 SQL 的第一课。

**③ 示例代码** ——

```xml
<select id="selectAll" resultType="com.example.entity.Article">
    SELECT * FROM article
    <where>
        <if test="title != null and title != ''">
            article.title LIKE CONCAT('%', #{title}, '%')
        </if>
    </where>
    ORDER BY article.id DESC
</select>
```

```js
const load = () => {
  loading.value = true
  request.get('/article/selectAll', {
    params: { title: query.title || undefined }
  }).then(res => {
    tableData.value = res.data || []
  }).finally(() => {
    loading.value = false
  })
}
```

**④ 逐行拆解** ——
- `resultType` 写全类名：列名与属性名一致时 MyBatis 自动映射，不用写 `resultMap`。
- `<where>`：内部条件全 false 时整段消失；有内容时自动补 `WHERE` 并去掉开头多余的 `AND`。
- `<if test="title != null and title != ''">`：OGNL 表达式，`title` 是参数对象的属性；空串也判，否则会拼出 `LIKE '%%'`，结果对但白扫全表。
- `CONCAT('%', #{title}, '%')`：`#{}` 走预编译；写成 `LIKE '%#{title}%'` 占位符就被包进引号里，变成字面量，永远搜不到。
- `ORDER BY article.id DESC`：新的在前；`time` 可能重复，id 才是稳定排序键。
- `params: { title: query.title || undefined }`：空串转 undefined，axios 会直接不带这个参数。
- `res.data || []`：接口出错时给个空数组，表格不会因为拿到 `undefined` 而报错。
- `.finally` 关 loading：成功失败都关，否则请求一失败表格就一直转圈。

**⑤ 在你仓库里** —— SQL 在 `D:\my-project\xm-pro\springboot\src\main\resources\mapper\ArticleMapper.xml` 第 9~17 行；接口在 `ArticleController.java` 第 27~31 行；前端 `load` 在 `vue/src/views/Article.vue` 第 156~165 行。首页"最新新闻"在 `Index.vue` 第 105~108 行，用 `res.data.slice(0, 5)` 在前端截前五条——因为 `selectAll` 没有分页。详情接口 `ArticleController` 第 33~36 行 / `ArticleService` 第 22~24 行已经有了，页面还没调用，作业做详情页时就是 `request.get('/article/selectById/' + id)`。

**⑥ 常见坑** —— ① 搜索"甘草"搜不到，数据库里明明有 → 用了 `LIKE '%#{title}%'`，占位符被包进引号变成字面量 → 必须 `CONCAT`。② 首页"最新"里出现旧文章 → 后端没 `ORDER BY`，前端 slice 只是截前五条 → 排序必须放 SQL 里。③ 详情请求 404 → 写成 `/article/selectById?id=1`，而后端是 `@PathVariable` → 用 `/article/selectById/1`。

**⑦ 自测** —— 搜索为什么必须在后端做？前端把已查到的数组 `filter` 一遍不行吗？

<details><summary>展开解析</summary>

不行。前端手上只有**当前已经查出来的那一页数据**，数据库里还有成千上万条没到浏览器；前端 `filter` 只能过滤"已经看见的"，会把本该命中的结果漏掉。搜索条件必须变成 SQL 的 `WHERE`，让数据库去全表找——这也解释了为什么分页 + 搜索时，条件要一起带到后端。

</details>

### 2.11 图片回显：从一串 URL 到一张图

**① 讲义怎么说** —— 讲义 12"功能说明 3"要求"删除成功后，页面自动刷新表格数据，给出绿色成功提示"——重点都在"刷新"上。新闻列表同理：封面存的是 URL，页面要做的只是**把这个字符串交给 `<img>`**。

**② 一句话讲透** —— 回显是三段接力：**上传接口给地址 → 数据库存地址 → 页面把地址当 `src`**。任何一段错，页面都是一个灰色方块，而且三种错长得一模一样。所以排查顺序要固定：先看数据库里 `img` 是不是以 `http://` 开头，再把这段地址粘到浏览器地址栏看能不能打开，最后才怀疑前端。`el-image` 比裸 `<img>` 多两件事：`fit="cover"` 按比例裁剪不变形，`:preview-src-list` 点一下能看大图。

**③ 示例代码** ——

```vue
<el-table-column label="封面" width="120">
  <template #default="{ row }">
    <el-image
        v-if="row.img"
        :src="row.img"
        :preview-src-list="[row.img]"
        preview-teleported
        fit="cover"
        class="article-cover"
    />
    <span v-else>—</span>
  </template>
</el-table-column>
```

**④ 逐行拆解** ——
- `#default="{ row }"`：作用域插槽，`row` 是当前行的 `Article`；普通 `prop` 只能显示文本，图片必须走插槽。
- `v-if="row.img"`：没封面显示"—"；否则 `src=""` 会让浏览器把当前页面地址当图片再请求一次。
- `:src="row.img"`：URL 来自上传接口，是**绝对地址**（`http://localhost:8080/files/download/...`），所以直接能用。
- `:preview-src-list="[row.img]"`：必须传**数组**，传字符串预览会空白。
- `preview-teleported`：把预览层传送到 `body`，否则会被表格的 `overflow: hidden` 裁掉一半。
- `fit="cover"`：等比填满并裁剪；`contain` 是完整显示留白。封面用 cover，证书类用 contain。
- `class="article-cover"`：`view.css` 第 42~46 行固定 90×60，行高才整齐。

**⑤ 在你仓库里** —— 列表封面在 `D:\my-project\xm-pro\vue\src\views\Article.vue` 第 26~38 行；弹窗里的封面预览在第 72 行；上传成功回调在第 183~190 行。样式 `vue/src/assets/view.css`：`.cover-preview` 第 11~18 行（弹窗 160×100）、`.article-cover` 第 42~46 行（表格 90×60）。首页 `Index.vue` 第 60~65 行也是同一套写法。地址由 `FileController` 第 70~73 行生成。

**⑥ 常见坑** —— ① 列表全是裂图但数据库有值 → 存的是相对路径 `/files/download/x.png`，浏览器把它拼到 5173 端口 → 存绝对地址，或配 Vite 代理。② 本地正常，换端口/换机器后全裂 → URL 里写死了 `localhost:8080` 且已入库 → 库里只存文件名、渲染时拼前缀。③ 表格里点不开大图、封面被裁掉半个标题 → 漏了 `:preview-src-list`（或传成字符串）、`fit` 用了 cover 而容器比例差太多 → 预览传数组，裁切场景按需换 `contain`。

**⑦ 自测** —— 页面上的封面裂了，你按什么顺序排查？

<details><summary>展开解析</summary>

**从后往前**：① 打开 F12 的 Network，看图片请求是 404、500 还是根本发不出去；② 把数据库里的 `img` 复制到地址栏直接访问——不通就是 URL 或后端的问题（端口、目录、文件名）；③ 地址栏能打开但页面裂，才看前端（`src` 是不是相对路径、是否被 `v-if` 挡住、容器宽高是不是 0）。这个顺序能避免"在后端改半天，其实问题是前端拼错了端口"。

</details>
